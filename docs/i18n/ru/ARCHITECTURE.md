## Настройка базы данных Open Omniscience

> **Статус (проверено в аудите v0.0.7, `docs/archive/audits/00_BASELINE.md`):** слой базы данных
> **работает и протестирован** — сервер запускается, создаёт и использует хранилище SQLite, применяет миграции Alembic,
> и полный набор тестов (800+) проходит на нём. Старый баннер «ранний концепт —
> не работает», который раньше стоял здесь, описывал состояние до перестройки и давно
> устарел.

### 🗃️ SQLite — поддерживаемое хранилище

SQLite — это **бэкенд по умолчанию и единственный поддерживаемый и протестированный**. Он соответствует
локальной, однопользовательской архитектуре продукта.

- **Нулевая настройка:** база данных создаётся автоматически при первом запуске, по пути
  `<data dir>/open_omniscience.db`. Каталог данных — `OO_DATA_DIR`, если она задана, иначе каталог
  `data/` репозитория при запуске из исходников, иначе `$XDG_DATA_HOME/open-omniscience` (см. `src/paths.py`).
- **Автоматическая настройка:** движок применяет режим журнала `WAL`, `foreign_keys=ON`,
  `busy_timeout=30000` и `synchronous=NORMAL` к каждому соединению
  (`src/database/session.py`) — задавать их самостоятельно не нужно.
- **Полнотекстовый поиск** — это SQLite **FTS5** (`article_fts`, с внешним содержимым, синхронизируется
  триггерами — `src/database/fts.py`).
- **Измените расположение** через переменную окружения `DATABASE_URL` (**не** редактируйте
  исходные файлы): `DATABASE_URL=sqlite:////absolute/path/to/your.db`
- **Обслуживание:** периодический `sqlite3 <db> "VACUUM;"` освобождает место (аудит v0.0.7
  также удалил избыточный индекс, занимавший ~63% файла на больших корпусах; выполните `make
  migrate` один раз после обновления, чтобы удалить его из существующих баз данных).

### 🐘 PostgreSQL — экспериментальная заготовка, НЕ поддерживается

Честность важнее амбиций (вывод аудита ARCH-06): слой движка *распознаёт*
`DATABASE_URL` PostgreSQL (пул соединений через `DB_POOL_SIZE`/`DB_MAX_OVERFLOW`), **но**

- **полнотекстового поиска на PostgreSQL нет** — настройка FTS5 намеренно ничего не делает на
  движках, отличных от SQLite, так что вкладка «Поиск» была бы мёртвой;
- набор тестов никогда не запускается на PostgreSQL, и никакая CI его не покрывает;
- ни одно опубликованное развёртывание его не использовало.

Считайте PostgreSQL **непротестированной заготовкой для возможного будущего**, а не выбором, который можно
сделать сегодня. Если масштаб с несколькими писателями когда-нибудь станет реальным требованием, пунктом дорожной карты будет
путь поиска на `tsvector` плюс матрица CI для PostgreSQL — пока это не реализовано, эта страница не будет
притворяться.

### 🔄 Миграции

Alembic настроен в **корне репозитория** (`alembic.ini`, `migrations/`). Alembic
устанавливается вместе с приложением (это основная зависимость — отдельная установка не нужна).

- **Новые базы данных** создаются полностью (`create_all` + FTS) и автоматически помечаются текущей
  головной миграцией при запуске.
- **Обновление существующей базы данных:**
  ```bash
  make migrate          # = alembic upgrade head, from the repo root
  ```
- **Создание миграции** (для участников): отредактируйте `src/database/models.py`, затем
  ```bash
  alembic revision --autogenerate -m "your message"
  alembic upgrade head
  ```
  и проверьте сгенерированный файл — автогенерация пропускает виртуальные таблицы FTS (они находятся в
  `src/database/fts.py` и применяются при запуске).
- **Откат:** `alembic downgrade -1`.

### 📊 Схема базы данных

#### Таблицы:

##### `sources`
| Столбец | Тип | Описание |
|--------|------|-------------|
| `id` | INTEGER | Первичный ключ |
| `name` | STRING(100) | Название источника (например, "BBC News") |
| `domain` | STRING(255) | Домен источника (например, "bbc.com") |
| `rss_url` | STRING(500) | URL RSS-канала (если есть) |
| `rate_limit_ms` | INTEGER | Задержка между запросами в миллисекундах |
| `enabled` | BOOLEAN | Активен ли источник для сбора |
| `priority` | INTEGER | Уровень приоритета (1 = высокий, 3 = низкий) |
| `tags` | STRING(500) | Список тегов через запятую |

##### `articles`
| Столбец | Тип | Описание |
|--------|------|-------------|
| `id` | INTEGER | Первичный ключ |
| `url` | STRING(1000) | Исходный URL статьи |
| `canonical_url` | STRING(1000) | Канонизированный URL (для обнаружения дубликатов) |
| `source_id` | INTEGER | Внешний ключ на `sources` |
| `title` | STRING(500) | Заголовок статьи |
| `content` | TEXT | Полный текст статьи |
| `published_at` | DATETIME | Дата/время публикации (формат ISO) |
| `language` | STRING(10) | Код языка (например, "en", "fr") |
| `hash` | STRING(64) | Хеш SHA-256 содержимого (для обнаружения дубликатов) |
| `created_at` | DATETIME | Метка времени поступления статьи |

> Столбцы выше — основные поля; источником истины служат действующая схема (`src/database/models.py`)
> и миграции Alembic в `migrations/versions/`.
> `articles` также содержит поля происхождения/анализа (author, word_count, region,
> country, sentiment) и столбец со сжатым содержимым.

##### Другие таблицы (полный список столбцов см. в моделях / миграциях)

| Таблица | Назначение |
|-------|---------|
| `source_groups`, `source_metadata`, `source_group_association` | Группировка источников + метаданные гео/robots |
| `commodity_prices` | Наблюдаемые ценовые точки (символ, дата, цена, валюта, **единица**, рынок, источник) — графики + корреляция цен и новостей |
| `market_extraction_rules` | Правило для источника (CSS-селектор / атрибут / регулярное выражение), находящее цену одного инструмента на одной странице; категория financial/stock/commodity |
| `keywords` | Уникальный термин ключевого слова/сущности (нормализованный, язык, `is_entity`/`entity_type`, происхождение **`extractor`**) |
| `keyword_mentions` | Одна запись на пару (статья, ключевое слово): число + смещение первого символа + денормализованные `observed_on`/`country`/`city` — на них работают тренды, ассоциации, контекст и карта в Аналитике |
| `wiki_pages` | Отслеживаемая страница Wikipedia в одном языковом разделе; хранит **одну** сжатую полнотекстовую базовую версию |
| `wiki_revisions` | Одна отслеживаемая правка: **diff + знаковая разница в байтах** + флаги/теги (а не повторная копия), необязательные оценки ORES, честный флаг крупной правки + причины |
| `article_analyses` | Производные результаты LLM (резюме/перевод) с указанием модели и промпта |
| `keyword_categories`, `external_sources`, `article_links`, … | Категоризация ключевых слов + отслеживание связей ссылок и источников |

#### Индексы:
- `idx_article_hash`: Уникальный индекс по `hash` (для обнаружения дубликатов).
- `idx_article_canonical_url`: Индекс по `canonical_url` (для поиска по URL).
- `idx_article_source_id`: Индекс по `source_id` (для запросов по источнику).
- `idx_article_content`: Индекс по `content` (для полнотекстового поиска).

### 🔍 Полнотекстовый поиск

Полнотекстовый поиск **уже создан и подключён** — включать ничего не нужно. Хранилище
содержит таблицу FTS5 с внешним содержимым (`article_fts`), синхронизируемую триггерами; схему см. в
`src/database/fts.py`, а путь запроса — в `search_ids` в `src/api/main.py`
(разрешение только идентификаторов в итоговом порядке, полные строки загружаются лишь для текущей страницы).

Раньше этот раздел предлагал рецепт «подумайте о создании виртуальной таблицы» для SQLite и
рецепт `to_tsvector` для PostgreSQL. Оба были ошибочны: рецепт для SQLite описывал ручное создание
таблицы, которую приложение поставляет и обслуживает само (под *другим* именем, так что следование ему
привело бы ко второму, необслуживаемому индексу), а у PostgreSQL здесь вообще нет пути поиска,
что раздел о хранилище выше называет первой причиной, по которой он не является поддерживаемым бэкендом.

### 🚨 Устранение неполадок

#### Распространённые проблемы:

##### SQLite:
- **«Database is locked»**:
  - SQLite допускает только одного писателя одновременно. Режим WAL включён по умолчанию
    (`src/database/session.py`), а общий для процесса шлюз единственного писателя
    (`src/database/writer.py`) упорядочивает записи внутри приложения, так что одновременные поступление данных и
    импорт больше не конфликтуют. Устойчивая блокировка означает, что запись ведёт другой *процесс*.

- **«Too many open files»**:
  - SQLite открывает новое соединение для каждого потока. Ограничьте число потоков или используйте пул соединений.

- **«Relation does not exist» / «no such table»**:
  - Выполните миграции: `alembic upgrade head`.

### 📌 Лучшие практики

1. **Создавайте резервные копии через приложение, а не с помощью `cp`**:
   - Используйте Настройки → Резервное копирование (или `GET /api/database/backup` для согласованного снимка).
     Ручное копирование `open_omniscience.db` — **не** резервная копия: хранилище работает в режиме WAL,
     поэтому в рабочем файле нет того, что ещё находится в `-wal`, а в **зашифрованном**
     по умолчанию хранилище скопированный файл бесполезен без парольной фразы и не несёт
     обязательства целостности. Собственный путь приложения выполняет контрольную точку, потоковую передачу и подпись.

2. **Тестируйте миграции**:
   - Всегда тестируйте миграции на резервной копии базы данных, прежде чем применять их в рабочей среде.

3. **Следите за производительностью**:
   - Настройки → Диагностика содержит журнал медленных запросов, журнал задержек запросов и
     отчёт о шлюзе записи; CLI `sqlite3` работает с незашифрованным хранилищем.

4. **Оптимизируйте запросы**:
   - Инструмент — `EXPLAIN QUERY PLAN`. Учтите, что SQLite пишет `SCAN` **как** для простого
     сканирования таблицы, **так и** для сканирования только по индексу — `SCAN <table> USING [COVERING] INDEX …`
     — это нормально; тревожный признак — простой `SCAN <table>` без `USING`
     (`src/monitoring/slowquery.py` классифицирует именно по этому признаку).

5. **Ограничивайте срок хранения данных**:
   - Регулярно архивируйте или удаляйте старые статьи, чтобы база данных оставалась управляемой.
   - Пример: удаление статей старше 1 года:
     ```python
     from datetime import datetime, timedelta
     one_year_ago = datetime.now(timezone.utc) - timedelta(days=365)
     session.query(Article).filter(Article.published_at < one_year_ago).delete()
     session.commit()
     ```

## Справочник по API

Актуальный и всегда точный справочник по API генерируется самим приложением:

- **Swagger UI / ReDoc:** по умолчанию отключены (они загружают ресурсы со сторонних хостов); запустите приложение с `OO_API_DOCS=1`, чтобы получить http://127.0.0.1:8000/docs и `/redoc`
- **OpenAPI JSON:** http://127.0.0.1:8000/openapi.json

Приложение привязывается только к loopback-интерфейсу и (для одного локального пользователя) не требует аутентификации.

### Группы конечных точек

Это **карта ключевых групп, а не исчерпывающий список** — действующий
`/openapi.json` (выше) всегда авторитетен. Маршрутизаторы подключаются в
`src/api/main.py` через `include_router(...)`; группы с пометкой **[analysis]** требуют
дополнения `[analysis]` (без него приложение всё равно запускается, а эти конечные точки отключены).

| Префикс | Что делает |
|--------|--------------|
| `GET /api/health` | Проверка работоспособности + версия |
| `GET /api/articles`, `/api/articles/export` | Булев полнотекстовый поиск (FTS5) + экспорт CSV/JSON |
| `POST /api/ingest`, `/api/sources/{id}/ingest`, `/api/sources/{id}/ingest-email` | Этичное поступление данных: один URL, RSS-канал, почтовый ящик IMAP |
| `… /api/sources`, `/api/sources/...` | Управление источниками + группами + метаданными |
| `POST /api/sources/seed-defaults` | Заполнение курируемых каталогов источников (новости + рынки + сгенерированный мировой каталог) |
| `GET /api/database/stats`, `/coverage`, `/countries` | Число строк корпуса + размер на диске; охват по странам; число источников + тематические ключевые слова по странам |
| `GET /api/database/backup` | Загрузка согласованного снимка SQLite (только для незашифрованного хранилища SQLite; отклоняется для запроса с другого сайта или с Host, который защита от DNS-rebinding не обслуживает, а при имени, отличном от loopback, — для запроса, не указывающего страницу, с которой он пришёл, если он не отправляет `X-OO-Download: 1`; по одному за раз на процесс; записывается в закрытую папку `.oo-backup-*` рядом с базой данных и удаляется, когда загрузка завершается или процесс останавливается (принудительное завершение оставляет её для очистки при следующем запуске, которая сразу удаляет папку мёртвого владельца); 507, когда том данных не может её вместить) |
| `POST /api/database/v2/restore/preview`, `/v2/restore/commit`, `/api/backup/v2/*` | **Только добавляющее** восстановление через подписанный артефакт `oo-backup-2`: предпросмотр плана слияния, затем применение. Восстановление **никогда не перезаписывает ваш корпус** — оно сливает данные без дубликатов, сохраняя локальные значения при конфликте (разрушительный путь замены был удалён 2026-06-13) |
| `GET/PUT /api/settings` | Настройки интерфейса (тема, лимит результатов по умолчанию) |
| `… /api/scheduler/...` | Фоновый сбор: статус, запуск, остановка, немедленный запуск, конфигурация. Начиная с цикла `0.4` сбор идёт **параллельными полосами** (`rss` / `crawl` / `markets` / `wiki` / `law`), а не в одном режиме планировщика — хранилище по полосам в `… /api/storage/...`, а вкладка **Живые источники** читает `… /api/living/...` (что изменилось в Wikipedia, законодательстве и картах) |
| `… /api/markets/rules`, `/rules/{id}/run`, `/overview` | Правила извлечения цен для источников + «тестовый» запуск + обзор Рынков |
| `GET /api/markets/feeds`, `POST /feeds/{key}/import`, `/feeds/import-url` | Каталог официальных ценовых CSV-каналов + импорт (FRED/World Bank/EIA) + импорт по пользовательскому URL |
| `GET /api/catalog/export.csv`, `/template.csv`, `/columns`, `POST /api/catalog/import` | Экспорт списка источников в CSV / шаблон / столбцы / импорт с обновлением по домену |
| `… /api/insights/...` | Аналитика ключевых слов и сущностей: статус, переиндексация, топ, растущие, тренд, ассоциации (PMI), контекст, карта |
| `GET /api/timemap`, `/timemap/range` | Пространственно-временные сигналы на одной карте с осью времени (якоря + геокодированный корпус + по выбору бедствия/упомянутые даты); `?kinds`, `?start`/`?end` окно в дробных годах, `?hazards`, `?articles`, `?mentions`, `?days` |
| `… /api/article-dates/...` | Даты, упомянутые в тексте статей, извлечённые как подтверждаемые человеком теги статьи: список/извлечение по статье, подтверждение/отклонение, пакетная индексация, фильтр корпуса по дате |
| `GET/POST /api/llm/...` | Локальная LLM (Ollama): работоспособность, модели, генерация, резюме статьи |
| `… /api/commodities/...` | Цены на сырьё (импорт / CSV / список) + честная корреляция цен и новостей |
| `POST /api/analysis/...` | Научно строгая статистика: t-критерий, корреляция, ANOVA, Манна — Уитни, доверительные интервалы |
| `GET /api/monitoring/...` | Реальная доступность источников + аномалии объёма корпуса |
| `POST /api/verify/image-metadata` | Честное извлечение EXIF/метаданных изображений |
| `POST /api/reports/evidence`, `/evidence/verify` | Подписанные пакеты доказательств с защитой от подделки |

Маршрутизаторы с пометкой **[analysis]** (сырьё, статистика, ключевые слова, фрейминг)
требуют дополнения `[analysis]`; без него приложение всё равно запускается с основным
ядром, а эти конечные точки отключены.

Примечания о поведении:
- Поступление данных идёт только через этичный загрузчик (robots.txt с отказом по умолчанию, ограничение
  частоты); конечные точки LLM возвращают **503**, если Ollama недоступна (никогда не поддельный ответ).
- Проверка доказательств: передайте открытый ключ подписанта, чтобы доказать происхождение, а не только
  целостность (см. [QUICKSTART](QUICKSTART.md) и `scripts/verify_evidence.py`).
- Настройки цепочки хранения — это *предпочтения*, а не гарантии: `GET/PUT /api/custody/settings`
  всегда сообщают **эффективное** состояние (предпочтение **и** доступность библиотеки), так что
  постквантовая подпись / OpenTimestamps никогда не выглядят включёнными, когда нужное дополнение
  отсутствует. Привязка по умолчанию использует офлайн-провайдер `local`; OpenTimestamps и
  привязка к публичным блокчейнам сопровождаются предупреждением о конфиденциальности (см.
  [CHAIN_OF_CUSTODY](USER_MANUAL.md)).

## Интернационализация (i18n) — как сделать приложение многоязычным

> Цель: **весь интерфейс** (а со временем и **документация**) примерно на
> дюжине языков, чтобы расширить открытый доступ в сторону «почти всех людей». Сделано
> по-проектному: **офлайн, без CDN, без API перевода во время работы, без телеметрии** и
> **честно** в отношении качества перевода (мы не выдаём машинные догадки за
> авторитетные).

**Позиция честности.** *Заготовка* делает язык **доступным для выбора уже сейчас** и показывает
английский для любой непереведённой строки — неполная локаль никогда не ломает интерфейс (с этого
механизма начинается любая будущая локаль — `it`, `tr`, `vi`, …). Каждая локаль помечается `complete | draft | stub`. Сопровождающий
поставляет только то, за что может поручиться; всё остальное заполняется **вкладом
сообщества** (именно так открытый код расширяет доступ).

### Архитектура (офлайн, без зависимостей)

`src/static/i18n.js` + `src/static/locales/<code>.json`. Без шага сборки, без сети.

- **Английский — это ключ.** Файлы локалей сопоставляют **английскую строку интерфейса → её перевод**
  (например, `"Search the corpus": "Rechercher dans le corpus"`). Это позволяет доработать
  существующий интерфейс, не помечая каждый элемент, и сохраняет английский как канонический
  источник.
- **`OOI18N.setLang(code)`** загружает `locales/<code>.json`, сохраняет выбор в
  `localStorage` (`oo.lang`), устанавливает `document.documentElement.lang` и `dir` (RTL для
  `ar`/`ur`), затем **`apply()`** обходит DOM — переводя текстовые узлы, чей обрезанный
  текст совпадает с ключом, а также атрибуты `placeholder`/`title`/`aria-label`. Неизвестные
  строки остаются как есть (откат на английский) — ничего никогда не ломается.
- **Динамическое содержимое** (данные: заголовки статей, названия источников, числа) **никогда**
  не переводится — только элементы интерфейса. Элементы интерфейса, отрисовываемые JS (палитра команд, выдвижная панель), вызывают
  `OOI18N.apply()` после отрисовки.
- Каждая локаль содержит `_meta` (`name`, `native`, `dir`, `status`).

#### Интеграция (фаза 2 — выпущена; Desk с тех пор выведен из употребления)

Две строки в `index.html` (и, до его вывода из употребления 2026-06-10, в `desk.html`),
затем выбор языка:

```html
<script src="/static/i18n.js"></script>
<!-- after first render and on each view change: --> OOI18N.apply();
```

Селектор **Язык** находится в Настройках и вызывает `OOI18N.setLang(code)`;
выбор сохраняется вместе с остальными локальными настройками интерфейса.

### Документация на многих языках

Документы длинные, и качество перевода для них важнее, чем для коротких строк интерфейса, поэтому:

- Структура: `docs/i18n/<code>/<DOC>.md` повторяет `docs/`.
- **Английские документы остаются каноническими**; переводы — работа сообщества/сопровождающего,
  каждый помечен датой перевода и коммитом английской версии, которому он соответствует.
- Мы **не** переводим документы машинным способом автоматически и не выдаём их за авторитетные — это
  нарушило бы принцип честности проекта. Начинайте с самых ценных и коротких
  документов (QUICKSTART, обзор «Что вы увидите первым», ETHICS) для каждого языка.

### Процесс участия (открытый доступ по замыслу)

1. Скопируйте `locales/en.json` → `locales/<code>.json`, переведите значения, установите `_meta.status`.
2. Для языков с письмом справа налево установите `_meta.dir: "rtl"`.
3. Запустите (запланированную) проверку покрытия ключей: отчёт об отсутствующих/лишних ключах относительно `en.json`.
4. Отправьте. Непереведённые ключи просто показываются на английском, пока их не заполнят.

## Контракт экспорта (с версиями)

Машиночитаемые экспорты несут стабильный, самоописывающий контракт (схема `oo-export-1`,
0.0.8 часть 2 / RM-15), чтобы последующим конвейерам никогда не приходилось гадать:

- **JSON** (`/api/articles/export?format=json`, `/api/links/export.json`): конверт —
  `{export_schema, kind, app_version, generated_at, query, count, articles|data}`. Объект
  `query` — дословная порождающая выборка; происхождение путешествует вместе с данными.
- **CSV** (`/api/articles/export?format=csv`): без строки комментария (она сломала бы наивные читатели);
  тот же конверт передаётся в HTTP-заголовках (`X-OO-Export-Schema`, `X-OO-App-Version`,
  `X-OO-Generated-At`, `X-OO-Query`). Столбцы сохраняют порядок, а новый всегда только
  добавляется в конец: `Fetched From Host` (пункт очереди 61) — хост, с которого страница была загружена после
  перенаправлений, пустой, если не записан; JSON-экспорт передаёт его как `fetched_host`.
- **Граф цитирования** (`/api/links/export.graphml`, `.json`): граф «кто кого цитирует»
  (сохранённые статьи → внешние регистрируемые домены). **Только подсчёты — никакой выведенной
  достоверности, никаких оценок**; оговорка встроена в сам файл. GraphML открывается в
  Gephi/yEd/NetworkX.

Изменения схемы повышают `oo-export-N`; существующие поля никогда не перепрофилируются молча. Поле,
добавленное рядом с ними (замыкающий столбец CSV, новый ключ JSON), оставляет поля каждого существующего читателя
на прежних местах, поэтому схему оно не повышает.
