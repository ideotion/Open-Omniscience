### 0. Контекст развёртывания (РЕШЕНО — определяет всё, что ниже)

Эта сборка нацелена на **одну конкретную среду и одного пользователя**. Эти ответы теперь зафиксированы и снимают
несколько прежних пунктов `⚠️ DECIDE`.

- **Хост:** Qubes OS, работа внутри **Debian AppVM** (на основе шаблона).
- **Python:** **3.13 как интерпретатор по умолчанию.**
- **Пользователь:** **один основной пользователь (владелец проекта)** — без многопользовательских учётных записей, без RBAC.
- **Интерфейс:** **веб-интерфейс + REST API, привязанные только к `127.0.0.1`** (loopback). Никаких внешних слушателей.
- **Сетевая позиция:** local-first; исходящие соединения только во время сбора данных/загрузки LLM; **никаких входящих** вообще.

#### 0.1 Что Qubes меняет в дизайне

Qubes — это не «просто Debian». Его модель безопасности и жизненный цикл AppVM накладывают жёсткие ограничения, которые
установщик и среда выполнения **обязаны** соблюдать:

1. **Сохранение файловой системы избирательно.** В AppVM перезагрузку переживают только **`/home`, `/usr/local` и `/rw`**;
   корневая файловая система **сбрасывается из TemplateVM при каждой загрузке**. Поэтому:
   - Приложение, его virtualenv, база данных, собранные данные, журналы, журнал аудита и любые загруженные модели LLM
     **должны находиться в `/home/user/...`** (рекомендуется: `/home/user/open-omniscience`).
   - **Пакеты `apt`/системные пакеты *не* сохраняются**, если установлены в AppVM. Системные зависимости нужно
     устанавливать **в TemplateVM** (и перезагружать AppVM) либо подключать через `bind-dirs` Qubes.
     Установщик должен **разделять**: «системные зависимости → TemplateVM» и «Python venv + приложение → AppVM `/home`».
2. **Никаких допущений о постоянном root.** Изменения root в AppVM исчезают при перезагрузке. Рассматривайте AppVM как:
   постоянный `/home`, эфемерный root.
3. **Сеть через NetVM.** AppVM выходит в интернет только через назначенный ей сетевой/межсетевой
   qube. Приложение должно **корректно деградировать без сети** и никогда не предполагать наличие подключения.
4. **Нет GPU.** Проброс GPU непрактичен в типичных конфигурациях Qubes → **инференс LLM только на CPU**.
   По умолчанию — **небольшие модели** (например, `gemma2:2b`, `llama3.2:3b`, `qwen2.5:1.5b`); большие модели — по выбору.
5. **Air-gap / разделение на ВМ — первоклассный *будущий* вариант (не v1).** Qubes делает естественным шаблон
   «этичный сбор в сетевом qube, анализ/хранение в офлайн-хранилище qube» через **qrexec/qubes-rpc**. v1
   работает в **одной AppVM**; архитектура должна сохранять чистую границу *загрузки*, чтобы последующее разделение было
   изменением развёртывания, а не переписыванием. (В репозитории уже есть рудиментарные материалы `src/qubes/rpc/` и
   `docs/QUBES_*` — их следует пересмотреть/заменить, а не доверять им.)

#### 0.2 Последствия Python 3.13 (снимает конфликты версий зависимостей)

- **Основной стек чист под 3.13:** FastAPI, uvicorn, SQLAlchemy 2.x, pydantic 2.x, requests, httpx,
  beautifulsoup4, feedparser, numpy, pandas, scipy, scikit-learn, statsmodels — все поставляют wheels для 3.13.
- **Локальной LLM НЕ нужно тяжёлое ML на Python.** Ollama — это **отдельный нативный бинарный файл**; приложение общается
  с ним **только по HTTP**. Полная функциональность LLM работает на 3.13 с одним лишь `httpx`/`requests` — без
  `torch`/`transformers` в приложении вообще.
- **Тяжёлые ML-библиотеки исключены из ядра.** `torch`, `onnx`/`onnxruntime`, `tensorflow`,
  `pyAudioAnalysis` и стек обнаружения дипфейков **удалены** для v1, потому что они (a) сейчас
  **сфабрикованы** («CNN для дипфейков» никогда не выполняет инференс), (b) тяжёлые и **здесь только на CPU**, и
  (c) несут риск отсутствия wheel для 3.13 у каждого пакета (`pyAudioAnalysis` не поддерживается; `igraph`/`leidenalg`/`gensim`
  нужно проверить каждый перед использованием). Любая будущая ML-функция должна оправдать свой вес и доказать наличие wheel для 3.13.
- **Один манифест зависимостей, закреплённый на 3.13.** Заменить шесть противоречащих друг другу файлов requirements одним
  корневым `pyproject.toml` (`requires-python = ">=3.13"`) + необязательными наборами (`[llm]`, `[analysis]`, `[dev]`).
  Удалить «корректирующие» комментарии от ИИ и невозможные закрепления версий.

#### 0.3 Модель безопасности для одного локального пользователя (упрощает P0)

Поскольку единственный слушатель — loopback, а единственный пользователь — вы:
- **Аутентификация:** для v1 не требуется *при условии*, что сервер привязан строго к `127.0.0.1` и никогда не открывается
  правилом межсетевого экрана Qubes. (Один необязательный API-токен можно добавить позже, если будет прокси.) Это **снимает**
  замечание «нет аутентификации на эндпоинтах» *для данного развёртывания* — за счёт устранения сетевой доступности, а не
  добавления RBAC.
- **`/metrics`:** только loopback, как и всё остальное.
- **Безопасность установщика по-прежнему обязательна:** никаких неподтверждённых `rm -rf`, никаких непроверенных `curl | sh`, никогда не отбрасывать
  stderr менеджера пакетов — это вопросы корректности/безопасности независимо от однопользовательского режима.
- **Фронтенд-ресурсы размещаются локально** (никаких Google Fonts / React с CDN) — это требуется для офлайна/Qubes и
  для принципа конфиденциальности.

### 1. Определение в одном предложении

Open-Omniscience — это **локальная (local-first) платформа разведки на основе открытых источников с открытым кодом для журналистов-расследователей**,
которая этично объединяет множество источников данных со всего мира в **единый корпус с поиском, перекрёстными ссылками
и отслеживанием происхождения**, с необязательным **локальным ИИ** для анализа — и где каждый результат
спроектирован так, чтобы быть **научно и юридически обоснованным**.

### 2. Для кого оно и какие задачи ему поручают

**Основной пользователь:** журналист-расследователь, исследователь или аналитик — скорее всего, работающий в одиночку или в
небольшой редакции, часто чувствительный к конфиденциальности (есть источники, которых нужно защитить), иногда в ограниченных/изолированных от сети
средах.

**Основные задачи (jobs-to-be-done):**
1. *«Собрать всё, что относится к моему расследованию, из множества источников, в одном месте, автоматически».*
2. *«Искать и сопоставлять всё это вместе — статьи, рынки, письма, — чтобы находить связи».*
3. *«Помочь мне разобраться в больших объёмах текста»* (резюмировать, перевести, извлечь сущности) — **не
   отправляя мои данные никому.**
4. *«Сказать мне, чему можно доверять — или не доверять»* (проверить медиа, отметить манипуляции).
5. *«Доказать, откуда это взялось и что я это не изменял»* (происхождение для публикации/суда).
6. *«Предупредить меня, когда что-то меняется»* (источник замолкает, цена резко растёт, возникает нарратив).

### 3. Руководящие принципы (то, что не обсуждается)

Это сердце замысла, и они должны ограничивать каждую функцию. Там, где сегодняшний код нарушает один из них,
это дефект, а не компромисс.

1. **Local-first и способность работать офлайн.** Работает целиком на машине/сервере пользователя. Должно функционировать
   без интернета, кроме самого сбора данных. Подходит для использования в изолированной среде (с заранее подготовленными данными/моделями).
2. **Сохранение конфиденциальности.** Никакой телеметрии. **Никакие данные пользователя никогда не покидают машину** — особенно при обработке
   LLM (только локально через Ollama). ✅ РЕШЕНО (§0): все фронтенд-ресурсы (шрифты, JS-библиотеки)
   **размещены локально** — никаких обращений к CDN — это требуется для позиции Qubes/офлайн.
3. **100% FOSS.** Весь код и модели — с открытым исходным кодом. ⚠️ DECIDE: лицензия в корне — **GPLv3**, но
   в столпе 3 — **AGPL-3.0**; выберите одну для всего проекта (AGPL строже в отношении сетевого использования).
4. **Этичность по конструкции.** Соблюдать `robots.txt`, ограничения частоты запросов, идентифицировать бота, только публичные данные,
   никогда не обходить платный доступ и не использовать учётные данные для сбора. **Отказывать *закрыто*** — если соответствие нельзя
   проверить, не собирать.
5. **Обоснованные результаты (научно + юридически).** Каждый аналитический результат несёт честную неопределённость и
   прослеживаемое происхождение. **Никаких сфабрикованных чисел.** Оценка достоверности должна исходить из реального метода или
   не существовать вовсе. Цепочка ответственного хранения должна быть настоящей (подписанной, с защитой от подделки), а не простым файлом журнала.
6. **Единый корпус.** Всё загруженное — новости, финансовые данные, сырьевые товары, почта — хранится в **одной
   базе данных** и **сопоставимо в одном запросе**. Это причина существования продукта.
7. **Прозрачность важнее «мягкого» отказа.** Система никогда не должна молча деградировать до недействительного результата.
   Отсутствующая модель, заблокированный источник, недоступная зависимость → **видимый, явный статус**, никогда не
   молчаливая заглушка.

### 4. Базовая ментальная модель

```
        ┌─────────────────────────── INGESTION ───────────────────────────┐
        │  Web articles · RSS · Financial · Commodities · Email/Newsletters │
        │            (all ethically scraped / retrieved)                    │
        └───────────────────────────────┬───────────────────────────────────┘
                                         ▼
        ┌──────────────────── ONE UNIFIED, PROVENANCE-TRACKED STORE ────────┐
        │  articles · financial_data · commodity_data · emails · entities    │
        │  + links between them (article ↔ price move ↔ email ↔ entity)      │
        └───────────────────────────────┬───────────────────────────────────┘
                                         ▼
   ┌──────────── RETRIEVAL ────────────┐   ┌──────────── ANALYSIS (opt-in) ───────────┐
   │ Boolean / full-text search        │   │ Local LLM · verification · stats ·        │
   │ filters · cross-source correlation│   │ monitoring/alerts · correlation engines   │
   │ export (CSV/JSON) · reports       │   │ (every result: method + uncertainty)      │
   └───────────────────────────────────┘   └───────────────────────────────────────────┘
                                         ▼
                         GUI (search, dashboards, source mgmt, reports)
                         + REST API (everything available programmatically)
```

**Хребет (загрузка → единое хранилище → поиск → экспорт) должен быть абсолютно надёжным до любого столпа.**
Столпы — это *обогатители*, которые читают из общего хранилища и записывают обратно в него.

### 5. Функциональный охват по областям возможностей

#### 5.1 Загрузка данных (P0)
- **Типы источников:** новостные сайты (HTML), RSS/Atom-ленты. Позже: API, социальные платформы, сброс файлов.
  ⚠️ DECIDE: столп 4 перечисляет Twitter/X, Reddit, Telegram, Mastodon, S3/SFTP — подтвердите, какие (если вообще)
  входят в реальный охват, а какие лишь желаемые.
- **Этичный сборщик (одна общая реализация):** проверка robots.txt (с кэшем, с учётом http+https,
  **закрытый отказ** при неопределённости), ограничение частоты по источнику, идентифицирующий User-Agent, повторы/отсрочка.
  **Одна загрузка на URL** — никакой двойной загрузки, никакого «сырого» обходного пути.
- **Дедупликация:** на основе хэша содержимого + канонического URL; никогда не хранить одну и ту же статью дважды.
- **Нормализация:** надёжно извлекать заголовок, автора, дату публикации, язык, канонический URL, основной текст.
  ⚠️ DECIDE: реальное извлечение новостей требует правил для каждого сайта или библиотеки (например, в стиле trafilatura);
  текущий универсальный CSS-подход молча выдаёт «No Title/No Content». Подтвердите, что мы принимаем надёжное извлечение.
- **Планирование и инкрементальные обновления:** периодический повторный сбор, загрузка только нового/изменённого содержимого, возобновление
  прерванных запусков.

#### 5.2 Единое хранилище данных (P0)
- **Одна база данных**, хранящая все типы сущностей, с явными **таблицами связей**, соединяющими их
  (статья ↔ финансовый инструмент, статья ↔ сырьевой товар, статья ↔ письмо, статья ↔ именованная сущность).
- **Поля происхождения в каждой записи:** источник, метка времени загрузки, исходный URL, хэш содержимого,
  разделение сырого и обработанного.
- **Бэкенды:** SQLite для одного пользователя/рабочего стола; PostgreSQL для сервера/конкурентного использования.
  ⚠️ DECIDE: подтвердите SQLite по умолчанию + необязательный Postgres (в документах упоминаются оба; также Redis для кэширования —
  включать или нет?).
- **Журнал аудита:** только дополняемая, **защищённая от подделки** запись каждой загрузки и изменения.

#### 5.3 Поиск и извлечение (P0)
- **Полнотекстовый поиск** по всему корпусу.
- **Булевы операторы** (`AND`/`OR`/`NOT`), **фразы в кавычках** и **скобки с правильным
  приоритетом** — реализованные настоящей грамматикой или нативным FTS базы данных, а не строковыми трюками.
- **Структурированные фильтры:** источник, диапазон дат, язык, теги/категория, сущность, тип данных.
- **Постраничный вывод**, ранжирование результатов, фрагменты/подсветка.
- **Экспорт:** CSV и JSON (и ⚠️ DECIDE: форматы PDF/отчётов?), точно соответствующий отфильтрованному набору результатов.

#### 5.4 Перекрёстные ссылки и корреляция (P1 — отличительная черта)
- Переход от любой записи к связанным записям разных типов (статья → упомянутые компании → движения цен
  около даты публикации → связанные письма).
- **Движки корреляции** (финансы/сырьё ↔ новости), выявляющие *кандидатные* связи с
  **честной, определённой мерой** (и чётко помечающие, что корреляция ≠ причинность). Никаких сфабрикованных p-значений.
- Представление, сосредоточенное на сущности: всё, что корпус знает о человеке/организации/месте/инструменте.

#### 5.5 Анализ локальной LLM (P1)
- **Среда выполнения:** Ollama, полностью локально. Модели подключаемые; поставлять небольшую разумную модель по умолчанию, которая *действительно
  существует*. ⚠️ DECIDE: текущая модель по умолчанию `gemma4:e2b` и большинство перечисленных моделей (Gemma 4, Llama 4, Qwen 3.5)
  выдуманы — заменить каталог реальными тегами (например, `gemma2:2b`, `llama3.2:3b`, `qwen2.5`,
  `phi3`).
- **Возможности:** генерация, чат (с контекстом), извлечение (сущности/ключевые слова/резюме/цитаты/ссылки),
  перевод (многоязычный), анализ (тональность/тон/читаемость; предвзятость — только при честно ограниченной оценке),
  синтез (резюме, сравнения, хронологии, отчёты), пакетная обработка.
- **Громкая деградация:** если Ollama или модель отсутствуют, сказать об этом — никогда не возвращать фальшивый анализ.

#### 5.6 Проверка и защита от обмана — *Столп 3* (P2, охват уточняется)
- **Замысел:** обнаруживать изменённые медиа (дипфейки изображений/видео/аудио), пропагандистские приёмы, когнитивные

### Что было спасено на этом шаге (Столп 2)
- `src/analysis/statistical_tests.py` — t-тесты, ANOVA, хи-квадрат, Пирсон/Спирмен,
  Манн — Уитни, Уилкоксон, регрессия, Tukey HSD (scipy/statsmodels). Каждый результат
  содержит статистику, p-значение, степени свободы, размер эффекта, размер выборки.
- `src/analysis/confidence_intervals.py` — средние и доли (t/нормальное/Уилсон/
  Клоппер — Пирсон/Агрести — Коулл).
- Доступно через `POST /api/analysis/{t-test,correlation,anova,mann-whitney,confidence-interval}`,
  чтобы журналист мог проверить, действительно ли закономерность в его данных значима.
- Подлинные наборы тестов столпа 2 переехали вместе с кодом (`tests/test_statistical_tests.py`,
  `tests/test_confidence_intervals.py`).

### Что НЕ было спасено (и почему)
- `peer_review` / `consensus` / `reproducibility` столпа 2 — спекулятивные или поверхностные
  (например, воспроизводимость была рубрикой усреднения булевых значений). Отложены; возродить с настоящими
  методами при необходимости.
- Криминалистические детекторы столпа 3, имитированный мониторинг/threat-intel столпа 4, каркасы столпов
  5/6 — сфабрикованы или только дизайн; честные части уже находятся в `src/`.

### Итоговый эффект
Репозиторий теперь отражает то, что действительно работает: живое ядро ~16 тыс. строк (плюс
спасённая статистика), а желаемые/сфабрикованные ~50 тыс. строк столпов отложены в
`quarantine/pillars/`, вместо того чтобы выдавать себя за работающие функции.

### 0. Задание, сформулированное заново

Переработать весь графический интерфейс для конкретного человека: **оперативника, ищущего правду, —
следователя/журналиста, который *не* любит компьютеры**, который хочет понимать
мир таким, какой он есть на самом деле, и убедительно сообщать о своих находках. Результат должен быть
изящным, красивым, адаптируемым, глубоко настраиваемым, простым *и* глубоким, и настолько
хорошим, чтобы коллега, заглянувший через плечо, сказал: *«что это — можно мне тоже?»*
Он должен уважать то, чем проект уже является: **один пользователь, только loopback,
офлайн в первую очередь, без зависимостей, без телеметрии**, и подчиняться **Мюнхенской хартии**
(правда, проверка источников, конфиденциальность, никакой пропаганды).

#### Инженерная позиция (и честный компромисс)

Предыдущий интерфейс — один `index.html` на 2 200 строк, связывающий ~110 функций с ~150
эндпоинтами API. Эти функции *работают и протестированы*. Переписывание с нуля дало бы
более красивую оболочку с высоким шансом молча сломанных кнопок — полную
противоположность инструменту, всё достоинство которого — **честность**. Поэтому это
**полный редизайн всего, что пользователь видит и чего касается**, — визуального языка,
компоновки, модели навигации, информационной архитектуры, названий, онбординга,
настройки и двух совершенно новых поверхностей (панели Главная и встроенного в приложение
просмотрщика документации), — построенный *поверх проверенного слоя данных*, с сохранением каждого исходного ID
элемента, чтобы ничего не регрессировало. Отсутствие зависимостей остаётся абсолютным: **никаких CDN, никаких веб-
шрифтов, никакого фреймворка** — один самодостаточный файл, работающий при отключённой NetVM.

*Условие успеха:* она может прочитать в приложении, что именно оно будет и не будет делать.

### 2. Принципы дизайна (выведенные, а не заимствованные)

1. **Ясность важнее изобретательности.** Простые глаголы, человеческие подписи, одно очевидное основное
   действие на экран. Жаргон («ingest», «корпус», «корень Merkle») переводится или
   поясняется на месте, никогда не предполагается известным.
2. **Доверие — это и есть продукт.** Проверяемость, происхождение и «это число реальное,
   а не оценочное» выводятся на поверхность, а не прячутся. Эстетика должна *ощущаться* как
   инструмент, а не игрушка.
3. **Постепенное раскрытие.** Просто по умолчанию; глубина в одном клике. Продвинутые
   панели сворачиваются; редко используемые модули можно скрыть полностью.
4. **Настраиваемость, потому что доверие — дело личное.** Темы, акцентный цвет, плотность, размер шрифта,
   компоновка и *какие инструменты вообще отображаются* — решает пользователь, и всё это
   сохраняется только локально.
5. **Честность в интерфейсе.** Если возможность зависит от необязательного набора, интерфейс
   говорит об этом, а не притворяется. Ничто не изображает успех.
6. **Суверенность по конструкции.** Никаких внешних запросов любого рода. Внешний вид
   достигается системными шрифтами и нарисованными вручную SVG-иконками.
7. **Ориентация на клавиатуру — это ещё и ориентация на доступность.** Командная палитра и сочетания клавиш
   служат Даниэлю *и* делают всё приложение доступным без точной работы мышью.

#### Добавленные новые поверхности

- **Главная (панель).** *Обоснование:* Амаре нужна ориентация, а не пустое поле поиска.

  обучает. Это самый большой выигрыш в удобстве для основной персоны.

#### Получившаяся информационная архитектура

Плоская полоса из 9 вкладок превращается в **сгруппированную боковую панель** (сворачиваемую до иконок), упорядоченную
по тому, как на самом деле идёт работа:

- **Расследование** — Главная · Поиск · Аналитика · Временная карта · Википедия · *Рынки (продвинутое)*
- **Сбор** — Сбор · Источники · Библиотека
- **Доверие** — Доказательства и хранение
- **Система** — Настройки · Справка

Группировка превращает «девять равноправных незнакомцев» в «четыре намерения», а именно так Амара
и думает («я хочу что-то *найти*» / «я хочу *собрать*» / «я хочу *доказать*»).

### 4. «Вау» — что заставляет журналиста подвинуться ближе

- **Цельная визуальная система.** Глубокая тёмная тема «чернила» по умолчанию с уверенным
  единственным акцентом, щедрым ритмом отступов, настоящей типографской иерархией, моноширинным шрифтом для
  данных/хэшей, мягкой глубиной и сдержанной анимацией. Она читается как *инструмент*, а не
  *шаблон панели*.
- **Командная палитра (Ctrl/⌘-K).** Наберите текст, чтобы перейти куда угодно, выполнить любое действие или открыть
  любой документ. Сила для Даниэля; карта «а что я вообще могу здесь делать?» для Амары.
- **Элементы управления внешним видом** (Настройки → Внешний вид; живая выдвижная панель до 0.06, включённая
  в Настройки в 0.07). Предустановки тем (Ink, Slate, Midnight, Paper, Sepia,
  Terminal, High-contrast), образцы акцентных цветов, плотность, размер шрифта, сворачивание боковой панели

- **Главная, которая ориентирует**, онбординг, который обучает, и пустые состояния, которые направляют.
- **Доверие, сделанное видимым.** Хранение/проверка и подача «измерено, а не оценено»
  — часть эстетики, а не мелкий шрифт.
- **Полная офлайн-целостность.** Никаких сетевых обращений для элементов интерфейса — что само по себе
  функция, которую можно *показать* коллеге, заботящемуся о безопасности.

### 5. Модель настройки

Оформление хранится в `localStorage` (`oo.ui`) — никогда никуда не отправляется, — поэтому оно

темы, акцентный цвет, плотность, масштаб шрифта, состояние боковой панели и набор видимых
модулей. Разумные значения по умолчанию означают, что пользователь при первом запуске не трогает ничего из этого.

### 0. Сначала вернёмся к тому, чем это приложение является на самом деле

Прежде чем спорить об элементах интерфейса, — то, что не обсуждается (из `ETHICS.md`,
`DESIGN.md`, Мюнхенской хартии):

- **Один пользователь, одна машина, только loopback, офлайн в первую очередь.** Никаких учётных записей, никакого облака,
  никакой телеметрии. Часто запускается в Qubes AppVM с *отключённым* сетевым qube.
- **Оперативник, ищущий правду, который не любит компьютеры.** Следователь /
  журналист, чья работа — *понимать реальность и убедительно о ней сообщать*.
- **Продукт — это доверие.** Происхождение, проверка источников, «измерено, а не
  оценено», защита от подделки. Мюнхенская хартия (правда, проверка источников, защита
  источников, сопротивление пропаганде) — это хребет.
- **Суверенитет как эстетика.** Инструмент должен *ощущаться* принадлежащим пользователю,
  а не платформе.

Любой интерфейс следует оценивать по *этим* критериям, а не по тому, «похож ли он на
SaaS-продукт 2025 года».

### 1. Обвинительное заключение против «Console» (редизайна 0.05)

Сильнейшая версия довода о том, что 0.05 — неверное направление:

1. **Он одевает суверенный инструмент в одежду капитализма слежки.** Постоянная
   левая боковая панель, плашки статуса, командная палитра, выдвижная панель настройки с восемью
   темами — это визуальная грамматика Slack, Linear, Notion: *облачного SaaS*. Для
   пользователя, который не доверяет Big Tech и работает над чувствительными материалами, эта грамматика может
   читаться как «ещё одно приложение, которое за мной следит», подрывая то единственное, что здесь важнее
   всего: доверие. Внешний вид борется с ценностями.

2. **Он оптимизирован под демонстрацию, а не под работу.** Задание включало «заставить
   журналиста сказать *можно мне тоже?*» — пятисекундную реакцию через плечо.
   Проектирование под неё тянет к эффектности панелей (градиенты, анимированные счётчики,
   зоопарк тем) и прочь от тихой, насыщенной чтением, ориентированной на документы реальности
   расследования. Лучшие инструменты для глубокой работы (текстовый редактор, блокнот) —
   *простые*. Console может быть впечатляющим и поверхностным.

3. **Настраиваемость — это налог под видом подарка.** Восемь тем, образцы акцентных цветов,
   плотность, масштаб шрифта, скрытие отдельных модулей. Для *Амары* (не любящей компьютеры) каждый
   из этих пунктов — решение, которого она не хотела, и способ неправильно настроить свой инструмент.
   «Глубоко настраиваемый» служил формулировке задания и представлению *дизайнера* о
   щедрости — но по-настоящему простой инструмент **имеет собственное мнение**: он принимает правильное
   решение, чтобы пользователю не пришлось. Выбор — это когнитивная нагрузка.

4. **Информационная архитектура по-прежнему принадлежит программе, а не пользователю.** Console
   переименовал и перегруппировал вкладки, но меню по-прежнему остаётся списком *модулей*
   (Поиск, Источники, Аналитика, Рынки, Хранение…). Амара не мыслит модулями;
   она мыслит **делом**: «я иду по следу этой истории — собрать, прочитать, связать, доказать,
   опубликовать». И 0.04, и 0.05 заставляют пользователя переводить свою *работу* в *функции*
   приложения. Постоянная навигация из девяти пунктов назначения — это карта кодовой базы.

5. **Элементы интерфейса конкурируют с содержимым.** Фиксированная боковая панель + верхняя панель постоянно тратят
   ~250px и горизонтальную полосу на *навигацию, которой пользователь пользуется две секунды за
   сеанс*. То, что он делает на самом деле, — читает статьи, просматривает результаты, сравнивает
   различия, — получает остатки. Расследование — это чтение; Console недостаточно обслуживает
   чтение.

6. **«Вау» заимствовано, а не заработано.** Палитра и темы — *обязательный минимум*
   в современных приложениях: впечатляют именно потому, что знакомы. По-настоящему
   отличительные функции из разряда «я такого не видел» здесь — это *суть*:
   обнаружение войн правок в офлайн-Википедии, цепочка хранения с защитой от подделки, «каждое число — это
   реальный COUNT(\*)». Console украшает; он не драматизирует то, что действительно уникально.

Это серьёзное обвинение. Оно заслуживает настоящей альтернативы, а не опровержения.

---

### 2. В защиту Console (чтобы спор был честным)

- Постоянная навигация **обнаруживаема**: ничего не скрыто, что важно для
  новичка, который ещё не знает, что умеет инструмент. Модели «ступица и спицы» прячут
  возможности за кликом и догадкой.
- Настройка **отключаема**: значения по умолчанию разумны; пользователь, игнорирующий выдвижную панель,
  ничего не теряет. А темы действительно помогают при усталости глаз/ночной работе, которой полна
  эта профессия, и доступности (высокая контрастность, размер текста) для *реальных* пользователей.
- «Грамматика SaaS» — это также просто **текущее соглашение об удобстве**: люди умеют
  ей пользоваться с первого дня. У новизны ради новизны есть свой налог.
- Он по-прежнему **на 100% офлайн и без зависимостей**. Грамматика заимствована; суть
  (никакой сети, никакой телеметрии) — нет.

Обе позиции правомерны. Способ разрешить спор — не спорить дальше, а
**построить антитезис и пользоваться обоими**.

### 3. Антитезис: «Desk»

Если Console — это **широкая операционная консоль** (всё всегда в одном клике,
максимальная гибкость, грамматика современных приложений), то **Desk** — противоположный тезис:

> **Рабочий стол следователя: спокойный, с собственным мнением, ориентированный на содержимое и на задачу.
> Почти никаких элементов интерфейса. Одна задача за раз. Интерфейс не мешает чтению
> и размышлению.**

Конкретные обязательства, в которых Desk намеренно *не соглашается* с Console:

| Измерение | Console (тезис) | Desk (антитезис) |
|---|---|---|
| Навигация | Постоянная левая боковая панель (всегда видна) | **Никакой постоянной навигации.** Навигация — *по запросу*: спокойная главная страница, оверлей «Перейти к…» и ⌘K. Элементы интерфейса появляются только по вызову. |
| Точка входа | Панель статуса | **Главная, построенная вокруг задачи:** «Над чем вы работаете?» → Собрать · Найти и прочитать · Связать · Проверить и поделиться. Подача через задачу пользователя, а не модули приложения. |
| Настройка | 8 тем, акцент, плотность, шрифт, переключатели модулей | **Только две темы** (Paper / Ink), никаких ручек. С собственным мнением. Инструмент решает, чтобы не пришлось вам. |
| Эстетика | Консоль современного приложения (sans, плашки, градиенты) | **Редакционная / печатная:** заголовки с засечками, тепло бумаги, щедрые поля, удобная ширина строки. Ощущается как редакция, а не SaaS. |
| Что получает пространство | Навигация + статус, затем содержимое | **Содержимое.** Одна центрированная колонка для чтения; таблицы и просмотрщик статей получают место. |
| Сигнал доверия | Плашка статуса | Постоянная, тихая строка **«Локально · Офлайн · Ничто не покидает эту машину»** — суверенитет заявлен, а не подразумевается. |
| Реакция на демонстрации | «Изящно!» | «…о, это *спокойно*. И это всё моё». Более медленное, более глубокое «вау». |

Что Desk **сохраняет** (потому что это суть приложения, а не элементы интерфейса): каждую функцию
и каждый работающий эндпоинт. Desk и Console используют один и тот же движок и одни и те же
панели содержимого — они различаются *только* оболочкой, моделью навигации, подачей информационной архитектуры
и эстетикой. Это сделано намеренно: эксперимент остаётся контролируемым, так что вы
сравниваете **философию**, а не то, какой из них я случайно подключил тщательнее.

### 4. Как их оценивать (критерии)

Оценивайте каждый по ценностям — а не по ощущению «какой выглядит симпатичнее»:

1. **Доверие** — какой из них *ощущается* принадлежащим вам и не предаст вас?
2. **Спокойствие против возможностей** — какой позволяет думать? какой делает возможности находимыми?
3. **Путь новичка** — посадите *Амару* без подготовки: какой быстрее приведёт её к результату, с
   меньшим страхом?
4. **Путь опытного пользователя** — *Даниэль* за клавиатурой: какой не мешает ему?
5. **Чтение** — откройте длинную статью / сравнение правок Википедии в каждом. Где лучше
   *читать*?
6. **Пятисекундный тест** — покажите каждый коллеге. Какой вызывает «можно мне тоже?» —
   и именно на эту ли реакцию вы действительно хотите оптимизировать?
7. **Соответствие духу** — какому из них вы бы доверили работу с отключённой сетью в
   хранилище Qubes?

### 5. Прогнозируемые плюсы / минусы (моя честная ставка, подлежит проверке)

**Console** — *Плюсы:* обнаруживаемость, привычность, гибкость, доступные ручки настройки, блеск
на демонстрации. *Минусы:* перегружен элементами интерфейса, нагрузка решениями, ощущение типичного SaaS, которое может подорвать доверие,
информационная архитектура по-прежнему построена вокруг модулей.

**Desk** — *Плюсы:* спокойствие, приоритет содержимого/чтения, собственное мнение (никакого налога на настройку),
вход через задачу, эстетика, которая *укрепляет* суверенитет и доверие. *Минусы:*
возможности — в одном вызове (клик/нажатие клавиши), меньше ручек доступности, менее
«впечатляющий» с первого взгляда, новизна требует небольшого обучения.

### 1. Основная идея: ссылки — это граф цитирования

Рассматривайте каждую статью как узел, а каждую исходящую ссылку — как направленное ребро к URL (и
к его домену). Этот граф отвечает ровно на то, что вы спросили:

- **«Собрать все статьи, говорящие об одной и той же ссылке».** = сгруппировать статьи по
  внешнему URL, который они цитируют → **входящая степень** URL — это «сколько моих статей указывают
  сюда». Высокая входящая степень = **хаб**: часто первичный документ, сообщение информагентства или
  широко обсуждаемый источник.
- **«Обнаруживать тренды через внутренние ссылки».** = следить за входящей степенью во времени; URL или
  домен, цитирование которого резко растёт, — это *тренд*, основанный на том, что репортёры действительно цитируют,
  а не просто на частоте ключевых слов.
- **«Проследить оригинальный / изначальный источник».** = в кластере статей об одной
  истории оригинал — это узел, на который **ссылаются** остальные, и/или самый ранний, и/или тот,
  который цитирует **первичный документ** (суд/госорган/набор данных). Ссылки + метки времени + указание
  на информагентство позволяют его триангулировать.

Это *анализ совместного цитирования* — дешёвый, прозрачный и объяснимый. Никакого чёрного ящика.

### 2. Поэтапные стратегии (каждую можно выпустить отдельно)

#### P0 — Подключить извлекатель к загрузке (чтобы граф существовал)
- Вызывать `LinkExtractor` во время загрузки на полученном HTML; сохранять исходящие
  **внешние** ссылки в `article_links` (пропуская внутреннюю навигацию, рекламу и — согласно
  `ROADMAP.md` — ссылки на изображения/двоичные файлы). Хранить normalized_url + текст якоря + тип.
- Сопоставлять домен каждой внешней ссылки с известным `Source`/`ExternalSource`, где
  возможно (чтобы «кто кого цитирует» можно было свести к изданиям и **владельцам**).
- Дёшево, детерминированно, офлайн. Ничего не загружается сверх того, что загрузка уже получила.

#### P1 — Агрегация + API (ответить на вопрос пользователя)
Эндпоинты только для чтения поверх графа:
- **`top-cited`** — самые цитируемые URL/домены в окне (сигнал тренда).
- **`articles-by-link`** — для заданного URL/домена каждая статья в корпусе, которая его цитирует
  («собрать все статьи, говорящие об одной и той же ссылке»).
- **`link-graph`** — узлы/рёбра для темы или окна, для визуализации.
- **`co-citation`** — статьи, цитирующие *одни и те же* внешние источники (кандидаты в кластеры
  «одна и та же история»), с подсчётом пересечений.

#### P2 — Интерфейс: представление «Ссылки и источники» в Аналитике
- Ранжированный список **самых цитируемых ссылок/доменов** (клик → все цитирующие статьи).
- Небольшой масштабируемый **граф цитирования** (повторно использовать SVG-подход, уже применённый для
  карты в Аналитике, — никаких новых зависимостей).
- Всегда показывает **размеры выборок** («цитируется в 14 ваших статьях») — измерено, а не
  угадано. Пользователь кликает, исследует, решает.

#### P3 — Родословная первоисточника
Для кластера статей об одной истории представить **родословную**, ранжированную по сигналам
(каждый показан, ни один не решающий):
- входящая степень (на кого ссылаются остальные),
- самая ранняя метка времени публикации,
- указание на информагентство (AFP/Reuters/AP — мы уже ставим тег `wire-agency`),
- наличие ссылки на **первичный документ** (госорган/суд/набор данных/препринт).
Результат: «первичный документ → первое сообщение → отголоски» в виде цепочки, которую читает пользователь.

#### P4 — Единообразие и эхо (связано с концентрацией СМИ)
- **Обнаружение почти дубликатов** (дешёвые MinHash/SimHash) для пометки синдицированного/скопированного текста
  в разных изданиях — строится на `src/ingestor/duplicate_detector.py`.
- **Оценка эха**: кластер, в котором многие издания цитируют **один** источник (или друг друга в
  замкнутой петле) и добавляют мало оригинальных ссылок = сильное эхо. Разнообразное цитирование первичных источников
  = независимая журналистика.
- **Наложение концентрации**: взвешивать эхо по **собственности** — если эхо-кластер соответствует
  одному владельцу/блоку (случай «~7 миллиардеров владеют ~90%»), показать это. Требует
  графа собственности (Wikidata P127/P749 + вручную), согласно `ROADMAP.md`.

---

### 3. Сохранение власти за пользователем (не обсуждается)

- **Показывать, никогда не подавлять.** Оценки эха/родословной *показываются и сортируются*; инструмент
  никогда не скрывает и не понижает источник автоматически. Любое понижение веса — явный, обратимый
  пользовательский элемент управления, **выключенный по умолчанию**.
- **Никаких меток истинности.** «Самое раннее, что мы видели» / «самое цитируемое» ≠ «истинное». Мы показываем структуру
  (кто сказал первым, кто кого цитирует, кто кому принадлежит) и останавливаемся.
- **Всё объяснимо и локально.** Каждое число прослеживается до строк, которые пользователь может проверить;
  никаких внешних обращений, никакого ML-чёрного ящика (хэширование + подсчёт + степень графа).
- **Открытый исходный код и проверяемость.** Чистые функции, пригодные для модульных тестов, правила классификации в
  данных (`LinkClassificationRule`), которые пользователь может редактировать.

---

### 4. Риски и честные ограничения

- Извлечение ссылок хорошо лишь настолько, насколько хорош полученный HTML (платный доступ/JS его ограничивают).
- Соглашения о якорях/цитировании различаются; «по словам X» без ссылки пропускается
  (последующий NLP-проход мог бы помочь, но начинаем с простого).
- Данные о собственности неполны и устаревают — они должны быть атрибутируемыми, а не угаданными.
- Поиск почти дубликатов в масштабе корпуса требует осторожности, чтобы оставаться дешёвым на одной машине (хэширование, сравнение
  в окне), а не O(n²) полнотекстовых сравнений.

### 5. Предлагаемый первый коммит

Подключить **P0** (заполнение `article_links` при загрузке) за настройкой, добавить **P1**
эндпоинты **`articles-by-link`** и **`top-cited`** и минимальный список в Аналитике. Уже
одно это даёт «собрать все статьи, цитирующие одну и ту же ссылку» и тренд на основе цитирования
— наименьший срез реальной ценности, полностью в духе проекта.
