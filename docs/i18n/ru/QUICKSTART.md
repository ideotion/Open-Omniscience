# Быстрый старт — запуск приложения

Это **надёжное ядро** (приложение честно находится в стадии **альфа** — `v0.5.0`, цикл
`0.5` «стол исследователя» (investigator's desk), тег от 2026-10-26; запущенное приложение сообщает свою точную
версию): добавить источник → этично собрать с него данные → сохранить с указанием происхождения →
булев полнотекстовый поиск → экспорт. Всё локально, только loopback, без учётных записей.

---

## 0. Простой путь — одна команда, затем запуск двойным щелчком

Если вы просто хотите пользоваться приложением (после установки знание командной строки не понадобится):

**Linux / macOS** — в терминале:

```bash
curl -fsSL https://raw.githubusercontent.com/ideotion/Open-Omniscience/HEAD/scripts/bootstrap.sh | bash
```

**Windows 11** — в PowerShell. Сначала скачайте файл, *затем* запустите его:

```powershell
irm https://raw.githubusercontent.com/ideotion/Open-Omniscience/HEAD/install.ps1 -OutFile $env:TEMP\oo-install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File $env:TEMP\oo-install.ps1
```

Защитник Windows (Windows Defender) всё равно может поместить файл в карантин — он не подписан и новый. Это
ложное срабатывание; в [§C](#c-в-windows-11-powershell) подробно объясняется, почему так происходит, и предлагается
путь без скрипта, который ничто не сможет удалить.

Поддержка Windows уже, чем Linux, и разница прямо описана в
[§C](#c-в-windows-11-powershell) — прочитайте этот раздел, прежде чем полагаться на неё.

> **Проверьте, прежде чем доверять.** Передавая скрипт в оболочку, вы запускаете код на своём
> компьютере. Оба скрипта намеренно небольшие — при желании сначала прочитайте их
> ([scripts/bootstrap.sh](../scripts/bootstrap.sh), [install.ps1](../install.ps1)).
> Они проверяют наличие git и Python 3.13, клонируют этот репозиторий в `~/open-omniscience`
> (`%USERPROFILE%\Open-Omniscience` в Windows) и передают управление установщику
> внутри репозитория. Вы можете точно так же клонировать репозиторий сами и запустить `./install.sh` / `install.ps1`.

`install.sh` работает **без вопросов** — **меню выбора компонентов нет**. Одна команда устанавливает
разумный набор по умолчанию:

| Устанавливается по умолчанию | Что вы получаете |
|----------------------|--------------|
| **Ядро** *(всегда)* | сбор · хранение с указанием происхождения · булев поиск · экспорт |
| **Анализ** | ключевые слова · сравнение подачи · тональность |
| **Сжатие** | более быстрое хранение корпуса на диске |

Настройка локальной LLM / Ollama **не** входит в установщик — она целиком находится во вкладке
приложения **Настройки → ИИ** (см. §E). Изменить устанавливаемый набор можно переменной окружения
`OO_COMPONENTS="…"` (например, `OO_COMPONENTS="analysis,nlp"`); повторный запуск
`./install.sh` идемпотентен и устанавливает только недостающее.

**Затем приложение запускается автоматически.** Установщик создаёт ярлык **Open Omniscience** (меню
приложений + Рабочий стол) и открывает приложение в браузере. Чтобы запустить его снова позже:

- откройте меню приложений и найдите **Open Omniscience**, **или**
- дважды щёлкните значок **Open Omniscience** на **Рабочем столе**.

Появится небольшое окно терминала, приложение запустится, и браузер откроет
**http://127.0.0.1:8000**. **Чтобы остановить приложение, закройте это окно (или нажмите кнопку
питания / выключения на верхней панели).** (В macOS ярлык — это `Open Omniscience.command` на
Рабочем столе; в Windows — ярлык на Рабочем столе и в меню «Пуск», созданный `install.ps1`.)

**Первый запуск.** При новой установке приложение проводит вас через короткую однократную настройку
*до* основного интерфейса: **выберите язык → прочитайте и примите юридические условия**
(отказ **удаляет** приложение, с подтверждением вводом текста) **→ создайте парольную фразу
корпуса**. Корпус **по умолчанию зашифрован на диске** (SQLCipher 4), и
**восстановить утерянную парольную фразу невозможно** (потеря парольной фразы стоит времени на повторный сбор —
корпус заново собирается из интернета). Затем приложение запускается **в автономном режиме (режим полёта)**;
переход в онлайн проходит через **одно окно согласия**, которое называет действие и показывает ваши локальные
IP-адреса интерфейсов до того, как будет отправлен какой-либо запрос.

Предпочитаете терминал? `cd ~/open-omniscience && ./scripts/launch.sh` делает то же самое.

**Проверка или удаление впоследствии:**
```bash
./install.sh --check        # health report: Python, data dir, database, LLM, launcher
#   (same as: open-omniscience doctor)
./install.sh --uninstall    # remove the virtualenv + launcher; your data is kept
                            #   (it asks separately, defaulting to NO, before deleting data)
```

## A. В AppVM на Debian в Qubes OS (целевая платформа)

Qubes сбрасывает корневую файловую систему AppVM при каждой загрузке; сохраняются только `/home` (а также
`/usr/local`, `/rw`). Поэтому системные пакеты устанавливаются в **TemplateVM**, а
приложение, виртуальное окружение и база данных находятся в `/home` в **AppVM**.

**1. В TemplateVM (один раз):**
```bash
sudo ./install.sh --template      # installs python3.13, venv, git, sqlite3, ...
```
Выключите TemplateVM, затем **перезагрузите AppVM**, чтобы пакеты стали видны.

**2. В AppVM (от имени вашего пользователя, без sudo):**
```bash
./install.sh                      # promptless: Core + Analysis + Compression, then auto-launches
# Qubes AppVM (unattended, creates the launcher, no prompts): Core + Analysis + Compression
./install.sh --appvm
```

**3. Запуск (привязка только к 127.0.0.1):**
Дважды щёлкните ярлык **Open Omniscience** (меню приложений / Рабочий стол) или выполните:
```bash
cd ~/open-omniscience && ./scripts/launch.sh    # starts the app + opens the browser
```
Откройте **http://127.0.0.1:8000** в браузере AppVM.

Сервер никогда не слушает за пределами loopback. Чтобы после сбора полностью перейти в офлайн, отключите
NetVM от AppVM — интерфейс не имеет внешних зависимостей и продолжает работать с сохранёнными данными.

## B. Локальный запуск для разработки (любой Linux с Python 3.13)

```bash
python3.13 -m venv .venv && . .venv/bin/activate
pip install -e ".[analysis,dev]"
pytest -q                          # full test suite
open-omniscience                   # serve at http://127.0.0.1:8000
```

Полезные переменные окружения: `OO_DATA_DIR` (где хранятся база SQLite и данные), `OO_HOST`/`OO_PORT`,
`OO_FETCH_MIN_INTERVAL` (вежливая задержка для каждого хоста, в секундах).

### В Tails

Debian/Ubuntu/Tails поставляют стандартные модули `venv`/`ensurepip` в **отдельном apt-пакете**, поэтому
`python3 -m venv` не работает, пока он не установлен. Теперь `install.sh` устанавливает его
**автоматически** — в Tails для этого нужен **пароль администратора** (задайте его на
приветственном экране; по умолчанию он отключён) и работающее **подключение к Tor** (apt скачивает через
Tor). Отключить это можно с помощью `OO_NO_APT=1`, если вы предпочитаете запускать apt сами.

Две честные оговорки, относящиеся именно к Tails:

- **Версия Python.** Tails основан на Debian 12 → **Python 3.11**, а приложение рассчитано на **3.13**.
  У вас должен быть доступен интерпретатор 3.13, и нужно указать его установщику
  (`OO_PYTHON=python3.13 ./install.sh`); 3.13 и его пакета `python3.13-venv` **нет**
  в стандартных репозиториях Tails.
- **Амнезия.** Всё, что установлено через apt, — и весь `.venv` — **теряется при перезагрузке**, если
  не находится в постоянном хранилище: добавьте пакет venv через **Persistent Storage → Additional
  Software** (Постоянное хранилище → Дополнительное ПО) и держите рабочую копию и `OO_DATA_DIR` на постоянном томе.

### Обновление существующей базы данных

При новой установке схема создаётся автоматически (`init_db()`), а базе данных
присваивается текущая базовая отметка миграций. Когда будущий выпуск изменит
схему, обновите существующую базу данных командой:
```bash
alembic upgrade head
```
`alembic check` сообщает, согласованы ли модели и миграции (CI следит за этим).

## C. В Windows 11 (PowerShell)

**Честный статус поддержки — прочитайте это в первую очередь.** Каждый прогон CI подтверждает три вещи на
`windows-latest`: установку зависимостей, **проверку загрузки** (всё приложение импортируется)
и **шифрование SQLCipher на диске** — последнее на *блокирующей* линии, так что
шифрование — не догадка. Ничего сверх этого не подтверждено. **Линия pytest для Windows
зависает** (недавние завершённые прогоны провели в `pytest` 3 ч 21 мин и ~6 ч против 18 минут
на macOS), и **никто не прокликал интерфейс в Windows**. Поэтому: рассчитывайте, что установка
и запуск сработают, считайте всё, что после загрузки, непроверенным и, пожалуйста, сообщайте о том, что
ломается. Эталоном выпуска остаётся Linux.

### 1. Установка

Откройте **PowerShell** (права администратора не нужны, если только не требуется устанавливать сам Python).
Скачайте установщик, при желании прочитайте его, затем запустите:

```powershell
irm https://raw.githubusercontent.com/ideotion/Open-Omniscience/HEAD/install.ps1 -OutFile $env:TEMP\oo-install.ps1
notepad $env:TEMP\oo-install.ps1                                     # optional: see what you are about to run
powershell -NoProfile -ExecutionPolicy Bypass -File $env:TEMP\oo-install.ps1 -Extras analysis
```

Он устанавливает Git и Python 3.13 через `winget`, только если их нет, клонирует репозиторий в
`%USERPROFILE%\Open-Omniscience`, создаёт `.venv` и проверяет результат,
импортируя настоящее приложение. Уберите флаг `-Extras`, чтобы получить более полный набор по умолчанию, или см.
[Параметры установщика](#параметры-установщика).

Репозиторий уже клонирован? Запустите установщик на месте — он распознает собственную рабочую копию и пропустит клонирование:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

> **Почему не одна строка `irm … | iex`?** Потому что загрузка удалённого кода и его выполнение
> прямо из памяти — самый распространённый способ доставки вредоносных программ для Windows, и
> Defender оценивает такую схему как враждебную, что бы ни содержал скрипт. Сначала записать файл
> на диск — и меньше шансов на блокировку, и честнее: вы можете прочитать его
> до запуска.

### 2. Если Защитник Windows поместил установщик в карантин

Он может удалить `install.ps1` сразу же. Это **ложное срабатывание**, и вам не нужно
верить нам на слово — вот точная причина, чтобы вы могли судить сами:

- Файл **не подписан и новый**, поэтому облачная репутационная служба Defender его никогда не видела.
  Неизвестности и отсутствия подписи самих по себе достаточно, чтобы сработала эвристика машинного обучения;
  название обнаружения обычно заканчивается на `!ml`.
- По своей **форме** он похож на установщик: вызывает менеджер пакетов, заново читает `PATH` из
  реестра, создаёт ярлыки в меню «Пуск», а его режим `-Uninstall` удаляет
  каталоги. Программы-загрузчики (droppers) делают то же самое. Классификатор оценивает форму, а не намерение.

Чего в нём *нет* — и это вы можете проверить сами примерно в 500 читаемых строках: нет
`Invoke-Expression`, нет закодированной или обфусцированной нагрузки, нет `WebClient`, нет скрытых
окон и нет загрузок откуда-либо, кроме этого репозитория.

Три пути дальше, начиная с лучшего:

1. **Используйте путь без скрипта** — [Ручная установка](#ручная-установка-без-скрипта) ниже.
   Те же команды, что выполняет установщик, и никакого файла для карантина. Это работает всегда.
2. **Сообщите о ложном срабатывании** в Microsoft по адресу
   <https://www.microsoft.com/en-us/wdsi/filesubmission> (выберите *Software developer* (Разработчик ПО)).
   Обычно это занимает день-два и исправляет проблему для всех, кто устанавливает
   после вас, — а не только для вас.
3. **Добавьте папку в исключения** (Безопасность Windows → Защита от вирусов и угроз → Управление
   настройками → Исключения (Windows Security → Virus & threat protection → Manage settings → Exclusions)).
   Прежде чем это делать, знайте цену: исключение останавливает
   сканирование этой папки Defender *полностью*, для всего, бессрочно — а не только
   для одного этого файла. Ваш компьютер, ваше решение; мы не будем делать вид, что это бесплатно.

Честное решение с нашей стороны — подписание кода, которого у нас пока нет.

### 3. Запуск

Установщик создаёт ярлык **Open Omniscience** на **Рабочем столе** и в
**меню «Пуск»**. Дважды щёлкните его: появится окно терминала, а браузер откроет
**http://127.0.0.1:8000**, как только приложение действительно ответит. Чтобы остановить его, закройте это окно (или
нажмите кнопку питания в приложении).

Вместо этого из терминала: `scripts\launch.cmd`.

### 4. Первый запуск

Тот же однократный процесс, что и на всех платформах: **выберите язык → прочитайте и примите
юридические условия → создайте парольную фразу корпуса**. Корпус **по умолчанию зашифрован
на диске**, и **восстановить утерянную парольную фразу невозможно**. Затем приложение запускается
**в автономном режиме (режим полёта)**; переход в онлайн проходит через **одно окно согласия**.

### Параметры установщика

| Флаг | Что он делает |
|------|--------------|
| *(нет)* | Ядро + `analysis,compression,columnar`, затем проверка и создание ярлыков |
| `-Path <dir>` | Установить в другое место, а не в `%USERPROFILE%\Open-Omniscience` |
| `-Extras "analysis"` | Выбрать дополнительные пакеты pip (`""` — только ядро) |
| `-Ref <branch>` | Клонировать определённую ветку или тег |
| `-NoPython` | Никогда не устанавливать Git/Python автоматически; вместо этого завершиться с инструкциями |
| `-NoLauncher` | Не создавать ярлыки на Рабочем столе / в меню «Пуск» |
| `-Check` | Отчёт о состоянии (то же, что `open-omniscience doctor`) |
| `-Uninstall` | Удалить `.venv` и ярлыки; данные сохраняются, если их удаление не подтверждено отдельно |
| `-Yes` | Отвечать «да» на все вопросы (автоматический режим) |

В Windows CI подтверждает только `analysis`. Если более полный набор по умолчанию не удаётся
установить, скрипт **возвращается к `analysis` и сообщает об этом**, а не завершается
молча с ошибкой и не делает вид, что дополнительные пакеты установлены.

### Ручная установка (без скрипта)

```powershell
# 1. Prerequisites -- skip either line if you already have it
winget install --id Git.Git -e --source winget
winget install --id Python.Python.3.13 -e --source winget --scope user

# 2. Find the interpreter. winget frequently installs Python WITHOUT adding it to
#    PATH, so `python` and `py` can still resolve to nothing on a freshly restarted
#    machine. This reads the record the installer itself writes (PEP 514) -- the same
#    one py.exe uses -- so it answers whatever PATH says:
Get-ChildItem 'HKCU:\SOFTWARE\Python','HKLM:\SOFTWARE\Python' -Recurse -ErrorAction SilentlyContinue |
  Where-Object PSChildName -eq 'InstallPath' |
  ForEach-Object { (Get-ItemProperty $_.PSPath).'(default)' }

$py = "$env:LOCALAPPDATA\Programs\Python\Python313\python.exe"   # or whatever that printed

# 3. Clone
git clone --depth 1 https://github.com/ideotion/Open-Omniscience.git $HOME\Open-Omniscience
cd $HOME\Open-Omniscience

# 4. Virtual environment. Everything is called by full path on purpose: activating a
#    venv needs Activate.ps1, which the default execution policy blocks.
& $py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[analysis]"

# 5. Verify -- the exact check CI's Windows lane runs
.\.venv\Scripts\python.exe -c "from src.api.main import app; print(sum(1 for _ in app.routes))"

# 6. Run
.\.venv\Scripts\open-omniscience.exe
```

### Замечания, относящиеся к Windows

- **Политика выполнения.** Политика по умолчанию блокирует `.\.venv\Scripts\Activate.ps1`.
  Здесь это нигде не нужно: вызывайте `.venv\Scripts\python.exe` по пути, и проблема
  полностью исчезает. `-ExecutionPolicy Bypass` в командной строке распространяется на сам установщик.
- **`python`, который открывает Microsoft Store.** Свежая Windows 11 поставляется с
  заглушкой-псевдонимом `python.exe`, которая запускает Store вместо выполнения
  кода. Установщик её игнорирует (заглушка не выводит версию) и использует
  загрузчик `py -3.13`. При ручной установке предпочитайте `py -3.13` вместо `python`.
- **Где хранятся ваши данные.** Поскольку это рабочая копия исходного кода, корпус, ключи
  подписи и настройки хранятся в **`<repo>\data`**, а не в `%APPDATA%`. Задайте `OO_DATA_DIR`, чтобы разместить
  их на другом диске.
- **Права на папку.** В Linux каталог данных доступен только вашему пользователю
  (`chmod 0700`); в Windows этот вызов ничего не делает, поэтому папка наследует обычные
  списки ACL Windows. На общем компьютере ограничьте доступ к `<repo>\data` сами. Сама база данных
  корпуса в любом случае остаётся зашифрованной на диске.
- **SmartScreen / Defender.** Здесь ничего не подписано, поэтому Windows считает всё это
  неизвестным: SmartScreen может выдать предупреждение на ярлыке, а Defender может сразу поместить
  `install.ps1` в карантин — см.
  [§2](#2-если-защитник-windows-поместил-установщик-в-карантин), что это такое и что
  с этим делать. Сканирование в реальном времени также заметно замедляет первый `pip install`.
- **Порт.** Задайте `OO_PORT` перед запуском, чтобы уйти с порта 8000; `scripts\launch.cmd`
  это учитывает.
- **Архитектура (x64 / ARM64 / 32-бит).** Определяется и обрабатывается установщиком; ниже
  описано, какое решение он принимает. Успех `pip install` зависит не от
  компьютера, а от того, какие wheel-пакеты существуют для платформы *интерпретатора*. Измерено по
  PyPI 2026-08-23 для CPython 3.13 по всему набору зависимостей этого проекта:

  | интерпретатор | wheel-пакеты |
  |---|---|
  | `win-amd64` | **все зависимости.** Единственная полная архитектура. |
  | `win-arm64` | все, кроме трёх — `cryptography` (ядро), `httptools` (ядро, через `uvicorn[standard]`) и `statsmodels` (`analysis`) |
  | `win32` | `cryptography` не публикует ни одного |

  Windows на ARM прозрачно запускает двоичные файлы x64, поэтому **интерпретатор x64 — правильный
  выбор и на ARM64** — не компромисс, а полный набор. Поэтому `install.ps1`
  везде предпочитает `win-amd64` и получит его, если на компьютере его нет:
  сначала winget с явным указанием архитектуры, затем winget в пользовательской области, затем автономный
  CPython x64 от Python Software Foundation с nuget.org — проверенный по
  SHA-512, который nuget для него удостоверяет, распакованный в
  `%LOCALAPPDATA%\Open-Omniscience\python-x64`, без повышения прав, без изменения PATH
  и без записи в реестре. Он намеренно находится **вне** рабочей копии: это ресурс
  компьютера, поэтому он переживает удаление папки приложения (иначе построенный на нём `.venv`
  сломался бы), а вторая рабочая копия с `-Path` использует его повторно. `-Uninstall` удаляет его. При несовпадении
  хеша или версии, для которой nuget не удостоверяет хеш, установщик **отказывается** продолжать.

  Если не срабатывает ни одна ступень, вы получите остановку с решением в виде одной загрузки, а не двадцатиминутную
  сборку Rust, заканчивающуюся ошибкой `linker link.exe not found`.

  Существующий `.venv` **проверяется, а не просто обнаруживается**: он сохраняет версию и платформу wheel-пакетов
  того интерпретатора, который его создал, поэтому окружение, оставшееся от предыдущего запуска на
  другом Python, заменяется, а не используется повторно — иначе всё описанное выше
  молча сводилось бы на нет на последнем шаге. Подходящее окружение используется повторно без изменений. Поэтому
  повторный запуск установщика — это и есть решение для незавершённой установки; ничего не нужно удалять
  вручную.

  - **Почему нативная установка ARM64 не включена автоматически.** Для неё потребовалось бы
    закрепить `cryptography` на версиях 46.0.0–46.0.3 — единственной серии с wheel-пакетами для ARM64. Для этого выпуска
    есть **13 открытых записей об уязвимостях** (включая одну в статически скомпонованном OpenSSL, исправленную в
    48.0.1). Это приложение подписывает доказательства; молча установить такое было бы показной
    безопасностью. Если на вашем компьютере действительно есть Visual Studio Build Tools **и** набор инструментов
    Rust, `-AllowSourceBuilds` скомпилирует эти три пакета нативно — это явный выбор,
    никогда не поведение по умолчанию.
  - **32-битная Windows не поддерживается**, и это реальное ограничение, а не искусственный запрет:
    `cryptography` не поставляет wheel-пакет для `win32`. Требуется 64-битная Windows.

## D. Полный цикл (интерфейс или API)

> **Источники уже настроены.** При первом запуске (или во время `install.sh --appvm`)
> отобранные каталоги (`configs/sources.yml` — ~3 200 общественно значимых изданий, а также
> каталоги рынков, политического спектра и права/ИС — **всего ~3 395 уникальных доменов**)
> заполняются автоматически — так что вы можете сразу начать сбор.
> (Эти числа **меняются** по мере роста каталогов; актуальное значение — то, что
> сейчас содержится в `configs/*.yml`.) Повторное заполнение идемпотентно. Отключить автозаполнение можно с помощью
> `OO_AUTOSEED=0`; заполнить заново вручную — командой `python scripts/seed_sources.py` или
> `POST /api/sources/seed-defaults`. Адреса лент и правила robots со временем меняются;
> этичный загрузчик отказывается от всего, что не может подтвердить, поэтому сокращайте или расширяйте список под
> своё расследование.

**В интерфейсе:** один раз **перейдите в онлайн** (переключатель режима полёта → одно окно согласия), и
**сбор будет идти сам** в фоновом режиме — с распределением по языкам и тегам
источников, с соблюдением robots и ограничением скорости. Затем **ищите во вкладке «Исследовать»** (вкладка на боковой панели; нажатие Enter в
омнибаре на верхней панели или по Ctrl/⌘-K открывает «Исследовать» в новой вкладке браузера) — анализ найденных статей появляется под
результатами, где вы фильтруете, читаете, выполняете булевы запросы и **экспортируете** (CSV/JSON, приложение
с описанием методов, подписанные доказательства). Вы по-прежнему можете добавить источник и вручную *загрузить* (*Ingest*) отдельную ленту или URL
в разделе **Настройки → Дополнительно → Сбор / Источники**.

**Через API:**
```bash
# add a source
curl -X POST http://127.0.0.1:8000/api/sources/ -H 'Content-Type: application/json' \
  -d '{"name":"Example News","domain":"example.com","rss_url":"https://example.com/feed.xml"}'

# ingest its feed (ethical: robots.txt respected fail-closed, rate-limited)
curl -X POST http://127.0.0.1:8000/api/sources/1/ingest

# or ingest a single article URL under that source
curl -X POST http://127.0.0.1:8000/api/ingest -H 'Content-Type: application/json' \
  -d '{"source_id":1,"url":"https://example.com/some-article"}'

# Boolean full-text search (AND / OR / NOT, "phrases", parentheses)
curl 'http://127.0.0.1:8000/api/articles?query=(climate OR energy) AND policy NOT opinion'

# export the filtered set
curl 'http://127.0.0.1:8000/api/articles/export?format=csv&query=climate'
```

Машиночитаемая схема API находится по адресу **http://127.0.0.1:8000/openapi.json**. Интерактивная страница Swagger по умолчанию отключена (она загружает ресурсы со сторонних хостов); разработчик может запустить приложение с `OO_API_DOCS=1`, чтобы получить её по адресу `/docs`.

## E. Возможности анализа

Все они работают локально и громко сообщают о сбоях (никогда ничего не выдумывают). Полные схемы — в `/openapi.json`.

**Локальная LLM (Ollama).** Настройте её в **Настройки → ИИ**: встроенный в приложение
установщик Ollama **с проверкой контрольной суммы** (Linux), а также **очередь загрузки моделей** (реальный
прогресс в байтах, отмена), выбор активной модели и панель редактируемых промптов. Или установите
Ollama сами с **ollama.com** и выполните `ollama pull llama3.2:3b`. Загрузка моделей идёт
через **открытый интернет (clearnet) процессом Ollama** (а не через Tor-путь приложения) — об этом сообщается при
запросе согласия. Значок LLM на верхней панели показывает текущее состояние (щёлкните его, чтобы открыть Настройки → ИИ); у каждого
результата поиска есть кнопки **Сводка** и **Перевести**. API:
```bash
curl http://127.0.0.1:8000/api/llm/health          # {available, installed_models}
curl -X POST http://127.0.0.1:8000/api/llm/articles/1/summarize -d '{}'  # persisted with provenance
```
Если Ollama не запущена, эти запросы возвращают HTTP 503 с понятным сообщением, а не поддельную сводку.

**Цены на сырьё + честная корреляция.**
```bash
curl -X POST http://127.0.0.1:8000/api/commodities/Nd/prices -H 'Content-Type: application/json' \
  -d '{"points":[{"observed_on":"2026-01-01","price":100,"unit":"kg"}]}'
curl 'http://127.0.0.1:8000/api/commodities/Nd/correlation?query=neodymium'
```
Корреляция возвращает настоящий коэффициент + p-значение + n из scipy (Пирсон/Спирмен)
с оговоркой «корреляция ≠ причинность»; при слишком малом перекрытии → `insufficient_data`.

**Мониторинг.** `GET /api/monitoring/health` выполняет настоящие проверки
доступности (через этичный загрузчик); `GET /api/monitoring/anomalies` отмечает
всплески объёма статей по z-оценке. **Электронная почта:** `POST /api/sources/{id}/ingest-email`
(IMAP) добавляет письма в тот же корпус с поиском.

**Проверка метаданных изображений.** `POST /api/verify/image-metadata`
(загрузите изображение) возвращает его формат, размеры, EXIF и GPS с простыми фактическими
наблюдениями (например, присутствует тег программы редактирования, нет отметки времени съёмки). Честно ограничено
*проверками метаданных* — это **не** обнаружение дипфейков/манипуляций (та функция была
выдуманной и была изъята из рабочего дерева в карантин; см.
[docs/QUARANTINE_ARCHIVE.md](QUARANTINE_ARCHIVE.md)).

**Подписанные пакеты доказательств.** Кнопка **Экспорт подписанных
доказательств** в окне анализа (или `POST /api/reports/evidence`) создаёт пакет с корнем Меркла,
подписанный Ed25519. Любой может проверить его офлайн, без этого приложения:
```bash
python scripts/verify_evidence.py evidence-bundle.json   # exit 0 = verified
```

**Цепочка ответственного хранения.** Панель интерфейса **Цепочка ответственного хранения** отслеживает подписанное
происхождение с защитой от подделки и позволяет переключать её поведение во время работы:
постквантовые подписи, режим привязки (офлайн `local` или привязка к Bitcoin через
**OpenTimestamps**) и автоматическое журналирование при сборе. Переключатели — это *предпочтения*:
панель показывает **фактическое** состояние, так что ничто не заявляет, что включено, если его дополнительный пакет
не установлен. API:
```bash
curl http://127.0.0.1:8000/api/custody/settings                       # effective state
curl -X PUT http://127.0.0.1:8000/api/custody/settings \
  -H 'Content-Type: application/json' -d '{"pqc_enabled": true}'
curl -X POST http://127.0.0.1:8000/api/custody/log -H 'Content-Type: application/json' \
  -d '{"item_id":"article:1","item_hash":"<sha256>","action":"ingest"}'
curl 'http://127.0.0.1:8000/api/custody/export' > custody-bundle.json  # offline-verifiable
python scripts/verify_custody.py custody-bundle.json                   # exit 0 = verified
```
Полная модель, модель угроз и оговорки о конфиденциальности: [USER_MANUAL.md](USER_MANUAL.md).

## Что гарантирует «этичный сбор»

- robots.txt загружается, кэшируется для каждого хоста и работает по принципу **«при сомнении — запрет»**: если его не удаётся
  подтвердить (сетевая ошибка, тайм-аут, 5xx или ограничительный 401/403), URL
  **не** загружается.
- Для каждого хоста соблюдается минимальный интервал (с учётом `Crawl-delay`).
- Один путь загрузки, идентифицирующий User-Agent (в защищённом режиме — обезличенный, кроме запросов к API и дампам на серверах Wikimedia), только HTML для статей — никакого прямого обхода.
- Извлечение текста выполняет trafilatura; если настоящий текст статьи не найден, ничего не сохраняется
  (никаких выдуманных строк «No Title / No Content»).
- Каждая сохранённая статья несёт сведения о происхождении: источник, исходный URL, канонический URL,
  хеш содержимого (используется для удаления дубликатов), время загрузки.
