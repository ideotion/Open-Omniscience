# Open Omniscience — 用户手册

*一个开源、合乎伦理、本地优先的调查新闻情报平台。* 本手册是一份友好、从头到尾的指南：介绍这款应用是什么、如何安装和运行，并逐一讲解**每个标签页、控件、设置和工作流程**，随后是技术参考（数据存放位置、环境变量、完整的 HTTP API）以及故障排除。

> **一句话概括：** Open Omniscience 以合乎伦理的方式把新闻（以及维基百科的编辑记录和市场价格）汇集到*你自己*电脑上的一个可搜索、已去重、可追溯来源的
> SQLite 数据库中，让你对其进行分析（搜索、趋势、地图、
> 报道框架、本地大语言模型摘要），并能生成**经密码学签名、
> 可离线验证的证据**，证明它在何时保存了哪些内容。

**贯穿下文一切设计的承诺：**

- **本地优先、保护隐私。** 一切都运行在 `127.0.0.1`（仅限回环地址）上。没有
  账户，没有遥测，任何数据都不会离开你的电脑——唯一的出站流量
  是合乎伦理的抓取器去获取你指定的那些来源（以及在你主动同意的情况下，访问
  Wikipedia/OpenTimestamps/Ollama）。
- **只给诚实的数字。** 每个数字都是真实的 `COUNT(*)`、真实的磁盘字节
  大小，或附带样本量和注意事项的真实统计汇总。应用
  宁可显示错误，也不会编造数值。（早先几个伪造评分的“AI 检测”
  功能已被移除——见 `docs/HISTORY.md`。）
- **合乎伦理的采集。** 只有一条抓取路径。`robots.txt` 以**失败即关闭（fail-closed）**的方式得到遵守
  （有疑问时就*不*抓取），每个主机都有速率限制，并且只有在真正提取到文章正文时
  才会存储内容。

## 1. 安装与首次运行

Open Omniscience 面向基于 Debian 的 Linux 上的 **Python 3.13**（它是为
**Qubes OS** 的 Debian AppVM 设计的，但可以在任何现代 Linux 上运行）。它是一款单用户、
本地优先的应用。

### 最简单的方式：一行命令安装

```bash
curl -fsSL https://raw.githubusercontent.com/ideotion/Open-Omniscience/HEAD/scripts/bootstrap.sh | bash
```

这条命令会克隆代码仓库并运行 `./install.sh`，整个过程**无缝衔接——不会问你任何问题**。
它会安装默认组件集——**核心（Core）**（抓取、存储、搜索、导出）加上
**分析（Analysis）**扩展（统计、关键词/实体分析、借助
scipy/scikit-learn 的市场相关性分析；可选 spaCy 以进行真正的命名实体识别）以及压缩功能——
然后在你的应用菜单和桌面上创建一个 **Open Omniscience** 启动器，并在浏览器中
**自动启动**应用，地址为 `http://127.0.0.1:8000`。（设置
`OO_COMPONENTS` 可覆盖组件集。）在本机进行摘要/翻译需要一个
本地模型——可从 **设置 → AI** 安装 **Ollama**（应用内经过验证的安装程序），也可以
从 ollama.com 安装。你可以随时重新运行 `install.sh`。

> 在把脚本通过管道交给 shell 执行之前，务必先检查它。
> [`bootstrap.sh`](../scripts/bootstrap.sh) 非常短小；你也可以自己克隆代码仓库
> 并运行 `./install.sh`。

**在 Qubes 上：** 在 TemplateVM 中运行 `sudo ./install.sh --template`，重启
AppVM，然后在 AppVM 中运行 `./install.sh`。

### 开发者 / 手动安装

```bash
python3.13 -m venv .venv && . .venv/bin/activate
pip install -e ".[analysis,dev]"     # core + analysis + test tooling
pytest -q                            # full suite should be green
open-omniscience                     # serves http://127.0.0.1:8000
```

首次启动时，应用会**自动预置一份覆盖全球的目录（约 3,400 个不重复的域名，
涵盖新闻、市场、政治光谱集合以及官方法律/知识产权门户）**，让你
立刻就有内容可以采集；它还会初始化 SQLite 数据库和 FTS
索引，并（如已启用）启动后台调度器。

### 首次启动页面（语言 → 条款 → 口令）

在**全新安装**时，你看到的第一个页面是位于 `/unlock` 的独立离线
设置页面，**在应用打开之前**分三步完成：

1. **选择你的语言**——从 12 种界面语言中选择；整个页面
   会即时切换，你的选择也会带入应用中。
2. **阅读并接受法律文件**（以你选择的语言显示；以法文版本为
   准）。点击**接受并继续（Accept and continue）**进入下一步，或点击**拒绝（Decline）**——拒绝会
   **卸载应用**（一个需要输入确认内容的子面板确保误点
   绝不会删除任何东西）。
3. **创建你的语料库口令。** 新数据库**默认在磁盘上以 SQLCipher 加密**，
   所以你要在这里设定**那个口令**（输入两次以确认）。它是
   一个固定不变的秘密，就像用户 ID 一样，**无法找回，也没有其他
   解密途径**——丢失口令的代价是重新采集所需的时间，因为语料库
   是从网络上重建的。完整的理由和诚实的威胁模型见
   [设置 → 高级 → 安全](#39-设置)。

在**之后的启动**中，存储已经创建好了，所以你会直接看到一个
**解锁**提示，输入同一个口令即可。无界面/脚本化运行通过
`OO_DB_PASSPHRASE` 提供口令；以明文方式运行始终是一个需要明确做出的选择（`OO_DB_PLAINTEXT=1`）。

### 引导设置与主页

进入应用后，一次性的应用内**引导设置**（一个分步对话框）可以带你
完成最初的选择：它从**语言**这一步开始，在**完成**这一步
结束，这一步会说明应用**以离线状态启动**，并提供一个*“联网并开始采集”*
按钮。联网总是要经过网络同意弹窗（见下文）——
引导只是邀请你；它从不自行联网。你可以随时
从 **设置 → 常规 → “重新运行首次启动向导”** 再次运行它。

之后，应用会打开**主页**，最上方是你的**简报**——一组
诚实的**线索**（见 [3.0 主页](#30-主页)）——其下是一条紧凑的**概览（at-a-glance）**栏，显示
实时计数。你无需手动预置任何内容：精选目录**在启动时
自动预置**，联网后会**自动开始采集**，随后**搜索**
中就有真实的文章了。

**外壳界面。** 导航位于**左侧边栏**——一个由数据工具组成的**平铺列表**：
**主页 · 信息流 · 浏览 · 洞察 · 天文台 · 世界地图 · 政府 ·
日程 · 气候 · 指数 · 大宗商品 *（高级）* · 活跃信息源 · 文库**（在
**精简**界面深度下，只有主页和信息流被固定显示，其余标签页位于一个
带文字标签的**显示更多**行后面；见 [3.](#3-逐一介绍各个工具)）（在窄窗口中它会收缩为图标栏，但绝不会
消失）。**设置**按钮位于**侧边栏底部**（与
折叠开关在一起），内容区上方的**极简顶栏**包含：

- **搜索 / 命令栏（⌘K / Ctrl-K）。** 输入即可跳转到任何工具、执行常用
  操作、打开任何文档——或对你的数据进行联合搜索（见 [3.1 搜索](#31-搜索)）。
  完整的搜索及其分析位于**浏览**标签页。
- **实时状态**——一个后端健康状态圆点和一个 **LLM** 标签（点击它可打开
  设置 → AI）。
- **任务管理器**——一个按钮，用于打开[任务管理器窗口](#30a-活动与任务管理器)。
- **飞行模式**——唯一的网络开关（一个飞机图标，其*填充*表示
  状态；实心 = 离线）。首次启动时，在离线状态下，会有一个小小的引导提示指向
  它，邀请你在准备好时联网。
- **语言切换器**——全部 12 种语言集中在一个菜单中（旗帜只是提示；
  语言的本地名称才是标识）。点击一次即可重新翻译整个界面。
- **帮助（?）**——打开应用内的文档阅读器（本手册和其他
  指南），可搜索，完全离线。（交互式的 Swagger/ReDoc 页面默认关闭，见 §5.4。）
- **关闭（电源）**——干净地停止服务器；你的数据不受影响，界面
  会被一个“你可以关闭此标签页”的遮罩层取代。（这*不是*卸载，也不是
  清除数据。）

**设置**从**侧边栏底部的设置按钮**打开（
命令面板也能直接跳转过去）；见 [3.9 设置](#39-设置)。
**外观**（**设置 → 图形**）提供 **14 种配色主题 + 跟随系统**、强调色、
密度、内置字体选择器以及侧边栏折叠。所有设置都
保存在本地；不会传输任何内容。

### 近期新增（0.0.8 实测周期，2026 年 6 月）

> **历史快照。** 本节描述的是 0.0.8 周期
> （2026 年 6 月）时的应用；此后应用已有变化。`CLAUDE.md` 是
> 之后所发布内容的实时权威来源——索引见 `docs/ledger/shipped.csv`。

- **网络开关是一个飞行模式切换按钮（顶栏）：** 一个固定不变的
  飞机图标，其**填充表示状态**——实心表示已进入离线状态
  （每个新的网络请求都会被立即拒绝；正在进行中的一个请求可能会
  完成）。**每次切换回在线状态都会先询问**：一个统一的同意
  弹窗会说明哪项操作需要网络，并列出你电脑的**本地
  接口地址**（从内核自身的表中读取——从不进行网络
  调用；应用刻意不去获取“我的 IP 是什么”这类回显，因为
  那本身就会产生流量）。除这些本地地址之外，互联网
  看到的是你的 ISP 或 VPN 所呈现的公网地址。在离线状态下，开始一次采集
  轮次、导入市场数据源、添加一个关注的维基百科页面或下载
  一份转储，都要经过同一个同意弹窗；每次切换时开关都会
  立即重绘——从不等待下一次轮询。

  **飞行模式是套接字层面的保证，而不只是每次调用时的约定。** 作为
  关于应用*自身*防护的知情同意说明：在飞行模式开启期间，
  应用会在底层套接字调用
  （`getaddrinfo` / `create_connection` / `connect`）之上安装一个**进程级防护**，因此**任何**试图访问
  非回环地址的尝试——无论来自哪条代码路径、第三方库还是 DNS 预取——
  都会在真正使用套接字之前抛出异常。回环地址（127/8、::1、`localhost`）和 Unix
  套接字始终可以通过，因此应用自己的服务器、本地 Ollama 和文件
  数据库都能继续工作。在你在线时它是透明的（采集期间零开销）。
  设置 `OO_AIRPLANE_SOCKET_GUARD=0` 可将其禁用（适用于把回环流量
  代理到别处的特殊部署）。
- **分层思维导图与词云（洞察）：** 一个真正的放射状思维导图（中心 →
  分支 → 向外的叶节点），跨越三个缩放层级（关键词 ↔ 词族 ↔
  超级分组），并配有词云作为第二视图、日期区间控件、
  文字大小滑块和 ⛶ 放大。字号始终表示共享文章的数量。
- **预先创建的超级分组：** 一套内置的起始分组（根据真实的实测
  日志起草）会在启动时预置；你自己的编辑和删除始终优先。
- **世界地图现在是分级统计地图（ooMap）：** 该标签页按一个实测
  维度（来源 · 文章 · 关键词提及次数 · 语气）为国家着色，并带有地图内控件，用于选择
  度量、国家↔大洲的粒度、地点叠加层、带有
  焦点时刻滑块的信号图层、服务器 IP 图层、滚轮缩放、拖动平移和 ⛶ 放大。见
  [3.6a](#36a-世界地图)。
- **从文本中提取的事件日期、地点、人物和组织：**
  日期提取器可读取六种语言、数字格式和锚定表达式
  （“昨天”、单独的星期几、“June 11”）；地点提取器能找出
  地名词典中的城市和国家名称；实体提取器会列出**人物**
  和**组织**这两个刻意分开的类别（以尊称开头的
  名字和反复出现的首字母缩写回答的是不同的问题——每个条目都记录了
  是哪条规则找到它的）。所有这些都会进入文章阅读器的元数据标题区，该区域
  把**“来自来源”**与**“由本应用推导 — 可靠性较低”**分开
  （虚线框）：提取结果是附带片段出处的词法候选项，
  从来不是已确认的事实。
- **按语言导出关键词：** 诊断用的关键词日志上限为 *每种主要语言*
  5,000 个关键词，因此小语种的词汇绝不会
  因英语的数量庞大而被挤出分析范围。
- **维基百科离线转储：** 语言版本列表又能正确加载了，并且
  支持多选——在一次排队运行中下载多个语言版本。
- **17 种主题与内置开源字体：** 九种新配色（Arctic、
  Solar、Forest、Aubergine、Garnet、Cyber、Mist、Dawn、Mint）加入了原有
  主题，六种 SIL-OFL 字体现在**内置于应用中**（Cantarell、Inter、
  Outfit、Manrope、JetBrains Mono、Source Serif 4——见
  `src/static/fonts/README.md`）：无需下载任何东西，任何字体请求都不会
  离开你的电脑。部分主题搭配了字体（Arctic→Inter、
  Cyber→Outfit、Sepia/Paper→Source Serif）；设置 → 图形中新增的**字体**选择器
  可以覆盖其中任何一种，文章阅读器则使用
  内置的衬线字体。表单控件（滑块、复选框、原生下拉菜单）现在
  也会跟随主题变化。

**关于“FOOS”的说明。** 应用打开的浏览器标签页（线索调查、
本地文章阅读器）带有后缀 **“· FOOS”——Free Open OmniScience**：足够短，
适合狭窄的标签栏，同时又能让人认出这是本应用。这是
alpha 阶段的工作名称；以后可能会正式改名。

**一个图标，一个界面。** 安装程序只创建**一个启动器**——**Open
Omniscience** → `http://127.0.0.1:8000/`——一个易于发现、可自定义的侧边栏
应用，能随窗口大小平滑适配（在较窄的窗口中侧边栏会收缩为图标
栏）。早期周期中曾有一个实验性的第二界面（“Desk”），
已在 0.0.8 中退役；它的历史记录见
[`DESIGN.md`](DESIGN.md)。

**在后台运行，即使关闭浏览器。** 应用运行在它的启动器
窗口中，而不是浏览器标签页中。你可以随时关闭浏览器：采集、
维基百科和地图下载、备份到文件夹或驱动器、导入、AI 任务（模型
下载、语言检测、AI 检查）以及诊断归档都会继续
运行。这样你就可以让一台机器连续采集好几天，同时省下浏览器
占用的内存（通常为 0.5 到 1 GB，这在小型虚拟机上很重要）。

应用运行期间，启动器窗口会显示一个**面板**，只要
应用还在运行，它就一直在那里：在 Linux、macOS 和 Windows 上都只有一个窗口。面板顶部显示
应用是否已锁定、网络和采集状态、服务器的内存和 CPU，
以及当前正在运行的内容。其下是一个**活动日志**：每发生一件事就记一行带时间的记录
（采集开始或停止、一次下载达到 40 %、一次备份完成、
网络断开、应用停止响应后又恢复响应），一行接一行地添加，
只要应用在运行就不断追加，最新的在最下面。可以用方向键、PgUp 和
PgDn 或鼠标滚轮向上翻看；按 End 回到最新一行。点击按钮，或按下
每个按钮上显示的按键：

- **打开界面（Open UI）（o）**：在浏览器中再次打开应用。
- **暂停采集（Pause collection）（p）**：停止采集并让应用进入飞行模式。要恢复，
  请打开界面：联网总是要经过界面中的同意窗口，绝不通过终端。
- **服务器消息（Server messages）（l）**：显示服务器自身的消息（Windows 上不可用）；按任意键
  返回。
- **停止应用（Stop app）（s）**：在第二次按下后停止应用。它会列出将被终止的任务。

应用运行期间面板不会自行关闭，即使应用正忙，或者
电脑曾经休眠、应用需要一段时间才能响应：它会显示应用已经
多久没有响应，并持续尝试。应用结束时，面板也随之结束。
面板从不索要你的口令：如果应用已锁定，它会如实说明，你需要在
浏览器中解锁。关闭启动器窗口或按 Ctrl-C 仍然会像
以前一样停止应用。设置 `OO_PANEL=0` 可以不带面板启动。在页面中给出结果的 AI 工具
（批量摘要或翻译、AI 关键词提取、提示词运行）在
标签页关闭后也会继续运行，并显示在面板中。要停止其中一个，请打开界面，在任务管理器中
它所在的行上按**停止**，或在页面中按**取消**（面板自己的“停止应用”会停止
整个应用）：它会在处理完当前这篇文章后停止，已经完成的文章仍会
保存。洞察尚未建立索引的文章的关键词索引，也会在应用空闲时
自行补齐。只有两件事需要保持标签页打开：你正在从浏览器
发送的上传，以及浏览器正在下载的文件。在
Windows 上，面板会在单独的窗口中打开（关闭它不会停止应用）。它需要
Python 的 curses 模块，Windows 通过 windows-curses 软件包获得该模块：安装程序
会在 Intel 和 AMD 电脑上添加它；对于在此版本之前完成的安装，你可以在应用所在文件夹中运行
`.venv\Scripts\python -m pip install windows-curses` 来添加。Windows on ARM 目前
还没有它的构建版本，因此在那里应用启动时不带面板。

## 2. 60 秒导览

核心循环是：

> **选择/添加来源 → 采集 → 浏览（搜索与分析）→ 导出 / 签名。**

1. **设置 → 高级 → 来源**——已经预置了一份覆盖全球的目录；如果愿意，也可以添加你自己的来源。
2. **设置 → 高级 → 采集**——抓取某个来源的 RSS 源，或粘贴单篇文章的 URL。
   也可以让**调度器**按设定的间隔自动完成。采集需要
   网络：顶栏中的飞机按钮必须处于关闭状态，而关闭它时会先
   询问你。
3. **主页**和**信息流**——阅读收集到的内容：主页以实测信号（线索）的形式呈现，信息流则是
   一串简单的文章流。
4. **浏览**——对你收集到的全部内容进行布尔全文搜索；
   匹配文章的分析会显示在结果下方。
5. **洞察 / 天文台 / 世界地图 / 政府 / 日程 / 气候 / 指数 /
   大宗商品 / 活跃信息源**——建立在语料库和公共
   数据之上的可选视图（模式、时空、法律、日期、气候记录、价格、变化内容）。
6. **导出**——CSV/JSON，或任何人都可以离线验证的**签名证据包**。

从侧边栏中选择任意工具，或者直接按 **⌘K / Ctrl-K** 并输入你
想去的地方。如果想按你的界面深度简短地走一遍侧边栏中的各个标签页，
请选择**开始导览**（设置 → 常规、帮助与文档，或命令面板）。
它只在你要求时才开始，不会更改任何内容，也不会留下运行过的记录。当前视图显示在
屏幕上时会实时自行刷新（每隔几秒），操作完成后会在角落弹出小提示通知加以确认。
破坏性操作总会先征求你的同意。

- **主页 · 信息流 · 浏览 · 洞察 · 天文台 · 世界地图 · 政府 · 日程 ·
  气候 · 指数 · 大宗商品 *（高级）* · 活跃信息源 · 文库**——外加侧边栏底部的**设置**
  按钮。帮助从顶栏中的 **?** 按钮打开。
  没有“采集”标签页：采集功能位于设置中。
- **浏览**是一个页面：搜索框在上方，一旦搜索返回结果，匹配文章的分析
  就显示在结果下方（见 [3.1](#31-搜索) 和

  都会在此页面上打开它的分析；文章阅读器中的关键词、主页线索上的**打开语料库 ↗**以及
  在全能栏中按 Enter，会在**新的浏览器标签页**中的浏览页面上打开它。
- **界面深度**（设置 → 常规）改变的是侧边栏*固定显示*哪些内容，绝不改变你
  能访问到哪些内容。在**精简**深度下，只有主页和信息流被固定显示，其他标签页位于
  一个带文字标签的**显示更多**行后面；**标准**和**完整**会列出所有标签页。
  命令面板（Ctrl/⌘-K）在任何深度下都能访问所有标签页。

**内容优先。** 侧边栏展示的是*数据*；获取和维护
界面位于**设置**中：**采集**（调度器 + 手动采集）、**来源**
（目录）、**维基百科**（变更跟踪 + 离线转储）、**证据与保管**
以及**来源完整性工作台**都从设置进入（各自的
小节见下文）。设置从**侧边栏底部的按钮**打开；
命令面板也能直接跳转过去。

有几个名称改得更通俗了（控件本身不变）：**摄取（Ingest）→ 采集**、
**数据库 → 文库**、**世界法律 → 政府**（现在带有 **国家 · 地图 · 法律**
子标签页）、**市场 → 大宗商品**（**指数**被拆分出来）。可以用
命令面板（Ctrl/⌘-K）跳转到任何工具。

### 3.0 主页

**用途：** 你的**简报**——一个用于分拣优先级的信息流，外加整体概况。

- **简报（信息流）：** 应用在后台收集并测量，然后
  以**线索**（简报卡片在屏幕上的名称）的形式呈现候选报道，
  并按编辑类别分组（*上升、过度报道、报道不足、调查、
  核查报道框架、关注、背景、数据完整性*）。每条线索都是**一个实测
  信号 + 证据链接 + 一条注意事项**——绝非结论，也**没有“可信度
  评分”**（在代码中被禁止）。
- **翻转卡片——警示信息在背面。** 线索是一张**双面翻转卡片**：
  **正面**是线索的一览；**点击它（或按 Enter）**，它就会翻到
  **背面**，背面载有**注意事项、方法、触发原因、证据，以及一个
  “打开语料库 ↗”**按钮（它会在新的分析
  窗口中打开该线索对应的确切文章集合）。注意事项默认就在 DOM 中，紧挨着操作按钮——它从不
  藏在某个“简洁模式”开关后面。**+ 加入草稿**会固定一条线索；**忽略**会隐藏它
  （可撤销）。信息流有缓存（即时显示）并会**自行更新**——每次抓取轮次后它会在
  后台重新计算，并自行重新轮询；没有刷新按钮。
- **通讯草稿：** 固定的线索 + 你的笔记，导出为 **Markdown**，其中
  每条论断都已附带来源链接、方法和注意事项——可复现的
  新闻报道。如需底层文章的签名副本，请使用证据与保管。
- **内容优先的布局：** 顶部固定一条紧凑的**概览（at-a-glance）**栏（实时
  计数 + 自动采集是否正在运行），下方的线索可以通过竖向子标签页
  按**类别**筛选（默认视图为**“全部线索”**，另外每个
  类别各有一个标签页，并有各自的色调）。精选目录会自动预置，联网后
  采集就会开始，因此空的主页只会显示一个诚实的空状态——没有欢迎卡片。*（
  旧的欢迎横幅和“快速操作”行已被移除——主页直接打开
  简报。）*

### 3.0a 活动与任务管理器

**用途：** 在任何标签页中查看——并操控——应用在
后台所做的一切。

- 顶栏中的**活动标识**会在有工作运行时亮起（一次采集轮次、一份
  维基百科转储、一次市场导入）；旁边有一个常驻的**任务管理器**按钮
  （即使应用空闲时也始终可以访问）。
- 打开**任务管理器**——一个真正的窗口（而不是弹出气泡），带有五个子标签页：
  - **进行中**——每个正在运行的任务：采集轮次、每个正在下载的维基百科转储、
    正在进行的抓取（只显示域名）、空闲循环，以及任何已暂停/失败的
    下载。每个任务都显示其真实进度和适用的控件——**停止**一次
    采集轮次（这也会启用网络总开关，使你进入离线状态；
    按钮上会说明这一点），以及对转储进行**暂停/取消**。不会编造预计剩余时间或速率——只显示
    任务所有者报告的真实字节进度。
  - **队列**——等待轮到自己的任务：按顺序排列的单下载维基百科转储队列，
    带有 **↑ / ↓** 控件用于调整顺序（把一个小的法语转储排到一个
    巨大的英语转储之前）。
  - **计划**——真实的调度器信息：状态（运行中 / 空闲 / 已停止）、
    当前轮次进度（仅显示域名）、频率、上次运行时间，以及后端自己给出的
    下次运行时间，以诚实的相对时间显示（方法写在悬停气泡中——
    绝不是编造的倒计时）。
  - **覆盖范围**——按标签统计的抓取覆盖范围和新鲜度（你的采集实际
    触及了每个主题/标签的多少内容，以及有多新），让你能看到缺口。
  - **系统**——实时的进程运行指标（CPU、内存、下载速率）。*（运行指标已从
    顶栏移到这里。）*
- 该窗口**直接从负责这些工作的系统实时读取数据**，因此它绝不会
  与实际发生的情况不一致——没有影子状态。

### 3.0b 信息流

**用途：** 以**文章流**的方式阅读你的语料库，而不是作为一组实测
信号。主页告诉你什么值得注意；信息流只是一篇接一篇地把文章
递给你，让你滚动浏览。

- **两种排序，都会说明。** **最新优先**按发布日期排列，最新的在最上面。
  **随机排序**是由一个**种子**决定的固定顺序：一篇文章的位置只取决于
  它的 id 和该种子，**与其他任何因素无关**。每一页都带有自己的方法说明行，
  告诉你正在阅读的是哪一种排序。
- **随机排序是浏览辅助，不是推荐系统。** **没有任何形式的
  互动评分**——不会测量你打开了什么、停留了多久，或跳过了什么，
  也**不会保存或参考任何阅读历史**。使用相同
  种子和相同语料库的两个人看到的顺序完全相同。这句话是页面所印出的方法说明
  文字的一部分，因此它不可能悄悄地不再成立。
- **被排除的内容，有确切计数。** 信息流显示的是**未被隔离**
  且**其来源已通过资格认定**的文章。这两类排除都**有确切计数**，并
  显示在第一页上，因此在语料库很完整而信息流很短时，你读到的是*“你的来源
  尚未通过资格认定”*——这是可以采取行动的——而不是*“你什么都没有”*，
  那会是错误的。这两个计数描述的是语料库而不是当前页面，所以
  它们只计算一次，不会随着你的滚动而变化。
- **你停在哪里。** 滚动位置会跨会话保留，方法是在你的浏览器中存储**一个
  位置标记**——一个种子和一个游标，绝不是你读过内容的列表。
  **设置 → 常规 → 信息流浏览进度**中有两个控件：
  **重新洗牌**（新的种子、新的顺序、回到开头）和**从头开始**
  （顺序不变，清除位置）。
- **每种排序的诚实缺口。** 你滚动时采集仍在继续，而每种
  排序漏掉新到文章的方式各不相同：在**随机排序**中，它们可能落在
  你已到达的位置*下方*（重新洗牌可以看到它们）；在**最新优先**中，它们
  出现在该位置*上方*（回到顶部可以看到它们）。页面会说明适用哪种情况。
- **每张卡片**显示标题、来源、日期，以及该文章**自身出现最多的三个
  关键词**——是这篇文章的关键词，而不是你所搜索的内容的关键词。**阅读更多**
  会**就地**展开摘要；点击标题会在本地阅读器中打开文章。

### 3.1 搜索

**用途：** 在你的语料库中查找文章。搜索是侧边栏中
**浏览**标签页的上半部分；它所匹配文章的分析
（[3.1a](#31a-分析语料库窗口)）就显示在结果正下方，无需
按任何按钮。不带任何词语和筛选条件的搜索只会列出所有文章，
不做任何分析。

- **布尔查询**——支持 `AND` / `OR` / `NOT`、`"exact phrases"`，以及
  具有正确优先级的括号，例如
  `(climate OR energy) AND policy NOT opinion`。由 SQLite FTS5 支持，并完全
  参数化（无注入风险）。
- **阿拉伯语、中文和日语词语无论怎么书写都能被找到。** 阿拉伯语
  词语无论有没有元音符号、无论 alef、teh
  marbuta 或 alef maksura 采用哪种拼写都能匹配（أحمد 能找到 احمد，مدرسة 能找到 مدرسه），中文或日语
  词语也能在更长的一段文字中被找到（东京 能找到写有 东京大学 的文章）。
  每个安装都使用 jieba 对中文进行分词；日语则由 sudachipy 分词，它
  随可选的 `[segmentation]` 扩展提供。在此版本之前建立索引的文章
  仍能像以往一样被找到，并且在运行**重建搜索索引（Re-index
  search）**（设置 → 高级 → 诊断）之后，也能按词被找到。
- **筛选条件：** 来源（确切名称）、语言（如 `en` 这样的代码），以及一个**时间范围**
  控件——起止日期字段、一个可拖动的范围条和快速预设
  （1M · 6M · 1Y · 5Y · All）——与市场、洞察和
  分析窗口中使用的是*同一个*控件。保持完整跨度时它不排除任何内容；缩小范围即可把
  搜索限定在某个时期内。以上均为可选。
- **搜索**执行查询；结果表显示**标题 · 信源 · 发布时间 ·
  语言**，以及一个计数（`N result(s)`，如果结果被截断，还会显示显示了多少条）。
- **每行操作：** **打开**（已存储文章的干净离线副本）、
  **来源 ↗**（原始 URL）、**摘要**和**翻译**（本地大语言模型，前提是
  Ollama 可用）。
- **导出：** **导出 CSV**、**导出 JSON** 和**导出签名证据**——一个
  可察觉篡改的签名证据包，恰好包含与你的查询匹配的文章（见
  [证据与保管](#38-证据与保管)）。它会先打开一个审阅界面：有多少
  篇文章和多少个来源、文件里包含什么、它是明文的，以及由哪把密钥签名；
  保存只需再点一次，之后的消息会列出文件中的各个成员以及
  需要交给接收方的密钥。另外还有**方法附录**（关于
  查询 + 方法的可复现记录）。
- **对全部匹配结果运行本地模型：** **全部摘要** / **全部翻译** 会排队
  进行一次后台运行，让你的本地模型处理每一篇匹配文章（连同模型 +
  日期一起存储，而且——由于是 AI 输出——绝不会进入可信的关键词索引）；**运行
  提取器**会在该集合上运行你的某个自定义 AI 提取器；**综合结果**
  会打开一个窗口，你可以在其中挑选最多 20 个成员，并让本地模型对它们进行一次带引用的处理
  （见深入介绍）。这些运行会排队且可取消；分析窗口中
  也有同样的控件。

> **两种进入方式。** 从侧边栏打开**浏览**，或在全能栏中输入内容并选择
> *“运行完整布尔搜索（Run the full Boolean search）”*：两者都会进入同一个页面，并预先填好查询。

**全能栏（Ctrl/⌘-K），在任何地方都可用：** 命令面板同时也是
对你数据的联合搜索。输入两个字符后，它会按组显示前
三个结果——**文章**（完整的布尔 FTS）、**关键词**（每个都会打开
其语料库窗口）、**来源**、**关注的维基百科页面**、**保存在本机上的维基百科
文本**（维基百科通道保留的旧版本和已变更页面的文本，
见 3.7）以及**跟踪的法律文件**——每组的标题中都会注明该组背后的*真实总数*。
一切都基于索引，并且只在本机上搜索；输入到一半的
查询绝不会报错。选择*“运行完整布尔搜索”*会把你带到
这个标签页，并预先填好查询，因此上述每项功能都只差
一步之遥。

### 3.1a 分析——语料库窗口

**用途：** 把一组文章或单个关键词变成一个可以从各个角度解读的分析
对象。一个关键词就是一个语料库；单篇文章就是只有一篇的
语料库。分析位于**浏览**页面上，在搜索结果下方。它会在以下情况下
出现：

- 在浏览中运行一次搜索（或在全能栏中选择*“运行完整布尔搜索”*），
- 在全能栏中按 **Enter**（这会在新的浏览器标签页中打开浏览），
- 在任何地方点击一个**关键词**（洞察、线索背面，或阅读器——在阅读器中会在新的浏览器标签页中打开），
- 点击一条**主页线索**（它的“打开语料库 ↗”会在新的浏览器标签页中打开*确切的*文章集合），或者
- 点击大宗商品图表的标题 / **分析 ↗**。

当分析是从其他地方打开的（一个关键词、一条线索、一种大宗商品）时，
搜索列表会被搁置一旁，页面会说明当前显示的是谁的分析，因此列表和
分析绝不会在不知不觉中描述两组不同的文章。多个分析
以**命名标签页**的形式并存于顶部的一条栏中；每个标签页都以其查询命名，并显示
它所基于计算的**文章数**。子标签页包括：

- **概览**——对该集合的一目了然的总结。
- **关键词**——排序后的关键词表（真实的共现 / n / PMI，没有评分）。
- **趋势**——提及量/文章量随时间的变化趋势，用共享的交互式图表
  工具绘制（滚轮缩放、拖动平移、悬停查看精确读数；在
  窗口内为全分辨率，稀疏的区段会诚实地显示为柱状 + 一条语料库早期的注意事项，而
  不是伪造的曲线）。
- **思维导图**——确定性的放射状关键词图（中心 → 分支，始终向外）。
- **文章**——成员文章（分页显示）。列：**标题 · 信源 ·
  发布时间 · 最常出现的关键词**，每个列标题都是**排序控件**——点击某一列
  即按它排序，再点击一次则反向排序；箭头标示当前生效的列。名称
  按 A–Z 排列，日期和计数则从最大的开始。在列表上方的
  **排序方式 / 顺序**选择框中也可以做同样的选择，因为它们是同样的两个字段：这个窗口中
  只有一种排序，所以不会有任何东西悄悄覆盖你的选择。*（
  排序过去位于**高级**中，与唯一使用它的列表隔了三个子标签页。）*

  **最常出现的关键词**是这篇文章*自身*被提及最多的关键词及其次数，在
  文章建立索引时计算得出——这和*所搜索*关键词的次数是不同的问题，
  后者是单独的 `↕ "term" count` 按钮。当多个关键词以相同次数并列时，
  该行会显示**并列**，因为列出的那个只是其中第一个，称其为
  最常出现的关键词就等于断言了一个计数从未给出的排名。重新索引尚未
  处理到的文章显示 **—**，绝不显示 0：它缺少的是一次测量，而不是缺少
  关键词。

  每一行都会在**离线阅读器**中打开，阅读器自己的标签栏是**阅读 · 摘要 ·
  翻译 · 关键词 · 思维导图 · 情感 · 相关 · 信源 · 链接**——你在那里
  阅读文章、查看其**原始来源**（链接的可见文字就是完整的
  URL），并用本地模型运行**摘要 / 翻译**。这三项过去
  以每行一个箭头和每行两个按钮的形式重复出现；现在它们被移到了唯一
  能真正显示结果的页面。下方操作行中的批量**全部摘要 / 全部翻译**
  保持不变。几乎相同的副本会带有“N 份副本 = 一个声音”的标记。
- **何时／何地／何人**——该集合提到的日期、地点以及人物/组织，以可点击的
  **分面**形式呈现；点击某个值会**深入**到只提及它的文章（一个细化的
  分析窗口）。由文本推导得出，从未经过确认。
- **链接**——哪些成员文章**共享出站链接**。这是刻意呈现
  *同源结构*：三篇文章引用同一个源头，其实是一个来源
  换了三顶帽子，因此只有当传播路径相互
  独立时，汇聚才算作相互印证。目标是找出*来源的来源*。
- **相关**——跨来源的几乎相同的副本（“N 份副本 = 一个声音”）以及共享的
  源头，每项都带有一个**“分支为新语料库 →”**，可针对恰好这些文章
  生成一个新的分析窗口。
- **情感**——按来源统计的语气（VADER；会显示仅适用于英语的注意事项）。
- **来源**——该集合中各媒体的描述性出处信息。
- **竞争**——该集合中各媒体之间的比较（数量 / 语气 / 时间 /
  侧重点——仅作描述，绝不评出赢家或给出评分）。
- **价格**——*（仅当窗口是从某种大宗商品打开时）*价格曲线
  与你的语料库报道量叠加在共享的时间轴上（是共现，绝非因果），
  每个序列使用各自的真实单位刻度。
- **高级**——按**来源 · 语言 · 日期范围**限定集合；一个“已筛选”标签
  和摘要会显示当前生效的条件。（排序已移到上面的文章标签页。）

操作行包含**方法附录**、**导出签名证据**、**综合
结果**（成员选择窗口），以及排队运行的**全部摘要 / 全部翻译 / 运行
提取器**本地模型任务——与其上方搜索中的那一组相同。

### 3.2 采集 *（位于 设置 → 高级 → 采集）*

> **现在的位置。** 采集属于获取数据的界面，因此它已从侧边栏移到
> **设置 → 高级 → 采集**（内容优先）。各项控件保持不变。

**用途：**把文章收进语料库——自动或手动均可。

**A. 自动采集（调度器）。** 一个按定时器在后台运行的采集程序。
控件如下：

- **开始 / 停止 / 立即采集**——持续运行、停止，或立即运行单独一轮。
  状态标签会显示 `running` / `running — scrape in progress` /
  `stopped` 以及下次运行时间；下面一行显示上一轮的统计结果。
- **间隔(分钟)** 和一个 **采集速度** 滑块（一个下载速率目标）。应用会
  测量自己的实际下载速率，并增减同时连接的主机数量来接近你设定的目标；
  当 CPU、内存或唯一的加密写入进程成为瓶颈时，它会自动降速；
  对每个主机的礼貌访问规则绝不会为了速度而让步。
  *（没有“每轮最多来源数”的上限——随着时间推移，每个来源都会被覆盖，
  不会有任何来源被饿死。）*
- **模式：** *RSS 源*、*递归抓取*、*市场（价格规则）* 或 *维基百科
  （关注的页面）*。选择 **抓取（crawl）** 后会出现 **爬取深度** 和 **每个来源最多页数**
  （抓取程序只在每个来源自己的域名内活动，以失败即拒绝的方式遵守 robots.txt，
  有速率限制，并有硬性上限——它的作用是*发现*文章，
  而不是镜像整个网站）。
- **定向：** **语言**、**来源类型** 和 **标签 / 关键词(匹配任意)**
  用于缩小一轮运行所涉及的来源范围。**预览目标** 会在你运行*之前*
  准确显示有多少来源符合条件（并按语言和类型细分）。
- **启动时自动开始** + **保存计划** 用于保存这些配置。

**B. 手动采集。**

- **采集某来源的 RSS 源**——选择一个来源，点击 **获取源**。
- **…或采集单篇文章的 URL**——粘贴一个 URL，点击 **采集 URL**。

无论哪种方式，结果行都会显示统计：已存储、跳过的重复项、被 robots
拦截的数量等。抓取始终是合乎道德的（robots 失败即拒绝、有速率限制）。

### 3.3 来源 *（位于 设置 → 高级 → 来源）*

> **现在的位置。** 与采集一样，来源目录已移到 **设置 →
> 高级 → 来源**（内容优先）。各项控件保持不变。

**用途：**登记并整理你从中收集内容的媒体与网站。

- **添加来源：**填写名称、域名、RSS URL、标签 → **添加信源**。或者点击 **添加初始来源**，
  登记一组精选的公共利益来源。
- **管理来源（表格）：**可按搜索文字、国家、语言、类型、标签
  和启用状态筛选。各列均**可排序**（名称、域名、类型、国家、语言、
  优先级（Priority）、文章）。你可以直接在表格中修改 **优先级**（1–3）、切换 **已启用**，
  以及 **删除**（需确认）。表格分页显示，并带有 `N source(s)` 计数。
- **导入 / 导出（CSV）：****全部导出（CSV）**、**下载模板** 和
  **导入 CSV**。列：`name`、`domain`（必填），以及 `rss_url`、
  `source_type`、`country`（2 个字母）、`language`、`region`、`tags`
  （逗号分隔）、`priority`（1–3）、`rate_limit_ms`、`enabled`、
  `reliability_score`（1–10）。导入时**按域名更新或插入**——新行会被创建，
  已有的行会被更新——而且**有问题的行会被报告出来，不会被悄悄丢弃**。

#### 来源资格审定——准入关卡

**仅仅启用一个来源本身是不够的**——一个来源只有在**通过资格审定**之后
才会被*抓取*。每个来源都带有三种分类标记之一，绝不是
质量评分：

- **未审核**——尚未判定（对于被发现的、被引用的或手动添加的来源，
  这是默认状态）；
- **已认证**——通过了一次小规模试抓取，该试抓取检查的是*提取有效性*
  （是真实的正文，还是损坏的/垃圾抓取结果，例如导航菜单页面或付费墙）——
  此后它会加入常规采集；
- **已取消资格**——试抓取提取出的页面在结构上看起来是损坏的，而不只是
  “无聊”或简短（文风从不被评判，只看是否真的取回了
  文章正文）。

**随应用一起提供的精选目录从一开始就是已认证的**（维护者
裁定，2026-09-10）。其中的条目——经人工审核的新闻、频谱、市场和法律目录——
带有一个以目录本身为*依据*的标记，在来源的出处面板中显示为
**已认证 · 来自目录（qualified · by catalogue）**，它们从第一天起就加入采集，而不必
排在发现积压的后面等候。这个标记不是一次测量，也绝不会被当作测量来显示：
它和**每个已认证来源一样，按三个月的周期重新检查**（见下文），
复查未通过的来源会像其他来源一样被取消资格，本实例已经得出的
判定绝不会被它覆盖，而且资格审定导出会把这类条目
单独计数，绝不会把它们当作实际测得的判定发布出去。被发现的、被引用的和手动添加的
来源仍需通过试抓取。

一个**后台任务会在每一轮联网采集时自动运行少量此类试抓取检查**
（一次有限范围的、经过同意的、联网的“少量文章”抓取——在飞行模式下
会被拒绝，与其他任何网络操作完全一样）。在全新安装、
有大量新添加/新发现来源的情况下，这种细水长流的处理可能会留下实实在在的积压：**设置
→ 来源 → “来源资格审定”** 会显示该面板，以及一个 **“审核来源积压”**
按钮，它以可取消的任务管理器任务的形式，批量运行*同样的*判定，
以便更快赶上进度。

**资格评定队列**（高级 → 质量关卡）按顺序显示接下来几轮将要
判定的内容：**新来源优先**（从未判定过，或尝试过但文章
还不够），然后是到期需要复查的来源。新来源总是比复查
更紧急（裁定 R94）。该面板还会说明有多少已认证来源正在等待，以及
下一个何时进入队列。

**每一轮判定多少个来源**会随机器性能而增长（裁定 R95）：
设置 → 高级 → 质量关卡 中的数字（*每轮采集要判定的来源数*）以及调度器的
*每轮资格复查数（qualification re-checks per pass）*（通过调度器配置 `PUT /api/scheduler/config` 设置；
设置中没有对应的控件）都是最小值；当 *资格预算自动（qualification budget auto）* 开启时（默认开启），每一轮会根据机器的内存和核心数
尽可能多地判定新来源和执行复查，没有固定上限。
低于默认值的设置（或 0）会按原样保留；关闭自动后，这些数字会被
精确固定。每个候选来源都根据其最新的文章进行判定，数量以可用内存能
容纳的为限（至少 2,000 篇），并且这一轮会说明这一限制作用于多少个候选来源。

**在配置较低的机器上**（内存少于应用的扫描下限），一轮判定会以
**最新的 20,000 篇文章的样本**而不是整个语料库来判定候选来源，
并在判定结果中记录这是基于抽样得出的（裁定 R93）。在此之前，这类机器会悄悄跳过每一轮，
从来没有任何来源被认证。如果连样本都放不下，这一轮会
说明情况并且不启动。

**被取消资格的来源会得到第二次机会**——它绝不会被删除，而且只有时间
（绝不是重新导入或新的引用）才会触发复查：
第一次取消资格后 1 个月，之后间隔翻倍，最长 6 个月（1 → 2 → 4 →
6），一旦某次复查通过就立即重置。**这就是为什么一个新添加的或
最近被取消资格的来源，可能会在已启用的状态下长达六个
月都没有被抓取**，不采集任何内容——如果你添加的某个来源似乎一直没有贡献文章，
请查看它所在行的资格标签（见下文）。

**资格计数去哪了：**文库中原本只显示单个
“来源”数字的方块，现在变成了**三个如实、互不重叠的数字**——*采集中的来源（Sources
(collecting)）*（已启用**且**已认证）、*等待资格审定的来源（已启用）（Sources awaiting qualification (enabled)）*，
以及 *发现的候选来源*（仍处于停用状态——见下文）——因为把它们混成
一个数字，会让机器自动增长、多达数万个候选来源的发现积压，
看起来就像应用已经在从所有这些来源收集内容一样。

#### 重新验证——标记不会永久有效

判定是一次测量，而测量会过时。**已认证标记大约每三个月
重新检查一次**（裁定 R94，2026-09-29）（由调度器的 `qualification_recheck_per_pass` 设置控制，仅能通过 API 设置；设为 0
会关闭重新验证）。复查采用固定间隔，而不是取消资格那套
翻倍递增的阶梯——翻倍体现的是屡次失败后希望递减，在一次成功之后
毫无意义。

**复查能看到什么、看不到什么，直白地说：**它根据一个来源的全部
已存储历史来判定，因此能发现*整体上*已损坏的来源，但如果多年的优质文章
压过了近期的文章，它**不会**注意到一个最近才变坏的来源。
它真正的价值在别处，而且值得了解：一个很早就被接纳的来源，
当时只有一两篇文章，判定时还没有足够的语料库可供
比较——复查是它第一次对照真正的基准
被测量。

复查有**自己独立**的预算，与接纳新候选来源的预算分开。
这并非细节：当它们共用一个预算时，一个积压了大量
未审查来源的安装会把所有名额都花在新候选来源上，于是没有任何复查——
包括上文所述的被取消资格来源的第二次机会——真正运行过。

#### 判定会随数据迁移：备份与全新安装

在一个实例上完成的资格审定工作，**在你迁移或合并语料库时不会丢失**。

- **导入备份**会带上其中的判定。被导入语料库判定过的来源，
  到达时就是已判定状态。*本*实例从未判定过的来源会**采用**导入的
  判定——双向都是如此，因此另一个实例认定已损坏的来源不会
  悄悄地在这里重新进入试抓取队列。*本*实例得出的判定总是优先：
  导入的语料库永远无法推翻你自己机器的判断，无论是哪个
  方向。
  目录自带的初始标记不属于这样的判定：导入的*实际测量*判定
  会取代它。如果一个仍然只带有目录标记的来源，有一个更新的导入
  判定为*已取消资格*，下次启动时会把它撤出采集，并在
  诊断信息中列出；如果你自己机器的判定与导入的不一致，会保留你的判定，
  并由你自己的资格审定轮次提前复查该来源。
- **全新安装从早先实例测得的结果开始。**应用附带
  `configs/source_qualification.yml`，这是一份自动生成的判定列表，并在
  首次启动时将其应用到从未判定过的来源上。该文件中**没有**的来源
  直接以未审核状态提供，并由本安装自己的首次资格审定轮次判定，与
  该文件出现之前完全一样——因此随附的目录实际上是两份列表：
  已由应用认证的来源，以及仍有待认证的来源。

被采用的判定会记录为**继承而来**，而不是本机测得的结果，
并且保留它最初得出的日期——因此任何内容都不会看起来像是你的
安装测量出来的。重新开始计时的是你机器自己的复查时钟：它从
你采用该判定的那一天算起，而不是从别人得出判定的那一天算起。因此首次下载
是安静的，这正是目的所在——随附的目录到达你手上时，总是已经超过
三个月的间隔，所以如果按原始日期计时，每个
全新安装都会在第一天重新认证整个目录，而这恰恰是
随附文件要省去的工作。

这种取舍是有意为之的，也有值得说明的代价：随附目录的新鲜度
不再由每个安装各自重新确立。它
会在新版本发布时得到重新确立——届时附带的覆盖文件是从*已经*完成
重新验证的实例中重新整理出来的。下文的导出会报告其判定有多旧，因此陈旧程度
是可见的，而不是悄无声息的。

#### 把你实例的判定贡献回来

`GET /api/diagnostics/source-qualification-export` 会报告你的实例对其
随附来源所知道的情况——多少个已认证、多少个已取消资格、多少个仍然
待定——而 `?fmt=yaml` 会以覆盖文件本身的格式返回同一份列表。
`scripts/merge_source_qualification.py` 可把多个实例的导出合并为一份。

如果你已经从这些实例收集了**全部诊断包（all-diagnostics bundles）**，就不必
回去重新导出：诊断包中已包含同一份导出作为其成员，而
`--from-bundle` 会直接从 zip 中读取它。两种方式可以互换，并能在
一次运行中自由混用：

```
python scripts/merge_source_qualification.py laptop-export.json \
    --from-bundle oo-all-diagnostics-desktop.zip \
    --from-bundle oo-all-diagnostics-server.zip
```

打印出的报告会说明它合并了多少个实例、各自通过哪种方式。如果某个诊断包的
导出成员没有完成，它会被点名，并附上该实例记录的原因——它
绝不会被悄悄跳过，因为一个你以为基于三个实例、
实际上只基于两个实例的覆盖文件，比报错更糟。

它有两件事是刻意不做的。它从不**裁决分歧**：如果一个
实例认证了某个域名，而另一个取消了它的资格，这会被报告出来交由人来查看，
因为自动挑选胜者会把一个无人审核过的判定发布到每一个安装。
它也从不把**继承而来**的判定算作佐证——把一个备份导入到
八台机器中，是同一次测量被看到了八次，而不是八次测量。

#### 发现轨迹与已认证引用统计

点击某个来源所在的行，即可**展开它的发现轨迹**：**它是在哪里被发现的**
（引用渠道、目录、维基百科参考文献……），以及对于
通过引用发现的来源，**第一篇引用它的文章**（附有指向该
文章和引用来源的链接）。旁边有一个**已认证引用统计**，统计
*该*来源自身所引用的域名，分为**已认证 / 已取消资格 /
待定 / 未登记**——每个数字都可以点击，展开后显示确切的列表。

这是一个**描述性事实，绝不是对任何一方来源的判定**——引用一个
已取消资格的域名并不代表有问题（一家健康的媒体经常会链接到它*只是在报道*的公司、
平台或损坏的页面），而引用很多已认证的
域名也不代表背书（通讯社会被所有人引用；一个
洗白信息的枢纽可能会故意引用信誉良好的来源）。请把它当作值得
调查的线索来读，就像本应用中其他每一个测得的信号一样，是线索，而不是
评分。

#### 我们暂时还无法分析的语言——默认停用（但保留）

关键词/分析引擎只能**处理**那些已有*停用词表*、
且其文字**以空格分词**的语言。权威列表只存在于一个
模块中——[`src/analytics/managed.py`](../src/analytics/managed.py)（`MANAGED_LANGUAGES`）
——来源准入控制和应用内的引擎报告都读取它，因此本手册不会
与代码脱节。按该模块的内容，受支持的语言集合为：**en, fr, de, es, it, pt, nl,
ru, ar, hu, id, sv, da, nb, no, pl, sr, sl, el, bg, hi, bn, fa, ur, uk, ro, cs, sk, ca,
sw, az, et, tr, fi, bs, hr**。**不在**该集合中的语言仍然可以*切分词元*，但其
功能词（相当于“the/of/and”的词）会混进来，成为虚假的关键词。**ja 和 th
未经分词**，除非安装了可选的 `[segmentation]` 扩展——这两种语言的词与词之间
没有空格，因此没有分词器时，无论有没有停用词表，关键词提取都会彻底
失效。**zh** 也曾处于同样的处境，直到 jieba 在 0.4 中成为核心依赖；
现在它在每个安装上都会被分词，因此也属于受支持的语言。

因此，抓取这些语言的内容会产生**垃圾关键词**，它们会：

- **污染分析结果**——虚假关键词会扭曲关联、趋势和
  超级分组，并且
- **让语料库膨胀**——每一次聚合（洞察、分组、思维导图）都要为
  数十万条毫无意义的行付出代价，这会对大型语料库的性能
  造成实实在在的拖累。

所以，按照设计：**使用不受支持语言的新来源在添加时是*停用*的**。它会被
**保留**（绝不删除），并且完全**可以重新启用**——你仍然可以阅读这些
媒体，而一旦为它们的语言添加了停用词表，你就可以把它们重新
打开。这是一个如实的取舍：我们宁可*不收集*那些我们会*搞乱*的内容，
也不愿呈现不可靠的分析结果。CSV 导入中**明确**写出的 `enabled: true`
总是优先（你的整理选择会得到尊重），而语言**未知**的来源
会保持启用（我们绝不停用自己无法分类的东西）。

**要把这一点应用到现有语料库：**设置 → 高级 → 来源 会显示有多少已启用的
来源使用不受支持的语言（以及是哪些），并提供 **“停用我们尚无法分析的语言的来源”**
——这是一个可撤销的批量操作，会停用这些来源
（但保留它们）。你随时可以在来源表格中重新启用其中任何一个。

### 3.4 文库

*（在 0.05 之前称为 **数据库**。）*

**用途：**如实地查看你实际掌握了什么，以及你的
来源覆盖范围有多广。

- **数据库统计（Database stats）：**实时的动画计数（文章、来源、不重复的域名，
  ……），以及数据库的后端类型和**磁盘占用大小与路径**。每一个
  数字都是真实的计数或字节大小——没有任何估算。
- **全球覆盖：**你的来源目录覆盖了多少个国家，以
  ISO 3166 为基准计算——`covered/total countries`、`coverage %`、*未*覆盖的数量，
  以及“薄弱”（低于阈值）的数量。国家以小写 ISO-2
  代码存储，并**以完整名称显示**（只有一个转换层，
  `src/catalog/countries.py`）。**区域平衡** 部分会把每个
  大洲的来源和已覆盖国家，与
  `configs/catalog_targets.yml` 中的工作下限进行比较（这些下限明确标注为目标，是根据
  真实目录的构成起草的），另外还有一个首位国家**集中度防护**——即 0.0.9 的
  去美国中心化指标。表格列出每个国家及其所属区域、来源
  数量和**主题关键词标签**（来自来源的标签）。**点击某个国家或某个
  关键词**，即可跳转到恰好筛选出这些来源的“来源”页面。一份缺口报告
  会列出尚无任何来源的国家。该面板会实时刷新（不需要刷新
  按钮）；同样的指标也可以离线通过
  `python scripts/catalog_coverage_report.py` 获得。

### 3.5 市场

**用途：**跟踪**真实的**大宗商品 / 货币 / 能源价格，并把它们
与新闻数量联系起来。

- **市场趋势看板（Market trends dashboard）：**每个价格序列一张卡片——代码、涨跌幅 %、最新
  价格（货币/单位）、数据点数量，以及一条迷你走势线。一个**时间范围**控件
  ——起止日期字段、一条可拖动的范围条，以及快捷预设（1M · 6M · 1Y ·
  5Y · All）——会按确切的起止时间窗口重新绘制每张卡片（而不是一组固定的
  尺度）；在该窗口内，完整序列始终以全分辨率绘制，绝不
  抽稀。点击一张卡片，可查看完整图表以及
  **价格↔新闻相关性**（真实的 Pearson/Spearman 系数、p 值和
  样本量——绝不是猜测的数字）。精选的官方数据源会在你联网时
  **在后台自动更新**（没有加载/刷新
  按钮）；看板还提供**类别子标签**、**卡片/家族** 视图切换、
  **比较** 叠加图（带有 绝对值/指数化/对数 刻度切换）以及共享的时间轴。
- **配置数据源**（可折叠——大多数用户用不到）：
  - **官方价格数据源**（FRED，其中包含 **世界银行“粉红单”（World Bank "Pink Sheet"）**
    和 **EIA** 序列）：一键 **导入**，以及 **图表**。
  - **价格提取规则（Price-extraction rules）：**添加一条规则（来源、代码、标签、页面 URL、**CSS
    选择器**、可选的属性/正则表达式、货币、单位、市场）。黄金法则是：
    **只有当你的选择器确实命中一个数字时，才会存储这个数字——绝不猜测。**
    在依赖某条规则之前，请用 **测试** 抓取一次该页面，查看找到的确切值，或者
    未能匹配的确切原因。
  - **自定义数据源（任意 CSV 网址）：**指向任意 CSV（默认映射为第 1 列 =
    日期，第 2 列 = 数值，即 FRED 的惯例）；缺失的值会被跳过，绝不会
    存储为零。

完整的提取规则参考请见 [`docs/USER_MANUAL.md`](USER_MANUAL.md)。

### 3.5a 指数

**用途：**全球股票市场**指数**（S&P 500、NASDAQ、Dow Jones、
VIX、Nikkei 225……）——与**大宗商品分开**，因为指数就是
指数，不是大宗商品。

- 一个指数序列看板，图表与大宗商品一样详细、全分辨率
  （类别子标签、标签筛选、比较叠加图、家族视图、共享的
  时间轴）。精选的官方数据源（FRED、Stooq）会在你联网时**在后台
  自动更新**——没有导入/刷新按钮。
- 当某个数据源无法抓取时，它会给出**如实的单源判定结果**——
  *被拒绝* ≠ *被 robots 禁止* ≠ *序列已停更* ≠ *无法访问* ≠ *离线*——因此
  被拦截的数据源会明确地降级，而不是显示一个假数字。通过 Tor 访问时，有些
  数据源会被主机拦截；判定结果会如实说明这一点（见 §5.5）。

### 3.6 洞察

**用途：**对**已采集文章的正文**进行关键词与实体分析。
*（需要 `[analysis]` 扩展；真正的命名实体识别需要
通过 spaCy 的 `[nlp]` 扩展自行开启。）*

- **状态与索引：**一个标签显示 `indexed/total articles · keywords (entities)
  · mentions · remaining`。**索引是自动的**——它紧随采集进行，而当你
  打开洞察时，一次静默的后台补充索引会清掉剩余的积压（“remaining”
  计数会自动降到 0）。**没有“索引语料库（Index corpus）”按钮**——它已
  被移除，改为自动索引。人物、组织和地点会作为
  单个整体保留；索引可以断点续做，进度条会实时更新。*（如需关闭自动
  索引，请使用 `OO_NO_INDEX=1`。）*
- 八个子标签：
  - **浏览**——输入一个关键词或实体（例如 *inflation*、*Emmanuel Macron*、
    *Rio Tinto*），即可获得：一条随时间变化的**趋势**线；一张**关联思维导图**
    （按 PMI 排序的共现词——边的粗细 = 共现次数，距离 =
    关联强度；点击一个节点可将其设为中心）；一张**框架**表（各媒体的
    语调有何不同，使用 VADER 计算，并列出其强调的词语）；以及**上下文**
    片段，附带来源/地点/日期链接。
  - **趋势**——**上升**（增长最快的关键词，近期窗口与基准窗口对比）和
    **热门**（被提及最多的），外加三个预设窗口（24h · week · month）并排
    显示，可按类型（词语/实体/人物/组织/地点）和国家筛选。点击任意
    词语可在“浏览”中查看它；点击 ✕ 可将其排除。
  - **来源**——整个语料库中的热门来源。
  - **家族**——关键词家族（合并了词形变体）。
  - **分组**——超级分组（持久的总括性概念）和跨语言的**环**
    （一个概念及其译名/同义词），可编辑。
  - **地图**——基于你语料库的 ooMap 分级设色地图（与世界地图
    标签页使用同一个组件）。
  - **汇聚**——只读的时空共现：在所提及事件日期的某个时间窗口内，
    聚焦于同一**地点**的文章。独立性以
    **不同来源的数量**来衡量（单个话多的来源无法凭空制造出一个汇聚）；每个聚类
    都带有“共现，绝非因果——是促你去阅读的提示，不是证据”这一说明。
  - **监视**——你保存的“若出现此情况则关注”条件：一个本地 FTS 查询 + 一个
    阈值 + 一个时间窗口。当语料库新增了足够多的匹配文章时，主页上会出现一条**监视
    线索（watch Lead）**。仅在本地运行，没有通知，不联网，没有遥测；
    可以创建 / 启用 / 编辑 / 删除，并保留匹配历史。

每一个数字都是真实的聚合结果，附有样本量和注意事项。请参见
[`docs/USER_MANUAL.md`](USER_MANUAL.md)。如需调整显示哪些关键词，请使用
[设置中的关键词过滤器](#39-设置)。

### 3.6a 世界地图

**用途：**查看你的语料库分布在*哪里*——一张**分级设色地图**（“全球
覆盖”），按你数据的某一项测量维度为每个国家着色，并可选择叠加
地点、信号和服务器位置图层。它基于一个可复用的地图组件
（**ooMap**）构建，所有控件都位于**地图内部**（Google 地图的惯例）：
缩放 ＋/－、滚轮缩放、拖动平移、⛶ 放大，以及图层/度量选择器。

- **分级设色的度量（地图内选择器）：**切换用于给国家着色的指标，可在
  **来源 · 文章 · 关键词提及 · 平均语调** 之间选择。计数使用顺序色阶；
  **平均语调** 使用**发散**色阶（以零为中心，正向 ↔ 负向），并带有
  **VADER 仅适用于英语**的注意事项以及已打分文章数 `n`——没有
  英文打分文章的国家显示“无数据”，绝不会伪造一个中性值。
- **如实区分无数据与零：**没有定位数据的国家会以**斜线阴影图案**显示，
  标注为“无数据”，在视觉上与真实的零值区分开。粗略轮廓无法绘出的
  小块领土显示为**点**；没有国家信息的来源会**被计数，但
  绝不会被放到地图上**（“N 个未映射（N not mapped）”）。
- **粒度（地图内切换）：**按 **国家** 查看，或汇总到 **大洲**
  （计数用求和，语调用按 `n` 加权的平均值——绝不是平均值的平均值；未知
  大洲如实显示为“无数据”）。
- **地点叠加层：**打开 **地点**，即可标出你的文章所*谈到*的位置
  （来自采集时提取的“何时/何地/何人”信息，使用地名词典坐标），
  以空心标记显示，大小按文章分布范围决定——并附有 **“由文本推断，从未确认。”**
  这一注意事项。
- **信号图层 + 聚焦时刻：**打开 **信号**，即可把可确定日期的时空
  事件（精选的锚点事件、语料库文章、提取出的日期）显示为按类型着色的点；一个
  **聚焦时刻滑块**可以在时间上移动（已确认 = 实心，未来/未确认 =
  虚线圆环，随时间距离逐渐淡出）。点击一个标记可打开详情面板——日期、
  地点、来源、官方链接、**“在您的语料库中查找报道”**，以及一个 **“空间与时间相近”**
  列表，该列表明确说明共现*“不是关联，也不是
  原因。由你来判断。”*
- **服务器 IP 图层：**可选择显示各来源经离线地理定位得到的**服务器位置**
  ——并如实说明：这是 CDN 边缘节点 / 任播主机，**并不能**证明
  发布者的真实所在地（通过 Tor 访问时也无法使用，因为此时套接字连接的是
  代理，而不是服务器）。
- **海岸线和国界随应用附带：**国家/海岸线几何数据随应用一起提供
  （Natural Earth，经过简化）——无需自行构建，也不会凭空编造国界。

一篇报道*所涉及*的日期也会成为**每篇文章的日期标签**：打开一篇文章的离线
阅读器即可看到这些标签，对每个候选日期**确认或拒绝**，或按需**提取**；
之后就可以按提及的日期筛选语料库（`GET /api/article-dates/by-date`）。
该提取器追求高精确度：单独的年份和模糊的时间段不会被提取，但
**有锚点的相对日期词**（“yesterday”）和**单独的星期几**会被提取。

### 3.6b 日程

**用途：**一份带日期事件的日历——即将发生什么，有出处且如实。

- **月视图网格**（周一开始；月份/星期名称使用你的界面语言）是
  默认视图，旁边还有 **周 · 季度 · 半年 · 年 · 十年 · 列表** 视图
  （共用一个导航栏）。有事件的日期会被标出；点击某一天可查看
  详情，点击事件标题可在语料库中打开它。
- **推断出的事件（来自你的文章）：**在多篇文章中*被提及*的未来日期
  会作为一个独立的、可筛选的 **推断** 图层显示出来——每个条目都显示一个
  “推断 · 从未确认（deduced · never confirmed）”标签以及文章/来源数量，点击其标题会打开
  产生它的确切文章集合。只有计数，绝不是判定。
- **天文现象，在本地计算：**四个主要月相（新月、上弦月、满月、下弦月）以及春分/秋分和夏至/冬至
  都在本机上计算（使用 Meeus 的算法，并已对照公开的天文年历
  数值验证）；每个条目都会在悬停气泡中说明其**方法和精度**。
  季节的命名**如实区分南北半球**——绝不会只写一个笼统的“夏季”。
- **气候背景：**一份随附的厄尔尼诺 / 拉尼娜事件数据集（采用 NOAA CPC ONI
  惯例）；任何仍在等待通过公开互联网交叉核对的条目都带有
  “待验证”标记。
- **日期不固定的节日会被如实标注**——对于每年日期都会变动的
  事件，应用绝不会编造一个确切的日子。
- **日历**（节假日 / 宗教 / 天文 iCal 来源）在
  **设置 → 日程** 中订阅，而不是在这里——标签页显示的是数据，底层配置放在
  设置中。订阅之后它们会自行保持更新：采集开启期间，新事件会被
  导入，每个订阅源会轮流重新检查，每一轮检查几个。失败的订阅源会在
  1 个月后重新检查，之后是 2、4 和 6 个月——**有上限，因此订阅源永远不会被
  永久放弃**——每一轮的统计可以在**任务管理器的计划
  标签页**中看到。这些都不会在启动时或离线状态下运行。约 500 个订阅源的**目录**本身
  （判定结果、重复提供方的文件夹、添加你自己的 `.ics`）属于底层配置，
  位于 **设置 → 高级 → 日历目录**。
- **如果导入事件的文件损坏到完全无法读取**（被截断、
  不是有效的 JSON，或在 Linux 或 macOS 上发生磁盘读取错误），日程会将其视为空，日志
  也会如实说明。在下一次保存替换它之前（一次导入、一次恢复、移除一个订阅源），应用会把这个损坏的文件
  原样保留一份，命名为 `calendar_feed_imports.json.damaged`，放在你的数据文件夹中，供你或
  恢复工具使用；第二次损坏绝不会覆盖第一份副本。它不属于
  备份的一部分。你可以随时自行删除它。只有部分条目损坏的文件
  仍然会被读取：这些条目会被略去，日志会统计它们的数量，并且不会生成副本。
  空文件也不会被复制：其中没有任何可恢复的内容。

### 3.6b 活跃信息源

**活跃信息源** 标签页显示那些在你采集之后仍在不断变化的来源
发生了哪些变化：维基百科、法律和地图，各占一个子标签。其中的所有内容
都从本机读取；绘制它不会抓取任何东西。

- **维基百科：**实时流关注了多少个页面，在过去 30 天内它报告了多少次变更，
  以及**其中有多少次存储了正文**（“2 of 4”：
  在预算限制下，它会存储一部分，其余只计数），每个
  订阅源都被不间断读取到的时间点，以及它知道自己漏掉的任何缺口。在此之下，是每一次
  变更，最新的在前；**显示差异** 会打开该变更到达时存储的差异。
  只被计数的变更会如实说明这一点，并且没有差异可看。你手动跟踪的
  页面（设置 → 维基百科）也会被列出：选择其中一个即可阅读其已跟踪的
  修订版本。比较两端的每个版本都有自己的 **加入语料库** 按钮：
  它会把那个确切的版本作为一篇独立的文章加入，日期为维基创建该版本的时间，
  并且在你的语料库已经包含它或相同文字时会如实说明。正文未被存储的
  版本无法加入，其按钮会说明原因。这就是 **立即追踪** 所存储的
  修订版本进入你的语料库的方式，因为搜索目前还不会读取它们。当 **页面遍历**
  开启时（见下文），一个*页面遍历*分组会说明它正在
  做什么（正在遍历；已暂停及原因；或正在等待维基的拒绝期结束），并且
  按版本列出它已列出的页面数，**与该版本自身的条目总数**并列
  （“1 234 000 of 2 700 000”）。这是两个计数，绝不是百分比：每个版本
  都按自己的方式统计条目数，因此第一个数字可能超过第二个。当
  获取**其他已变更页面**开启时（见下文），一个*其他已变更页面*分组
  （位于遍历分组上方）会统计已保存正文的页面、仍在等待正文的
  已变更页面、已获取的正文数，以及此后已成为实时流关注页面的
  页面数，同样按版本列出，并说明它何时停止：在存储
  预算达到某个明示的比例时停止——这个比例是应用显示的建议默认值，而不是一项裁定。
- **法律：**法律跟踪器关注的文件、最新和最早的检查时间，以及
  每一次真实的变更（没有任何改动的复查不计入），附带其
  存储的差异和指向你本地副本的链接。
- **地图：**你已下载的地图区域、其中哪些已暂停或失败及其原因，以及
  它们占用的空间。

新鲜度以日期显示，绝不加以评判：多新才算够新，取决于
具体的报道。预算会在这里显示，但需在 **设置 → 数据与备份** 中设定。

### 3.6c 气候

**用途：**在你的语料库旁阅读六份已发布的气候与地球记录，
每一份都与其发布方发布时完全一致。该标签页为每个数据集设一个子标签：

- **气温**——NASA GISTEMP v4：每月和每年的全球气温
  *距平*（相对于 1951-1980 年平均值的差值，单位为 °C，不是气温本身）。
- **海冰**——NSIDC Sea Ice Index v3：每日的北极或南极海冰范围，单位为
  百万 km²。
- **厄尔尼诺**——NOAA 的海洋尼诺指数（Oceanic Niño Index）：太平洋 Niño 3.4 区域
  三个月的海面温度距平。
- **地震**——USGS 目录：全球 6.0 级及以上的地震，
  自 1973 年 1 月起按月计数，并给出每月的最大震级。
- **排放与能源**——Our World in Data：按国家和地区划分的每年排放与能源
  数据，每一列都保留其原始提供方的条款。
- **气象站**——NOAA GHCN-Daily：**某一个**气象站的每日气温、降水和降雪，
  该站通过其 11 个字符的编号选定（例如 `USW00094728`，纽约
  中央公园）。一个气象站描述的是一个地点，既不代表一个区域，也不代表气候。

**它如何获取数据。**在你要求之前，不会下载任何东西。每个子标签都有自己的
**从发布方获取** 按钮（一旦已存储了数据，它会显示为 **从发布方更新**；
在 **气象站** 中，你需要输入站点编号并按 **获取站点**，之后则是
**更新此站点**），按钮会注明它将连接的服务器。它与其他所有网络操作一样，
要经过同一个同意弹窗，并且在飞行模式开启时会被拒绝。获取在
后台运行；任务管理器会显示它。读取已存储的内容不会发起任何网络
请求。

**你可以依赖什么。**每个子标签都注明其来源、许可证、方法，以及
本机上次获取它的时间。新的获取只会存储新的值或经发布方
修订的值：早先的值仍可读取，发布方不再提供的时间段
会被计数，绝不会被删除。空白单元格表示发布数据中的缺口，绝不是零。这里没有任何内容是
预测、评分或风险等级。

### 3.6d 天文台

**用途：**一次性看到你的整个语料库，以夜空的形式绘出。每个
**星系** 是一组相关的关键词；圆的每个扇区是十二个主题
领域之一。

- **角度（Angle）**只表示领域。星系在其扇区内的位置由一个稳定的
  哈希值决定，因此每次访问时它都停在原处，这个位置本身没有任何含义。
- **距中心的距离** 表示你所选的那一个度量，并带有标注的圆环。
  **星的大小（Star size）**以面积绘制（提及次数），是次要的提示。
- **颜色** 显示语言，或 **趋势** 视角；它绝不是唯一的信号。
  星座连线连接的是共享某个成员关键词的星系，绝不是仅仅
  看起来靠得近的星系。
- 夜空下方的 **排序表** 完整列出每一个星系，包括
  夜空无法放置的那些。表格是标准视图；夜空是阅读它的
  第二种方式。表格上方有一行，统计画面中略去的内容（尚未观测到的星系，以及
  不属于任何星系的关键词）。
- 同一个语料库总是绘出同一片夜空，因此你看到的变化就是你
  数据的变化。这里没有综合评分。

### 3.7 维基百科 *（位于 设置 → 维基百科）*

> **现在的位置。** 维基百科变更追踪和离线转储工具已移入
> **设置 → 维基百科**（内容优先）；被监视的页面仍会像任何文章一样出现在
> 通用搜索和分析中。各项控件保持不变。

**用途：** 监视特定的维基百科页面并**标记可疑
编辑**——*编辑*本身才是数据，而不是文章的副本。

- 通过**语言版本**（语言代码，例如 `en`、`fr`、`ar`）、
  **文章标题（Article title）**以及可选的**监视列表**标签添加要监视的页面。应用会保存**一份
  基线快照**，之后只保存每次新编辑的**差异/增量**——因此表面性的
  修改几乎不占空间。
- **立即追踪**（可选择**使用 ORES 评分**）会拉取新的修订版本，并标记
  幅度大或可疑的修订：大幅的字节增减、回退/清空标签、匿名编辑、
  集中爆发的编辑，以及（如已启用）ORES 的“破坏性/善意”机器学习评分。候选编辑
  只是*呈现出来供你自行判断*；不会把任何内容标记为“虚假信息”。
- **已标记的变更**列出各项编辑（时间 · 语言版本 · 页面 · 编辑者 · Δ 字节 ·
  原因 · ORES），并提供**差异**查看器和指向维基百科的**实时（live）**链接。
  可按*仅已标记*和语言版本筛选。

**被监视的页面就是语料库文章（活跃信息源的取舍，明确说明）：**
你监视的每个页面也会作为文章加入你的语料库，归在按语言版本划分的
信源下（“Wikipedia (en)”），因此它会**像其他任何文章一样出现在通用搜索、关键词和
When×Where×Who 中**。应用替你做出的取舍，均公开可见：（1）搜索和分析看到的始终是
追踪器已获取的**最新版本**，并记录其对应的确切修订编号；（2）**每个被追踪修订版本的全文都保存在本机**
——过去的版本可以被精确重建（基于版本的分析，无需重放差异），坦白地说，代价是存储会随编辑
活跃程度增长；（3）被分析的文本是转换为纯文本的 wikitext——绝不会
冒充渲染后的文章。一切都保留在本地；每个页面的变更
历史始终可查，**活跃信息源**标签页会显示它
（[3.6b](#36b-活跃信息源)）。

**该通道的存储预算（默认 150 GB，可由你调低）：** 维基百科通道
在达到你于首次运行向导中（或在**设置 →
存储**中，旁边会列出与本机可用磁盘空间的对比计算）设定的总量后停止保存文本。自 2026-09-29 的裁定起，默认值为
**150 GB**，此前为 20 GB；如果磁盘较小，可将其降至 20 GB，或降至
最低 1 GB 的任意数值。已经完成过向导的安装会保留
当时同意的数值；从未见过向导的安装则遵循新的默认值，
直到你自行设定。

**页面遍历（默认关闭，除非你开启）：** 实时流只会得知
有人编辑过的页面，因此一部百科全书的大部分内容永远不会到达它。勾选
**同时遍历每个条目标题**（设置 → 维基百科，位于*实时编辑流*
下方）会列出你所选语言版本的每一篇条目，每次请求 50 个标题，一次只发
一个请求，穿插在实时流自身的读取之间，持续数天。它保存每个
页面的标题、大小、最新修订版本和 Wikidata 编号，从不保存其正文，且计入同一
存储预算；它也绝不会把这些页面变成实时流完整跟踪的页面。它
只在实时流运行时运行，使用同一连接：飞行模式，或
没有可用代理的保护模式，会让它**等待**（它从不直连），而
要求放慢速度的维基会在一段暂停后再次被请求，暂停时长逐次加倍，最长一
小时。重启后，每个语言版本都会从停下的地方继续。其进度显示在**活跃
信息源**和任务管理器中。

**为什么遍历可能要排在实时流首次排空之后。** 实时流每 30 秒执行一次排空（drain），
保存它接收到的内容；搜索索引、其他已变更页面的获取以及遍历，都在每次排空*之后*的
时间里运行。一次排空会获取所跟踪页面中已变更页面的文本，
而在有积压时（例如实时流从数小时前恢复），这意味着成千上万个礼貌的请求，因此
排空现在设有**获取文本的 20 秒上限**，在各语言版本之间分配
（每次排空轮换首个语言版本）。每一项变更仍会被记录；未能及时获取的文本
会被计为*已推迟*，并且**由之后的某次排空获取**：先是从未保存过的页面，然后是
最久未检查的页面（每次排空每个语言版本最多 200 个页面；排空报告中的 `text_backlog`
表示补取过程*发现*有多少在等待，这与已获取的数量并不相同）。在每个语言版本的时间份额内，
这些页面会先于该版本最新的变更被尝试。获取失败或被拒绝的页面，
补取过程会在 5 分钟内不再理会，这样服务持续拒绝的页面就不会
每 30 秒被请求一次。客户端
每秒发出一个请求，因此一次排空大约获取二十个文本：在积压数千个被推迟的
文本时，补取需要数小时，而不是一次排空就能完成。该上限限制的是获取何时可以*开始*：已在
进行中的获取会先完成（每次连接或读取最多等待 30 秒），因此一次排空可能
略微超过 20 秒。页面遍历开启时，它会保留 30% 的空闲时间，因此获取其他已变更页面
不能占满全部空闲时间。状态（`/api/scheduler/status` 中的 `wiki_lane.service.drain`
块）会说明排空进行到哪里：所处阶段（`hot-sets` 或 `feeds`）、语言版本、本次排空
已持续多久，以及连续失败了多少次排空及其原因。

**读懂顶栏中的 W。** W 是**实时流**的开关，不是遍历的开关：
遍历是上面那个勾选框，并且只在实时流运行时运行。W 角落的
小标记以形状表示实时流的状态：实心圆点表示已连接并正在接收；
圆环表示*已选择但未连接*（被飞行模式挡住，或在本次会话中尚未启动）；
带圆点的圆环表示正在连接但失败，并在自动重试；短横表示已暂停；
叉号表示已停止。将鼠标悬停其上可看到文字说明，包括页面遍历是否开启。点击
圆环会**启动**实时流（你需确认一次联网）；点击圆点或带圆点的
圆环会**暂停**它；Shift+点击会停止它。设置 → 维基百科在语言版本上方用文字
显示同样的两行。在你联网或断网，以及勾选
或取消勾选遍历时，两者都会重新绘制。

**其他已变更页面（默认关闭，除非你开启）：** 实时流会保存
它所跟踪页面的文本，而对其他所有页面，只统计它报告的变更次数。
勾选**同时获取其他已变更页面的文本**（设置 →
维基百科，位于遍历勾选框旁边）会同样获取那些其他页面的最新文本，
每次请求 50 个页面，等待最久的页面优先。在等待期间被编辑了十次的页面
只需获取一次，取其当前状态。应用会保存每个页面的
**最新和上一版**文本，之后被删除的页面会保留它当时的文本。这些
文本**保留在该通道自己的文件中，不进入你的语料库**；搜索框可以找到它们
（见下文*搜索该通道保存的内容*）。当通道文件占到其**存储预算的 90%** 时，它们就会停止，
其余空间留给实时流跟踪的页面；这一比例是提议的默认值，而非
裁定，活跃信息源中会显示它。它只在实时流运行时运行，使用
同一连接，并与遍历一样等待：飞行模式，或没有可用代理的保护
模式，会让它等待（它从不直连），而要求放慢速度的维基
会在一段暂停后再次被请求，暂停时长逐次加倍，最长一小时。

**崩溃或更新不会让运行丢失。** 通道保存的所有内容都以
小的、要么全部完成要么完全不做的步骤写入，因此一次崩溃（或强行关闭应用）最多丢失正在进行的那一步；
遍历会从其书签处恢复，实时流则从它最后保存的位置恢复。真正会
停下来的是通道本身：应用总是以**离线**状态启动，因此重启后不会
获取任何内容，直到你用飞行按钮再次联网——如果运行原本开启，就会恢复运行；原本关闭，则保持关闭（运行等待期间，主页会显示一行提示）。等待期间不会丢失任何内容
（实时流自身的历史可追溯约一周）。活跃信息源 → 维基百科 → 实时
流会显示**已运行时长**（本安装保存或请求过内容的小时数，
跨重启累计，并附停止次数），并在通道沉寂时显示一行
**已停止**，说明已停多久、从何时开始。同样的数据也作为 `wiki_lane.run`
出现在浸泡测试窗口（soak-window）报告中。“停止”只表示通道在三个或更多
小时内没有任何活动迹象，并不说明原因：崩溃、更新、飞行模式和关闭的应用看起来都一样。

**搜索该通道保存的内容：** 该通道为其保存的文本维护一个搜索索引，
位于同一文件中，并计入同一存储预算。已变更页面的
**最新**文本会被完整索引，包括标题。每个**较旧版本**（已变更
页面的上一版文本，以及实时流所跟踪页面除最新版本以外的每个版本——最新版本
已经是你的语料库文章）都按**后续编辑删除的行**来索引：
其余内容都在较新的版本中，在那里已经能被找到。
因此，如果一次搜索的词语一部分位于保留的行中、一部分位于被删除的行中，
两个版本都找不到，而这类结果的每个列表都会说明这一点。索引在
实时流运行时建立，在获取之前进行，最多占用获取空闲时间的一半；
搜索会说明还有多少文本在等待建立索引；无法读取的文本
会被搁置，并在通道下次启动时重试。中文、日文和
阿拉伯文的切分和归一化方式与你的语料库自身的索引完全相同，印地文和
孟加拉文的词语保持完整。在搜索框（Ctrl/⌘-K）中，这些结果列在
**本机保存的维基百科文本**下，位于你的语料库结果旁边，从不与之
混合排序；每条结果都注明其语言版本、属于哪种文本（已变更页面的最新或
上一版文本，或实时流所跟踪页面的较早版本）及其日期。
打开一条会显示该版本的文本、它保存在哪里，以及它在
维基百科上的完整地址；**加入语料库**会把这个确切版本作为一篇独立文章加入，日期为
维基生成该版本的时间；如果你的语料库已包含它或相同的文字，会如实说明，
而不会重复保存。除此之外，通道中的任何内容都不会进入你的语料库。
**浏览**页面会在你的语料库结果下方，用单独的一节列出同样的结果，
每条都附有匹配的段落和各自的**加入语料库**
按钮。在它们上方会说明搜索了什么：只是维基百科通道
在本机保存的文本，绝不是维基百科本身，以及这些文本来自哪些页面和语言版本、
还有多少文本在等待建立索引，以及获取其他已变更页面是否关闭。因此列表为空
意味着通道的文本中没有你的词语，而不是维基百科中没有。**立即追踪**（设置 → 维基百科）
为被监视页面保存的版本也在这一搜索中：它们保留在你的语料库数据库中，
而通道位于自己文件中的索引会以同样方式读取它们（每个较旧版本按下一个已保存版本
删除的行索引，最新版本完整索引，除非你的语料库
文章已经就是那个版本）。它们出现在同一标题下，标注为
由页面追踪器保存，**加入语料库**会像其他结果一样加入那个确切版本；
搜索会说明它读取了多少个被追踪的页面。一个你既跟踪又追踪的页面，
可能会在每个存储中各列出一次同一版本：两个存储是分别读取的，彼此互不
依赖。已下载的转储不在这一搜索中：其文本
可在搜索框的维基百科分组中找到。同一查询在两个列表中的含义相同（`salt*`、
`NEAR(salt works, 5)`、`title:salt`），但描述文章的筛选条件（
信源、语言和时间框，以及 `source:`、`author:`、`url:`、`tag:` 和
`title:=`）不作用于这些文本，只要设置了其中任何一个，该节都会说明。
导出、分析窗口和批量操作作用于你的语料库；维基百科
文本在你加入后才会纳入其中。

**跨语言版本的一个条目，以及浏览量最高的页面**（活跃信息源 → 维基百科，位于
底部）。这两个视图只读取本机已有的内容；都不会联网获取。
*跨语言版本的一个条目*：输入一个 Wikidata 条目（Q42），或点击其中一个建议（
本周实时流为其页面记录到最多变更的条目），表格会针对
你跟踪的每个语言版本，显示该版本的页面、其 **wikitext 大小（字节）**（在页面遍历
到达该页面时读取一次）、读取时间，以及**本机
在过去七天内记录的变更**。没有该页面的语言版本会说明原因：遍历尚未在该版本
运行、尚未完成（并说明进行到哪里，因此该条目可能存在），或已完成
但未找到。变更计数是实时流在本机记录的数量；对于实时流
未为其记录任何内容的语言版本，显示为“未知”，因为这与零并不相同。大小旁边的条形是该大小除以屏幕上最大值的比例，
从零开始；除此之外不做任何计算，而且各语言版本是各自独立的文章，而不是
译本。页面遍历在你开启之前处于关闭状态（设置 → 维基百科），因此在
尚未遍历的实例上还没有可比较的内容，表格会说明这一点。
*浏览量最高的页面与您的语料库并排*：信息源自己发布的其最新一天浏览量最高的页面列表
（名次和浏览次数按其原样给出；保留前五十行），每行旁边是
**你的语料库**中以短语形式提及该标题、并于该
UTC 日以及截至该日的七天内发布的文章数量。它是**一天的数据，而不是时间序列**：该列表
每天都会被覆盖，不保留任何单页浏览历史。计数来自你的语料库，
即本机所收集的内容，而不是整个新闻界；标题可能有歧义，或在另一种语言中
写法不同；来自维基百科的文章和被隔离的文章不计入；
在时间限制内未完成计数的行，或标题中没有搜索索引可匹配的词（例如单独的“-”）的行，显示为“未计数”，原因见其悬停提示；建议只读取本周变更最多的 400 个页面。这两个数字并排
显示，从不合并。

重量级的**离线全文基线**（整个语言版本的转储）是*独立*的，位于
**设置 → 维基百科**中——变更追踪并不需要它们。参见
[`docs/USER_MANUAL.md`](USER_MANUAL.md)。

**读取已下载的转储（离线）：** 新的转储下载使用
*multistream* 格式，并会同时下载小型的配套索引——这
一对文件使转储可以随机定位。在**设置 → 维基百科 → 从已下载的转储中读取页面**中，
选择一个已就绪的语言版本，输入页面标题，应用就会扫描
索引，在其字节偏移处解压一个小数据块，并显示该
页面的**原始 wikitext**——完全在本机完成，同时显示扫描统计。
你读到的是*截至转储日期的快照*，而不是实时的文章；会提供
不区分大小写的标题匹配，并加以标注。较旧的单流（single-stream）
文件无法随机访问——应用会如实说明并建议重新下载。
转储的**语言列表仅限于应用支持的语言**（12 种界面
语言加上分析器支持的语料库语言）；上面的被监视页面
语言版本选择器保留完整列表。

### 3.7a 政府

**用途：** **政府**侧边栏标签页（代码锚点仍为 `law`，
标签显示为“政府”）汇集各国官方数据，并追踪**法律**
如何变化。它有六个子标签页：

- **国家**——来自世界银行的各国**官方统计数据**（GDP、
  人口、预期寿命、劳动力、公共财政以及常用指数）。**加载标准
  国家数据**会获取这些数据（需联网，经同意门控）。每个数值都是数据发布机构
  公布的数字，**绝不是可信度评分**；**缺失值是公布中的空缺，
  不是零**；会显示各数据发布机构，**从不取平均**。每个数字都带有单位，
  每个指标的悬停提示说明其衡量的内容——有两种看似错误而其实不是：
  移动电话订阅数可以超过每百人 100 个（人们持有多张 SIM 卡），毛
  入学率可以超过 100%（它计入了复读生和超龄学生）。
- **比较**——两个国家并排，每个指标作为对齐的一行。这只是一种
  **展示**，而非计算：它显示每个国家自己最新公布的数字以及
  该数字所属的年份；某个国家没有数字时，单元格显示为**空缺**。
  它从不对两国做减法、排名或评分——比较由你自己来做。
- **分组**——汇总数据和国家集团，可在两种**视角**之间切换：
  - *由发布机构公布*显示数据发布机构自己公布的汇总数据（世界银行的
    “高收入”“撒哈拉以南非洲”“欧盟”等）。首先打开的是一份精选的简短列表；
    **显示全部**会展开为完整集合。这些是数据发布机构自己的
    数字，不是我们的。**世界银行的区域并不是大洲**——“撒哈拉以南非洲”
    不包括埃及、利比亚、突尼斯、阿尔及利亚和摩洛哥，它们属于其中东与
    北非区域，因此这一视角**完全没有非洲大陆的数字**，并会如实
    说明，而不是拼凑出一个看起来像官方数字的结果。
  - *由成员国计算得出*由我们自己对成员国进行汇总，并**并排显示多种计算方法**
    （人口加权平均、简单平均、GDP 加权、中位数，以及在有意义时给出
    总和），让你看到结果在多大程度上取决于方法，
    而不是只交给你一个数字。不做任何排名，也不称任何方法为
    最佳。只有在求和有意义的指标上（人口、GDP、劳动力）才提供**总和**；
    对于百分比、比率或预期寿命，**会拒绝计算并显示原因**，
    因为把百分比相加得到的是一个没有人测量过的数字。每个数字都注明其**覆盖范围**和**离散程度**（最小/最大/n）——
    一个掩盖了十倍差距的国家集团总体数字虽然属实却具有误导性，因此范围会
    随之一起显示。缺少成员国数据时，汇总**默认会被拒绝**；你可以
    仍然发布，此时结果会被标注为不完整，并准确列出缺少的是哪些
    成员国。国家集团的成员构成会随时间变化（金砖国家在 2024 年之前
    有五个成员；欧盟在 2020 年失去了英国），因此每个集团数字都注明其计算所依据的**成员构成
    版本**；对于我们尚无法找到成员名单来源的集团，会直接
    说明这一点，而不是显示一个数字。
- **地图**——可选指标的 **ooMap 分级统计地图**，带有年份/历史
  选择器；点击某个国家，会在“国家”子标签页中打开其详情。
- **法律**——从全球官方来源追踪**法律**（成文法、政府公报、知识产权记录），
  观察它如何随时间变化（*变化本身就是数据*）。这是一个**研究用
  镜像**，绝非权威来源，**也不构成法律意见**——每条记录都链接
  回其官方公报。默认预置了一份覆盖全球的真实官方来源目录
  （`legislation.gov.uk`、EUR-Lex、Légifrance、govinfo、WIPO Lex、USPTO、EPO……）。
  **立即跟踪更改**会通过合乎伦理的
  获取器拉取被追踪的文件，先保存一份基线，然后保存如实的**差异**，并对大幅变更加以标记；**已标记的法律
  变更**列出这些变更（司法辖区 · 标题 · Δ 字节 · 原因），并附上差异和
  指向官方来源的链接。当几乎相同的文本出现在多个司法辖区时，简报还会呈现一条
  **示范立法（model-legislation）**线索。
- **统计**——数据发布机构名录，以及其他子标签页背后的原始、带版本的数字，
  另有**将序列加入语料库**（见下文）。

**普通搜索中的统计数据。** 一个谁也找不到的数字，并不真正存在于你的语料库中，
因此每个**序列**——某一国家的某一指标，涵盖所保存的每一年——也可以
转化为一篇普通的**文章**。之后它就走常规路径：搜索能找到
“life expectancy France”，其词语会进入趋势和线索，并像其他任何内容一样出现在信息流中，
无需记住什么特殊的搜索框。有四点值得了解：

- 它是**每个国家每个指标一篇文章**，而不是每次修订一篇。重新公布的 1991 年
  数字会更新现有文章，而不是新增一篇近乎相同的副本，因此重新运行该
  任务不会有额外开销，也不会新增任何内容。
- 这些文章**按其实际性质标注**——信源显示为“Official statistics
  (World Bank)”，来源类别为 `statistics`——因此你可以在任何视图中将它们筛入或
  筛出，而查找多家媒体相互重复的协同检查
  也不会把成千上万条形状相同的行误认为是一致意见。
- 正文刻意**只包含主题和数字**，**公布中的空缺
  显示为空缺**。若在约 9,800 篇文章的每一篇中都重复数据发布机构的名称和机器序列代码，
  会把“World Bank”推到整个语料库关键词
  排名的最顶端——脚手架压过了你的语料库真正关注的内容——所以不这样做。
- 若要**按数据发布机构**而非按主题查找它们，请按信源或
  `statistics` 标签筛选；若要**按序列代码**查找某一序列，请使用“统计”子标签页，它会
  精确回答，而不是靠文本匹配。

转化这些序列是一个后台任务，从**政府 → 统计**启动；它
可以恢复、可以取消，并且不会耽误收集。

### 3.8 证据与保管

*（从**设置 → 高级 → 安全**进入——“保管链”是该面板的标题；在内容优先的改版中，
它已离开侧边栏。）*

**用途：** 向持怀疑态度的第三方离线证明：你的语料库
在*这个*时间持有*这个*条目、内容为*这些*，并且该记录此后
未被更改。它**不是**举报人/SecureDrop 系统；这里的“来源”是指
新闻媒体，而不是需要保密的个人。

该面板分为三部分：

- **设置与状态（Settings & status）。** 开关包括**后量子签名**（在 Ed25519 之外
  再添加一个 ML-DSA / FIPS-204 签名）、**OpenTimestamps 锚定**（锚定到
  比特币，以独立证明时间）、**采集时自动记录**（每次成功采集时追加一条签名
  记录），以及一个**默认操作者**标签。关键在于，
  状态始终显示**实际生效**的状态，而不只是你的意愿：如果你启用了 PQC
  或 OpenTimestamps，但没有安装所需的库，它会显示*“已请求，
  库未安装”*，并保持仅 Ed25519/仅本地——**它绝不会显示一盏它无法兑现的
  绿灯。** 还会显示密钥保护方式（持有口令时为 `aes256gcm-scrypt`，
  口令来自 `OO_KEY_PASSPHRASE` 或数据库口令；否则为 `plaintext-0600`；对于 0.6 之前、
  尚未能重新封装的密钥，则为 `pkcs8-pbkdf2`，或在持有口令时为 `plaintext-0600`，
  它会说明其文件实际保存的内容）。
- **查看与验证链（View & verify chain）。** 输入一个条目编号（例如 `article:42`），可**查看链**
  （序号、操作、操作者、时间、签名算法）、**验证**（重新检查链的
  链接、哈希、签名、时间戳），或**导出捆绑包**（一个
  可离线验证的文件）。
- **锚定 Merkle 根（Anchor Merkle root）。** 粘贴一个 Merkle 根，通过已配置的提供方进行锚定。

> **应用内显示的隐私警告：** 锚定到公共区块链会永久公开一个
> 哈希，并向日历服务器运营者暴露你的 IP/时间信息。与其使用有资金的链上钱包，
> 不如优先选择本地 + OpenTimestamps；如需匿名，请经由 Tor（`HTTPS_PROXY`）路由；
> 或者保持仅本地（默认设置不会泄露任何内容）。

**OpenTimestamps 与飞行模式。** 在 OpenTimestamps 模式下，如果某条采集记录的
提交被网络总开关拒绝（在收集过程中按了停止），不会用一份仅本地的证明
代替它，因为那份证明将是永久的：这条记录处于待补状态，
之后再写入，标记为补录，并附上其锚定。待补队列没有大小限制，
每轮收集结束时最多写入其中 200 条，每条最多进行三次
日历提交，期间保管日志处于写锁定状态。因此，大量积压
会在你恢复联网后的一段时间内拖慢每轮收集的结束阶段。
在总开关仍处于启用状态时，写入待补记录（“予以记录，并标记为补录”，或
`POST /api/custody/reconcile`）会在第一次被拒绝时停止，并说明是总开关拒绝了
它；这些记录仍处于待补状态。单独的缺口检查仍会给出结果，其 `drained` 块
会报告 `refused_offline`。

无需本应用，即可在任何地方验证捆绑包：

```bash
python scripts/verify_custody.py custody_bundle.json [--pin]
python scripts/verify_evidence.py bundle.json [signer_pubkey]
```

完整设计——以及每种机制能证明什么、**不能**证明什么——
见 [`docs/USER_MANUAL.md`](USER_MANUAL.md)。*（一项计划中的改造，旨在让
此标签页做到傻瓜式且基本自动化，记录在
[`docs/ROADMAP.md`](archive/roadmaps/DESIGN_MEMORY_pre-0.2.md) 中。）*

### 3.8a 来源完整性

*（来源完整性工作台已移入**设置 → 高级 → 安全 → “打开来源完整性
工作台”**；协同行为现在也会自动呈现——作为主页上的线索、在分析
窗口的**相关**视图中，以及作为文章列表和阅读器中的内联“N 份副本 = 一个声音”徽标。）*

**用途：** 看清你的信源背后的*结构*——并由你自己决定
谁的信号算数。这里刻意**没有信任评分**；单一数字会
固化偏见，并压制小型、外国、新兴或持不同意见的信源。完整指南：
[`docs/USER_MANUAL.md`](USER_MANUAL.md)。

- **反放大（Anti-amplification）（系统提议 → 由你处置）：** *扫描协同行为*会找出
  在多个信源中同步发布的近似重复内容洪流，并附上证据
  （共享文本、时间、主机）。默认情况下它们只会被**注释**——从不会被悄悄
  折叠。**应用折叠**可将一个网络算作**一个声音**（在任何衡量共识的
  计数中）；它仍保持标记状态，**展开（撤销）**会精确恢复原始的同等权重
  视图。未经你的操作，任何内容都不会被折叠。主页上的回音室线索
  也带有同样的操作。
- **信源画像：** 一个由多个测量维度组成的面板——协同行为、新颖性
  （原创还是转述）、产出能力、透明度事实、过往记录——每一项都附有
  方法和注意事项，**没有综合评分**。
- **共享注释（信任网络）：** 撰写关于
  信源的描述性、可争议的事实（所有权、倾向、协同行为、更正）；将其**导出**为
  **已签名**的捆绑包；**导入**你选择信任的捆绑包。*谁说了什么？*会显示
  某个信源的所有归属说法，并呈现**异议**——从不平均成一个数字。
  参见 [`docs/USER_MANUAL.md`](USER_MANUAL.md)。

日常使用完全用不到**高级**：采集的底层管线、来源管理、关键词
整理、统计机构目录、日历订阅源目录、诊断
台、**安全**以及**卸载并清除**都在那里，放在**折叠的分区中，只有在你打开某一分区时
才会加载其数据**（仅来源目录就可能有数万
行）。安全过去是一个独立的子标签页；现在它是高级中倒数第二个分区，
而两项不可逆的操作——**紧急清除**和**卸载应用**——被单独拆分
到一个自己的分区（**卸载并清除**）中，这样在你阅读加密相关内容时，
两者都不会被误触。这两次调整都没有丢失任何东西：原来在安全子标签页上的每个控件
都仍然在那里，标题也相同。**采集**和**来源**已在
上文介绍（[3.2](#32-采集-位于-设置--高级--采集)、
[3.3](#33-来源-位于-设置--高级--来源)），通过高级进入；
**维基百科**（[3.7](#37-维基百科-位于-设置--维基百科)）保留其独立分区。
官方**数据**根本不在这里——它们属于数据，因此位于
**政府 → 统计**下。

- **图形（外观）：** 主题、强调色、密度、**字体**，
  以及侧边栏展开/收起。（没有文字大小滑块：它只会缩放
  根元素，而样式表中几乎没有任何内容继承它，所以它实际上不起作用。

  Focus、Terminal、Canvas、Editorial**——基于同样的数据和同样的诚实

  现在就是这个正式的分区。）
- **卡片（主页上的线索）：** 应用能运行的每个线索生成器，按其类别分组
  （*上升 · 过度报道 · 报道不足 · 值得调查 · 核查报道框架 · 持续关注 ·
  背景 · 数据完整性*）。关闭其中任何一个，它就不再出现——这不会改变
  文章本身的任何内容，只改变哪些提示会出现在你的主页上。凡是线索带有
  阈值的地方，现在都可以看到并调整，每个阈值都标明了**安全范围**、
  一行说明调整它会产生什么效果，以及一个**重置**按钮。你随时可以让一条线索
  *更严格*；设置下限是为了让线索永远不能声称超出其证据
  所能支持的内容——例如，“刷屏”检查不会低于 p<0.05 的阈值，
  因为低于该阈值，检验就再也无法区分真正的激增与普通波动。任何
  超出范围的值都会被纠正**并报告出来**，绝不会被悄悄调整。
- **偏好设置（常规）：** **主题**（系统/深色/浅色）、**语言**以及**默认搜索结果数**。
- **关键词过滤（高级 → 关键词）：** “无意义”的虚词（the、you、not……）由
  内置的多语言停用词表移除。你可以调整它：设置**关键词最短长度**、**丢弃
  纯数字词条**、开关内置停用词表，并维护一个**已排除的
  关键词**列表（每行一个或用逗号分隔）。排除会在所有地方隐藏一个词条，
  但可以撤销——已保存的提及记录会保留。（你也可以在洞察中点击任何关键词旁的
  ✕。）
- **维基百科离线基线：** 从一个**平铺列表**中选择一个**语言版本**
  （先是你的界面语言，然后是规模最大的版本），每个选项都以
  **本地名称**（自称）开头——各版本是按语言而不是按国家划分的，因此
  没有按大洲分组。每个可下载转储的版本都会显示一个**内联的大致
  大小**（`~X GB`，来自随应用附带的带日期的表格——不产生任何额外网络请求），方便你在
  下载前做出判断；准确大小会在下载开始时读取。**下载**
  可以续传（暂停/继续 + 进度表）。这些离线转储体积大且
  是可选的，仅用于离线阅读/搜索——实时变更追踪（维基百科
  标签页）不需要它们。
- **AI（本地大语言模型）：** 顶部的**设置本地 AI**框在一处列出剩下的全部
  计划——本机将使用哪个后端（在有独立
  NVIDIA GPU 可以支撑时使用 vLLM，否则使用 Ollama）、还需要安装什么，以及
  下载大小——并在**一次**同意之后，通过**一个按钮**执行。当没有剩余事项时，
  它会自行隐藏；它下方的各组件控件保持
  不变，所以你仍然可以自己完成每一步。再往下是：当前使用的后端
  以及**为什么**选择它、已安装的模型和一个整理过的带日期目录、**拉取**一个
  模型（一个**排队的**下载任务——一次一个、可取消，并实时显示字节
  进度；这些字节通过 Ollama 进程走明网，**不**经过 Tor——会在
  同意提示中说明）、**移除**模型，以及设置**当前模型（active model）**。
  **硬件适配性**只在这里说明一次，并说明它对你意味着什么：只有低于某个下限时
  （少于 4 个 CPU 核心，或少于
  6 GB 内存，且没有加速器），默认才会拒绝本地推理；在没有独立 GPU、
  显存很小的显卡，或统一内存较小的 Mac 上运行，只是**关于预期效果的
  警告**，而不是拒绝。它**从不构成阻拦**——勾选一个复选框即可重新开启 AI，而且
  无论哪种情况，说明都始终可见。**启动**本地 AI 使用顶栏的
  **AI 胶囊按钮**，在任何界面都可以操作。
  **“行为与提示词”**编辑器开放了四个可编辑的系统提示词
  （摘要 / 翻译 / 综合 / 关键词提取）以及模型保活时间。
  这四个提示词**以全部十二种界面语言提供**，因此法语或
  日语读者得到的是用其语言撰写的摘要，而不是英文结果；
  编辑器显示的是**你的**语言的内置文本，并且每个结果都会记录所使用的确切提示词。
  你自己写的提示词（如果有的话）会**完全按照
  你写的样子**使用，无论你用什么语言写成。**自定义提取器**列表
  让你定义托管的提示词，用于写入由 AI 生成的元数据（标记为
  *不可靠*，绝不会进入可信的关键词索引）。
  当没有安装 Ollama 时，会出现一个**应用内安装程序**（Linux/Debian）：它会下载
  官方安装脚本，用 GitHub 经过证明的 sha256 摘要对其进行校验，显示
  一个可见的提权步骤，然后运行它——只要摘要不匹配就会拒绝。macOS/Windows
  则会得到一个如实的指引，指向 ollama.com/download。
- **统计——统计机构目录（高级 → 官方统计）：** 一个
  描述性的政府及国际统计机构目录。**数据**
  本身属于数据，因此位于**政府 → 统计**下，
  而不在设置中。每个统计机构都附有**同样的描述性立场来源
  说明**——官方数据会写明其发布机构及其立场——**绝不会给
  单个来源贴“有争议”标签、下结论或打分**。你可以**把它们加入你的来源**——新闻/新闻发布
  栏目已知的统计机构会被启用并从那里采集，而
  地址尚未经过调研的统计机构则以禁用状态加入，而不会被爬进其
  数据集门户——还可以从有文档的机器接口
  （World Bank API / Eurostat SDMX）**获取官方数据**，与完整出处以及一等公民的
  **版本年份（vintage）**一起保存（重新获取会生成新的一行，绝不会覆盖）。各统计机构的数据**并排
  显示，绝不取平均**，**对来源进行三角校验**视图会标出混合了不可比较的
  单位 / 季节调整 / 基准年的单元格。**检查修订异常**会纯粹以
  回顾的方式，标出这样一个已保存的数据：其最新版本对某个过去值的修改幅度，
  相对于该序列自身的修订历史而言异常地大（不打分）。获取数据通过你配置的
  传输方式出网，并在飞行模式下被拒绝。
- **OpenStreetMap：** 选择一个地图区域（附带一个带日期的 `~GB` 估算）并将其
  作为可续传、可暂停的任务管理器任务下载（受唯一的网络同意弹窗把关）。
- **新闻邮件：** 将新闻邮件作为文章导入——**在导入时匿名化**（
  从不保存收件人，涉及收件人的回显内容会被涂黑，追踪令牌会被剥除，
  服务器端的追踪跳转包装会被标记；**从不抓取任何内容**，因此导入
  永远不会暴露你打开或点击过邮件）。有三种途径：
  - **选择 .eml 文件（Choose .eml files）**——一个小型多文件上传。
  - **导入整个文件夹**——指向本机上的一个文件夹；其下的每个 `.eml`
    都会作为一个**可暂停、可续传的后台任务**导入（在任务管理器中可见），
    可以处理 20 GB 以上的归档，并跳过已导入的邮件。
  - **从邮箱拉取 (IMAP/POP3)**——从邮箱实时拉取，并在使用时显示
    说明（与服务商之间使用 TLS，你的 IP 可见，**不**经过
    Tor，凭据不会被保存）。使用 TLS 时，服务器证书必须与其名称匹配，
    并且来自你的电脑信任的证书颁发机构；否则拉取会在
    发送密码之前被拒绝，并在提示中说明原因。通过 API 进行拉取时，若将
    `use_ssl` 设为 false（通常在 143/110 端口），会先在同样的检查下用 STARTTLS 升级连接，
    如果服务器不支持 STARTTLS，拉取就会被拒绝：你的密码绝不会以
    未加密的形式发送。
  - **每封新闻邮件属于哪个发布者？**——导入的新闻邮件目前
    全部放在一个统一的来源里。`GET /api/newsletters/publisher-preview` 会针对你已有的新闻邮件，
    展示按发布者归档后**会**是什么样子：每个发件
    域名、来自该域名的邮件数量，以及它会对应到哪个现有来源（一个真实的
    eTLD+1，来自随应用附带的 Public Suffix List——因此 `email.bbc.com` 对应到 `bbc.com`——
    而新闻邮件平台则反过来处理，因此两个 Substack 刊物绝不会
    被合并成一个“Substack”）。它**只是预览**：不会关联或移动任何内容，而且
    在证据不足以判断的地方，它会如实说明，而不是猜测。
  - **移除已导入的简报**——从实时语料库中删除每一篇导入的新闻邮件文章（.eml +
    邮箱），用于把有问题的一批替换成干净的重新导入
    （恢复是累加式的，所以备份中不包含新闻邮件绝不会移除它们——而这个操作
    会）。
- **数据与备份——统一的导出 / 导入：** 一处即可备份所有内容，
  **无论数据库多大**。**导出 / 备份…**会打开一个对话框：选择一个**目标文件夹
  或驱动器**，勾选要包含的内容（语料库、导入的新闻邮件、本地大语言模型、
  离线地图、维基百科转储），并提供一个**口令**——加密的语料库会以流式方式写入
  该文件夹，形式为**各自独立认证的分卷加上 Reed-Solomon 校验数据**（因此
  丢失/损坏的分卷，即使是语料库分卷，也可以重建），而大型公共数据块
  （模型 / 地图 / 转储）则**原样**复制。**没有大小上限**，归档也
  从不整体保存在内存中。口令**无法找回**——丢失口令意味着
  语料库备份无法打开。
  - **每次导出都会创建自己的带日期文件夹。** 你选择的目标是**上级**文件夹：
    在其中，每次导出都会创建 `YYYYMMDDHHMM_OpenOmniscience_Backup`——即导出开始时的本地日期
    和时间，因此文件夹会按你创建的顺序排列。同一分钟内的第二次
    导出会得到 `_2`、`_3`，以此类推。已存在的文件夹**绝不会被
    写入**，因此同一驱动器上较早的备份不会被之后的备份损坏。
  - **每次导出都是一份全新的完整备份。** 不会复用之前任何一次的内容，因此一次
    导出所花的时间和空间就是你选中的全部内容——作为交换，该文件夹中的每个
    字节都是由这一次导出写入的。
  - **写入后校验（Verify after writing）**（默认开启）。最后一个分卷写完后，每个分卷都会
    从目标位置读回，并将其校验和与写入时记录的校验和进行比较。
    它会把每个字节再读一遍，在慢速驱动器上这大约会使导出
    时间翻倍；这是唯一能发现“驱动器接受了
    写入却存下了别的东西”这种情况的办法。完成面板随后会显示**“已校验（Verified）”**——
    如果没有显示，它会说明是四种原因中的哪一种：校验被关闭了、
    校验被取消了、这组分卷无法重新读取，或者校验**失败**并列出相应
    分卷。
  - **`BACKUP_SUMMARY.md`** 会在每次导出结束时写在 `volumes.json` 旁边：
    内容与完成面板显示的相同——分卷、字节数、每个表的行数（文章
    排在最前）、各类别复制的文件数、耗时、目标位置、加密状态、
    数据库结构版本和应用版本、校验结果，以及适用于
    备份内容的署名说明。它的存在是为了让文件夹在多年后放在移动硬盘上时
    仍能自我说明，那时显示这一切的面板早已不在了。它是一份说明，
    而不是签名：证明这些字节完好的是 `volumes.json` 中每个分卷的校验和。
    **它也是该文件夹中唯一未加密的文件**——没有你的口令，语料库
    无法读取，而这份摘要是放在旁边的纯文本，写明了
    语料库包含多少篇文章、多少个来源和多少份被追踪的文档。这就是该文件
    所做的取舍，文件本身也写明了这一点；如果对你来说，让文件夹
    自我说明，不如对捡到这个驱动器的人什么都不透露重要，你可以删除它。
  - **导出从不定时执行。** 没有自动或定时导出，也没有这样的
    计划——导出是一个**有意的操作**，因为它会把你的语料库写到
    你选择的地方，在你选择的时刻。
  **导入…**指向一个文件夹，找出其中可以导入的内容（一个要恢复的备份、
  大型数据或新闻邮件），并进行恢复。**恢复只做累加**——它
  **补充**你的语料库，**绝不替换**它：你已有的任何内容都不会被
  覆盖，重复内容按比特逐位检测，冲突的值**保留你的
  本地值并同时报告两者**，绝不取平均。
  - **导入报告。** 恢复合并和文件夹新闻邮件导入
    之后都会自动向磁盘写入一份**持久保存的报告**（以“文章”为
    单位——绝不是跨表的行数总和，那样看起来像是几百万篇文章，而实际上
    只是分布在许多表中的行）——内容包括进来了多少篇文章、有多少被
    筛除为非文章（见下文的**非文章筛查**），以及它留下的
    “后续工作”（例如，有多少新导入的来源仍在
    等待资格评估，见 [§3.3](#33-来源-位于-设置--高级--来源)）。报告
    本身会随你的**下一次**加密备份一起保存，因此会跟着语料库走。可以
    通过 `GET /api/backup/import-reports`（列表）和
    `GET /api/backup/import-reports/{filename}`（JSON 格式，或用 `?format=md` 获取
    易读的 Markdown 版本）下载——目前还没有专门的应用内界面来查看，
    所以请使用这些接口（或浏览器）来阅读报告。
  - **非文章筛查。** 每次恢复合并和文件夹新闻邮件导入
    都会自动筛查刚导入的文章，并**隔离**——保留、
    从不删除、且可撤销——任何符合来源资格试验所用的同一套提取有效性
    标准的条目（导航菜单页、链接列表、
    抓取失败的页面）。被隔离的文章不会出现在搜索和分析中，但
    仍保留在数据库里并随你的备份保存；统计数字记录在导入报告中。
  > **旧版 / 迁移路径（为较早的备份保留）。** 一个单独的面板用于恢复
  > **较早的单文件 `oo-backup-2`** 归档，在**应用（Apply）**之前同样提供累加合并**预览**
  > （新增 / 重复 / 冲突）（在经过校验的暂存副本上进行、原子替换，
  > 并在数据库旁保留一份 `pre-restore-*.db` 快照）。原始的**下载备份 (.db)**
  > 快照（SQLite 在线备份 API）收在*“旧版备份工具…（Older backup tool…）”*下，供手动
  > 使用。**破坏性的“替换你的语料库”恢复已被彻底移除**——没有任何流程
  > 能覆盖你的数据，而且恢复一个**加密**备份绝不会悄悄解密
  > 你的语料库。
- **维护（诊断面板）：** **清理关键词（重新索引，然后清理）**和
  **重新索引整个语料库**会运行一个**可暂停、带持久化游标的后台任务**
  （关闭标签页或重启后仍然有效，并从停下的地方继续）。在关键词引擎升级后
  运行清理，可将更新的停用词表/词族应用到已有文章上。
  旁边的**合并关键词词形（studies → study）**完成该清理中
  词形还原所需的那一部分，而无需重新读取任何文章：在加入词形还原之前
  索引的关键词会把“studies”与新文章使用的“study”分开，而合并会把这些
  较早的提及记录归到基本形式下，结果与重新索引完全相同。随后它会根据每个
  关键词的提及所用的语言来设置该关键词的语言。短语、名称，以及你的

- **安全与高风险环境使用（高级 → 安全）：** 为在压力下工作的记者提供的工具，
  每个都标明了其**如实的局限**：
  - **静态加密（新语料库默认开启）。** 新数据库在磁盘上
    使用 SQLCipher 4 加密：每次启动时，应用都会要求输入**那个
    口令**——一个固定不变的秘密，就像用户 ID 一样（脚本/无界面运行时使用 `OO_DB_PASSPHRASE`）。
    **没有找回方式，也没有其他解密
    途径**：丢失口令的代价是重新采集所需的时间，因为
    语料库是从网络重建的——除了从公开来源抓取和推断出的内容之外，
    它不包含任何个人信息。现有的明文语料库照常
    使用，不受影响；**设置 → 高级 → 安全 → “加密此语料库…”**可以
    *就地*转换一个语料库（需要明确同意，在替换前进行完整校验，并会
    特意保留一份明文快照作为你的退路——在你成功解锁后
    将其删除）。**体检工具（doctor）**（`GET /api/system/doctor`，
    以及同一面板）通过读取文件头来证实每个存储的*真实*状态
    ——语料库、保管日志、签名密钥——从不凭假设。
    **如实的局限：** 静态加密保护的是*被扣押或被复制的
    文件*。它无法保护已被入侵的运行中会话（应用运行时密钥就在
    内存中），而且只有当两个口令不同时，它才独立于全盘加密。
    明文运行仍可作为明确的选择（`OO_DB_PLAINTEXT=1`）——应用绝不会在
    明文文件上显示锁屏，因为那就是虚假的安全。
    来自加密语料库的备份照常可用：归档成员是
    可移植的，加密归档自身的封装在静态时保护它们，
    并且恢复会保持你的语料库的加密状态（已由测试验证）。
  - **加密备份**——一个受口令保护的快照（AES-256-GCM + scrypt）。
    丢失或输错口令意味着文件无法打开：没有找回方式。
    要恢复加密备份，请使用上文**数据与备份**中的
    **累加合并恢复**——它会先预览，然后补充你的语料库，绝不会
    替换它，也绝不会悄悄解密你的实时存储。*（旧的破坏性
    加密替换式恢复已被移除。）*
  - **数据库维护**——*压缩数据库（VACUUM）*会重建数据库
    文件：它会回收删除操作留下的空间（显示为“可回收
    空间”，是真实的 `PRAGMA freelist_count` 读数），并整理索引碎片。
    所需时间与文件大小成正比，运行期间会暂停采集
    写入；结果会报告实际释放的字节数和耗时。它
    从不解读或删除数据。它在内存中构建压缩后的副本
    （把副本写入临时文件会在本应用的页面大小下损坏加密文件，
    这一点经过实测），所以它会先检查电脑是否有足够的内存
    （大约是文件已用部分的 1.25 倍，另加应用始终为自己保留的空闲
    内存），以及驱动器是否有足够空间（大约是已用部分的两倍，
    再加上文件日志的大小）；任何一项不足时，
    它都会说明是哪一项并给出数字，而不会开始。无法
    读取的数值不做检查，它也会说明这一点。
  - **网络抓取模式**——*透明*（默认；礼貌，会在
    User-Agent 中写明本工具）或*保护*（应用的网页抓取通过一个由**你**运行的代理转发，
    例如 Tor，并使用通用的 User-Agent）。User-Agent 的唯一例外是应用向
    Wikimedia 服务器发出的 API 和转储请求（其维基百科、Wikidata 和转储功能）：
    Wikimedia 的 API 政策要求每个工具写明自己的身份，因此在保护模式下，这些
    请求仍然带有本工具自己的 User-Agent，通过同一个代理，并且只经由
    https。从 Wikimedia 网站抓取的其他任何内容（像其他页面一样采集的文章）
    则使用通用 User-Agent。即使在保护模式下，也有三项会直接连接，
    网络同意窗口的悬停提示会逐项说明：新闻邮件邮箱拉取、
    OpenTimestamps 锚定以及本地 AI 下载。
    保护模式**无法保证匿名**——你必须自己运行并信任该
    代理；没有代理 URL 时它会拒绝启用。像 Tor 这样的 SOCKS 代理
    无需额外安装任何东西。
  两项**不可逆**的操作位于再往下一个分区，即**高级 →
  卸载并清除**中，有意与上面的所有内容分开：

  - **紧急清除**——不可逆地删除本机上的语料库、密钥和缓存
    （需要两次确认）。**局限：** 就地覆盖在 SSD/闪存上*无法*保证
    数据无法恢复——为此，请使用全盘加密（LUKS/Qubes/Tails）
    并销毁密钥。另外还有一个 `panic` 命令行工具和一个 `--ephemeral` 运行模式
    （数据只存在内存中，退出时清除）。
  - **卸载应用**——移除应用的**虚拟环境（virtualenv）**和**桌面启动器**，
    然后停止服务器（需输入确认）。你的**数据会被保留**（要销毁数据，请先使用紧急清除）；
    应用文件夹会留在原处，供你手动删除。等同于
    `./install.sh --uninstall`，或安装程序在两个应用启动器旁创建的
    **“卸载 Open Omniscience”（Uninstall Open Omniscience）**桌面图标。

  约束这一切的治理规则和双重用途红线见
  [`GOVERNANCE.md`](GOVERNANCE.md)（也可在**帮助与文档**中查看）。

## 4. 常见工作流程（操作指南）

**收集某个主题的新闻并进行搜索**
1. **设置 → 高级 → 来源** → 确认相关来源已启用（可按国家/标签筛选）。
2. **设置 → 高级 → 采集** → 可以对每个来源点击 **获取源**，也可以把
   **调度器（scheduler）** 设为 RSS 模式，填好 **标签 / 关键词（Tags/keywords）** 后点击 **开始**（或者直接上线
   ——采集会自动运行）。
3. 在 **全局搜索栏（omnibar）** 中搜索 → 使用布尔查询 → 如有需要，点击 **导出 CSV/JSON（Export CSV/JSON）**。

**在后台持续监测某个报道领域**
1. **设置 → 高级 → 采集** → 将调度器的 **模式：RSS 源** 选好，设置 **语言**/**标签**，
   点击 **预览目标**，设置 **间隔**，勾选 **启动时自动开始**，
   然后 **保存**。
2. 可选：启用 **证据与保管 → 采集时自动记录**，这样每次抓取的内容在入库时
   就会被签名。

**为一篇文章制作经得起法庭/编辑审查的证明**
1. 在全局搜索栏中搜索这篇（或这些）文章。
2. **导出签名证据**（或对单个条目使用 **证据与保管 → 导出捆绑包**）。
3. 把捆绑包以及 `scripts/verify_evidence.py` /
   `verify_custody.py` 交给接收方；对方可以离线验证，既不需要信任你，也不需要信任本工具。
4. 如需独立的*时间*证明，请启用 **OpenTimestamps**，并对捆绑包的
   Merkle 根进行锚定（注意隐私警告）。

**监视一篇有争议的维基百科文章是否被篡改**
1. **设置 → 维基百科** → 添加页面（语言版本 + 标题），勾选 **使用 ORES（use ORES）**，
   点击 **立即追踪**。
2. 查看 **已标记的变更**；对任何可疑之处打开 **差异**。

**将某种大宗商品价格与新闻对照追踪**
1. **大宗商品** ——精选的数据源已在后台自动更新；
   如需获取某个特定网页上的价格，请添加一条 **价格提取规则** 并 **测试** 它。
2. 点击序列卡片 → 查看图表，以及它与某个新闻查询之间的 **相关性**。

**将语料库迁移（或合并）到另一台机器**
1. **设置 → 数据与备份 → 导出 / 备份…** ——选择目标文件夹/驱动器以及
   一个口令；语料库会以加密卷 + 校验冗余（parity）的形式流式导出（任意大小均可）。
2. 在另一台机器上，**设置 → 数据与备份 → 导入…** ——指向那个文件夹并
   进行恢复。恢复是叠加式的——它补充那台机器上已有的语料库，绝不会
   替换它，因此你也可以用它来*合并*两个语料库。旧版的单文件
   `oo-backup-2` 无需特别处理：导入扫描会在你指定的文件夹中的任意嵌套位置找到它，
   并把它作为单独一项列出，所以旧备份依然可以恢复。

**改为直接复制整个文件夹——迁移或备份的一等方式**

应用内的工具之所以存在，是为了提供文件复制做不到的功能（签名清单、能修复损坏卷的
校验冗余、两个语料库的叠加式合并、选择性恢复）。它们并不是你必须通过的关卡。
复制数据文件夹是一种在任何大小下都受支持的方式，而且在整体迁移一台机器时，
这正是正确的做法：

1. **停止应用**——点击顶栏中的电源按钮，或在其终端中按 Ctrl-C。这一步
   不可省略：在应用运行时复制，可能会复制到写了一半的 WAL。
2. 复制整个 **data** 文件夹（§5.1 —— `<app folder>/data/`，或 `OO_DATA_DIR`
   所指向的位置）。不是应用/代码文件夹：代码可以重新安装，数据不行。
3. 在另一台机器上，把文件夹放到你想要的位置，并让 `OO_DATA_DIR` 指向它——
   或者，在全新安装时，在首次启动的步骤中选择该文件夹（§5.1）。

在复制过程中，语料库在存储时始终保持加密，而密钥就在文件夹之内一同迁移，
因此 **口令是你唯一必须另行携带的东西**。自 2026-08 起，本地 AI
权重也存放在数据文件夹中，所以复制时会把它们一并带走——正因如此，这才是
真正的整机迁移，而不仅仅是迁移语料库。

## 5. 技术参考

### 5.1 数据存放在哪里

由 `src/paths.py` 按以下优先顺序确定：

1. **`OO_DATA_DIR`**，如已设置（始终优先）。
2. **源代码检出目录**——如果从一个可写的代码仓库运行（开发/可编辑安装/Qubes
   `$HOME` 安装），数据位于 `<repo>/data/`。
3. **按用户**——否则使用 XDG：`$XDG_DATA_HOME/open-omniscience` 或
   `~/.local/share/open-omniscience`。

对于通过 `install.sh` 安装的情况，第 2 种是常态：安装程序会克隆一个
可写的目录树，因此你的数据位于 `<app folder>/data/`，而第 3 种情况中的 XDG 路径
根本不会被创建。当你去找这个路径却发现它不存在时，这并不是 bug。

**在首次启动时选择文件夹。** 你第一次启动应用时——
在语言和法律条款步骤之后、设置口令之前——它会询问你的语料库应存放在
哪里。保留默认位置只需点击一次。如果你选择了别的
文件夹（例如外置硬盘），应用会在其中创建一个名为 **`OOS data`** 的文件夹，
并把这一选择记录在安装根目录下的 `oo.env` 中，
`scripts/launch.sh` 每次启动时都会读取它。

这一步有两点是有意为之的，值得了解：

* **它只在全新安装时出现。** 一旦已有语料库，应用就会拒绝
  更改这项设置，因为它无法搬动已经存在的内容：密钥、
  保管日志和模型存储会跟随新设置，而语料库
  却留在原处，下次启动时会找到一个空文件夹并提议新建
  一个。迁移现有语料库，就是 §4 中所述的普通文件夹复制（“改为直接复制
  整个文件夹”）——停止应用，复制数据文件夹，让 `OO_DATA_DIR`
  指向这份副本。
* **选择其他文件夹会结束设置流程，并要求你重新启动应用。**
  此时还没有创建任何东西；该文件夹要到下次启动
  才生效，所以如果在同一会话中继续，语料库就会被放进旧文件夹，
  而记录下来的选择却指向新文件夹。

如果文件夹不寻常，你会收到提示，而不会被阻止：已经存有
语料库的文件夹（继续操作会打开它，而不是新建一个）、以内存为后端的
文件系统（写入其中的内容在重启后会丢失），或可用空间不足（会给出
具体数字）。只有应用确实无法写入的文件夹才会被拒绝。

**如果驱动器被拔出。** 用这种方式选定的文件夹会得到一个小的标记文件
`.oos-volume`，其 id 也会记录在 `oo.env` 中（`OO_DATA_VOLUME_ID`）。应用
运行期间每两秒读取一次这个文件。如果驱动器不见了：

* 应用会把断开事件记录在内部磁盘上（位于
  `~/.local/state/open-omniscience/` 下，因为它无法写入已消失的驱动器）。
  诊断包会附带这份日志，下次启动时在说明上一个会话如何结束时
  也会提到它。
* 采集会暂停，并弹出一个窗口，请你在 30 秒内重新连接驱动器。
  如果连回来的是同一个驱动器，应用会重新启动以重新打开你的数据（加密的
  语料库会再次要求输入口令）。它无法直接继续运行：数据库
  连接在应用启动时就已确定。
* 这 30 秒过后，会开始第二个倒计时，在再过 30
  秒后干净地关闭应用；点击 **立即关闭** 则会立刻关闭。在第二个倒计时期间重新连接
  驱动器，应用仍然会改为重新启动。
* 拔出前最后几个瞬间正在写入的内容可能会丢失。但
  数据库本身保持一致：SQLite 会在下次打开时回滚未完成的
  写入。

如果你在驱动器未连接时启动应用，它不会在原处新建一个空
文件夹：它会显示一个“您的数据驱动器未连接”页面，每隔几秒再检查
一次，并在驱动器重新连上后立即打开应用。挂载在同一路径上的另一个
驱动器会被识别为不同的驱动器（其标记不
匹配）。如果你是有意删除了该文件夹，请从 `oo.env` 中删除 `OO_DATA_DIR` 和
`OO_DATA_VOLUME_ID` 这两行，以便用一个新的空语料库重新开始。
紧急擦除会替你完成这一步。如果系统在重新插入后把驱动器挂载到了新路径，
应用就无法在那里找到它：请关闭应用，并把 `oo.env` 中的 `OO_DATA_DIR`
指向新路径。

在该目录中你会找到：`open_omniscience.db`（语料库，SQLite/WAL）、
`app_settings.json`（主题、结果数量上限）、`custody_settings.json`（保管
偏好）、保管密钥、已下载的维基百科转储、任何 `pre-restore-*.db`
快照，以及 `models/` ——本地 AI 权重，它们存放在应用自己的
数据目录中，而不是各个后端各自的主目录里：

| 路径 | 内容 |
| --- | --- |
| `models/ollama/` | Ollama 的模型存储（`OLLAMA_MODELS` 指向这里） |
| `models/huggingface/hub/models--<org>--<name>/` | vLLM 的权重，每个仓库一个文件夹（`HF_HOME` 指向 `models/huggingface`） |
| `cache/` | vLLM 服务器的计算缓存——Triton 内核、torch Inductor、CUDA JIT 缓存、vLLM 自身的缓存和配置根目录。首次运行时建立，可以安全删除（会重新建立），可能达到数 GB |
| `vllm_start_attempts.jsonl` | 每一次 vLLM 服务器启动和每一次退出，连同失败时的原话。之所以存放在**这里**而不是 vLLM 环境内部，是为了让重新安装 vLLM——大多数人在服务器无法启动时首先会尝试的做法——不会删掉它为何失败的记录 |
| `vllm_failed_starts/` | 最近几次**失败**启动各自的完整日志。实时服务器日志会被下一次尝试覆盖，而重试循环会在一分钟内就覆盖它，因此一旦发现启动失败，就会立即复制一份。最多几百 KB |

如果你自己设置了 `OLLAMA_MODELS`、`HF_HOME` 或任何缓存变量
（`XDG_CACHE_HOME`、`TRITON_CACHE_DIR`、`TORCHINDUCTOR_CACHE_DIR`、
`CUDA_CACHE_PATH`、`VLLM_CACHE_ROOT`、`VLLM_CONFIG_ROOT`），则始终以你的设置为准——
应用会重新导出你的值，而不是覆盖它。这种重定向只适用于
**服务器**：安装 vLLM 时仍使用 pip 常规的 wheel 缓存，因此
重新安装不会重新下载它已有的数 GB 内容。在 2026-08-04 **之前**下载的权重
仍位于 Hugging Face 自己的 `~/.cache/huggingface/hub/` 中；设置 → AI 会报告
它们并说明应移到哪里，但不会替你移动或删除任何东西。

### 5.2 环境变量

> **如实说明：** 本表列出的是面向操作者的要点——它**并非**代码可读取的每一个
> 环境变量（一次审计在代码库中统计到约 259 处环境变量
> 引用）。本表中没有列出某个变量，只是因为手册求简，
> 并不表示该变量不存在。

| 变量 | 用途 |
|---|---|
| `OO_DATA_DIR` | 覆盖数据目录（见上文）。 |
| `OO_HOST` / `OO_PORT` | 绑定地址/端口（默认 `127.0.0.1:8000`）。 |
| `OO_AUTOSEED` | 首次运行时导入全球来源目录（默认开启；设为 `0` 可禁用）。 |
| `OO_NO_SCHEDULER` | 设为 `1` 则永不自动启动后台调度器；此时应用启动后处于在线状态，而不是飞行模式。无论如何都会安装飞行模式的套接字防护（只有 `OO_AIRPLANE_SOCKET_GUARD=0` 才会不安装），因此之后开启飞行模式时，仍会在套接字层面阻止对外连接（少数遗留情况列于 SECURITY.md）。 |
| `OO_NO_INDEX` | 设为 `1` 可跳过洞察的自动索引。 |
| `OO_CUSTODY_ON_INGEST` | 采集时自动记录保管日志的旧版默认值（一旦在界面中保存了偏好，以界面偏好为准）。 |
| `OO_KEY_PASSPHRASE` | 对静态存储的保管私钥加密（AES-256-GCM，经由 scrypt）。如未设置，则由数据库口令对其进行封装；两者都没有时，密钥以 `0600` 权限明文写入，并如实报告为 `plaintext-0600`。 |
| `OO_FETCH_TIMEOUT` / `OO_FETCH_MIN_INTERVAL` | 调整合规抓取器的超时时间和每台主机的最小间隔。 |
| `OO_LLM_MODEL` / `OO_OLLAMA_URL`（或 `OLLAMA_BASE_URL`） | 默认的本地模型和 Ollama 端点。 |
| `OO_ALLOW_BIG_SCANS` | 设为 `1` 可在内存低于下限的机器上运行全语料库后台扫描（参见[小型机器上的内存](#55a-小型机器上的内存唯一真正的上限)）。此后的判定会报告你已强制越过该限制。 |
| `OO_CKPT_GATE_TIMEOUT_S` | 两轮采集之间的 WAL 检查点等待单写入者闸门的时长，超时后如实记录一次跳过并继续（默认 `30`）。`0` 恢复旧的无限期等待（存储防护自身的检查点仍然最多为写入闸门等待 30 s，且在它自己的线程上进行，因此强制继续之后仍处于监视之下）。 |
| `OO_STORAGE_GUARD` | 设为 `0` 可关闭存储防护（不采样、不暂停）。当数据库的预写日志增长超过一个按你的机器确定的上限，或驱动器快满时，该防护会自行暂停采集，并会自行恢复；通知中的“仍然继续”会在上限仍然成立时强制继续采集，而如果可用空间降得过低或无法读取、某次写入因空间不足而失败，或越过了第二个上限，这种强制继续会自行结束。在暂停期间，用于完成被中断的导入的后台重新索引，以及文章列表索引的一次性构建，也同样被暂停（它们在任务管理器中的行会说明这一点，并会自行继续；“仍然继续”强制继续的是采集，而不是这些）。 |
| `OO_DAMAGE_GUARD` | 设为 `0` 可关闭在数据库报告你的某个数据文件损坏后所触发的暂停（报告本身仍会记录在数据文件夹中的 `database-damage.json` 里，通知随后会说明暂停已关闭）。不关闭时，被数据库认定为损坏的文件，在你重新开始采集之前（维基百科文件：在你关闭再重新开启维基百科抓取之前），不会被采集、维护步骤或维基百科通道写入（每一项都只针对其自己的文件）。由启动检查（见 `OO_BOOT_VERIFY`）设置的暂停，只有在检查所指出的表再次读取无误时才会结束；其他暂停则会结束，并且如果损坏仍然存在，在第一次读取失败时会再次停止。与 `OO_STORAGE_GUARD` 相互独立。 |
| `OO_BOOT_VERIFY` | 设为 `0` 可关闭对数据文件的启动检查。该检查在意外停止之后（以及之前的检查未完成或发现损坏之后）、应用仍处于离线状态时运行：每张表用 SQLite 的 `PRAGMA quick_check` 读取一次，一次一张表，使用只读连接，因此检查本身不写入任何内容。报告损坏的表、表清单或页面检查，会在一个新连接上再读取一次，只有第二次读取结果一致时才算作损坏：第二次读取结果不同或无法进行时，会附上原因标记为未检查，也不会因此暂停或修复任何东西。对于加密文件，当某张表无法给出结论时（SQLCipher 对许多损坏页面只抛出一个笼统的错误），它还会调用一次 SQLCipher 自己的页面检查（`PRAGMA cipher_integrity_check`，大约每 230 MB 一秒），并记录哪些页面未通过认证（大于 4 GiB 的文件不会交给这项页面检查，因为超过这个位置后它读取的字节是错的；记录中会说明这一点，且不会把该文件判定为完好）；有页面未通过的文件即为损坏，而所有页面都通过的文件，只要还有某张表未能给出结论，也仍不会被判定为完好。完全无法读取的页面（驱动器故障）会单独计数，其本身不算一项发现；在这项检查运行时退出应用，不会消耗三次尝试中的一次。采集会等到检查结束；被发现损坏的文件会被暂停（见 `OO_DAMAGE_GUARD`），重新开始采集时，会先再次读取检查所指出的表，然后才解除暂停（对维基百科文件，则是关闭再重新开启维基百科抓取）。无法完成的检查在连续三次启动后不再尝试，应用会说明这一点（这种搁置会一直持续到应用下一次意外停止为止，期间每次正常启动都如此，而意外停止是需要检查的新理由）；但这绝不会清除已有的发现：之前的检查发现损坏的文件会一直处于暂停状态，直到它所指出的表读取无误（或文件被替换）。每个文件的结果都记录在数据文件夹中的 `database-damage.json` 里。 |
| `OO_BOOT_REPAIR` | 设为 `0` 可关闭对损坏的资料库文件的修复（同时也关闭下文所述的删除）。默认情况下，当启动检查（见 `OO_BOOT_VERIFY`）读出资料库文件的某张表损坏时，应用会在本次启动时、仍处于离线状态且采集尚未写入任何内容之前修复该文件：它把所有仍能读取的行逐表复制到旁边的一个新文件中，重建索引和搜索索引，用同样的逐表读取检查新文件，然后才切换过去。位于无法读取的页面上的行不会出现在新文件中；通知会说明复制了多少条、有多少条无法读取，以及它们在哪些表中。父行无法读取的行会被保留，绝不删除，并按表计数；如果某张表原本会把一条丢失行的编号交给下一条保存的行，修复会在最高的丢失编号处添加一条标记为«(lost …)»的占位行（这是一条可见的行，搜索索引可以通过该标记找到它），通知会列出这些表。修复进行期间，应用要保存的任何内容都会等待（修复需要写入闸门，该闸门默认开启：设置 `OO_WRITE_GATE=0` 时修复会拒绝进行并说明原因）；如果在复制期间仍有内容被保存到该文件，副本会被丢弃，并在下次启动时重新制作，而不是覆盖那次保存切换过去。它需要的可用空间为整个文件加上其日志，再加上磁盘防护保留的余量，还需要一个能给文件起第二个名字（硬链接）的驱动器；缺少其中任何一项时，它会说明缺的是什么，并且不做任何更改。只有资料库文件会被修复，而且只在本次启动自己的检查发现损坏之后：维基百科和法律文件照旧会被暂停，但不会被修复；在应用运行期间发现损坏的文件，会在下次启动时检查，如果检查确认损坏，届时再修复；检查无法读取的表不算一项发现。**损坏的文件会被保留，而不是删除：** 修复会在新文件旁给它起第二个名字 `<name>.damaged-<date and time>.<ending>`（其日志使用相同名称加 `-wal`），因为它可能仍含有副本未能读取的行，可供恢复工具使用。**应用会在新文件首次读取无误 30 天后删除这一个文件**，即在该日期当天或之后的第一次启动时删除；修复或检查正在运行时，或资料库再次被报告损坏时，绝不会删除；修复通知和诊断 zip 会说明它有多大、在哪里以及删除日期，删除之后会说明已删除及其大小。如果驱动器本身无法读取资料库文件的某个页面（通知会说明有多少页），应用就完全不会删除该文件，因为驱动器故障可能正是页面无法读取的原因：它会一直保留到你自己删除为止，通知会提示你检查驱动器。设置 `OO_BOOT_REPAIR=0` 时删除功能关闭，通知会说明这一点。你可以随时自己删除它。它只删除修复时留存的那个文件（该文件必须位于你的数据文件夹中、是普通文件、名称完全一致，并且与修复记录的是同一个文件），不删除其他任何东西；只要其中任何一项不成立，它就什么都不删除，并说明原因，也不会再次尝试。已开始但未结束的修复会在下次启动时重试；连续两次启动都在修复中途结束后，在应用更新之前不会进行第三次（记录为数据文件夹中的 `database-repair-attempt.json`）。每次修复的记录（日期、计数、文件名，以及删除发生后的删除记录）都在 `database-damage.json` 中；它保留最近十条，而记录已超出这十条范围的留存文件，应用永远不会删除。 |
| `OO_ARTICLE_INDEXES` | 设为 `0` 可不构建文章列表的两个索引。默认情况下，应用会在更新后的第一次启动时、仍处于离线状态时构建它们一次：一个用于语言筛选，一个用于按标题排序，这样随着资料库增长，两者都能保持快速（每 150 万篇文章约占 190 MB）。在慢速驱动器上的大型资料库中，构建可能需要几分钟；它会在任务管理器中显示为“正在建立文章列表的索引”，应用要保存的任何内容都会等到它完成；它需要两样东西，会事先测量，任一不足时会说明情况而不开始构建：数据文件所在驱动器上每篇文章约 400 字节的可用空间，以及对标题排序所需的内存（每篇文章约 300 字节，全部保存在内存中，从不写入临时文件，另加应用始终为自己保留的可用内存；它会给出具体数字）。在构建中途结束的启动会重新开始构建；连续两次启动都在构建中途结束（计算机内存耗尽或断电）之后，在应用更新之前不会进行第三次尝试，因为一次本身就会让应用崩溃的构建，绝不能变成一个永远无法完成的启动（相关记录为数据文件夹中的 `article-indexes-attempt.json`；删除它可让应用再次尝试，而以正常方式退出应用会退还这次尝试）。在开关关闭时，或在反复拒绝之后，每次启动会花不到一秒的时间比对数据库版本与其表。开关关闭时，列表照常工作，只是在这两项选择上会更慢。 |
| `OO_WAL_HIGH_MB` / `OO_DISK_RESERVE_MB` | 用以 MB 为单位的数字替换存储防护的两个推算上限：使采集暂停的预写日志大小，以及使采集暂停的可用空间下限（默认：按你的机器确定；防护在暂停采集期间于任务管理器中显示的通知里会列出这些上限）。 |
| `OO_STORAGE_GUARD_TRIP_AFTER` / `OO_STORAGE_GUARD_RESUME_AFTER` | 需要连续多少次采样（间隔约五秒）才会触发和解除防护（默认 `2` 和 `2`）。 |
| `OO_WRITE_GATE_WARN_S` | 当单次写入占用闸门的时间超过此值时（默认 `60`），记录一条警告，附上占用线程的名称和一份调用栈；警告在发现占用时写入，因此其中的数字至少等于该阈值，而不是占用的实际时长。这类占用结束时，日志会再记录一行 `write gate released after 61.3s by 'name'`（以实际时长代替 61.3，精确到十分之一秒；不足一秒的占用不会有这一行）。`OO_WRITE_GATE_WATCHDOG=0` 会完全关闭这项监视。 |
| `OO_REINDEX_HOLD_TARGET_S` | 重新索引的一个批次在提交并让等待中的写入者进入之前，可以占用单写入者闸门多长时间（默认 `10`）。它适用于导入文章的后台重新索引、全语料库重新索引任务（当 `OO_REINDEX_COMMIT_BATCH` 大于 1 时）以及恢复结束时的重新索引。一旦批次已占用闸门至少一秒，只要有其他写入排在它后面，它会在下一篇文章时更早提交（因此一次占用可能因正在处理的那篇文章和提交本身而略超目标时长；而对于一个始终在排队的写入者，重新索引的代价大约是每秒一次提交，而不是每篇文章一次）。批次宽度（`OO_IMPORT_REINDEX_COMMIT_BATCH`、`OO_REINDEX_COMMIT_BATCH`）仍是上限；宽度为 `1` 时每篇文章单独提交，因此不存在可被目标时长提前结束的批次（恢复报告和重新索引任务的进度仍会列出当前生效的目标）。`0` 即旧规则：只在达到批次宽度时提交。如果取值不是大于或等于零的秒数，则保持默认值。 |
| `OO_HEAVY_TAIL_WAIT_S` | 主页简报的重新计算与后台维护通道相互等待（而不是同时运行）的时长（默认 `900`）。`0` 表示无限期等待。 |
| `HTTPS_PROXY` | 让对外流量（例如 OpenTimestamps）经由代理/Tor 发出。 |

### 5.4 HTTP API

本应用是一个运行在 `127.0.0.1:8000` 上的 FastAPI 服务器；网页界面是一个
无依赖的 `index.html`，在 `/` 提供。机器可读的模式位于 **`/openapi.json`**。交互式 Swagger（`/docs`）和 ReDoc
（`/redoc`）页面**默认关闭**：它们会让浏览器从第三方主机获取脚本、样式和一种字体，
因此需要它们的开发者应以 `OO_API_DOCS=1` 启动应用。Prometheus 指标位于 `/metrics`。按设计**没有身份验证**
（仅限本机回环、单用户）。所有端点都有**速率限制**（大致为：读取
100/小时，写入/导出 50/小时，删除 20/小时，批量导入 10/小时；超出时返回 `429` 并附带
`Retry-After`）。

精简清单（权威且始终最新的模式请参见 `/openapi.json`，或在 `OO_API_DOCS=1` 时参见 `/docs`；
文字说明请参见 `docs/ARCHITECTURE.md`）：

### 5.5 通过 Tor 运行

本应用可以通过 Tor 运行（保护抓取模式 → 你自己运行的 Tor 代理），但可达范围
如实地说会更小——这是实测而非猜测（2026-06-12 的实时日志：50 个
默认来源中有 32 个在一轮中通过 Tor 导入成功）：

- **按连接的拒绝是正常的，不是致命错误。** 有些主机会拒绝某些
  Tor 出口：在同一次运行中，28 个 FRED 序列中有 21 个导入成功，其余失败。
  这就是为什么数据源失败会附带**感知传输方式的判定**——*被拒绝*
  （“连接被拒绝/重置——通过 Tor 时，这往往只是某一个出口的
  拒绝；重试时常会换到另一条线路”）不同于 *robots
  不允许*（主机声明的政策，我们会遵守，绝不重试或
  规避），不同于 *序列已失效*（HTTP 404——目录条目需要
  替换；重试无济于事），也不同于 *无法访问*。暂时性
  失败会自动重试一次；**重试失败的数据源** 按钮
  会重新运行的，恰好是那些确实值得重试的数据源。
- **主机屏蔽 Tor 是主机自己的选择。** 我们会把它显示出来；我们绝不规避
  robots、屏蔽或验证码。在有容许 Tor 的官方端点时，
  请优先使用它们。
- **模型下载无法通过 Tor 进行。** Ollama 通过它自己的进程经由明网
  下载模型（在 **设置 → AI** 中安装/拉取）；可用的
  明网连接是下载模型的明确前提条件。一旦拉取完成，推理
  在本机回环上进行，不受影响。*（打包好的离线 LLM 套件已在计划中，尚未发布。）*
- **如果 vLLM 安装中途中止**，几乎总是因为下载某个超大的 wheel 时
  超时——单是 torch 就约有 500 MB。提示信息会指出是哪一个，
  而已下载的 wheel 会被缓存，所以重新开始安装会接着进行，
  而不是从头开始。如果链路慢到反复失败，请在启动应用前调大
  `UV_HTTP_TIMEOUT`（以秒为单位）。
- **如果 vLLM 服务器反复启动又退出**，无论你当时是否在看，原因都会
  被记录下来：每一次启动和每一次退出都会写入
  `vllm_start_attempts.jsonl`，附带失败时的原话，而最近几次失败启动
  各自的完整日志保存在 `vllm_failed_starts/` 中——两者都在
  数据目录里，因此重新安装 vLLM 不会把它们清除。两者都包含在
  **诊断 → 全部诊断（all diagnostics）** 导出中，所以答案就在诊断包里，而不是
  必须实时捕捉的东西。
- **匿名性仍需由你自己把控**：保护模式无法保证
  匿名——代理由你运行、由你信任；应用所负责的，是让它的网页
  抓取经由该代理、并使用通用的 User-Agent，但它向 Wikimedia 服务器发出的 API 和转储
  请求除外，这些请求仍会标明本工具（Wikimedia 的 API
  政策要求这样做）。新闻邮件邮箱的拉取、OpenTimestamps 锚定以及
  本地 AI 下载都是直接连接的。

### 5.5a 小型机器上的内存——唯一真正的上限

在小型机器上，应用已经会自动收缩：当 **内存（RAM）低于 4 GB**，或
**可用内存不足 1 GB** 时，它会使用更小的数据库缓存和更少的连接池
连接，限制同时抓取的来源数量，并**暂停
全语料库后台扫描**（来源资格评估）。它会在 设置 → 高级 → 采集 中的采集状态旁
告诉你这一点，并给出具体数字。

**把代价说清楚：** 在一台语料库很大、可用内存很少的机器上，
这可能意味着来源资格评估在那里永远不会运行。这是这项
设置的代价，而不是故障。如果仍要运行这些扫描，请以
`OO_ALLOW_BIG_SCANS=1` 启动应用——此后的判定会报告你已强制越过该限制，并且
仍会继续报告这台机器内存较小，因为强制越过改变的是应用*做什么*，
绝不改变它*测量到了什么*。

#### 繁重的视图会在拖垮应用之前停止

繁重的分析读取（大多数洞察视图、天文台、被引用最多的
来源、诊断包）本来就有时间限制。它们还会在
数据库向它们交付数据行时监视可用内存。如果可用内存降到
内存防护的下限（默认 **256 MB**，`OO_MEM_GUARD_AVAIL_MB`），读取
会被停止，视图会说明原因并给出数字：*“在 12 秒后停止了这次读取：
机器内存几乎耗尽（可用 180 MB，等于或低于内存防护所用的
256 MB 下限）……”*。如果请求读取时内存
已经这么低，读取不会开始，而是显示*“未开始这次读取”*。
等内存恢复后再打开该视图即可；没有任何东西丢失，
因为读取不会改变任何内容。

**它不做什么：** 它是一个停止，而不是一个上限。它只看到读取数据行期间增长的部分——
加载整张表的视图正是在这里增长——除此之外什么也看不到。
`OO_READ_MEMORY_STOP=0` 可以关闭它，而不影响内存防护。

#### 当内存持续耗尽时，应用会自行停止并说明原因

内存不足时，内存防护会暂停新的采集。暂停并不会
归还应用已经占用的内存，所以在小型机器上，内存可能连续好几分钟停留在
下限，然后操作系统在不作任何说明的情况下杀掉应用。现在应用会
改为自行结束。只有在以下条件**全部**满足时才会这样做：内存防护在最近整整
**5 分钟**内一直处于启用状态（`OO_MEM_STOP_WINDOW_S`），其读数中至少十分之九
等于或低于 **64 MB** 可用（`OO_MEM_STOP_AVAIL_MB`），没有任何读数高于 128 MB，读数之间
没有超过时间窗口十分之一（30 s）的间隔，并且本应用占用了机器内存的
至少三分之一（如果占用内存的是别的东西，停止也释放不了什么，
应用就不会停止）。只要出现一次恢复（哪怕很短暂），或者按下开始或
继续，时间窗口就会清空。

停止之前，它会保存它所知道的信息：每个线程正在
做什么的快照、会话台账中的一行记录，以及数据旁边的 `memory_stop.json`
（数字和步骤名称，最多 8 KB）。然后它通过与电源按钮相同的路径
结束。你已保存的数据不受影响；它会先最多等待一分钟，
让正在进行的导入、占用语料库的后台任务或数据库写入
完成（恢复或数据驱动器迁移会被记录为进行中，但
不会专门为它们等待），并在记录中说明是否仍有某项在进行；在这段时间内无法
完成的内容就不会完成。
在它运行期间，任务
管理器会显示*“应用正在自行停止，因为内存持续耗尽”*。
下次启动时，“系统”标签页中的 **会话** 一行会显示*“已自行停止 —
内存持续耗尽”*（悬停可查看注意事项），一条一次性消息也会说明
同样的情况，诊断 zip 中会附带该记录。**结束的是当时正在
运行的内容；你需要重新启动它。** `OO_MEM_STOP=0` 会关闭这一停止，只保留
暂停。

#### 为什么应用无法简单地给自己的内存设上限

程序没有诚实可靠的办法给自己强制设定内存上限：

- **Linux 会忽略 `RLIMIT_RSS`。** 它存在于 API 中，却不起任何作用。
- **`RLIMIT_AS` 限制的是*地址空间*，而不是实际使用的内存。** 本应用
  使用的库（DuckDB、numpy）会预留远多于其实际
  使用量的虚拟地址空间，因此地址空间上限会在进程真正变大之前很久，
  就在不相关的代码中引发 `MemoryError`。应用刻意两者都不设置，而且如果
  有人添加了其中之一，会有一项测试让构建失败。

#### 真正有效的上限：在 cgroup 中运行

在使用 systemd 的 Linux 上，以硬性内存上限启动应用：

```bash
systemd-run --user --scope -p MemoryMax=3G -p MemorySwapMax=0 \
  ~/open-omniscience/scripts/launch.sh
```

**如实地说，它能换来什么：** 它把一次*桌面卡死*变成一次*干净的应用
重启*。没有上限时，内存耗尽的机器会不停地使用交换空间，直到
一切都无法使用——浏览器、终端、桌面——你可能
不得不断电重启。有了上限，内核会改为杀掉**本应用**，而且
只杀本应用。

**它的代价：** 应用会在工作中途被杀掉，没有机会进行收尾。

**为什么你的语料库仍然安全：** 数据库以 WAL 模式运行，并使用
`synchronous=NORMAL`，因此被杀掉时只会丢失从未提交的工作。
所有已提交的内容都在磁盘上，预写日志会在你下次解锁时
重放。**你已经采集的内容不会丢失。**

以这种方式被中断的**备份**则是另一回事：它会处于不完整状态。
不过它不会被悄悄地信任——每个卷在清单中都带有校验和，
备份自身的验证步骤会检查所有校验和，并指出哪些卷
缺失或不匹配。在依赖一份曾被中断的备份之前，请先运行一次验证（或干脆重新备份）。

`MemoryMax` 请设为大约 **总内存的 60–75 %**，为
桌面和浏览器留出空间。`MemorySwapMax=0` 是阻止系统疯狂换页的那一半：
没有它，应用在达到上限之前，仍可能通过交换让机器慢如蜗牛。

如果你不使用 systemd，同样的功能可以通过 Docker/Podman
（`--memory=3g --memory-swap=3g`）或普通的 cgroup v2 `memory.max` 实现。

#### 崩溃之后：下次启动能告诉你什么

当应用被杀掉或崩溃时，启动器窗口现在会保持打开，并说明
它是如何结束的：`SIGKILL` 通常是低内存终止程序留下的标志。正常的
停止（应用自己的停止按钮、关闭窗口、注销）会像以前一样关闭
窗口。

下次启动时，会在 **设置 →
高级 → 诊断 → 会话取证** 中，以及诊断归档内的 `session-forensics.json` 里，
说明上一个会话是如何结束的，依据的是以下任何一个给出了回答的证据来源：

- 启动器对退出状态的记录（`diagnostics/launcher_exits.jsonl`）；
- 内核日志，其中会写明内核自己执行的内存耗尽终止；
- 用户空间内存终止程序（systemd-oomd、earlyoom、
  nohang）以及 systemd-coredump 中提到本应用的日志行。这些从不出现在
  内核日志中，而且 systemd-oomd 写的是应用的 cgroup，而不是它的进程；
- 原生代码中止时每个线程的崩溃跟踪
  （`diagnostics/crash_trace.log`）。

这些日志读取都在本地进行、只读，并且只保留与本应用有关的行。
`OO_NO_KERNEL_LOG=1` 会关闭这些读取；`OO_CRASH_TRACE=0` 会关闭崩溃跟踪。
内存终止程序会写入系统日志（journal），只有 `adm` 或
`systemd-journal`（Fedora 上为 `wheel`）组的成员才能读取；当你的账户无法读取时，报告
会如实说明，而不是声称日志为空。如果完全没有任何证据来源，报告
会说结束方式未知，绝不会说结束是干净的。

同一份报告还会说明在本会话的峰值时内存由什么构成。如果
那次峰值出现时内存已经紧张到无法安全读取 C 堆——这
通常发生在内存耗尽崩溃之前——它还会显示最近一次
成功读取了 C 堆的较早峰值，并附上该峰值自己的大小和时间。它还会说明
每个线程在两类时刻正在做什么（线程名称、正在运行的应用代码以及它所用的 CPU）：
一是当可用内存降到内存（RAM）的 15% 以下时
（最多 1 GB），在越过该线时记录一次，之后每创新低再记录一次；二是当
应用在五秒内创建了一百万个或更多 Python 对象时，最多每五分钟
记录一次。最新的八个快照保存在数据文件夹中的
`session_pressure.json` 里，它们和其他诊断信息一样
只留在这台计算机上。

## 5.6 已知局限与诚实披露

“从构造上保证诚实”意味着不仅要说明工具*能*告诉你什么，还要说明它*不能*告诉你什么。
以下是这些方法长期存在的局限（audit-07“披露排查”）。它们都不是缺陷；
但每一条都会影响你应当如何解读结果。

- **关键词/趋势计数是词汇层面的，而非语义层面的。** 它们衡量的是词语出现的频率，
  而不是表达的含义。否定（“不是危机”）、引用、
  讽刺和反语都按字面计数。数量代表的是报道覆盖面，绝不代表
  重要性或真实性。
- **情感/语气分析使用 VADER，这是一种基于英语词典的方法。** 对非英语
  文章的评分并不可靠；情感（Sentiment）和框架（Framing）界面会披露这一点，并
  显示按英语评分的文章所占比例。语气是一个可测量的信号，绝不是判定
  某家媒体存在偏见的结论。
- **LLM 生成的摘要/翻译是模型产物。** 本地模型可能语句流畅却内容错误。
  每个生成的单元格都标注了“请对照已存储的
  文章核实”；请把它的输出当作线索，并对照你采集到的
  原文进行核查。
- **长文章会被拆分，而不是被截断。** 模型的上下文窗口是有限的。当
  你要求对一篇放不进窗口的文章做摘要或翻译时，
  应用会在段落边界处拆分文章，并处理每一部分——翻译结果是
  各部分拼接而成，摘要则是先对各部分分别摘要，再合并做一次摘要。
  无论哪种情况，结果都会注明这一点（“分 N 部分翻译”“基于 N 部分的
  分层摘要”），因为两步生成的摘要与一次生成的摘要是不同的产物，
  你应当知道自己读的是哪一种。它绝不会悄悄
  中途停止：被截断的翻译看起来与完整的翻译一模一样。
  后台批处理（人物/地点/时间抽取）*确实*会截断长文章，并且
  会记录这一点——“分析了 M 个字符中的前 N 个”——因此抽取结果单薄
  绝不会被误认为文章本身单薄。
- **后台 AI 只有一条通道，而且你的操作优先。** 你启用的批处理
  在唯一的本地后端上逐个运行，而不是相互争抢资源。
  你自己发起的任何请求——批量翻译、手动运行一次批处理——都会在其运行期间暂停
  这条通道，结束后通道会自动恢复；任何任务都不会失去
  排队位置。在本地推理不现实的机器上，这条通道默认
  关闭，并说明原因，你仍然可以手动开启它。
- **本应用只处理文本。** 它分析文章文本。对图片只做 EXIF/元数据层面的
  如实呈现（不做取证/深度伪造判断）；不分析音频或视频。
  只存在于视频或图片中的说法，超出了本工具
  能看到的范围。
- **日语和泰语需要可选的 `[segmentation]` 扩展。** 关键词提取
  依赖空格分词，除非安装了分词器。中文在每次安装中都会
  进行分词（jieba，自 0.4 起为核心依赖）；如果没有该扩展（janome、pythainlp），日语和泰语的关键词
  分析实际上无法使用，尽管
  界面提供这两种语言；而且只有安装了该扩展中的 sudachipy，日语搜索才会按词
  切分。**受管理的**语言集合
  （以空格分词，并带有停用词表）定义在
  [`src/analytics/managed.py`](../src/analytics/managed.py) 中；各语言的*分析深度*
  各不相同，不以空格分词的文字是目前最大的缺口。
- **宽松站点的幸存者偏差。** 由于 robots.txt 采用失败即关闭（fail-closed）策略，
  语料库中*允许*抓取的网站占比偏高，而付费墙或限制抓取的新闻
  在结构上占比偏低。这一点无法以符合伦理的方式
  “修复”——我们通过优先使用官方 API/存档来缓解，并
  在此披露，以便你据此理解覆盖情况。
- **你的记录始于你开始采集的那一刻。** 趋势和“上升”信号
  受限于你的采集时间窗口；对于你开始采集之前的历史，本工具一无所知。
  维基百科转储以及（未来的）存档可以向过去延伸；否则请结合
  显示 n 的注意事项来解读早期语料的结果。
- **维基百科带有其自身的系统性偏差。** 关注/导入的维基百科
  会带入每个语言版本中有据可查的编辑倾向和覆盖偏差。
  按语言版本区分的来源（`xx.wikipedia.org`）使其可以被筛选，并且它和其他来源一样
  可以交叉验证——它绝不是神谕。
- **目录选择偏差是被测量的，而不是被隐藏的。** 来源目录是一个
  人工整理、正在逐步“去美国中心化”的集合；**全球覆盖**视图
  会显示哪些国家有代表、哪些国家没有，让你看清
  你正在（以及没有）采集的内容的轮廓。

## 6. 故障排除

- **页面无法加载。** 确认进程正在运行，并绑定在
  `127.0.0.1:8000`（或你的 `OO_HOST`/`OO_PORT`）上。如果无法访问 API，
  页眉的健康状态标签会变为 `offline`。
- **搜索结果为空。** 你还没有进行采集——用飞行模式
  按钮**联网**（会弹出一次同意弹窗），采集会自动开始；手动方式是
  **设置 → 高级 → 采集 → 获取源**。
- **一次导入什么也没存下。** 这往往是正确且合乎伦理的：该页面可能
  被 `robots.txt` 阻止（失败即关闭）、受到速率限制、属于重复内容，或者没有
  可提取的正文。结果统计会告诉你是哪一种情况。
- **洞察/市场的控件缺失或报错。** 没有安装 `[analysis]` 扩展
  ——请重新运行 `install.sh`（分析扩展默认会被安装）。
- **LLM 标签显示离线。** Ollama 没有运行或无法访问；请启动它，或设置
  `OLLAMA_BASE_URL`。不可用时，摘要/翻译会返回明确的 `503`。
- **保管功能显示“已请求，库未安装”。** 安装 `pqc` 和/或
  `timestamping` 扩展；库就位后，实际生效状态就会切换。
- **恢复功能拒绝了我的文件 / 预览无法应用（Apply）。** 这是设计使然——它必须是
  真正的 Open Omniscience 备份，而且如果预演
  验证失败，**应用（Apply）**按钮会保持禁用。无论哪种情况，你当前的语料库都不会被改动；恢复只会
  *添加*，绝不会替换。
- **维基百科转储非常大。** `enwiki` 有数十 GB。请先使用**估算大小（Estimate size）**；
  大多数语言版本要小得多，而且做变更跟踪并不需要转储。

## 7. 术语表

- **语料库（Corpus）**——你本地存放所采集文章的 SQLite 数据库。
- **来源记录（Provenance）**——每个条目所存储的来源信息（来源、URL、规范 URL、
  内容哈希、抓取时间），用于去重和建立信任。
- **FTS5**——SQLite 的全文搜索功能，支撑布尔查询。
- **合乎伦理的抓取（Ethical fetch）**——唯一的、遵守 robots 规则、受速率限制的抓取路径。
- **保管链（Chain of custody）**——只能追加、以哈希串联并经过签名的日志，用于证明某个条目的
  完整性、来源和时间。
- **证据包（Evidence bundle）**——对选定文章进行的、经过签名、带 Merkle 根、可离线验证的
  导出。
- **OpenTimestamps**——一种把哈希锚定到比特币中的方法，作为独立证据，证明某内容
  “不晚于”某个区块时就已存在。
- **ML-DSA**——FIPS-204 后量子签名方案（在*混合*模式下与
  Ed25519 一起使用）。
- **ORES**——Wikimedia 的机器学习服务，为编辑的破坏性/善意程度打分。
- **PMI**——逐点互信息；衡量两个词的共现强度超出随机水平的程度，并据此排序
  （即洞察中的“思维导图”）。
- **VADER**——一种基于词典的语气/情感评分器（即洞察中的“框架”视图）。

## 主页简报——以诚实的“卡片”呈现情报

> **状态：** `0.06` 阶段 A（图形界面主干）——已发布并经过测试。分阶段计划
> 见 [`ROADMAP.md` → “0.06 — The Intelligence Layer”](archive/roadmaps/DESIGN_MEMORY_pre-0.2.md)；
> *内容与原因*见 [`ROADMAP.md`](archive/roadmaps/DESIGN_MEMORY_pre-0.2.md)。

**主页**标签页不再只是一览式统计。它是一个**分诊信息流**：
应用在后台采集和测量，然后把*候选报道*以
**卡片——在屏幕上显示为“线索”**的形式呈现出来（本章用“卡片”指内部
机制；界面上的标签是“线索”）。采集由应用完成；**判断由你来做**。每张卡片
是**一个可测量的信号 + 证据链接 + 一条注意事项**，被归入一个编辑
分组，并以**双面翻转卡片**的形式呈现（正面 = 线索；背面 = 注意事项 +
方法 + 证据 + “打开语料库”）。

卡片**只呈现信号；它从不给出结论。** 没有“有偏见”，没有
“宣传”，没有“真/假”，而且——按照设计并*在代码中强制执行*——**没有综合
信任评分**（见下文“诚实保障”）。

---

### 你会看到什么

简报把卡片归入以下**分组**（按显示顺序）：

| 分组 | 含义 | 编辑用途 |
|---|---|---|
| **正在上升** | 有事情在变化 / 新出现 | 选题候选 |
| **过度报道** | 各来源一致得太快 / 太整齐 | 拆解齐声附和 |
| **报道不足** | 有事情发生了变化，却很少或没有人报道 | 揭示空白 |
| **值得调查** | 来源或数据之间存在分歧 | 深入挖掘 |
| **核查报道框架** | 同一事件被以相互对立的方式框定 | 核实说法 |
| **持续关注** | 值得留意的变化（例如某条记录被改写） | 持续监测 |
| **背景** | 背景信息 / 自我审查 / 长期事实 | 提供语境 |
| **数据完整性** | 关于语料库本身的卫生信号 | 修复处理流程 |

它们背后的三元组就是引擎：**趋同 → 过度报道**，**分歧 →
调查/拆解**，**缺失 → 报道不足**。

每条线索（简报卡片在屏幕上的名称）在**正面**显示其**标题**、一行
**摘要**，以及**测得的信号**（例如 `growth_ratio = 4.2`、`n=6`）。
**点击它（或按 Enter）即可翻面：** **背面**载有
**注意事项**、**方法**（这个数字究竟如何计算，以及它*不*代表
什么）、触发原因、指回你语料库的**证据链接**，以及一个**“打开语料库
↗”**按钮。注意事项默认就在 DOM 中，位于与正面同等地位的背面、紧挨着
操作按钮——绝不藏在某个“简洁界面”开关后面。这正是要点所在：**透明本身就是
界面。**

> **平等视图。** 在这个版本中，每个来源都只计一次，**没有任何来源被
> 降低权重**。信源完整性 / 反放大层（把
> 协同刷屏合并为单一行为体、按新颖度加权）属于下一阶段，并且是
> **由用户引导的**——应用负责*提议*，由你来*决定*。在此之前，
> 简报坦率地说就是原始的平等对待视图。

### 卡片 → 草稿 → 通讯的闭环

这个产出闭环从第一天起就清晰可见：

1. 在任意卡片上点击 **+ 加入草稿**。
2. 打开**通讯草稿**面板；为每张已固定的卡片添加你自己的备注。
3. **导出 Markdown**（或**复制**）。每一条论断都**附带其来源链接、
   方法和注意事项**——从设计上保证新闻报道可复现。

如果需要底层文章的*经签名、可发现篡改*的副本，可从**证据与保管**导出**证据
包**——这些凭据可以随你的这一期通讯一起发出。

### 卡片是如何生成的（简报 v0）

每张卡片都由一个**生成器（producer）**产生：一个 `corpus → [Card]` 函数。生成器组合的是
*已经返回真实数字*的分析功能——没有任何东西是编造的。如果一个生成器
缺少输入，或缺少可选的 `[analysis]` 依赖，它会**什么也不返回并记录
原因**（大声降级）；它绝不会捏造一张卡片。

| 卡片 | 分组 | 数据来源 | 状态 |
|---|---|---|---|
| **“X”正在上升** | 正在上升 | `insights.trending`（近期与前一时期之比） | 现有 |
| **框架分歧** | 核查报道框架 | 某个趋势词在各来源中的 VADER 语气 | 现有¹ |
| **条目被改写** | 持续关注 | 维基百科大幅/被标记编辑检测 | 现有 |
| **价格 ↔ 叙事（Price ↔ narrative）** | 背景 | 如实的 scipy 相关性（系数 + p + n） | 现有¹ |
| **数据过时** | 数据完整性 | 市场提取规则的 `last_run_at` / `last_status` | 现有 |
| **阅读结构自查（Diet self-audit）** | 背景 | `signals.concentration`（对你的来源计算 Gini + 前 3 名占比） | 现有 |
| **回音室** | 过度报道 | `signals.coordination` 行为体图（近似重复 + 时间同步 + 主机） | 新增 |
| **孤立信号** | 报道不足 | 未被转载的单一来源近似重复簇 | 新增 |
| **不合理的产能（Capacity implausible）** | 值得调查 | 每日文章数与语料库中位数对比 | 新增 |
| **情绪画像** | 背景 | 基于某关键词上下文窗口的情绪词典 | 新增² |
| **知识产权 / 法律动态（IP / legal pulse）** | 背景 | 新闻语料中正在上升的知识产权/法律术语 | 初步 |
| **所有权变更** | 值得调查 | 近期新闻中的交易类动词（收购/合并/剥离） | 初步 |
| **报道溯源** | 背景 | `signals.lineage`——按发布时间排序的近似重复簇 + 通讯社署名 | 新增 |
| **覆盖顾问** | 背景 | 对你的来源所属国家/语言计算 `signals.concentration`（显示偏斜，不设上限） | 新增 |
| **可进行天气核查（Weather check available）** | 值得调查 | `analytics.corroboration`——气候事件词 × 推断出的地点 × 文章日期 | 新增 |

¹ 需要 `[analysis]` 扩展（VADER / scipy）。没有它，这些卡片就不会
出现——简报的其余部分仍可正常工作。
² 使用情绪词典；随附的是一个最小的英语**样本**，如需认真使用，请将
`OO_EMOTION_LEXICON` 指向一个更完整的 JSON 词典（仅限英语）。

**回音室**、**孤立信号**和**不合理的产能**卡片来自
信源完整性层——见 [`USER_MANUAL.md`](USER_MANUAL.md)。回音室卡片带有一个
*折叠为一个行为体*操作（由用户引导的反放大——应用提议 → 由你决定）。

**阅读结构自查（Diet self-audit）**使用了共享
[`src/signals/`](../src/signals/) 基础层的第一个纯函数原语：**集中度**（Gini 系数 +
前 N 名占比）。它与计划用于媒体所有权集中度
（FUTURE_DEVELOPMENTS §1）和人物显著度（§4）的是*同一套数学*——一个引擎，多个领域。

**报道溯源**会把一则被转载的报道追溯到其**原始来源**：对于跨越众多媒体的近似重复
簇，它按发布时间对各篇报道排序，并检测明确的
**通讯社署名**（“据路透社报道”“(AFP)”），从而让原创报道
优先于衍生转载。这条界线是诚实的：*“我们看到的最早版本” ≠ “真相”*——它
呈现结构；由人来判断。**覆盖顾问**会揭示
**你自己的采集中存在的地理/语言偏斜**（例如“你采集的内容中约 80% 来自同一个国家”），作为
一个温和的扩展建议——它从不过滤或限制任何内容；偏斜的语料库会使所有
下游信号都发生偏斜，因此看到这种偏斜正是关键。

**可进行天气核查（Weather check available）**是第一张*“若出现此情况，则给出建议”*的卡片：当你的若干篇
文章在同一时间窗口内同时提到同一个气候事件词（干旱、洪水、热浪……——一份经整理的
12 种语言种子列表，`configs/corroboration_rules.yml`）以及同一个推断出的
地点时，这张卡片会**提议**为
恰好这个地点和时间窗口获取独立的天气数据。卡片本身是在本地计算的——它会注明这一点——在你点击**获取天气背景数据**之前，
不会抓取任何东西；点击后会经过与其他所有联网操作
相同的网络同意弹窗。返回的是一个有范围限制的
Open-Meteo **再分析**数据切片（CC BY 4.0，显示署名）：它是*模型估计值*，而不是
气象站记录——它可以**佐证或质疑**文章中的说法，但绝不能证明
它们。该切片会缓存在磁盘上，因此之后再次查看时无需联网；缓存状态和
抓取时间始终会显示。

### 性能——预先计算、缓存、提供缓存结果

简报**从不按请求实时计算**。后台调度器会在
每次抓取后刷新简报并写入缓存（位于你的数据目录下的 `briefing_cache.json`）；
主页读取缓存，因此能即时加载。它是**自动更新的**——每轮采集后会在
后台重新计算，主页会自行重新轮询（刷新进行时会显示进度横幅）；
没有手动刷新按钮。已忽略项
（`briefing_dismissed.json`）和草稿（`briefing_draft.json`）都是很小的本地 JSON
文件——单用户、本地优先，从不传输。

### 诚实保障（写在代码里，而不仅是文档里）

FUTURE_DEVELOPMENTS §6 禁止使用单一的自动化信任/质量评分（它会把
评分者的世界观嵌进一个看似客观的数字里，并且*必然*会误判小型、外国、
新兴或持不同意见的来源）。这一禁令是以**机械方式**强制执行的：

- `src/briefing/card.py:assert_no_score_fields()` 会拒绝任何名称
  暗示综合评分的 `Card` 字段（`score`、`trust_score`、`credibility`、`rating`、
  `verdict`……）。它在导入时运行，并有测试断言其成立。
- 卡片所携带的数值存放在 `signal` 中，是**一个附有
  说明方法的测量量**——增长比率、Gini 值、相关系数——绝不是
  跨越不可通约维度的混合评分。
- **呈现，而非压制。** 忽略操作是可撤销的；未来任何降权都将
  是透明的、可调节的、默认关闭的，并且可撤销。

## 信源完整性与反放大

> **状态：** `0.06` 阶段 C——已发布并经过测试。情报层的
> 基石（FUTURE_DEVELOPMENTS §6）。与 [`USER_MANUAL.md`](USER_MANUAL.md) 和
> [`USER_MANUAL.md`](USER_MANUAL.md) 配套。

其他工具负责呈现信号；**这个工具决定谁的信号算数**——*而不
成为真相的仲裁者*。它是对“垃圾进”问题的回答。

### 出人意料的是：平等对待每个来源**并不**中立

趋势、显著度、同步性以及“哪些内容被报道”都在**计算媒体数量和报道量**。
因此，把“平等对待每家媒体”用在一个基于数量的指标上，本身就带有偏差：
*谁产出最多，谁就赢。* 一个资源充足的行为者如果开设 40 家媒体（或
水军工厂、内容农场），就能把资本直接转化为表面上的共识，并把
诚实的单一来源报道**稀释**到无足轻重。什么都不做并不中立——
它是在补贴刷屏者。

解决之道不是给来源*打分*，而是在正确的**单位**上定义中立：
平等对待*按其贡献的新信息加权的独立行为体*，而不是平等对待
*媒体*。**把马甲账号当作独立声音来计数是一种测量
错误，而不是中立。**

### 测量什么（以及禁止什么）

我们严格停留在 §6 区分中**被允许**的那一半：

- **(A) 真实性 / 质量评分**——“这个来源是否诚实 / 是否优质？”——
  **禁止自动化。** 它会把评分者的世界观嵌进一个看似客观的
  数字里，并且*终将*把一个优质但不寻常的来源也打低分。
- **(B) 真伪性 / 结构信号**——“这个来源是否就是它所声称的那样？它是否是
  某个协同网络中的一个节点？它是*原创*还是只是*转载*？它的产出是否
  在人力可及的范围内？它是否公开了由谁运营？”——这些在相当
  程度上是**可测量的结构性事实。** 所有设计都在这一范畴内。

#### 共享引擎（`src/signals/`）

| 原语 | 测量内容 | 支撑功能 |
|---|---|---|
| `concentration` | Gini + 前 N 名占比 | 所有权/阅读结构集中度、显著度 |
| `near_dup` | MinHash + LSH 近似重复簇 | 转载 / 联合发布检测 |
| `coordination` | 基于近似重复 + 同步时间 + 共享主机的行为体图 | 行为体合并 |
| `novelty` | 对语料库而言是新出现的词组（shingle）所占比例 | 原创与转载的加权 |

这四个原语都是**纯函数**（不访问数据库、不联网），经过基于属性的测试，并附带方法 + 注意事项。

### 反放大是**由用户引导的**（应用提议 → 由你决定）

反放大**绝不是**由应用悄悄执行、而你只能事后
*撤销*的变换——那会让应用变成 §6 所禁止的仲裁者。

- **默认 =“平等但知情”。** 原始的平等对待视图是基线；
  协同刷屏会被**标注在其上**（即*回音室*卡片），而不会被合并。
- **由你来应用合并**，可以按簇进行，也可以全局进行。只有这样，一个协同
  网络才会在任何衡量共识的计数（有多少个
  独立声音在传播某则报道）中被合并为**一个声音**。
- **每一次已应用的合并都会保持标记并可撤销。** 点击一下即可将其展开为
  各个成员；撤销后会**精确地**还原原始的平等计数。*未经你的明确操作，
  绝不会应用任何合并*——这一点由测试强制保证。

这就是**来源完整性工作台**（设置 → 高级 → 安全 → “打开来源完整性
工作台”）：*扫描协同行为*会列出提议的行为体及其证据（共享文本、
同步时间、共享主机）；*应用折叠* / *展开（撤销）*由你选择。
主页上的回音室线索也带有同样的*折叠为一个行为体*操作。

### 来源档案——测得的维度，**没有综合评分**

对每个来源，都有一个由*测得的*信号组成的面板——并且**刻意不提供单一的信任
数值**（被禁止的“B”）。0–100 分的评分是在不可通约的维度上制造虚假精确，
容易被古德哈特效应钻空子，是单一的被操控点，并且*必然*会误判
小型 / 外国 / 新兴 / 持不同意见的来源。这一禁令在代码中强制执行（档案
返回 `no_composite_score: true`，并有测试断言不存在任何聚合的 `*score*` 键）。

维度（每一项都有其自身的方法 + 注意事项）：

- **协同**——行为体归属、与谁协同、共享了多少则报道。
- **新颖度**——这个来源是原创还是多为转载？（相对于*你的*语料库而言）。
- **产出能力**——每日文章数与语料库中位数对比（这是一个*问题*，而不是结论；
  通讯社和大型新闻编辑部本来就产出丰富，这是正当的）。
- **透明度**——国家、语言、所有权/立场标签（基于声誉、
  可争议、可编辑），以及由操作者设置的 `reliability_score`（不在此处计算）。
- **过往记录**——这个来源为你的语料库贡献了什么。

由你来决定哪些维度对*你的*视图重要并加权——默认关闭、可撤销，
原始的平等视图始终只需点击一下即可返回。

### 这一层带来的新简报卡片

- **回音室**（过度报道）——同一则报道在 N 个协同来源中传播。
- **孤立信号**（报道不足）——一则有实质内容、但未被转载的单一来源报道。
- **不合理的产能**（值得调查）——一个发布量远高于语料库常态的来源。

### API

| 方法与路径 | 用途 |
|---|---|
| `GET /api/integrity/profile?source=` | 无综合评分的测得信号面板 |
| `GET /api/integrity/actors` | 提议的协同行为体，每个都标明是否已应用 |
| `GET /api/integrity/prominence` | 以独立声音计算的报道显著度，原始与合并后对比 |
| `POST /api/integrity/collapse/apply` · `/revert` | 应用 / 撤销一次合并（按行为体） |
| `POST /api/integrity/collapse/apply_all` · `/revert_all` | 全局合并 / 重置 |

### 诚实的局限（明确列出）

- **军备竞赛 / 古德哈特效应**——每一个公开的信号都会成为优化目标；这是
  纵深防御，绝不声称完备。
- **错误合并会伤及无辜**——检测追求高精度，倾向于
  *少*合并，始终展示证据，始终可撤销。
- **被操控**——我们提供的是*机制，而非结论*；默认是透明的
  平等视图；一切都可以由你推翻。
- **目标**不是“检测出所有垃圾”（这不可能，而声称能做到才是
  不诚实的做法），而是**剥夺垃圾内容的机械优势**，让“开设 40 家机构”的
  玩法*不再奏效*。

## 共享来源注释——经签名、可移植、按信任联合

> **状态：** `0.06` 阶段 D——已发布并经过测试。这是来源
> 档案在规模化上的答案（FUTURE_DEVELOPMENTS §6）。与 [`USER_MANUAL.md`](USER_MANUAL.md) 配套。

来源档案让*你*来决定哪些维度重要并加权。但**没有人能够独自中立地
评估成千上万个来源**——所以加权必须是**集体的**。以
诚实、本地优先、非中心化的方式做到这一点，就是使用**经签名、可共享的注释
包**。

- 你把自己的来源注释——协同标签、所有权/透明度
  事实、立场标签、更正、备注——发布为一个**经保管签名、可验证、可移植的
  包**（复用与保管链相同的混合 Ed25519 + ML-DSA 签名器——
  这是*共用*，而不是第二套加密体系）。
- 其他用户**导入**他们选择信任的包——这是一个需主动选择加入的**信任网络**，
  **绝不是**中心化的权威机构。
- 聚合是**透明的**：你始终能看到*谁断言了什么*，而且**分歧会被
  展示出来，而不会被平均**成一个隐藏的数字。

没有服务器，没有账户，没有全局评分——**通过签名交换实现联合。**

### 注释是什么（以及不是什么）

注释是关于某个来源的**描述性、可争议的事实或标签**。类型包括：
`ownership`、`leaning`、`coordination-tag`、`transparency-fact`、`correction`、`note`。
它**绝不是**综合的信任/质量评分——这在设计上和
代码中都是被禁止的（像 `trust-score` 这样的无效类型会被拒绝）。

### 信任模型——签名能证明什么、不能证明什么

每个包都嵌入了作者的**公开身份**以及对规范化
清单的签名。验证会**锁定**嵌入的密钥，因此篡改后重新签名的攻击无法
*冒充*原作者——它只会产生一个**不同的**作者。因此，一个
经过验证的包总是被如实地归属于签署它的那个密钥。
然后由你来决定*信任哪些密钥*；只有受信任作者的注释才会被聚合。

这是**信任网络，而不是正确性证明**：信任一位作者意味着“我想
看到他们的断言”，而不是“他们的断言是真的”。受信任作者之间的分歧
会呈现出来供你判断，绝不会替你裁决。

### 使用方法（来源完整性工作台——设置 → 高级 → 安全）

1. 在*共享注释*下**撰写**注释（对象 + 类型 + 值）。
2. **导出签名证据包** → 得到一个可以发布或分享的 JSON 文件。
3. **导入捆绑包…** → 应用在存储之前会**验证签名**（无效的
   包会被拒绝，并给出明确提示），然后在*可信作者*下列出该作者，并附带一个
   信任开关。
4. **谁说了什么？** → 汇总你和受信任作者关于某个来源的所有断言，
   并显示归属和分歧。

取消信任某位作者会排除其注释；移除某位作者则会彻底删除其注释。

### API

| 方法与路径 | 用途 |
|---|---|
| `GET /api/annotations/mine` · `POST` · `DELETE /mine/{i}` | 你撰写的注释 |
| `POST /api/annotations/export` | 你的注释的签名、可移植包 |
| `POST /api/annotations/import` | 验证并存储导入的包（无效则拒绝） |
| `GET /api/annotations/authors` · `PUT /authors/trust` · `DELETE /authors/{id}` | 信任网络 |
| `GET /api/annotations/for?target=` | 透明聚合——谁断言了什么 |

### 诚实约束

- **不取平均，不给共识数值，不打分。** 聚合返回的是带归属的
  断言，并明确指出*分歧*；它绝不会把分歧压缩成一个数字。
- **本地优先。** 一切都是你数据目录下的文件；不传输任何内容，
  也没有服务器或账户。
- **从构造上即可争议。** 每条注释都是一个你和其他人都可以
  公开表示不同意的标签/事实。

## 洞察——关键词与实体分析

### 目的

把统一的语料库从一个搜索框变成一件分析工具。关键词
和实体从**已导入的文章文本**中提取，与其
出现位置和上下文一起存储，并呈现出来，让调查记者可以追问：
*人们在谈论什么、在哪里、在什么时候、由谁谈论，又与什么一同出现？*

这里的一切都是基于已存储数据的**真实聚合**，并附有说明的方法和
样本量——绝不是捏造的评分（PRODUCT_SYNTHESIS §3.5）。

### 工作原理

```
ingest an article ──► extract (baseline / opt-in spaCy) ──► KeywordMention rows
                          terms + entities, offsets        (count + first offset +
                                                            denormalised date/country/city)
                                                                   │
                          Insights tab / /api/insights  ◄──────────┘
                          trends · associations (PMI) · context · map
```

- **提取**（`src/analytics/extract.py`）：主题性的 n-gram **词项**
  （经停用词过滤）以及**实体**——人物、公司/组织、地点——作为
  单个单元。基线方法（无依赖）把多词
  首字母大写序列识别为实体，并且只依据
  地名词典来指定 `person`/`org`/`location` 类型（否则如实地使用通用的 `entity`）；可选的 **spaCy** `[nlp]`
  扩展会加入真正的 `PERSON`/`ORG`/`GPE` 命名实体识别。每个关键词都会记录**是哪个提取器
  给它打的标签**——实体类型是一个*由 X 标注的断言*，而不是事实真相。
  最适合以空格分词的文字；CJK/阿拉伯文分词是已知的后续步骤。
- **存储**（`src/analytics/store.py`）：每个（文章，
  关键词）对应一条 `KeywordMention`——出现次数 + 首个字符偏移量（上下文句子在读取时
  从已存储的文章中截取，因此数据库保持精简）+ 从来源反规范化得到的
  `observed_on` / `country` / `city`。索引在导入时
  尽力而为地运行（快速的基线方法，失败即放行）。索引是**自动的**——任何积压
  都会在你打开洞察时由一次静默的后台补充处理清空（“剩余”计数会自行
  归零）；没有“索引语料库”（Index corpus）按钮。对现有语料库的完整重新索引
  可在**设置 → 高级 → 诊断**中进行（“重新索引整个语料库” / “清理
  关键词”），作为一个可暂停的后台任务。

### 功能（洞察标签页 + `/api/insights`）

| 视图 | 端点 | 显示内容 |
|------|----------|---------------|
| 浏览——趋势 | `GET /trend?term=&bucket=` | 随时间变化的提及量（按日/周/月），附带解析后的关键词 + 类型 |
| 浏览——思维导图 | `GET /associations?term=` | 按 **PMI**（逐点互信息）排序的共现关键词，附带样本量 + “关联 ≠ 因果”注意事项；点击某个节点可将其设为中心 |
| 浏览——背景 | `GET /context?term=` | 从文章文本中截取的近期提及片段，附带文章/来源链接 + 国家/城市/日期 |
| 趋势 | `GET /trending`, `GET /top` | 上升词项（近期与前期之**比**，一个有标注的指标）和热门词项，可按时间窗口 / 类型 / 国家筛选 |
| 地图 | `GET /map?days=&kind=` | **按国家和按城市**的热门关键词（基于来源的地区信号） |
| 索引（Indexing） | `GET /status`, `POST /reindex?limit=` | 已索引/剩余数量；分块回填语料库 |

`kind` 筛选项：`term`、`entity`、`person`、`org`、`location`。

### 诚实保证

- 趋势/热门是真实计数；“上升”是一个有明确定义的近期与前期之**比**，
  明确*不是*显著性检验。
- 关联使用基于文章共现的 **PMI**，返回时附带 `n` 以及
  “小样本噪声大”的注意事项。
- 实体类型带有提取器来源信息；基线方法绝不会声称一个
  它无法证明的精确人物/组织/地点类型。
- 地图上的地区是**来源的**国家/城市（可靠的信号）。
  地图视图现在包含一个**交互式等距圆柱投影 SVG**（可缩放/平移，放大时显示城市
  标签），依据**地名词典**中的真实经纬度标绘城市：随附一个小
  样本（`configs/cities.sample.yml`）；完整集合由
  Wikidata 生成（`scripts/build_city_gazetteer.py` → `configs/cities.yml`）。在
  地名词典中没有匹配的城市会保留其关键词数据，但**不会被标绘位置**（绝不
  捏造地点）。国家/城市表格仍与地图并列显示。

## 维基百科变更跟踪

### 目的

维基百科是一块充满争议的阵地：条目被持续编辑，而在 LLM
时代，删除或改写历史比以往任何时候都更容易。这个工具把每个
维基百科**语言版本**都当作一个被跟踪的来源，其*编辑*就是数据，因此
记者可以**发现并记录**大规模或篡改历史式的修改——
例如，证明某句话在某个日期存在过，并被某个
账户删除。

> 语言版本是按**语言**划分的（`en`、`fr`、`ar`、`ru`、`zh`……），而不是
> 按国家划分的（不存在国家维基百科）；界面会把语言映射到国家。

### 为什么这不是“常规文章”导入

条目会随时间变化，因此不能作为一次性的 `Article` 行来存储。
由此产生两个设计选择：

1. **使用 MediaWiki Action API，而不是抓取网页**——`revisions`、
   `recentchanges`（附带字节增量）和 `compare`（由服务器计算的差异）。这
   是高效、符合服务条款、面向变更的途径。
2. **存储增量，而不是重复拷贝**——每个页面只保留**一份**压缩的全文基线
   （`wiki_pages.baseline_text`）；此后的每次编辑都是一条 `wiki_revisions`
   记录，保存**差异 + 带符号的字节增量 + 标记**，绝不保存整篇新
   条目。任何历史版本都可以通过重放差异来重建。

**这回答了冗余/磁盘空间的问题：** 一次外观性的编辑只是一个很小的差异，
带有 MediaWiki 的 `minor` 标记，并会被大小/小编辑阈值过滤，因此它
几乎不占空间。存储量随**被关注页面上的编辑活动**而增长，而不是随
数 GB 的条目语料增长——做跟踪永远不需要完整转储。

### 检测大规模 / 可疑编辑（诚实地）

`src/wiki/flagging.py` 会标记一次编辑并记录**原因代码**——它呈现的是
*候选项*，并不宣判“虚假信息”：

- `large_removal` / `large_addition`——字节增量超过阈值
- `revert` / `blank`——MediaWiki 变更标签（`mw-reverted`、`mw-undo`、`mw-blank`……）
- `anon_large`——来自匿名 IP 的中等及以上规模编辑
- `burst`——短时间内对同一页面的大量编辑
- `ores_damaging`——可选的 **Wikimedia ORES**“破坏性”概率，以
  *由 ORES 标注*的断言形式呈现（就像我们的实体来源信息一样）

小的外观性编辑从不会被标记。每一次被标记的编辑都会连同其
差异 + 来源信息（revid、编辑者、时间戳）一起记录，并接入现有的
**保管链**，以形成经签名/加时间戳的证据。

### 两个明确分开的子系统（用户体验）

1. **关注与跟踪**（轻量、即时、默认）：按语言版本建立的页面 /
   分类关注列表；通过应用内调度器轮询修订；存储
   修订 + 差异 + 标记；提供差异查看器 + 每页时间线。无需批量下载。
2. **离线基线**（重量级、可选）：位于**设置 → 维基百科离线基线**
   （特意与轻量级跟踪器分开放置）。一个
   **可选择的语言版本列表**（经整理、按规模从大到小排列，显示每种
   语言的本名和粗略的规模档位）取代了手动输入代码；
   当前转储的确切大小会按需从服务器读取（`Estimate size`），
   然后可以下载 / 暂停 / 继续 / 删除。该列表来自
   `GET /api/wiki/languages`；下载器仍接受任何语言版本代码。
   （实际大小：当前文本版 enwiki 压缩后约 22 GB；完整历史达
   TB 级——只有离线查看历史差异时才需要。）

  EventStreams 实时流；通过保管链导出被标记差异的证据。

### 伦理

所有抓取都遵守 MediaWiki API 使用政策（可识别身份的 User-Agent、
`maxlag`、速率限制）——比抓取网页更体贴。我们只存储公开的
修订数据；在跟踪运行之前不会抓取任何内容。

## 世界法律——法规、公报与知识产权的变更跟踪

> **状态：** `0.06` 阶段 E——已发布。§5 垂直功能：一个“法律界的维基百科”。
> 复用变更跟踪引擎（`src/wiki`）以及共享的 `src/signals/` 引擎。

从世界各地的官方来源汇集**法律**——法规、立法、官方公报、知识产权记录——
并**跟踪它如何随时间变化**。在许多国家，法律是公开的，并通过修订而变化，
因此数据*本身就是差异*：改了什么，什么时候改的。

### 默认开启——一份由真实官方来源组成的全球目录

`configs/legal_sources.yml` 随附一套经整理、覆盖全球的**真实官方一手
来源**——各国立法数据库（`legislation.gov.uk`、EUR-Lex、Légifrance、
`gesetze-im-internet.de`、`congress.gov`/`govinfo.gov`、`legislation.gov.au`、
`indiacode.nic.in`、`elaws.e-gov.go.jp`、`law.go.kr`……）、官方公报、知识产权机构
（WIPO Lex、USPTO、EPO、EUIPO、JPO……）以及开放的判例法/文件提交系统（CourtListener、
SEC EDGAR）。首次运行时，它们会被作为普通的**可导入、可搜索**来源预置
（`source_type` legal/ip），因此会流经与新闻*相同的*合乎伦理的处理流程。

其中一部分经过挑选、稳定且广为人知的**合并法律文本**（例如英国《人权法》、
欧盟 GDPR、美国宪法）开箱即被登记用于**变更跟踪**。

### 跟踪如何运作（复用维基百科引擎）

对于每份被跟踪的文件，第一次成功抓取的结果就是不可变的**基线**
（“截至日期 X 时的法律”）。此后每次抓取，只要其*规范化后的可见文本*
有所不同，就会记录一个修订，其中包含字节增量、相对于
基线的有上限的统一格式**差异**，以及一个如实的**大幅变更标记**（复用维基的标记阈值）。
可从**政府标签页 → 法律子标签页**（“立即跟踪更改”）运行，或交由
后台调度器（`law` 模式）运行。所有抓取都通过**合乎伦理、
robots 失败即关闭**的路径进行。

### 从发布方自己的 XML 读取法律（结构化来源）

网页必须经过*重建*才能变成文本：去掉导航栏、搜索表单、
Cookie 横幅，然后指望剩下的就是法案本身。这种做法行得通，跟踪器对大多数来源
也正是这样处理的——但有一次，一部英国法案的存储副本开头竟是
门户网站自己的搜索表单，而由它派生出的一切（一个“Personal Acts”人物、一个
“PART”组织）都来自从未出现在该法案中的文字。

如果发布方提供**自己的 XML**，上述问题都不存在：文件里没有页面外框，
因为这个文件本来就不是网页。Open Omniscience 可以直接读取
`legislation.gov.uk` 的 CLML，这还额外带来两样网页无法提供的东西：

- **带可引用地址的条款。** 读取每一节时都会连同其上层的编/章路径一起读取，
  因此一处变更可以报告为*“第 2 编第 12 节已变更”*，而不是
  一个字节数。各节按这个地址匹配，绝不按位置匹配——
  否则插入一节就会把法案其余的全部内容都报告为已修订。
- **含义准确的日期。** 颁布日期、合并时间点，以及*我们*
  抓取它的日期，是三个相互独立的字段，彼此之间没有任何回退替代。文件中
  没有写明的日期显示为未知，绝不会用另一个日期来填补。（这就是为什么
  被跟踪的法律不会显示发布日期，除非文件本身提供了发布日期：此前唯一
  可用的日期是我们轮询该页面的那一天，而轮询日期不是发布
  日期。）

逐节比较是**附加性的、实验性的**：普通的文本差异仍然
决定是否记录一个修订，并且仍然承载大幅变更标记。另有一项
局限是直接说明而不是含糊带过的——在同一次修订中*被重新编号并改写*
的一节，会被报告为一次删除加一次新增，因为若要把它与
原来的自己匹配起来，就意味着要猜测两个编号不同的节中哪一个是“同一节，
只是改过了”。

**尚未具备的功能：** 目前还没有任何机制会自动抓取这些 XML 文件。要读取
一个法域的全部法律语料，就得遍历发布方自己提供的清单（英国
列出了每一部法案；法国列出了 76 部法典），而这种枚举尚未构建。在那之前，
被跟踪的集合仍是经过整理的那一组，覆盖范围报告会如实显示
“覆盖范围未知”，而不是把被跟踪文件的数量当作
整个语料库来呈现。

### 检查法律修复是否已作用到你的数据

有两项法律修复会**在文件下一次成功抓取时悄悄生效**：页面外框会
从存储的基线中重新读取剔除，而实际上是轮询日期的发布日期会被
清除。两者都是正确的——但门户网站无法访问的文件永远不会被修复，而这
恰恰是值得了解的情况。

**law-ingest** 报告（在全部诊断信息包中，或单独生成）基于
存储的数据回答这个问题，不发起任何网络调用：每份被跟踪文件的最近一次检查记录了什么（按结果
计数，例如未变更、重新读取、出错或推迟，以及每份文件各自的
结果和最近一次尝试的时间），以及是否仍有法律文章带着
不该有的发布日期。最近一次检查失败的文件值得
关注，但报告无法判断它在开始失败之前是否曾被重新读取过一次：
这一点没有记录。重新读取的计数本身只统计最近一次
轮询即为重新读取的文件，因此在所有文件都已修复的安装中，该计数会回落
到接近零。

它还会报告**外框残留**——存储正文中仍然存在的导航文字。请把
它理解为一项*测量*，而不是一个结论：外框剔除功能刻意只移除
标记中声明为外框的部分，其余一概保留，因为基于文本匹配的规则
也会删掉法案自身的节标题。正确重新读取之后仍有残留是预料之中的；
这个数字告诉你语料库中有多少未声明的外框，而标记列表只是
一个下限，所以零的意思是“这些都没有”，绝不是“没有外框”。

### 来自法律语料的简报卡片

- **法律已变更（Law changed）**（关注）——被跟踪法律文件的一次被标记的变更。
- **示范立法**（调查）——两个或更多法域之间几乎相同的法律文本
  （§1/§2 近似重复检测引擎），一种可测量的扩散模式。

此外，由于法律文本属于统一语料库，**法律 ↔ 新闻**关联分析和
关键词分析对它同样适用，就像对任何其他来源一样。

### API

| 方法与路径 | 用途 |
|---|---|

### 诚实约束（法律事关重大）

- **不是法律意见，也不是权威来源。** 汇集的副本是一个
  *研究镜像*；每条记录都链接回官方公报，界面上也这样说明。
  只跟踪和呈现；绝不解释合法性，也不评判一部法律。
- **“公开” ≠ “可自由再分发”。** 即使文本是公开的，许可也各不相同——
  每一种都会得到尊重和署名，并存储出处，robots 失败即关闭（与新闻相同）。
- **如实界定范围。** “每个国家”是北极星目标，而不是 v1：目录覆盖面广，但
  经过整理；变更跟踪基于规范化文本的差异（合并文本门户网站提供
  最干净的信号）。如果发布方提供结构化 XML，就可以获得逐节差异
  （见上文）——目前是 CLML；Akoma Ntoso / ELI 尚不能读取。工具会说明
  每份文件具备哪一种，并且拒绝猜测：无法从结构上解析的文件
  会保留文本差异，而不会被报告成好像它有分节一样。
- **翻译**（通过本地 LLM）是一项独立的、标注清楚的辅助功能——绝不是
  权威的法律译文。

### 获取真实的价格数字

只有当你告诉应用**这个数字究竟在哪里**时，才会生成价格序列——
按照设计，不存在神奇的页面读取。有两条如实的途径：

#### 1. 按页面设置的提取规则（大宗商品标签页 → “配置数据源”）

*（数据源和提取规则位于大宗商品标签页上一个折叠起来的“配置数据源（数据源与提取规则）”区域中；
经过整理的数据源本身会在后台自动刷新。）*

添加一条规则（来源、代码、页面 URL、**CSS 选择器**、可选的属性 /
值正则表达式、货币、单位），然后按**测试**。“测试”会抓取该页面一次，并
显示找到的*确切*数值——或者没有匹配上的*确切*原因——这样你就可以
根据真实的反馈调整选择器。匹配成功的规则每天存储一条 `CommodityPrice`，
供内嵌图表和价格↔新闻关联分析读取。

可供复制的模板：`configs/market_rules.example.yml`。

**注意事项（请务必阅读）：** 大多数交易所/行情页面用 JavaScript 渲染价格，
因此这个数字*不在*抓取器收到的静态 HTML 中，选择器
什么也找不到。这就是为什么**不**预先提供可用的选择器——靠猜测
就意味着捏造数字。服务器端渲染的页面（许多官方/统计
网站、部分数据表格）效果很好；大量依赖客户端渲染的行情小组件则不行。

#### 2. 官方 CSV 数据源（推荐——可靠，并随附目录）

若要获得可信的数值历史，请从官方来源导入机器可读的 CSV 序列。
这是可靠的途径，应用随附一份入门目录
（`configs/commodity_feeds.yml`），你可以在
**大宗商品 → 配置数据源 → 官方价格数据源**中一键导入，也可以通过 API 导入：

```
GET  /api/markets/feeds                # list curated feeds + how many points each has
POST /api/markets/feeds/{key}/import   # import one (e.g. copper, wti_crude, brent_crude)
POST /api/markets/feeds/import-url      # import ANY CSV URL you supply (user-customizable)
```

**主要提供方——FRED**（圣路易斯联邦储备银行）：一个稳定的、
无需 API 密钥的 CSV 端点，`https://fred.stlouisfed.org/graph/fredgraph.csv?id=<ID>`，
它**转发世界银行“Pink Sheet”大宗商品序列**（即
“Global price of …”系列 ID——铜 `PCOPPUSDM`、布伦特原油 `POILBREUSDM` 等）以及
**EIA** 能源序列（`DCOILWTICO`、`DHHNGSP`……）。第一列是日期，
第二列是数值；缺失值（`.`）会被跳过，绝不会存成零。导入
按 `(symbol, market, date)` 具有幂等性。

可以作为自定义数据源添加的**同类来源**（URL + 可选的列名）：
- **世界银行**大宗商品市场（“Pink Sheet”）：`.xlsx` 文件位于
  <https://www.worldbank.org/en/research/commodity-markets>；同样的序列以
  干净的 CSV 形式可通过上面的 FRED 数据源获得。
- **美国 EIA** 能源开放数据：<https://www.eia.gov/opendata/>
- **IMF** 初级商品价格：<https://www.imf.org/en/Research/commodity-prices>
- **USGS** 矿产商品数据（稀土）：<https://www.usgs.gov/centers/national-minerals-information-center>

默认的列映射是第 1 列 = 日期，第 2 列 = 数值（FRED 的
惯例）；其他布局请明确指定 `date_column` / `value_column`。

对于你手头已有的 CSV，还有一条直接上传文件的途径：

```
POST /api/commodities/{symbol}/prices/import-csv      (multipart file upload)
```

> 如果提供方重命名或停用了某个序列，导入会**明确地**失败（HTTP
> 错误 / 没有可用的行），而不会编造数据——请在
> `configs/commodity_feeds.yml` 中修正 URL，或使用自定义数据源。

### 为什么第一天没有自动提取的价格？

因为一个来源无法核实的数字比没有数字更糟。这个工具中的
一切都是这样构建的：显示给用户的数字都来自真实的
测量——一个确实匹配上的选择器，或者一个确实被
导入的 CSV。目录能让你立刻获得这些*来源*；而何时某个价格可信到值得记录，
由你逐页决定。

## 保管链

Open Omniscience 刻意提出一个*范围狭窄且诚实*的证据性主张：

> **这个语料库包含了_这一_条目，内容是_这些_，记录于_这个_
> 时间，并且该记录此后未被改动——这里有可供你自己离线核验、
> 无需信任本工具的密码学证明。**

这对调查记者确实有用：它可以抵御
“这是你捏造的”“你倒签了日期”或“你事后悄悄改过”这类指控，
还能让你证明自己是在某个来源页面被修改或删除*之前*报道了某件事。它**不是**
举报人投递系统（如 SecureDrop），而且本工具中的“来源”指的是*新闻媒体*，而不是保密的
人类线人。在思考保护问题时，请记住这一范围。

本文介绍真实的机制（`src/custody/`、`src/reporting/`），并
明确说明每一项能证明什么、**不能**证明什么。

---

### 三项属性，以及我们如何如实地获得每一项

| 属性 | 机制 | 能证明什么 | **不能**证明什么 |
|---|---|---|---|
| **完整性** | 对规范序列化结果进行 Ed25519（+ 可选 ML‑DSA）签名；对全部出处字段计算 Merkle 根 | 字节自签名以来未被改变；覆盖的是全部内容，而不只是正文 | — |
| **出处** | **固定（pin）**签名者已知的公钥 | 记录是由*那个*签名者签署的 | 如果你不固定公钥，就什么也证明不了——单凭有效签名只能说明“由包内嵌入的密钥签署” |
| **时间** | `local`（自我声明）**或** OpenTimestamps（锚定到比特币） | Local：工具自己声明的一个时间。OTS：内容*不晚于*某个比特币区块就已存在 | 本地时间对第三方毫无证明力；OTS 证明的是时间的*上限*，而不是确切时刻 |

我们拒绝伪造其中任何一项。如果无法获得真正的第三方时间戳
（离线，或未安装相应的库），代码会抛出错误，而不是编造一个
时间——这正是项目章程所禁止的失败方式（PRODUCT_SYNTHESIS §3.7）。

---

### 组件

#### 1. 签名的证据包 — `src/reporting/evidence.py`
所选文章在某一时间点的导出，每篇都带有其出处和内容
哈希，由一个**域分离的 Merkle 根**和一个 **Ed25519 签名**绑定在一起。
可用 `scripts/verify_evidence.py <bundle.json> [signer_pubkey]` 离线验证。
接口为 `POST /api/reports/evidence` 和 `/api/reports/evidence/verify`。

签名密钥位于你的数据文件夹下的 `keys/evidence_ed25519.pem`。在加密的
存储中，它由你的口令封装（之前生成的密钥会在存储解锁状态下第一次被导出加载时
原样封装），因此仅凭一份数据文件夹的副本无法以你的身份
签名；没有设置口令时，它以 `0600` 权限明文保存。如果恢复的备份带来了一个
用另一套安装的口令封装的密钥，证据导出以及每一次备份（备份会用这个密钥
签署其清单）都会提示无法打开它，并且不会替换任何东西：请使用当初封装它的口令，
或者把该文件移到别处，让系统生成新密钥（用旧密钥签名的证据包仍然可以用
旧密钥的公钥验证）。丢失口令就会丢失密钥；无法恢复。

#### 2. 混合签名 — `src/custody/signing.py`
将 **Ed25519**（快速、经典）与 **ML‑DSA**（FIPS 204，后量子，
CRYSTALS‑Dilithium 的标准化后继者）结合起来。有两条规则保证这一点是诚实的：

- **诚实的标签。** 只有在确实使用了 ML‑DSA 密钥时，签名才会被标注为 `hybrid`。
  如果没有安装 `pqc` 扩展，签名会生成 `ed25519`
  签名，并如实说明——它绝不会声称自己具备并未实现的抗量子能力。
- **混合意味着“与”。** `hybrid` 签名只有在**两个**组成部分都
  验证通过时才算验证通过。缺少后量子库的验证方无法检查 ML‑DSA
  那一半，因此会**明确地失败**——绝不会仅凭经典的那一半就悄悄
  通过。（一种接受*任一*签名的方案，一旦经典签名被攻破就毫无价值。）

当应用持有口令时（`OO_KEY_PASSPHRASE`，否则使用数据库
口令），私钥在静态存储时使用 AES‑256‑GCM 加密，密钥由 scrypt 派生；
否则私钥以 `0600` 权限明文写入，保护
级别会如实报告为 `plaintext-0600`。

#### 3. 保管日志 — `src/custody/log.py`
一个**只追加**的 SQLite 账本。每个操作（`ingest`、`access`、`export`、
`redact`……）都会成为一个条目，与其前一条目**以哈希相链**，
并经过**签名**和**加盖时间戳**。`verify()` 会重新检查顺序、链接、
每个条目的哈希、签名以及时间戳摘要。导出可以离线验证：

```bash
python scripts/verify_custody.py custody_bundle.json [--pin]
```

REST：`POST /api/custody/log`、`GET /api/custody/{item}`、`.../verify`、
`GET /api/custody/export`、`POST /api/custody/verify`。

采集时自动记录日志需要主动开启：设置 `OO_CUSTODY_ON_INGEST=1`
（`Config.custody_on_ingest`）。它**默认关闭**——这是一项明确的证据性
选择，每篇文章有少量签名开销，而不是悄悄常开的行为。
它采用失败放行（fail-open）方式：保管出错绝不会中断采集。

#### 4. 锚定 — `src/custody/anchor.py`
把 Merkle 根发布给外部见证方，使其存在时间不再依赖
你自己的时钟或密钥：

- **`local`**（默认，离线）：把根记录在本地锚定簿中。只能证明
  *本工具*存储了它——属于内部审计，而不是第三方证明。
- **`opentimestamps`**（联网）：把一个不透明的哈希锚定到比特币中。无需钱包，
  无需费用，可独立验证。离线时会退回到一个明确的*不可用*错误——
  绝不会给出伪造的回执。
- **`ethereum` / `ipfs` / `arweave`**：已声明但**未实现**。它们
  会以清楚的错误拒绝，而不是以存根形式发布、其 `verify()` 永远
  返回 false。

REST：`POST /api/custody/anchor`、`GET /api/custody/providers`。

#### 5. 设置 — `src/custody/settings.py`（可在图形界面中配置）
保管行为由操作者在运行时控制，而不仅仅通过环境变量/YAML 配置。
偏好设置保存在数据目录下的 `custody_settings.json` 中，可以
在网页界面的**保管链**面板中编辑（或通过 REST API）：

- **`pqc_enabled`** — 请求使用 Ed25519 + ML‑DSA 混合签名。
- **`anchoring_mode`** — `local`（默认）或 `opentimestamps`。
- **`auto_log_on_ingest`** — 每次成功采集时追加一条签名条目
  （在保存偏好设置之前，默认沿用旧的 `OO_CUSTODY_ON_INGEST` 标志）。
- **`default_actor`** — 自动记录条目时可选的操作者标签。

**诚实不变量。** 开关是一个*请求*，而不是保证。API 和图形界面
始终显示**实际生效**的状态（偏好设置**与**库是否可用）：
如果启用了 PQC 但没有安装 `pqcrypto`，签名器仍然只使用 Ed25519，
界面也会如实说明——它绝不会亮起一个无法兑现的绿色“hybrid”指示灯。没有安装
`timestamping` 扩展时的 OpenTimestamps 也是如此。

REST：`GET /api/custody/settings`、`PUT /api/custody/settings`。

一个典型的“最大证明”工作流程：

```
export evidence bundle  ->  take its merkle_root  ->  POST /api/custody/anchor
  (POST /api/reports/evidence)                         {merkle_root, "opentimestamps"}
```

### ⚠️ 隐私：锚定可能使你失去匿名性

锚定到**公共**区块链等于**永久公开**一个哈希和一个
时间戳。哈希本身不会透露任何内容，但提交这一*行为*
会向日历服务器/RPC 运营方暴露你的 IP 和时间，而一个有资金的
链上钱包会留下资金流向记录。对于任何需要匿名的人：

- 优先使用**本地 + OpenTimestamps**，而不是公链钱包。
- 通过 **Tor** 发送 OpenTimestamps 提交（例如 `HTTPS_PROXY`）。
- 或者完全不做外部锚定，只依靠本地时间戳 + 签名。

保密性与公链锚定之间存在矛盾。默认
配置（离线的本地提供方、自我声明的本地时间）不会泄露任何信息。

---

### 我们刻意**没有**构建的东西

- **没有伪造的 RFC‑3161 TSA。** 返回 `datetime.now()` 并称之为“可信
  时间戳”是表演。请使用 OpenTimestamps（真实的）或本地时间（如实标注的）。
- **没有“或”语义的混合签名。** 见上文“混合意味着‘与’”。
- **没有常驻后台的完整性守护进程，也没有被宣传成“已加密”的未加密密钥库。**
  密钥会说明自己受到怎样的保护；验证按需进行。

### 一段话讲清威胁模型

本工具以**单一本地用户、仅限回环地址、在 Qubes 上**运行（见
`docs/SECURITY.md`）。保管系统保护的是*你自己证据链的完整性与出处*，
使其免遭事后篡改，并能应对“这是你编造的”这类
质疑。它本身不会、也无法保护人类线人的身份，
而且草率地锚定到公链反而可能主动*损害*匿名性——因此锚定需要
主动开启、默认离线，并附带上述警告。

说明它如实的局限。

## 调查配方（主页）与 `/investigate` 仪表板

主页简报现在会在你自己的语料库中留意**时空信号**并生成卡片——
全部在本地计算，绝不来自网络：

- **承诺到期**——某篇文章提到了一个在其发表时*尚属未来*的日期；
  这个日期现在已经到了。是时候问问实际发生了什么。
- **编辑战激增**——你跟踪的某个维基百科页面的编辑频率达到其自身近期
  每周频率的 ≥3 倍；它的公开记录正在变动。
- **地区报道沉寂**——一个一直稳定为你提供文章的国家（几乎）
  停止了。注意事项是内置的：它测量的是*你的语料库*，而不是该地区——失效的
  数据源与真正的沉寂看起来一模一样，所以请先检查来源。
- **候选来源等待审阅（Source candidates await review）**——见下文*发现的候选信源*。

带有**“打开调查 ↗”**按钮的卡片会**在新的
浏览器标签页中**打开一个专门的仪表板（主应用继续工作；可以同时打开多个）。仪表板
会自动汇集相关面板——带有出处片段的原始文章、
预先填好的后续搜索、存储的修订列表、覆盖范围背景——并在顶部原样附上
卡片的注意事项，最后是一条**“深入挖掘”**栏，其中每条
建议都是一个普通操作，并显示其参数。页面的全部状态都保存在
它的 URL 中：可以加入书签、重新打开，或在你自己的几台机器之间共享。

可以在**设置 → 卡片**下关闭单个配方；它们现在与本应用能生成的所有其他
线索放在一起，按类别分组——同一个开关，适用于所有线索。

## 方法附录

**方法附录**按钮（位于搜索页面和分析窗口的操作
栏中）会下载一份 Markdown 文档，记录你当前的选择结果是*如何*得出的：
应用版本、原样的布尔查询、结果数量、语料库背景，以及每篇文章一行
出处信息（标题 · 来源 · 发布时间 · URL · 内容 SHA-256）。它
只记录选择，不作任何结论——分析性的主张仍归你所有，
可以对照这些行加以核查。它为事实核查结论和同行评审而设计；当你需要文档与证明兼备时，
可与签名的证据包（证据与保管）搭配使用。

## 综合结果

**综合结果**（位于搜索页面和分析窗口中）会打开一个分两步操作的
窗口：它先获取一个候选集，向你展示匹配的文章及其元数据，
并让你**最多选择 20 篇**（前 ≤20 篇已预先勾选）；然后对这些文章且仅对这些文章运行一次
本地模型处理，返回共同事实、分歧点以及
悬而未决的问题，并按编号引用成员文章。结果附带完整的被综合
语料，其中包括每篇文章的元数据和阅读器链接，并提供**导出**选项（复制、.md，或
作为独立页面打开）。综合结果会连同每篇成员文章的模型 + 提示词版本出处
一起存储，注意事项也随之附带：这只是针对
所列成员的阅读辅助——绝非结论。与其他 LLM 功能一样，需要 Ollama；
没有它时，你会看到一条如实的“无法连接”消息。

## 带版本的导出与引用图谱

- 机器可读的导出现在遵循一份稳定的约定（`oo-export-1`）：JSON 导出是
  自描述的封装（模式、应用版本、生成时间、确切的查询、数量）；
  CSV 的列保持顺序不变，并以 `X-OO-*` HTTP 头提供相同的出处信息。最后
  一列 **Fetched From Host（实际抓取主机）**（JSON 中为 `fetched_host`）是页面经过重定向后
  实际被抓取的主机；对于在记录此信息之前存储的文章，该列为空。
- **引用图谱**——你存储的文章引用了哪些外部域名，只有计数，
  不推断可信度——可导出为 GraphML（`/api/links/export.graphml`），供
  Gephi/yEd/NetworkX 使用，也可导出为 JSON。

## 调度器运行日志与本地文件夹导出（采集）

每一次调度器运行——无论成功还是失败——都会向一个本地的、可审计的运行日志
（`scheduler_runs.jsonl`）追加一行，因此语料库可以回答“我不在的时候运行了什么？”。另外，
你可以在“采集”的调度器卡片中设置一个**导出到本地文件夹**路径：此后每次运行都会把
新文章的增量以封装 JSON 文件的形式写入该本地文件夹，供你自己的处理流程
监视。留空 = 关闭（默认）；没有新内容 = 不生成文件。

## 发现的候选信源（来源）

应用现在会自行推荐来源——**仅限离线**：你存储的文章
反复引用的域名，以及你的语料库覆盖较少的国家在随附目录中的媒体。
推荐只会暂存，绝不会被自动采用：每条推荐都在**发现的
候选信源**面板（设置 → 高级 → 来源）中附带其证据，运行次数受调度器的发现预算限制，并
记录在运行日志中，主页卡片会在有候选项等待审阅时提醒你。
**采纳**会创建一个*停用*的来源，你仍需手动启用它；**忽略**会被记住，
不会再次推荐。基于 DuckDuckGo 的主题搜索仍是独立功能，**默认
关闭**，并受“设置 → 高级 → 安全”控制（见下文）。

## 外部主题发现需主动开启（设置 → 高级 → 安全）

*主题发现*是唯一一项**把自由文本搜索查询发送给搜索
引擎**的功能：它会把你的主题查询发送给 DuckDuckGo。（其他联网操作——采集、
市场/统计数据抓取、Ollama 模型拉取、OpenTimestamps——也都需要同意并会被明确指出；
而这是唯一一项会传输你所输入查询的功能。）它**默认停用**，
在你启用**设置 → 高级 → 安全 → 外部主题发现**（“您的查询将离开本机。”）之前，
会以如实的提示拒绝运行。为你自己添加的来源发现 RSS 源，仍走
本地的合乎伦理抓取路径，不受影响。
