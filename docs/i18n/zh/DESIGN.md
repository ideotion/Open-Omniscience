### 0. 部署环境（已解决 — 决定下文的一切）

本构建面向**一个特定环境和一位用户**。以下答案现已确定，并解决了此前若干 `⚠️ DECIDE` 事项。

- **宿主：** Qubes OS，运行在一个 **Debian AppVM**（基于模板）内。
- **Python：** **3.13 作为默认解释器。**
- **用户：** **单一主要用户（项目所有者）** — 没有多租户账户，没有 RBAC。
- **界面：** **Web 界面 + REST API，仅绑定 `127.0.0.1`**（回环）。没有对外监听。
- **网络姿态：** 本地优先；仅在抓取/拉取 LLM 时有出站连接；**任何入站**连接都没有。

#### 0.1 Qubes 对设计的改变

Qubes 并不“只是 Debian”。它的安全模型和 AppVM 生命周期带来了硬性约束，安装程序和运行时**必须**遵守：

1. **文件系统持久化是有选择的。** 在 AppVM 中，只有 **`/home`、`/usr/local` 和 `/rw`**
   能在重启后保留；根文件系统**每次启动都会从 TemplateVM 重置**。因此：
   - 应用、其虚拟环境、数据库、抓取的数据、日志、审计轨迹以及任何下载的 LLM
     模型**必须存放在 `/home/user/...` 下**（建议：`/home/user/open-omniscience`）。
   - 在 AppVM 中安装的 **`apt`/系统软件包*不会*持久保留**。系统依赖必须
     **在 TemplateVM 中**安装（然后重启 AppVM），或通过 Qubes `bind-dirs` 引入。
     安装程序必须**拆分**：“系统依赖 → TemplateVM”与“Python venv + 应用 → AppVM `/home`”。
2. **不假定根文件系统持久。** AppVM 中对根的修改在重启后消失。应将 AppVM 视为：
   持久的 `/home`，短暂的根。
3. **通过 NetVM 联网。** AppVM 只能经由为其指定的网络/防火墙 qube 访问互联网。
   应用必须**在离线时平稳降级**，绝不假定有网络连接。
4. **没有 GPU。** 在典型的 Qubes 配置中 GPU 直通不现实 → **LLM 推理仅用 CPU**。
   默认使用**小模型**（例如 `gemma2:2b`、`llama3.2:3b`、`qwen2.5:1.5b`）；大模型需主动选用。
5. **物理隔离 / 拆分虚拟机是一流的*未来*选项（不在 v1）。** Qubes 通过 **qrexec/qubes-rpc**
   让“在联网 qube 中合乎伦理地抓取，在离线保险库 qube 中分析/存储”的模式变得自然。v1
   运行在**一个 AppVM** 中；架构必须保持*抓取*边界清晰，以便日后的拆分只是一次
   部署变更，而不是重写。（仓库中已有残留的 `src/qubes/rpc/` 和
   `docs/QUBES_*` 材料 — 有待审查/替换，不可信赖。）

#### 0.2 Python 3.13 的影响（解决依赖版本冲突）

- **核心技术栈与 3.13 兼容：** FastAPI、uvicorn、SQLAlchemy 2.x、pydantic 2.x、requests、httpx、
  beautifulsoup4、feedparser、numpy、pandas、scipy、scikit-learn、statsmodels — 都提供 3.13 wheel。
- **本地 LLM 不需要重量级 Python 机器学习库。** Ollama 是一个**独立的原生二进制程序**；应用
  **仅通过 HTTP** 与之通信。完整的 LLM 能力在 3.13 上只需 `httpx`/`requests` 即可 — 应用中
  完全没有 `torch`/`transformers`。
- **重量级机器学习库从核心中移除。** `torch`、`onnx`/`onnxruntime`、`tensorflow`、
  `pyAudioAnalysis` 以及深度伪造相关技术栈在 v1 中**被移除**，因为它们 (a) 目前是
  **虚构的**（“深度伪造 CNN”从未运行推理），(b) 笨重且**在此处只能用 CPU**，以及
  (c) 存在逐包的 3.13 wheel 风险（`pyAudioAnalysis` 已无人维护；`igraph`/`leidenalg`/`gensim`
  在使用前必须逐一核实）。任何未来的机器学习功能都必须证明其分量值得，并证明有 3.13 wheel。
- **一份依赖清单，固定于 3.13。** 用一个根目录的 `pyproject.toml`（`requires-python = ">=3.13"`）
  加可选附加项（`[llm]`、`[analysis]`、`[dev]`）取代六份相互矛盾的 requirements 文件。
  删除 AI 写的“纠正性”注释和不可能满足的版本固定。

#### 0.3 单一本地用户的安全模型（简化了各项 P0）

由于唯一的监听在回环上，唯一的用户就是您：
- **认证：** v1 不需要，*前提是*服务器严格绑定 `127.0.0.1`，且绝不通过 Qubes 防火墙规则
  对外暴露。（如需代理，以后可增加一个可选的 API 令牌。）这**解决了**针对*本部署*的
  “端点无认证”问题 — 方法是消除网络暴露，而不是增加 RBAC。
- **`/metrics`：** 与其他一切一样仅限回环。
- **安装程序安全仍然是强制要求：** 不得有未经确认的 `rm -rf`，不得有未经验证的 `curl | sh`，
  绝不丢弃包管理器的 stderr — 无论是否单用户，这些都是正确性/安全问题。
- **前端资源本地内置**（没有 Google Fonts / CDN React）— 这是离线/Qubes 环境以及
  隐私原则的要求。

### 1. 一句话定义

Open-Omniscience 是一个**面向调查记者的本地优先、开源情报平台**，
它以合乎伦理的方式将全球众多数据源聚合成一个**统一、可搜索、可交叉引用、
并可追踪来源的语料库**，可选配**本地 AI** 用于分析 — 并且每一项输出都
被设计为**在科学上和法律上都站得住脚**。

### 2. 它为谁服务，以及用户雇用它完成的工作

**主要用户：** 调查记者、研究人员或分析师 — 很可能独自工作或在小型
编辑部工作，常常对隐私敏感（有需要保护的消息来源），有时处于受限/物理隔离的
环境中。

**核心待办工作：**
1. *“把与我的调查相关的一切，从众多来源自动收集到一处。”*
2. *“把它们放在一起搜索和交叉引用 — 文章、市场、电子邮件 — 以发现关联。”*
3. *“帮我理解大量文本”*（摘要、翻译、提取实体）— **而不把我的
   数据发送给任何人。**
4. *“告诉我什么可以信任 — 或不可信任”*（核实媒体、标记操纵）。
5. *“证明这来自何处，并证明我没有篡改它”*（用于发表/法律的来源追溯）。
6. *“当有变化时提醒我”*（某个来源消失、某个价格飙升、某种叙事浮现）。

### 3. 指导原则（不可妥协之处）

这些是意图的核心，必须约束每一项功能。凡是当前代码违反其中一条之处，
都是缺陷，而不是取舍。

1. **本地优先且可离线运行。** 完全在用户自己的机器/服务器上运行。除抓取本身外，
   必须在无互联网时正常工作。适合物理隔离使用（需预先准备数据/模型）。
2. **保护隐私。** 无遥测。**用户数据绝不离开本机** — 尤其是 LLM
   处理（仅通过 Ollama 在本地进行）。✅ 已解决（§0）：所有前端资源（字体、JS 库）均
   **本地内置** — 没有 CDN 调用 — 这是 Qubes/离线环境的要求。
3. **100% 自由开源。** 所有代码和模型均开源。⚠️ DECIDE：根目录的许可证是 **GPLv3**，但
   支柱 3 中是 **AGPL-3.0** — 需在全项目范围内选定一个（AGPL 对网络使用更严格）。
4. **天生合乎伦理。** 遵守 `robots.txt` 和速率限制，表明机器人身份，只抓取公开数据，
   绝不绕过付费墙或使用凭据抓取。**失败即*关闭*** — 如果无法核实合规性，
   就不抓取。
5. **站得住脚的输出（科学 + 法律）。** 每一项分析结果都带有诚实的不确定性和
   可追溯的来源。**没有虚构的数字。** 置信度评分必须来自真实的方法，否则就
   不存在。保管链必须是真实的（签名、可发现篡改），而不是一个普通的日志文件。
6. **统一语料库。** 所有导入的内容 — 新闻、金融数据、大宗商品、电子邮件 — 都存放在**同一个
   数据库**中，并且**可在一次查询中交叉引用**。这是本产品存在的理由。
7. **透明优先于优雅降级。** 系统绝不能悄无声息地退化为无效输出。
   缺少模型、来源被屏蔽、依赖不可用 → **可见、明确的状态**，绝不是
   悄无声息的占位内容。

### 4. 核心心智模型

```
        ┌─────────────────────────── INGESTION ───────────────────────────┐
        │  Web articles · RSS · Financial · Commodities · Email/Newsletters │
        │            (all ethically scraped / retrieved)                    │
        └───────────────────────────────┬───────────────────────────────────┘
                                         ▼
        ┌──────────────────── ONE UNIFIED, PROVENANCE-TRACKED STORE ────────┐
        │  articles · financial_data · commodity_data · emails · entities    │
        │  + links between them (article ↔ price move ↔ email ↔ entity)      │
        └───────────────────────────────┬───────────────────────────────────┘
                                         ▼
   ┌──────────── RETRIEVAL ────────────┐   ┌──────────── ANALYSIS (opt-in) ───────────┐
   │ Boolean / full-text search        │   │ Local LLM · verification · stats ·        │
   │ filters · cross-source correlation│   │ monitoring/alerts · correlation engines   │
   │ export (CSV/JSON) · reports       │   │ (every result: method + uncertainty)      │
   └───────────────────────────────────┘   └───────────────────────────────────────────┘
                                         ▼
                         GUI (search, dashboards, source mgmt, reports)
                         + REST API (everything available programmatically)
```

**主干（导入 → 统一存储 → 搜索 → 导出）必须坚如磐石，然后才轮到任何支柱。**
支柱是*增强器*，它们从共享存储中读取数据并写回其中。

### 5. 功能范围，按能力领域划分

#### 5.1 数据导入（P0）
- **来源类型：** 新闻网站（HTML）、RSS/Atom 订阅源。以后：API、社交平台、文件投放。
  ⚠️ DECIDE：支柱 4 列出了 Twitter/X、Reddit、Telegram、Mastodon、S3/SFTP — 请确认其中哪些（如有）
  属于真实范围，哪些只是愿景。
- **合乎伦理的抓取器（单一、共享的实现）：** robots.txt 检查（带缓存，区分 http+https，
  在不确定时**失败即关闭**），按来源的速率限制，表明身份的 User-Agent，重试/退避。
  **每个 URL 只抓取一次** — 不重复抓取，没有原始的绕行路径。
- **去重：** 基于内容哈希 + 规范 URL；同一篇文章绝不存储两次。
- **规范化：** 可靠地提取标题、作者、发布日期、语言、规范 URL、正文。
  ⚠️ DECIDE：真正的新闻提取需要按站点的规则或一个库（例如 trafilatura 风格）；
  当前的通用 CSS 方法会悄无声息地产出“No Title/No Content”。请确认我们采用稳健的提取方式。
- **调度与增量更新：** 定期重新抓取，只抓取新的/有变化的内容，恢复
  中断的运行。

#### 5.2 统一数据存储（P0）
- **单一数据库**存放所有实体类型，并以明确的**关联表**将它们连接起来
  （文章 ↔ 金融工具，文章 ↔ 大宗商品，文章 ↔ 电子邮件，文章 ↔ 命名实体）。
- **每条记录上的来源字段：** 来源、抓取时间戳、原始 URL、内容哈希、
  原始数据与处理后数据分离。
- **后端：** 单用户/桌面使用 SQLite；服务器/并发使用 PostgreSQL。
  ⚠️ DECIDE：确认默认 SQLite + 可选 Postgres（文档两者都提到了；还有用于缓存的 Redis —
  纳入还是排除？）。
- **审计日志：** 只追加、**可发现篡改**的记录，涵盖每一次导入和变更。

#### 5.3 搜索与检索（P0）
- 覆盖整个语料库的**全文搜索**。
- **布尔运算符**（`AND`/`OR`/`NOT`）、**带引号的短语**，以及**优先级正确的括号**
  — 用真正的语法或数据库原生 FTS 实现，而不是字符串拼凑。
- **结构化筛选：** 来源、日期范围、语言、标签/类别、实体、数据类型。
- **分页**、结果排序、摘录/高亮。
- **导出：** CSV 和 JSON（以及 ⚠️ DECIDE：PDF/报告格式？），忠实于筛选后的结果集。

#### 5.4 交叉引用与相关性（P1 — 差异化所在）
- 从任意记录跳转到不同类型的相关记录（文章 → 提及的公司 → 发布日期附近的
  价格变动 → 相关电子邮件）。
- **相关性引擎**（金融/大宗商品 ↔ 新闻）以**诚实、明确定义的度量**呈现*候选*关系
  （并清楚标注相关 ≠ 因果）。没有虚构的 p 值。
- 以实体为中心的视图：语料库关于某个人/组织/地点/金融工具所知道的一切。

#### 5.5 本地 LLM 分析（P1）
- **运行时：** Ollama，完全本地。模型可插拔；附带一个*确实存在*的、小而合理的默认模型。
  ⚠️ DECIDE：当前默认的 `gemma4:e2b` 以及列出的大多数模型（Gemma 4、Llama 4、Qwen 3.5）
  都是幻觉产物 — 用真实标签替换目录（例如 `gemma2:2b`、`llama3.2:3b`、`qwen2.5`、
  `phi3`）。
- **能力：** 生成、对话（带上下文）、提取（实体/关键词/摘要/引语/链接）、
  翻译（多语言）、分析（情感/语气/可读性；偏见分析仅在有诚实边界时提供）、
  综合（摘要、比较、时间线、报告）、批处理。
- **大声降级：** 如果 Ollama 或模型不存在，就明说 — 绝不返回虚假的分析。

#### 5.6 核实与反欺骗 — *支柱 3*（P2，范围待定）
- **意图：** 检测被操纵的媒体（图像/视频/音频深度伪造）、宣传手法、认知
  偏差、机器人和协同行动；验证元数据（EXIF/ID3）和跨模态一致性。
- ⚠️ DECIDE（重要）：如今这部分是**虚构的** — “深度伪造 CNN”从未运行推理；评分
  只是模糊度启发式；偏见/宣传的覆盖大多无法触达；“准确率 >95%”只是愿景。
  请选择其一：
  - **(a) 暂时砍掉**媒体取证，只发布诚实的部分（元数据/EXIF 验证是真实的
    而且有用）；**(b) 重建**，采用真正经过评估的自由开源模型并公布准确率；或
    **(c) 保留**，但**明确标注“实验性启发式，不构成证据”。**
  我的建议：现在选 (a)，以后选 (b)。对于新闻/法律工具而言，虚构的取证是最大的单一隐患。

#### 5.7 科学严谨性 — *支柱 2*（P1）
- **意图：** 让平台的量化结论站得住脚 — 真正的统计检验、置信
  区间、可复现性/谱系评分，以及通过多个本地 LLM 相互核查的“同行评审”。
- 这个支柱是实现得最真实的（真正的 scipy/statsmodels）。保留它，加固它，并让它成为
  **把关者**：应用向用户显示的任何数字都应经过诚实的不确定性报告。

#### 5.8 实时监控与警报 — *支柱 4*（P2）
- **意图：** 持续的来源监视；异常/趋势/模式检测；威胁情报增强；
  带规则和升级机制的多渠道警报（电子邮件/webhook/聊天）。
- ⚠️ DECIDE：当前的健康检查是模拟的（`sleep; return HEALTHY`），威胁情报/STIX-TAXII
  并不存在。请确认范围：对语料库进行真实的来源可用性监控 + 异常警报是
  可以实现且有价值的；STIX/TAXII、SMS/Twilio、Slack/Teams 很重 — 纳入还是排除？

#### 5.9 金融情报 — *支柱 5*（P2，文档中标记为 0%）
- **意图：** 从开放的网络来源（不用 API/付费墙）抓取全球交易所数据（OHLC + 基本面），
  检测波动/模式/异常，并在共享数据库中**将价格变动与新闻相关联**。
- ⚠️ DECIDE：尽管已提交了脚手架代码，这部分**只有设计（0% 已构建）**。请确认它是真实的

### 0. 重述任务

为一个特定的人重新设计整个图形界面：**一位追求真相的行动者 — 一位
*不太*喜欢电脑的调查者/记者**，希望了解世界的真实面貌，
并可信地传达调查发现。结果必须
流畅、美观、适应性强、高度可定制、既简单*又*有深度，并且好到
让一位从肩后瞥见的同事说出*“这是什么 — 我能用吗？”*
它必须尊重项目已有的本质：**单用户、仅限回环、
离线优先、无依赖、无遥测**，并受**慕尼黑宪章**约束
（真相、核实来源、隐私、拒绝宣传）。

#### 工程立场（以及诚实的取舍）

先前的界面是一个 2,200 行的 `index.html`，把约 110 个函数连到约 150 个
API 端点。这些函数*能用且经过测试*。从零重写会
产出一个更漂亮的外壳，却很可能有按钮悄无声息地失效 — 这恰恰
与一个以**诚实**为全部卖点的工具背道而驰。所以这是一次
**对用户所见所触一切的全面重新设计** — 视觉语言、
布局、导航模式、信息架构、命名、新手引导、
定制，以及两个全新的界面（一个主页仪表板和一个应用内文档
阅读器）— 建立在*经过验证的数据层之上*，保留每一个原有元素 ID，
因此没有任何退化。无依赖仍是绝对要求：**没有 CDN，没有网络
字体，没有框架** — 一个自包含的文件，在断开 NetVM 时也能运行。

### 2. 设计原则（推导而来，而非照搬）

1. **清晰胜于巧妙。** 平实的动词、人性化的标签、每个界面一个明显的主要
   操作。行话（“ingest”“corpus”“Merkle root”）要在原处翻译或
   解释，绝不默认用户懂。
2. **信任就是产品。** 可验证性、来源追溯以及“这个数字是真实测得的，
   不是估算的”要呈现出来，而不是埋起来。整体美感应当*感觉*像一件
   仪器，而不是玩具。
3. **渐进式展开。** 默认简单；深度只需一次点击。高级
   面板可折叠；很少使用的模块可以完全隐藏。
4. **可定制，因为信任是个人化的。** 主题、强调色、密度、字号、
   布局，以及*哪些工具出现*都由用户设定 — 并且只在
   本地保存。
5. **界面中的诚实。** 如果某项能力依赖可选附加项，界面
   就如实说明，而不是假装。没有任何东西伪造成功。
6. **天生自主。** 不发出任何形式的外部请求。外观
   通过系统字体和手工绘制的 SVG 图标实现。
7. **键盘优先也就是无障碍优先。** 命令面板和快捷键
   服务于 Daniel，*也*让整个应用无需精确使用鼠标即可操作。

### 3. 逐个工具分析 — 优点、缺点、决定

旧的顶部标签页组合：*搜索 · 导入 · 来源 · 数据库 · 市场 · 洞察 ·
维基百科 · 保管链 · 设置。* 针对我们的用户画像逐一评估。

| 旧标签页 | 优点 | 缺点 | **决定** |
|---|---|---|---|
| **搜索** | 核心操作。人人需要。 | 埋在九个标签页之一；对新用户没有指引。 | **保留并提升。** 成为核心，可即时到达；新的**主页**围绕它提供指引。 |
| **导入** | 拉取数据所必需。 | “Ingest”是工程师行话；令人生畏；把调度器和手动抓取混为一谈。 | **保留，更名 → “采集”。** 以简单的手动操作为先；调度器是“自动采集”，定位为设好即可不管。 |
| **来源** | 可信度在此；来源追溯从*出处*开始。 | 表格密集；感觉像管理后台，而不是新闻工作。 | **保留，重新定位为“来源”（您编辑部的跑线清单）。** 重新设计样式，读起来像图书馆，而不是数据库控制台。 |
| **数据库** | 诚实的实时计数；备份/恢复。 | “数据库”对 Amara 毫无意义；她有的是*文库/档案*，而不是数据库。 | **保留，更名 → “文库”。** 同样真实的计数和全球覆盖，定位为“您已收集的内容”。 |
| **市场** | 对“追踪资金”类调查很有用。 | 与大多数报道无关；笨重、小众；对 Amara 是干扰。 | **保留，标为高级，可隐藏。** 不在关键路径上；不做财经报道的用户一个开关即可移除。 |
| **洞察** | 视觉上的亮点 — 趋势、关联、地图。“惊艳”所在。 | 原本是一个不起眼的中间标签页；被低估了。 | **保留并推广。** 这是一项招牌功能；给予突出位置并精心打磨。 |
| **维基百科** | 非常契合：“世界的真实面貌”、离线知识、编辑战检测。 | 两件不同的事（实时追踪与笨重的离线转储）令人困惑地分散在不同标签页。 | **保留。** 追踪留在这里；笨重的转储留在设置中，并清楚地交叉链接（已在先前工作中完成）。 |
| **保管链** | 信任的差异化所在。正是它让 Elliot 信任输出、让 Amara 显得专业。 | 名称是法律术语；感觉像一个很少有人会打开的保险库。 | **保留，更名 → “证据与保管”，推广。** 是“这是什么？！”时刻的一部分。 |
| **设置** | 必需。 | 原本是个杂物抽屉（偏好 + 关键词过滤 + 转储 + 备份）。 | **保留，重组**为若干部分（外观 · 常规 · 维基百科 · 数据与备份 · 安全）。*（0.07：独立的“自定义”抽屉被并入为**外观**部分 — 外观与风格只有一个归宿，浮动的界面元素更少。）* |

#### 新增的界面

- **主页（仪表板）。** *理由：*Amara 需要指引，而不是一个空白的搜索框。
  一目了然的状态（语料库规模、来源、调度器、最近活动）、醒目的快捷
  操作（“搜索”“立即采集”“核实一份文件”），以及能起到
  教学作用的空状态。这是对主要用户画像而言最大的单项可用性改进。
- **帮助 / 文档阅读器。** 用户明确要求能直接访问详细
  手册。一流的**帮助**界面在应用*内部*呈现用户手册（以及其他文档）
  — 可搜索、离线、无需离开工具。也可从
  顶部栏（`?`）和命令面板到达。

#### 由此形成的信息架构

扁平的 9 标签页条变为一个**分组侧边栏**（可折叠为图标），按
工作的实际流程排序：

- **调查** — 主页 · 搜索 · 洞察 · 时间地图 · 维基百科 · *市场（高级）*
- **采集** — 采集 · 来源 · 文库
- **信任** — 证据与保管
- **系统** — 设置 · 帮助

分组把“九个平起平坐的陌生人”变成“四种意图”，这正是 Amara 的
思考方式（“我想*找到*某样东西” / “我想*收集*” / “我想*证明*”）。

### 4. “惊艳”— 让记者凑近来看的东西

- **一套连贯的视觉体系。** 默认采用深沉的“墨色”深色主题，配一个
  自信的单一强调色、宽裕的间距节奏、真正的字体层级、用于
  数据/哈希的等宽字体、柔和的层次感，以及克制的动效。它读起来像*仪器*，而不是
  *仪表板模板*。
- **命令面板（Ctrl/⌘-K）。** 输入即可跳转到任何地方、运行任何操作或打开
  任何文档。对 Daniel 是利器；对 Amara 是一张“我在这里到底能做什么？”的地图。
- **外观控制**（设置 → 外观；0.06 及以前是一个实时抽屉，在 0.07 中并入
  设置）。主题预设（Ink、Slate、Midnight、Paper、Sepia、
  Terminal、High-contrast）、强调色色板、密度、字号、侧边栏折叠，
  以及**模块可见性** — 全部即时、全部本地、全部持久保存。
- **一个提供指引的主页**、一个起到教学作用的新手引导，以及会引导用户的空状态。
- **让信任可见。** 保管/核实以及“实测，而非估算”的
  定位是美感的一部分，而不是小字附注。
- **完全离线的完整性。** 界面外壳不发出任何网络调用 — 这本身就是一项
  可以*展示*给注重安全的同事看的功能。

### 5. 定制模型

外观与风格存储在 `localStorage`（`oo.ui`）中 — 绝不发送到任何地方 — 因此它
即时生效且在离线时依然有效。功能性偏好（默认结果数量、基础
主题）继续通过 `/api/settings` 在服务器端保存。可定制项：主题
预设、强调色、密度、字体缩放、侧边栏状态，以及可见
模块的集合。合理的默认值意味着首次运行的用户无需动其中任何一项。

### 6. 我刻意**没有**做的事（诚实起见）

- **没有框架 / 构建步骤 / CDN。** 这会为了表面效果而破坏离线、可审计、自主的
  理念。原生实现、单一文件、系统字体、手绘 SVG。
- **没有虚构的功能。** 每个按钮都对应一个真实可用的端点。依赖可选附加项的
  能力仍会如实说明。
- **没有悄无声息的后端变更**，唯一的例外是一个新增的、只读的、基于白名单的文档
  端点（`/api/docs`），用于支持帮助阅读器。
- **自由文本的语言输入框仍保持自由文本**（已在 OPEN_QUESTIONS 中注明）；
  重新设计不会发明后端无法支撑的下拉菜单。

## 两套界面，一场论证 — “Console” 与 “Desk”

> 您要求的是一场*正反*论证：不是为 0.05 重新设计辩护，而是
> 诚实地论证它可能是本应用的**错误**界面 — 并提供一个
> 具体的替代方案来与之对照检验。本文档就是这场论证。两套
> 界面并排发布，让您可以在相同数据上同时运行两者，自行
> 判断。

---

### 0. 首先，重新立足于本应用的真实本质

在争论界面外壳之前，先看不可妥协之处（来自 `ETHICS.md`、
`DESIGN.md`、慕尼黑宪章）：

- **一个用户、一台机器、仅限回环、离线优先。** 没有账户，没有云端，
  没有遥测。常常运行在网络 qube *已断开*的 Qubes AppVM 中。
- **一位不太喜欢电脑的追求真相的行动者。** 一位调查者 /
  记者，其工作是*理解现实并可信地传达它*。
- **产品就是信任。** 来源追溯、来源核实、“实测而非
  估算”、可发现篡改。慕尼黑宪章（真相、核实来源、保护
  消息来源、抵制宣传）是主干。
- **自主即美学。** 这个工具应当*感觉*属于用户，
  而不属于某个平台。

任何界面都必须以*这些*为标准来评判，而不是以“它看起来像不像一个
2025 年的 SaaS 产品”。

---

### 1. 对 “Console”（0.05 重新设计）的控诉

以最有力的方式陈述 0.05 走错方向的理由：

1. **它给一个自主的工具穿上了监控资本主义的外衣。** 常驻的
   左侧边栏、状态胶囊、命令面板、带八种主题的定制抽屉
   — 这是 Slack、Linear、Notion 的视觉语法：*云端 SaaS*。对于
   一位不信任大型科技公司、从事敏感报道的用户来说，这种语法可能
   读作“又一个监视我的应用”，从而削弱此处最重要的东西：
   信任。外观与价值观相冲突。

2. **它为演示而优化，而不是为工作。** 任务要求包括“让一位
   记者说出*我能用吗？*” — 一种从肩后瞥见的五秒钟反应。
   为此而设计会倾向于仪表板式的炫目效果（渐变、动画计数、
   主题大全），而远离调查工作安静、以阅读为主、以文档为中心的
   现实。最适合深度工作的工具（文本编辑器、笔记本）都是
   *朴素的*。Console 也许令人印象深刻却流于表面。

3. **定制是一种伪装成礼物的税。** 八种主题、强调色色板、
   密度、字体缩放、按模块隐藏。对*Amara*（不太喜欢电脑）而言，每一项
   都是她不想做的决定，也是一种把工具配置错的途径。
   “高度可定制”迎合了任务要求的措辞和*设计者*对
   慷慨的理解 — 但一个真正简单的工具是**有主见的**：它替用户做出
   正确的决定，用户就不必自己做。选择就是认知负担。

4. **信息架构仍然是软件的，而不是用户的。** Console
   重命名并重新分组了标签页，但菜单仍然是*模块*列表
   （搜索、来源、洞察、市场、保管……）。Amara 不按模块思考；
   她按**案子**思考：“我在追这个报道 — 收集、阅读、关联、证明、
   发表。” 0.04 和 0.05 都让用户把自己的*工作*翻译成应用的
   *功能*。一个由九个目的地组成的常驻导航，就是一张代码库的地图。

5. **界面外壳与内容争夺空间。** 固定的侧边栏 + 顶部栏永久占用
   约 250px 和一条横向区域，用于*用户每次会话只用两秒钟的导航*。
   用户真正做的事 — 阅读文章、浏览结果、比较
   差异 — 只能用剩下的空间。调查就是阅读；Console 对阅读
   服务不足。

6. **“惊艳”是借来的，不是挣来的。** 命令面板和主题在现代应用中是*基本配置* —
   正因为人们熟悉才显得令人印象深刻。这里真正
   与众不同、“我从没见过”的功能是*实质内容*：
   离线维基百科编辑战检测、可发现篡改的保管、“每个数字都是
   真实的 COUNT(\*)”。Console 只是装饰；它没有把真正独特之处戏剧化地呈现出来。

这是一份严肃的控诉。它值得一个真正的替代方案，而不是一份反驳。

---

### 2. 为 Console 辩护（以使论证公平）

- 常驻导航是**可发现的**：没有任何东西被隐藏，这对一位
  尚不知道工具能做什么的新手很重要。中心辐射式模型把
  强大功能藏在一次点击和一次猜测之后。
- 定制是**可选退出的**：默认值合理；无视抽屉的用户
  不会损失任何东西。而且主题确实有助于缓解工作中的眼睛疲劳/深夜工作的现实，
  以及*真实*用户的无障碍需求（高对比度、文字大小）。
- “SaaS 语法”也不过是**当前的可用性惯例** — 人们第一天就知道怎么
  用。为新奇而新奇有它自己的代价。
- 它仍然是**100% 离线且无依赖的**。语法是借来的；
  实质（无网络、无遥测）不是。

两种立场都有道理。解决之道不是继续争论 — 而是
**构建对立面，然后两者都用**。

---

### 3. 对立面：“Desk”

如果说 Console 是一个**宽泛的操作控制台**（一切总是一键可达，
最大限度地灵活，现代应用语法），那么 **Desk** 就是相反的论点：

> **一张调查者的书桌：沉静、有主见、内容优先、以任务为框架。
> 几乎没有界面外壳。一次只做一件事。界面为阅读和
> 思考让路。**

Desk 刻意*不同意* Console 的具体承诺：

| 维度 | Console（正题） | Desk（反题） |
|---|---|---|
| 导航 | 常驻左侧边栏（始终可见） | **没有常驻导航。** 导航*按需*出现 — 一个沉静的主页、一个“前往…”浮层，以及 ⌘K。界面外壳只在被召唤时出现。 |
| 入口 | 一个状态仪表板 | **以工作为框架的主页：**“您在做什么？” → 收集 · 查找与阅读 · 关联 · 核实与分享。以用户的任务为框架，而不是应用的模块。 |
| 定制 | 8 种主题、强调色、密度、字体、模块开关 | **只有两种主题**（Paper / Ink），没有旋钮。有主见。工具替您决定，您就不必决定。 |
| 美学 | 现代应用控制台（无衬线、胶囊、渐变） | **编辑 / 印刷风格：**衬线标题、纸张般的温暖、宽裕的页边距、适合阅读的行宽。感觉像编辑部，而不是 SaaS。 |
| 空间给谁 | 先是导航 + 状态，然后是内容 | **内容。** 单一居中的阅读栏；表格和文章阅读器获得空间。 |
| 信任信号 | 一个状态胶囊 | 一行常驻、安静的 **“本地 · 离线 · 没有任何东西离开本机”** — 自主被明确说出，而不是暗示。 |
| 演示反应 | “好流畅！” | “……哦，这很*沉静*。而且全是我的。” 一种更慢、更深的惊艳。 |

Desk **保留**的东西（因为它是应用的要义，而不是界面外壳）：每一项功能
和每一个可用的端点。Desk 和 Console 共享完全相同的引擎和
相同的内容面板 — 它们*只*在外壳、导航模式、信息架构框架
和美学上有所不同。这是有意为之：它让实验保持受控，因此您
比较的是**理念**，而不是我碰巧把哪一个接线接得更仔细。

---

### 4. 如何评判它们（评分标准）

以价值观为标准为每一个打分 — 而不是凭“哪个更好看”的直觉：

1. **信任** — 哪一个*感觉*属于您，不会背叛您？
2. **沉静与能力** — 哪一个让您能够思考？哪一个让强大功能可被找到？
3. **新手路径** — 把*Amara*直接丢进去：哪一个让她更快得到结果，
   更少恐惧？
4. **高级路径** — 用键盘的*Daniel*：哪一个不碍他的事？
5. **阅读** — 在每一个中打开一篇长文章 / 一个维基百科差异。哪一个是更好的
   *阅读*场所？
6. **五秒测试** — 把每一个给同事看。哪一个能引发“我能用吗？” —
   这又是不是您真正想要优化的反应？
7. **契合理念** — 您会信任哪一个在 Qubes 保险库中断网
   运行？

---

### 5. 预测的优缺点（我诚实的押注，有待检验）

**Console** — *优点：*可发现、符合惯例、灵活、无障碍旋钮、演示
光彩。*缺点：*界面外壳繁重、决策负担、可能侵蚀信任的通用 SaaS 观感、
信息架构仍以模块为中心。

**Desk** — *优点：*沉静、内容/阅读优先、有主见（没有配置税）、
以任务为框架的入口、一种*强化*自主与信任的美学。*缺点：*
强大功能要召唤一次才出现（一次点击/按键）、无障碍旋钮更少、不那么
立刻“令人印象深刻”、新奇带来少量学习成本。

---

### 6. 我的建议（综合 — 暂定，有待您的检验）

我预计正确答案**既不是纯 Console 也不是纯 Desk**，而是一种综合，
倚重 Desk 的*价值观契合*和 Console 的*可发现性*：

- **采用 Desk 以任务为框架的主页和编辑式的沉静**作为默认基调。工作
  框架（“收集 / 阅读 / 关联 / 核实”）是对
  “信息架构就是代码库”这一批评最大的单项修正。
- **采用 Desk 在定制上的克制：**提供两种出色的主题
  （Paper/Ink）+ 一个用于无障碍的文字大小控制，并**砍掉**强调色 /
  密度 / 模块隐藏的蔓延。在这里，有主见胜过可配置。
- **保留 Console 的一个*安静、可折叠的*导航**以利于可发现性 — 但
  默认折叠，让内容为先，需要时导航就在那里。
- **保留 ⌘K**（它同时服务新手和高级用户，而且确实有用）。
- **把实质而不是外壳戏剧化：**让保管、离线维基百科和
  “真实计数”成为视觉主角 — 那才是挣来的惊艳。
- **处处以信任声明为先**（“没有任何东西离开本机”）。这就是

> 利用文章的**链接**汇集谈论同一件事的内容，揭示媒体的

### 1. 核心思路：链接就是一张引用图

把每篇文章当作一个节点，把每个出站链接当作一条指向某个 URL（以及
其域名）的有向边。这张图恰好回答了您提出的问题：

- **“汇集所有谈论同一链接的文章。”** = 按文章引用的外部 URL 对文章
  分组 → 该 URL 的**入度**就是“我的文章中有多少指向
  这里”。高入度 = 一个**枢纽**：常常是一份原始文件、一篇通讯社稿件，或一个
  被广泛讨论的参考资料。
- **“通过内部链接发现趋势。”** = 观察入度随时间的变化；一个被引用次数
  激增的 URL 或域名，就是一个以记者实际引用为基础的*趋势*，
  而不只是关键词频率。
- **“追溯原始 / 最初来源。”** = 在关于同一报道的一组文章中，原始来源是其他文章
  **链接指向**的那个节点，和/或最早的那个，和/或
  引用了**原始文件**（法院/政府/数据集）的那个。链接 + 时间戳 + 通讯社
  署名可以三角定位它。

这就是*共被引分析* — 成本低、透明、可解释。没有黑箱。

### 2. 分阶段策略（每一阶段都可以独立发布）

#### P0 — 将提取器接入导入流程（让这张图存在）
- 在导入期间对抓取到的 HTML 调用 `LinkExtractor`；将出站的
  **外部**链接持久化到 `article_links`（跳过内部导航、广告，以及 — 按
  `ROADMAP.md` — 图像/二进制链接）。存储 normalized_url + 锚文本 + 类型。
- 尽可能将每个外部链接的域名映射到一个已知的 `Source`/`ExternalSource`
  （这样“谁引用谁”就能汇总到媒体机构和**所有者**层面）。
- 成本低、确定性、离线。除了导入已经抓取的内容外，不抓取任何其他东西。

#### P1 — 聚合 + API（回答用户的问题）
基于这张图的只读端点：
- **`top-cited`** — 某个时间窗口内被引用最多的 URL/域名（趋势信号）。
- **`articles-by-link`** — 给定一个 URL/域名，语料库中引用它的每一篇文章
  （“汇集所有谈论同一链接的文章”）。
- **`link-graph`** — 某个主题或时间窗口的节点/边，用于可视化。
- **`co-citation`** — 引用*相同*外部来源的文章（候选的
  “同一报道”聚类），附带重叠计数。

#### P2 — 界面：洞察中的“链接与来源”视图
- 一份**被引用最多的链接/域名**的排名列表（点击 → 所有引用它的文章）。
- 一张小型、可缩放的**引用图**（复用洞察地图已经采用的 SVG 方法
  — 不引入新依赖）。
- 始终显示**样本量**（“被您的 14 篇文章引用”）— 实测，而非
  猜测。用户点击、探索、决定。

#### P3 — 原始来源谱系
对于关于同一报道的一组文章，呈现一条**谱系**，按信号排序
（每个信号都显示出来，没有一个是决定性的）：
- 入度（谁被其他文章链接指向），
- 最早的发布时间戳，
- 通讯社署名（AFP/Reuters/AP — 我们已经标记了 `wire-agency`），
- 是否存在指向**原始文件**的链接（政府/法院/数据集/预印本）。
输出：“原始文件 → 首篇报道 → 回声”，作为一条供用户阅读的链条。

#### P4 — 同质化与回声（与媒体集中度相关）
- **近似重复检测**（低成本的 MinHash/SimHash），用于标记各媒体之间
  联合发布/复制的文本 — 建立在 `src/ingestor/duplicate_detector.py` 之上。
- **回声分数**：一个聚类中许多媒体都引用**同一个**来源（或在一个紧密的
  循环中相互引用），且几乎不添加原创链接 = 高回声。多样化的原始来源
  引用 = 独立报道。
- **集中度叠加**：按**所有权**为回声加权 — 如果形成回声的聚类对应于
  同一个所有者/集团（“约 7 位亿万富翁拥有约 90%”的情形），就把它呈现出来。需要
  所有权图（Wikidata P127/P749 + 手工整理），按 `ROADMAP.md`。

---

### 3. 让用户掌握主导权（不可妥协）

- **呈现，绝不压制。** 回声/谱系分数*显示出来且可排序*；工具
  绝不隐藏或自动降级任何来源。任何降权都是一个明确的、可撤销的
  用户控制，**默认关闭**。
- **没有真相标签。** “我们看到的最早的” / “被引用最多的” ≠ “真实的”。我们展示结构
  （谁先说的、谁引用谁、谁拥有谁），然后止步。
- **一切都可解释且在本地进行。** 每个数字都可追溯到用户能够查看的数据行；
  没有外部调用，没有机器学习黑箱（哈希 + 计数 + 图的度）。
- **开源且可审计。** 纯函数、可单元测试、分类规则存于
  数据中（`LinkClassificationRule`），用户可以编辑。

---

### 4. 风险与诚实的局限

- 链接提取的质量取决于抓取到的 HTML（付费墙/JS 会限制它）。
- 锚文本/引用惯例各不相同；没有链接的“据 X 称”会被遗漏（以后的
  NLP 处理可能有帮助，但先从简单做起）。
- 所有权数据零散且过时 — 必须可归属来源，而不是猜测。
- 语料库规模的近似重复检测需要小心处理，才能在一台机器上保持低成本（哈希、按时间窗口
  比较），而不是 O(n²) 的全文比较。
