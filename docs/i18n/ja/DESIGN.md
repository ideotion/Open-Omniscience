## Open-Omniscience — プロダクトの総括（アプリがなすべきこと）

> **ステータス:** レビュー用の草案。本文書は、リポジトリのドキュメント全体に散らばっていた*意図された*設計を、
> 一つの首尾一貫した重複のない仕様にまとめたものです。バージョン間のずれ、マーケティング的な誇張、
> 検証不能な QA の主張は意図的に取り除いています。記述しているのは**目標とするプロダクト**であり、
> 現在の（大部分が機能していない）コードではありません。
>
> 使用する記号:
> - `⚠️ DECIDE:` 元のドキュメントが曖昧だった、または互いに矛盾していた点 — あなたが判断してください。
> - `(P0/P1/P2)` その機能の*提案*優先度（P0 = MVP の中核、P1 = 重要、P2 = 後回し）。

### 0. デプロイの前提（解決済み — 以下のすべてを左右する）

このビルドは**一つの特定の環境と一人のユーザー**を対象とします。以下の回答は確定しており、
かつての `⚠️ DECIDE` の論点のいくつかを解決しています。

- **ホスト:** Qubes OS、**Debian AppVM**（テンプレートベース）内で稼働。
- **Python:** **デフォルトのインタープリタとして 3.13。**
- **ユーザー:** **単一の主ユーザー（プロジェクトのオーナー）** — マルチテナントのアカウントも RBAC もなし。
- **提供形態:** **`127.0.0.1` のみにバインドされた Web UI + REST API**（ループバック）。外部向けのリスナーはなし。
- **ネットワーク方針:** ローカルファースト。外向き通信はスクレイピング／LLM の取得時のみ。**内向きは一切なし**。

#### 0.1 Qubes が設計にもたらす変化

Qubes は「単なる Debian」ではありません。そのセキュリティモデルと AppVM のライフサイクルは、
インストーラとランタイムが**必ず**守らなければならない厳しい制約を課します。

1. **ファイルシステムの永続性は選択的です。** AppVM では、**`/home`、`/usr/local`、`/rw`** だけが
   再起動後も残ります。ルートファイルシステムは**起動のたびに TemplateVM からリセット**されます。したがって:
   - アプリ、その virtualenv、データベース、スクレイピングしたデータ、ログ、監査証跡、ダウンロードした
     LLM モデルは、**すべて `/home/user/...` の下に置かなければなりません**（推奨: `/home/user/open-omniscience`）。
   - AppVM にインストールした **`apt`／システムパッケージは永続しません**。システム依存関係は
     **TemplateVM に**インストールする（そして AppVM を再起動する）か、Qubes の `bind-dirs` で取り込む必要があります。
     インストーラは「システム依存関係 → TemplateVM」と「Python venv + アプリ → AppVM の `/home`」に**分割**しなければなりません。
2. **永続的なルートを前提にしない。** AppVM でのルートへの変更は再起動で消えます。AppVM は
   永続する `/home`、揮発するルート、として扱ってください。
3. **NetVM 経由のネットワーク。** AppVM は割り当てられた net／firewall qube を通じてのみインターネットに到達します。
   アプリは**オフライン時にきれいに縮退**しなければならず、接続性を前提にしてはなりません。
4. **GPU なし。** 一般的な Qubes 構成では GPU パススルーは現実的でない → **LLM の推論は CPU のみ**。
   デフォルトは**小さなモデル**（例: `gemma2:2b`、`llama3.2:3b`、`qwen2.5:1.5b`）とし、大きなモデルはオプトイン。
5. **エアギャップ／VM 分割は一級の*将来*オプション（v1 ではない）。** Qubes では「ネットワーク接続された qube で
   倫理的にスクレイピングし、オフラインの保管庫 qube で分析・保存する」パターンが **qrexec/qubes-rpc** によって自然に実現できます。
   v1 は**一つの AppVM** で動作しますが、アーキテクチャは*取得（fetch）*の境界をきれいに保ち、後の分割が
   書き直しではなくデプロイの変更で済むようにしなければなりません。（リポジトリには痕跡的な `src/qubes/rpc/` と
   `docs/QUBES_*` の資料が既に含まれています — 信頼せず、見直す／置き換える対象です。）

#### 0.2 Python 3.13 の影響（依存関係のバージョン衝突を解決する）

- **コアスタックは 3.13 で問題なし:** FastAPI、uvicorn、SQLAlchemy 2.x、pydantic 2.x、requests、httpx、
  beautifulsoup4、feedparser、numpy、pandas、scipy、scikit-learn、statsmodels — いずれも 3.13 用の wheel を提供しています。
- **ローカル LLM に重い Python ML は不要。** Ollama は**独立したネイティブバイナリ**であり、アプリは
  **HTTP のみ**で通信します。LLM の全機能は 3.13 上で `httpx`/`requests` だけで動作し、アプリに
  `torch`/`transformers` は一切含まれません。
- **重い ML ライブラリはコアから外します。** `torch`、`onnx`/`onnxruntime`、`tensorflow`、
  `pyAudioAnalysis`、ディープフェイク関連一式は v1 では**削除**します。理由は、(a) 現在**捏造**されている
  （「ディープフェイク CNN」は推論を一度も実行しない）、(b) 重く、**ここでは CPU のみ**、
  (c) パッケージごとに 3.13 wheel のリスクがある（`pyAudioAnalysis` はメンテナンスされておらず、`igraph`/`leidenalg`/`gensim`
  は使用前にそれぞれ検証が必要）ためです。将来の ML 機能はいずれも、その重さを正当化し、3.13 wheel の存在を証明しなければなりません。
- **依存関係マニフェストは一つ、3.13 に固定。** 互いに食い違う六つの requirements ファイルを、ルートの単一の
  `pyproject.toml`（`requires-python = ">=3.13"`）+ オプションの extras（`[llm]`、`[analysis]`、`[dev]`）に置き換えます。
  AI による「修正」コメントと実現不可能なピン留めは削除します。

#### 0.3 単一ローカルユーザーのためのセキュリティモデル（P0 を単純化する）

唯一のリスナーがループバックで、唯一のユーザーがあなた自身であるため:
- **認証:** v1 では不要。*ただし*サーバーが厳密に `127.0.0.1` にバインドされ、Qubes のファイアウォールルールで
  決して公開されないことが条件です。（プロキシ経由にする場合は、後から単一のオプション API トークンを追加できます。）これにより
  「エンドポイントに認証がない」という指摘は*このデプロイについては* **解決**されます — RBAC を追加するのではなく、
  ネットワークへの露出をなくすことによって。
- **`/metrics`:** 他のすべてと同様にループバックのみ。
- **インストーラの安全性は引き続き必須:** 確認なしの `rm -rf` 禁止、未検証の `curl | sh` 禁止、パッケージマネージャの
  stderr を決して捨てない — 単一ユーザーかどうかに関係なく、正しさと安全性の問題です。
- **フロントエンドのアセットはローカルに同梱**（Google Fonts／CDN の React は使わない）— オフライン／Qubes のため、
  そしてプライバシー原則のために必要です。

### 1. 一文での定義

Open-Omniscience は、**調査報道ジャーナリストのための、ローカルファーストでオープンソースのインテリジェンス・プラットフォーム**です。
世界中の多数のデータソースを倫理的に集約し、**単一の、検索可能で、相互参照可能な、出所（プロヴナンス）が追跡されたコーパス**とします。
分析のためのオプションの**ローカル AI** を備え、すべての出力が**科学的にも法的にも擁護可能**であるよう設計されています。

### 2. 誰のためのものか、そして何の仕事のために使われるのか

**主なユーザー:** 調査報道ジャーナリスト、研究者、またはアナリスト — 一人で、あるいは小規模な編集部で働いていることが多く、
プライバシーに敏感で（守るべき情報源がある）、時には制限された環境やエアギャップ環境にいます。

**中核となる「片付けるべき用事（jobs-to-be-done）」:**
1. *「自分の調査に関係するものすべてを、多数の情報源から一か所に、自動で集めたい。」*
2. *「それをまとめて検索・相互参照したい — 記事、市場、メール — つながりを見つけるために。」*
3. *「大量のテキストを理解する手助けがほしい」*（要約、翻訳、エンティティ抽出）— **自分のデータを誰にも送らずに。**
4. *「信頼できるもの — あるいは疑うべきもの — を教えてほしい」*（メディアの検証、操作の指摘）。
5. *「これがどこから来たのか、そして自分が改ざんしていないことを証明したい」*（公表・法的手続きのための出所）。
6. *「何かが変わったら知らせてほしい」*（情報源が途絶えた、価格が急騰した、ナラティブが現れた）。

### 3. 指導原則（譲れない一線）

これらは意図の核心であり、すべての機能を制約しなければなりません。現在のコードがそのいずれかに反している場合、
それはトレードオフではなく欠陥です。

1. **ローカルファーストかつオフライン対応。** すべてユーザーのマシン／サーバー上で動作します。スクレイピングそのもの以外は
   インターネットなしで機能しなければなりません。エアギャップでの使用に適しています（データ／モデルを事前に用意すれば）。
2. **プライバシーの保護。** テレメトリなし。**ユーザーデータは決してマシンの外に出ない** — 特に LLM の処理
   （Ollama によるローカル処理のみ）。✅ 解決済み（§0）: フロントエンドのアセット（フォント、JS ライブラリ）はすべて
   **ローカルに同梱** — CDN 呼び出しなし — Qubes／オフライン方針のために必要です。
3. **100% FOSS。** すべてのコードとモデルがオープンソース。⚠️ DECIDE: ライセンスはルートでは **GPLv3**、
   Pillar 3 では **AGPL-3.0** — プロジェクト全体で一つに決めてください（AGPL はネットワーク利用についてより厳格です）。
4. **構造的に倫理的。** `robots.txt` とレート制限を尊重し、ボットであることを名乗り、公開データのみを扱い、
   ペイウォールの回避やスクレイピングへの認証情報の使用は決して行いません。**フェイルクローズ** — 準拠を確認できなければ、スクレイピングしません。
5. **擁護可能な出力（科学的 + 法的）。** すべての分析結果は正直な不確実性と追跡可能な出所を伴います。
   **捏造された数値はなし。** 信頼度スコアは実在の手法から導かれるか、さもなければ存在してはなりません。
   証拠保全の連鎖（チェーン・オブ・カストディ）は、単なるログファイルではなく、本物（署名済み、改ざん検知可能）でなければなりません。
6. **統合コーパス。** 取り込まれたものすべて — ニュース、金融データ、コモディティ、メール — は**一つのデータベース**に置かれ、
   **一つのクエリで相互参照可能**です。これがこのプロダクトの存在理由です。
7. **穏やかな失敗よりも透明性。** システムは決して黙って無効な出力へと縮退してはなりません。
   モデルがない、情報源がブロックされた、依存関係が利用できない → **目に見える、明示的なステータス**を示し、
   黙ってプレースホルダーを出すことは決してしません。

### 4. 中核となるメンタルモデル

```
        ┌─────────────────────────── INGESTION ───────────────────────────┐
        │  Web articles · RSS · Financial · Commodities · Email/Newsletters │
        │            (all ethically scraped / retrieved)                    │
        └───────────────────────────────┬───────────────────────────────────┘
                                         ▼
        ┌──────────────────── ONE UNIFIED, PROVENANCE-TRACKED STORE ────────┐
        │  articles · financial_data · commodity_data · emails · entities    │
        │  + links between them (article ↔ price move ↔ email ↔ entity)      │
        └───────────────────────────────┬───────────────────────────────────┘
                                         ▼
   ┌──────────── RETRIEVAL ────────────┐   ┌──────────── ANALYSIS (opt-in) ───────────┐
   │ Boolean / full-text search        │   │ Local LLM · verification · stats ·        │
   │ filters · cross-source correlation│   │ monitoring/alerts · correlation engines   │
   │ export (CSV/JSON) · reports       │   │ (every result: method + uncertainty)      │
   └───────────────────────────────────┘   └───────────────────────────────────────────┘
                                         ▼
                         GUI (search, dashboards, source mgmt, reports)
                         + REST API (everything available programmatically)
```

**背骨（取り込み → 統合ストア → 検索 → エクスポート）は、どのピラーよりも先に盤石でなければなりません。**
ピラーは共有ストアから読み取り、そこに書き戻す*付加機能（エンリッチャー）*です。

### 5. 機能範囲（機能領域別）

#### 5.1 データの取り込み（P0）
- **ソースの種類:** ニュースサイト（HTML）、RSS/Atom フィード。後に: API、ソーシャルプラットフォーム、ファイル投入。
  ⚠️ DECIDE: Pillar 4 には Twitter/X、Reddit、Telegram、Mastodon、S3/SFTP が挙がっています — どれが（もしあれば）
  実際の範囲で、どれが願望にすぎないかを確認してください。
- **倫理的スクレイパー（単一の共有実装）:** robots.txt の確認（キャッシュあり、http と https を区別、
  不確実な場合は**フェイルクローズ**）、ソースごとのレート制限、身元を示す User-Agent、リトライ／バックオフ。
  **URL ごとに取得は一回** — 二重取得なし、生のバイパス経路なし。
- **重複排除:** コンテンツハッシュ + 正規 URL に基づく。同じ記事を二度保存しない。
- **正規化:** タイトル、著者、公開日、言語、正規 URL、本文を確実に抽出する。
  ⚠️ DECIDE: 本格的なニュース抽出には、サイトごとのルールかライブラリ（例: trafilatura 方式）が必要です。
  現在の汎用 CSS による方法は、黙って「No Title/No Content」を生みます。堅牢な抽出を採用することを確認してください。
- **スケジューリングと増分更新:** 定期的な再スクレイピング、新規／変更されたコンテンツのみを取得、
  中断された実行の再開。

#### 5.2 統合データストア（P0）
- すべてのエンティティ型を保持する**単一のデータベース**。それらを結ぶ明示的な**リンクテーブル**を持つ
  （記事 ↔ 金融商品、記事 ↔ コモディティ、記事 ↔ メール、記事 ↔ 固有表現）。
- **すべてのレコードに出所フィールド:** ソース、取得タイムスタンプ、元の URL、コンテンツハッシュ、
  生データと処理済みデータの分離。
- **バックエンド:** 単一ユーザー／デスクトップには SQLite、サーバー／同時利用には PostgreSQL。
  ⚠️ DECIDE: SQLite をデフォルト + オプションの Postgres で確定してください（ドキュメントは両方に言及しています。
  キャッシュ用の Redis も — 入れるか外すか?）。
- **監査ログ:** すべての取り込みと変更を記録する、追記専用で**改ざん検知可能**な記録。

#### 5.3 検索と取得（P0）
- コーパス全体にわたる**全文検索**。
- **ブール演算子**（`AND`/`OR`/`NOT`）、**引用符付きフレーズ**、**正しい優先順位の括弧** —
  文字列の小細工ではなく、本物の文法か DB ネイティブの FTS で実装する。
- **構造化フィルタ:** ソース、日付範囲、言語、タグ／カテゴリ、エンティティ、データ型。
- **ページネーション**、結果のランキング、スニペット／ハイライト。
- **エクスポート:** CSV と JSON（そして ⚠️ DECIDE: PDF／レポート形式は?）。フィルタ済みの結果集合に忠実であること。

#### 5.4 相互参照と相関（P1 — 差別化要因）
- 任意のレコードから、種類をまたいで関連レコードへ移動できる（記事 → 言及された企業 → 公開日前後の値動き
  → 関連メール）。
- **相関エンジン**（金融／コモディティ ↔ ニュース）は、*候補となる*関係を**正直で定義された尺度**とともに示す
  （そして相関 ≠ 因果であることを明確に表示する）。捏造された p 値はなし。
- エンティティ中心のビュー: ある人物／組織／場所／金融商品についてコーパスが知っていることのすべて。

#### 5.5 ローカル LLM による分析（P1）
- **ランタイム:** Ollama、完全にローカル。モデルは差し替え可能。*実在する*小さく妥当なデフォルトを同梱する。
  ⚠️ DECIDE: 現在のデフォルト `gemma4:e2b` と、掲載されているモデルの大半（Gemma 4、Llama 4、Qwen 3.5）は
  幻覚（ハルシネーション）です — カタログを実在するタグ（例: `gemma2:2b`、`llama3.2:3b`、`qwen2.5`、
  `phi3`）に置き換えてください。
- **機能:** 生成、チャット（コンテキスト付き）、抽出（エンティティ／キーワード／要約／引用／リンク）、
  翻訳（多言語）、分析（感情／トーン／読みやすさ。バイアスは正直に範囲を限定できる場合のみ）、
  統合（要約、比較、年表、レポート）、バッチ。
- **大きな声で縮退する:** Ollama やモデルがない場合はそう伝える — 偽の分析は決して返さない。

#### 5.6 検証と欺瞞への防御 — *Pillar 3*（P2、範囲は未定）
- **意図:** 操作されたメディア（画像／動画／音声のディープフェイク）、プロパガンダの手法、認知バイアス、
  ボット、組織的なキャンペーンを検出する。メタデータ（EXIF/ID3）とモダリティ間の一貫性を検証する。
- ⚠️ DECIDE（重要）: 現時点でこれは**捏造**です — 「ディープフェイク CNN」は推論を一度も実行せず、スコアは
  ぼかしのヒューリスティックにすぎず、バイアス／プロパガンダの対応範囲の大部分には到達できず、「精度 >95%」は願望です。
  次のいずれかを選んでください:
  - **(a) 削除** — メディアフォレンジックは当面やめ、正直なものだけを出す（メタデータ／EXIF の検証は本物で
    有用）。**(b) 再構築** — 本物で評価済みの FOSS モデルと公表された精度で作り直す。または
    **(c) 維持** — ただし**「実験的ヒューリスティックであり、証拠ではない」と明確に表示する。**
  私の推奨: 今は (a)、後で (b)。捏造されたフォレンジックは、ジャーナリズム／法的用途のツールにとって最大の負債です。

#### 5.7 科学的厳密性 — *Pillar 2*（P1）
- **意図:** プラットフォームの定量的な主張を擁護可能にする — 本物の統計検定、信頼区間、

### 6. 非機能要件

- **プラットフォーム:** ✅ 解決済み（§0）— **Qubes OS の Debian AppVM** が v1 で*唯一*サポートされる対象です
  （そこでビルド・テストされる）。素の Debian 13 でも動く可能性はありますが目標ではなく、クロスプラットフォームの約束はしません。
- **Python:** ✅ 解決済み（§0）— **3.13** を、`pyproject.toml`、`.python-version`、
  あらゆる CI で一貫して使用。3.13 の wheel がない依存関係は外す（§0.2 参照）。
- **インストールの規模:** 真の**最小限のコア**（Web + DB + 検索、軽量）を、オプションの
  extras（`[llm]`、`[analysis]`）から分離可能にする。`pyproject.toml` は**一つ** — 食い違う六つのマニフェストではなく。インストーラは
  Qubes の永続性（§0.1）を尊重する: システム依存関係は TemplateVM に、venv とデータは `/home` に。
- **セキュリティ:** ✅ 解決済み（§0）— 単一のローカルユーザー、**ループバックのみ**なので RBAC なし。それでも必須:
  パラメータ化された DB アクセスのみ（ブロックリスト方式の「サニタイザ」は削除）、コード内に秘密情報を置かない、ループバックの `/metrics`、
  そして**安全なインストーラ**（確認なしの `rm -rf` 禁止、未検証の `curl | sh` 禁止、パッケージの stderr を決して捨てない）。
- **パフォーマンス:** ネットワーク／LLM 処理にはノンブロッキング I/O。並行数は上限付き。スクレイピングや推論の間も
  アプリは応答性を保つ。**CPU のみ**を前提とする（Qubes には GPU なし）。目標値は願望ではなく、現実的な AppVM の
  リソースに即して定める。
- **オフライン:** すべてのアセット、フォント、（事前取得した）モデルはローカル。データ／モデルの取得後に
  NetVM を切り離した状態で運用する手順を文書化する。
- **可観測性:** 構造化ログ（`/home` の下）、正直なヘルスチェック、ループバックの Prometheus メトリクス —
  実際の状態を反映するもの。

### 8. データ、出所、法的擁護可能性のモデル（横断的）

|---|---|---|

### この段階で救出したもの（Pillar 2）
- `src/analysis/statistical_tests.py` — t 検定、ANOVA、カイ二乗、Pearson/Spearman、

  統計量、p 値、自由度、効果量、標本サイズを伴います。
- `src/analysis/confidence_intervals.py` — 平均と比率（t／正規／Wilson／
  Clopper-Pearson／Agresti-Coull）。
- `POST /api/analysis/{t-test,correlation,anova,mann-whitney,confidence-interval}` で公開され、

  5/6 のスキャフォールド — 捏造または設計のみ。正直な部分はすでに `src/` にあります。

結果は洗練され、美しく、適応性があり、高度にカスタマイズ可能で、シンプル*かつ*奥深く、そして
同僚が肩越しにちらりと見て*「これは何？ 私ももらえる？」*と言うほど良いものでなければなりません。
プロジェクトがすでにそうであるもの — **単一ユーザー、ループバックのみ、
オフラインファースト、依存関係なし、テレメトリなし**、そして**ミュンヘン憲章**
（真実、情報源の検証、プライバシー、プロパガンダの拒否）に従うこと — を尊重しなければなりません。

#### エンジニアリングの立場（と正直なトレードオフ）

以前の UI は 2,200 行の単一の `index.html` で、約 110 の関数を約 150 の
API エンドポイントに結びつけていました。それらの関数は*動作し、テストされています*。ゼロからの書き直しは、
見た目はより美しいが、ボタンが黙って壊れている可能性の高い殻を生んでいたでしょう — それは、
**正直さ**こそが唯一の売りであるツールにとって、まさに正反対のことです。したがってこれは
**ユーザーが目にし触れるすべての全面的な再設計**です — ビジュアル言語、
レイアウト、ナビゲーションモデル、情報アーキテクチャ、命名、オンボーディング、
カスタマイズ、そして二つのまったく新しい画面（ホームのダッシュボードとアプリ内のドキュメント
リーダー）— を、*実証済みのデータ層の上に*構築し、元の要素 ID をすべて
保持して何も退行しないようにしています。依存関係なしは絶対のままです: **CDN なし、Web
フォントなし、フレームワークなし** — NetVM を切り離した状態で動く、自己完結した一つのファイル。

### 2. 設計原則（借り物ではなく、導き出したもの）

1. **巧妙さより明快さ。** 平易な動詞、人間的なラベル、画面ごとに明らかな主要
   操作を一つ。専門用語（「取り込み（ingest）」「コーパス」「Merkle ルート」）は言い換えるか
   その場で説明し、決して前提にしない。
2. **信頼こそがプロダクト。** 検証可能性、出所、そして「この数値は推定ではなく本物」であることは、
   埋もれさせずに表に出す。見た目は玩具ではなく計測器のように*感じられる*べき。
3. **段階的開示。** デフォルトはシンプル、奥深さはワンクリック先。高度な
   パネルは折りたたまれ、めったに使わないモジュールは完全に隠せる。
4. **カスタマイズ可能に、なぜなら信頼は個人的なものだから。** テーマ、アクセント、密度、フォントサイズ、
   レイアウト、そして*どのツールがそもそも表示されるか*はユーザーが設定するもの — そして
   ローカルにのみ保存される。
5. **インターフェースにおける正直さ。** ある機能がオプションの extra に依存するなら、
   UI はそれを偽らずにそう伝える。成功を装うものは何もない。
6. **構造的に主権的。** いかなる種類の外部リクエストもしない。見た目は
   システムフォントと手作りの SVG アイコンで実現する。
7. **キーボードファーストはアクセシビリティファーストでもある。** コマンドパレットとショートカットは
   Daniel に仕える*と同時に*、正確なマウス操作なしでアプリ全体に到達できるようにする。

### 4. 「すごい」— ジャーナリストが身を乗り出す理由

- **首尾一貫したビジュアルシステム。** デフォルトは深い「インク（ink）」のダークテーマで、自信のある
  単一のアクセント、ゆとりある余白のリズム、本物のタイポグラフィの階層、データ／ハッシュには
  等幅フォント、柔らかな奥行き、そして控えめな動き。*ダッシュボードのテンプレート*ではなく
  *計測器*として読める。
- **コマンドパレット（Ctrl/⌘-K）。** 入力してどこへでも移動し、あらゆる操作を実行し、
  あらゆるドキュメントを開ける。Daniel にとっては力、Amara にとっては「ここでそもそも何ができるの？」の地図。
- **外観のコントロール**（設定 → 外観。0.06 まではライブのドロワーで、0.07 で設定に
  統合）。テーマのプリセット（Ink、Slate、Midnight、Paper、Sepia、
  Terminal、High-contrast）、アクセントの見本、密度、フォントサイズ、サイドバーの折りたたみ、
  そして**モジュールの表示／非表示** — すべて即時、すべてローカル、すべて永続。
- **道案内をするホーム**、教えてくれるオンボーディング、導いてくれる空の状態。
- **目に見える信頼。** 保全／検証と「推定ではなく計測」という
  枠組みは、細則ではなく美観の一部。
- **完全なオフラインの完全性。** UI の枠組みのためのネットワーク呼び出しは一切なし — それ自体が、
  セキュリティ意識の高い同僚に*見せられる*機能です。

### 5. カスタマイズのモデル

見た目と操作感は `localStorage`（`oo.ui`）に保存されます — どこにも送られません — そのため
即時で、オフラインでも保持されます。機能的な設定（デフォルトの結果件数、基本
テーマ）は引き続き `/api/settings` を通じてサーバー側に保存されます。カスタマイズ可能なもの: テーマ
プリセット、アクセントカラー、密度、フォント倍率、サイドバーの状態、表示する
モジュールの集合。妥当なデフォルトがあるので、初回起動のユーザーはどれにも触れる必要がありません。

### 6. 意図的に**しなかった**こと（正直さ）

- **フレームワーク／ビルド工程／CDN はなし。** 見た目のための得と引き換えに、オフラインで監査可能で主権的な
  理念を壊すことになるため。バニラ、単一ファイル、システムフォント、手描きの SVG。
- **捏造された機能はなし。** すべてのボタンは本物の、動作するエンドポイントに対応します。オプションの
  extra に依存する機能は、引き続きそのことを伝えます。
- **黙ったバックエンドの変更はなし。** ただし、ヘルプリーダーを動かすための、追加的で読み取り専用の、許可リスト方式の
  ドキュメントエンドポイント（`/api/docs`）を除きます。
- **自由入力の言語欄は自由入力のまま**（OPEN_QUESTIONS ですでに記録済み）。
  再設計は、バックエンドが裏付けられないドロップダウンを作り出しません。

### 0. まず、このアプリが実際に何であるかに立ち返る

UI の枠組みについて議論する前に、譲れない一線（`ETHICS.md`、
`DESIGN.md`、ミュンヘン憲章から）:

- **一人のユーザー、一台のマシン、ループバックのみ、オフラインファースト。** アカウントなし、クラウドなし、
  テレメトリなし。多くの場合、ネットワーク qube を*切り離した*状態の Qubes AppVM で動かされる。
- **コンピュータが好きではない、真実を求める工作員。** 仕事が*現実を理解し、それを信頼できる形で伝えること*である
  調査員／ジャーナリスト。
- **プロダクトは信頼である。** 出所、情報源の検証、「推定ではなく計測」、
  改ざん検知。ミュンヘン憲章（真実、情報源の検証、情報源の保護、
  プロパガンダへの抵抗）が背骨。
- **美観としての主権。** ツールは、プラットフォームではなくユーザーのものであると*感じられる*べき。

どのインターフェースも、「2025 年の SaaS 製品のように見えるか」ではなく、*これら*に照らして評価されなければなりません。

### 1. 「Console」（0.05 の再設計）に対する告発状

0.05 が間違った方向であるという主張を、最も強い形で組み立てると:

1. **主権的なツールに、監視資本主義の服を着せている。** 常設の
   左サイドバー、ステータスピル、コマンドパレット、八つのテーマを持つカスタマイズ用ドロワー
   — これは Slack、Linear、Notion の視覚文法、つまり*クラウド SaaS* です。巨大テック企業を
   信用せず機微な記事を扱うユーザーにとって、その文法は「また自分を監視するアプリだ」と
   読める可能性があり、ここで最も重要な一つのもの — 信頼 — を損ないます。見た目が価値観と戦っています。

2. **仕事ではなくデモに最適化している。** 依頼には「ジャーナリストに
   *私ももらえる？*と言わせる」が含まれていました — 肩越しの 5 秒間の反応です。
   それを狙って設計すると、ダッシュボードの派手さ（グラデーション、アニメーションするカウント、
   テーマの動物園）へと引き寄せられ、調査の静かで、読むことが中心で、文書中心の現実から
   遠ざかります。深い仕事のための最良のツール（テキストエディタ、ノート）は*簡素*です。
   Console は印象的で、そして浅いのかもしれません。

3. **カスタマイズは、贈り物に見せかけた税金である。** 八つのテーマ、アクセントの見本、
   密度、フォント倍率、モジュールごとの非表示。*Amara*（コンピュータが好きではない）にとって、
   そのどれもが望んでいなかった決断であり、ツールを誤設定する道です。
   「高度にカスタマイズ可能」は依頼の文言と*設計者*の考える寛大さに応えたものでした
   — しかし本当にシンプルなツールは**意見を持っています**: ユーザーがしなくて済むよう、
   正しい判断を下すのです。選択は認知負荷です。

4. **情報アーキテクチャは依然としてユーザーのものではなく、ソフトウェアのもの。** Console は
   タブの名前を変えて再グループ化しましたが、メニューは依然として*モジュール*の一覧です
   （検索、情報源、インサイト、マーケット、保全…）。Amara はモジュールで考えません。
   彼女は**案件**で考えます: 「この記事を追っている — 集め、読み、つなげ、証明し、
   公表する。」0.04 も 0.05 も、ユーザーに自分の*仕事*をアプリの*機能*へ
   翻訳させます。九つの行き先を持つ常設のナビゲーションは、コードベースの地図です。

5. **UI の枠組みがコンテンツと競合する。** 固定のサイドバー + 上部バーは、
   *ユーザーがセッションあたり 2 秒しか使わないナビゲーション*のために、
   約 250px と横一列の帯を恒常的に消費します。ユーザーが実際にしていること — 記事を読む、結果に目を通す、差分を
   比較する — には残り物しか回りません。調査とは読むことであり、Console は読むことに十分に
   仕えていません。

6. **「すごい」は借り物であり、勝ち取ったものではない。** パレットとテーマは現代のアプリでは
   *当たり前の要件*です — 見慣れているからこそ印象的なのです。ここで本当に
   差別化となる「見たことがない」機能は*中身*です:
   オフラインの Wikipedia 編集合戦の検出、改ざん検知可能な保全、「すべての数値は
   本物の COUNT(\*)」。Console は飾り立てますが、本当に独自なものを劇的に見せてはいません。

これは深刻な告発です。反論ではなく、本物の代替案に値します。

---

### 2. Console の弁護（議論を公平にするために）

- 常設のナビゲーションは**発見しやすい**: 何も隠されておらず、これはツールに何ができるかを
  まだ知らない初心者にとって重要です。ハブ・アンド・スポーク型のモデルは、
  力をクリックと推測の向こうに隠します。
- カスタマイズは**オプトアウト**: デフォルトは妥当で、ドロワーを無視するユーザーは
  何も失いません。そしてテーマは、仕事につきものの目の疲れや深夜作業という現実に、また
  *実際の*ユーザーのアクセシビリティ（ハイコントラスト、文字サイズ）に本当に役立ちます。
- 「SaaS の文法」は単に**現在のユーザビリティの慣習**でもあります — 人々は初日から使い方を
  知っています。新しさのための新しさには、それ自体の税金があります。
- それでも**100% オフラインで依存関係なし**です。文法は借り物ですが、
  中身（ネットワークなし、テレメトリなし）は借り物ではありません。

どちらの立場も正当です。それを解決する方法は議論を重ねることではなく —
**アンチテーゼを作り、両方を使ってみること**です。

---

### 3. アンチテーゼ: 「Desk」

Console が**幅広い運用コンソール**（すべてが常にワンクリック先、
最大限に柔軟、現代的なアプリの文法）だとすれば、**Desk** は正反対のテーゼです:

> **調査員の机: 穏やかで、意見を持ち、コンテンツファーストで、タスクを軸にした枠組み。
> UI の枠組みはほとんどない。一度に一つの仕事。インターフェースは読むことと考えることの
> 邪魔をしない。**

Desk が意図的に Console と*異なる*具体的な約束:

| 観点 | Console（テーゼ） | Desk（アンチテーゼ） |
|---|---|---|
| ナビゲーション | 常設の左サイドバー（常に表示） | **常設のナビゲーションなし。** ナビゲーションは*必要なときだけ* — 穏やかなホーム、「移動…」オーバーレイ、そして ⌘K。UI の枠組みは呼び出されたときだけ現れる。 |
| 入口 | ステータスのダッシュボード | **仕事を軸にしたホーム:**「何に取り組んでいますか？」→ 集める · 見つけて読む · つなげる · 検証して共有する。アプリのモジュールではなく、ユーザーのタスクで枠づける。 |
| カスタマイズ | 8 つのテーマ、アクセント、密度、フォント、モジュールのトグル | **テーマは二つだけ**（Paper / Ink）、つまみなし。意見を持つ。ツールが決めるので、あなたは決めなくてよい。 |
| 美観 | 現代的なアプリのコンソール（サンセリフ、ピル、グラデーション） | **編集／印刷物:** セリフ体の見出し、紙の温かみ、ゆとりある余白、読みやすい行長。SaaS ではなく編集部のように感じられる。 |
| 何が場所を得るか | ナビゲーション + ステータス、その後にコンテンツ | **コンテンツ。** 中央に一本の読み物カラム。表と記事リーダーが場所を得る。 |
| 信頼のシグナル | ステータスピル | 常設の控えめな **「ローカル · オフライン · 何もこのマシンから出ない」** の一行 — 主権を暗示するのではなく明言する。 |
| デモでの反応 | 「洗練されてる！」 | 「…ああ、これは*穏やか*だ。そして全部自分のものだ。」よりゆっくりで深い種類の「すごい」。 |

Desk が**維持する**もの（UI の枠組みではなく、アプリの要点だから）: すべての機能
とすべての動作するエンドポイント。Desk と Console はまったく同じエンジンと
同じコンテンツパネルを共有します — 違いは*殻、ナビゲーションモデル、情報アーキテクチャの枠組み、
美観だけ*です。これは意図的です: 実験を統制された状態に保つことで、比較しているのが
**哲学**であって、たまたま私がどちらをより丁寧に配線したかではないようにするためです。

### 4. どう評価するか（評価基準）

それぞれを、「どちらが見た目がいいか」という直感ではなく、価値観に照らして採点してください:

1. **信頼** — どちらが自分のものであり、自分を裏切らないと*感じられる*か？
2. **穏やかさ対能力** — どちらが考えさせてくれるか？ どちらが力を見つけやすくしているか？
3. **初心者の道筋** — *Amara* を予備知識なしで放り込む: どちらがより速く、より少ない恐れで
   結果に到達させるか？
4. **パワーユーザーの道筋** — キーボードを使う *Daniel*: どちらが彼の邪魔をしないか？
5. **読むこと** — それぞれで長い記事／Wikipedia の差分を開く。どちらがより良い
   *読む*場所か？
6. **5 秒テスト** — 同僚にそれぞれを見せる。どちらが「私ももらえる？」を引き出すか —
   そしてそれは、本当に最適化したい反応なのか？
7. **理念との適合** — Qubes の保管庫で、ネットワークを切り離して動かすことを信頼できるのは
   どちらか？

### 5. 予想される長所／短所（私の正直な賭け、検証待ち）

**Console** — *長所:* 発見しやすい、慣習的、柔軟、アクセシブルなつまみ、デモでの
輝き。*短所:* UI の枠組みが重い、決断の負荷、信頼を損ないかねない汎用 SaaS 的な感触、
情報アーキテクチャが依然としてモジュール中心。

**Desk** — *長所:* 穏やか、コンテンツ／読むことファースト、意見を持つ（設定の税金なし）、
タスクを軸にした入口、主権と信頼を*強化する*美観。*短所:*
力が一回の呼び出し（クリック／キー入力）の先にある、アクセシビリティのつまみが少ない、
すぐには「印象的」でない、新しさには小さな学習コストがある。

---

### 6. 私の推奨（総合 — 暫定、あなたの検証待ち）

正解は**純粋な Console でも純粋な Desk でもなく**、Desk の*価値観との適合*と
Console の*発見しやすさ*に寄りかかる総合だと予想しています:

- **Desk のタスクを軸にしたホームと編集的な穏やかさ**をデフォルトの雰囲気として採用する。仕事の
  枠組み（「集める／読む／つなげる／検証する」）は、「情報アーキテクチャがコードベースそのもの」という
  批判への唯一最大の修正です。
- **カスタマイズに対する Desk の抑制を採用する:** 優れたテーマを二つ
  （Paper/Ink）+ アクセシビリティのための文字サイズのコントロールを同梱し、アクセント／
  密度／モジュール非表示の乱立は**削る**。ここでは、意見を持つことが設定可能性に勝ります。
- **発見しやすさのために、Console の*控えめで折りたたみ可能な*ナビゲーションを残す** — ただし
  デフォルトでは折りたたみ、コンテンツが先導し、ナビゲーションは必要なときにそこにあるようにする。
- **⌘K を残す**（初心者とパワーユーザーの両方に仕え、本当に役立つ）。
- **UI の枠組みではなく、中身を劇的に見せる:** 保全、オフラインの Wikipedia、
  「本物の件数」を視覚的な主役にする — それが勝ち取った「すごい」です。
- **信頼の一行をあらゆる場所の先頭に**（「何もこのマシンから出ない」）。それが
  ブランドです。

しかし、それは仮説です。両方を動かし、§4 に照らして採点し、現実が私の賭けからどこで
外れたかを教えてください — そうすれば、その評決を一つの 0.06 にまとめます。

> **最終評決（メンテナー、2026-06-10、実際の使用後）:** この弁証法は
> 決着しました — **Desk は完全に廃止。インターフェースは一つ: Console**（`/`）。
> 二つのアイコンは役立つよりも混乱を招きました。Desk の縮小されたツールセットは、
> 出荷済みの機能（時間地図、アジェンダ）を迷子のように見せました。そして Console はすでに
> ウィンドウサイズに滑らかに適応します（サイドバーはアイコンレールへと格納されます）。
> `desk.html` ファイルは削除され（git の履歴に残っています）、`/desk` は今では
> `/` にリダイレクトします。Desk の最良のアイデア — タスクを軸にしたホーム、⌘K、編集的な
> 穏やかさ — は、上記 §6 に従い、時間をかけて Console に取り込まれるべきです。

### 7. 両方を同時に動かす

両方のインターフェースは、同じデータに対して同じローカルバックエンドから提供されます:

- **Console** → `http://127.0.0.1:8000/`（デフォルト）
- **Desk** → `http://127.0.0.1:8000/desk`

インストーラは**二つのデスクトップアイコン** — *Open Omniscience*（Console）と
*Open Omniscience — Desk* — を作成するので、どちらかを起動することも、両方のウィンドウを一緒に開いて
同一のデータでタブごとに比較することもできます。勝者を選んでください（あるいは
総合を求めてください）。そうすれば 0.06 で一つに戻します。

## コンテンツ分析の戦略 — リンク、画一性、そして元の情報源

> [`ROADMAP.md`](archive/roadmaps/DESIGN_MEMORY_pre-0.2.md) にあるビジョンのための、具体的で段階的な戦略:
> 記事の**リンク**を使って同じことについて語っているものを集め、メディアの
> **画一性**を浮かび上がらせ、情報をその**元の情報源**までたどる — その間、
> **ユーザーが主導権を持ち**、分析は**透明でローカル**であり続け、ツールが
> 真実の裁定者になることは決して許さない（ミュンヘン憲章）。全体を通じて
> オープンソースかつオフライン。

---

### 0. 現在地（正直なステータス）

記事リンクの検出は**骨組みはあるが配線されていません**:

- ✅ **`src/services/link_analyzer/extractor.py`**（`LinkExtractor`）— HTML から
  リンクを抽出し、URL を正規化し、アンカーテキスト + 位置を追跡し、リンクの*種類*
  （内部／外部／画像／…）を分類し、リンクの統計を生成する。約 500 行、単体テスト向きの形。
- ✅ **DB スキーマ** — `ArticleLink`（url、normalized_url、link_text、position、
  link_type、**classification** = source/reference/ad/social/navigation、
  `external_source_id`、`source_article_id`、is_working、http_status…）、
  `ExternalSource`、`LinkClassificationRule`。リレーションシップは整っている
  （`Article.links`、`ExternalSource.links`）。
- ✅ **取り込み時に呼び出される** *（完了 — P0）* — `src/ingest/pipeline.py:_maybe_index_links`
  が外向きの**外部**リンクで `article_links` を埋める（ベストエフォート、フェイルオープン。
  内部／画像／広告／ソーシャル／トラッカーは `ROADMAP.md` に従い除外。重複排除 + 上限あり）。
- ✅ **API** *（完了 — P1）* — `src/api/link_analysis.py`（`/api/links`）: `stats`、
  `top-cited`（url|domain 別、期間指定）、`articles-by-link`（url|domain 別）。件数
  のみ。何もスコア化も判定もされない。
- ❌ **UI はまだない** — リンクグラフに対するインサイトのビューはない（P2、後述）。

つまり P0/P1 は配線済みで、残る作業は UI とより深い分析（P3/P4）です。

### 1. 中核となる考え: リンクは引用グラフである

各記事をノードとし、各外向きリンクを URL（および
そのドメイン）への有向エッジとして扱います。そのグラフは、あなたが尋ねたことにまさに答えます:

- **「同じリンクについて語っている記事をすべて集める。」** = 記事を、
  それが引用する外部 URL でグループ化する → その URL の**入次数**は「自分の記事のうち何本が
  ここを指しているか」。入次数が高い = **ハブ**: 多くの場合、一次資料、通信社の記事、または
  よく議論される参照先。
- **「内部リンクを通じてトレンドを発見する。」** = 入次数を時間とともに観察する。引用が急増する URL や
  ドメインは、単なるキーワードの頻度ではなく、記者が実際に引用しているものに根ざした*トレンド*です。
- **「元の／最初の情報源をたどる。」** = 一つの記事をめぐる記事のクラスタの中で、元の情報源とは、
  他の記事が**リンクする**ノード、かつ／または最も早いもの、かつ／または**一次資料**
  （裁判所／政府／データセット）を引用しているものです。リンク + タイムスタンプ + 通信社の
  クレジットが、それを三角測量します。

これは*共引用分析*です — 安価で、透明で、説明可能。ブラックボックスなし。

---

### 2. 段階的な戦略（それぞれ単独で出荷可能）

#### P0 — 抽出器を取り込みに配線する（グラフを存在させる）
- 取り込み中に取得した HTML に対して `LinkExtractor` を呼び出し、外向きの
  **外部**リンクを `article_links` に永続化する（内部ナビゲーション、広告、そして —
  `ROADMAP.md` に従い — 画像／バイナリのリンクはスキップ）。normalized_url + アンカーテキスト + 種類を保存する。
- 可能な場合、各外部リンクのドメインを既知の `Source`/`ExternalSource` に対応づける
  （「誰が誰を引用しているか」をメディアや**所有者**の単位に集約できるように）。
- 安価で、決定的で、オフライン。取り込みがすでに取得したもの以外は何も取得しない。

#### P1 — 集計 + API（ユーザーの問いに答える）
グラフに対する読み取り専用のエンドポイント:
- **`top-cited`** — ある期間で最も引用された URL／ドメイン（トレンドのシグナル）。
- **`articles-by-link`** — ある URL／ドメインについて、それを引用しているコーパス内のすべての記事
  （「同じリンクについて語っている記事をすべて集める」）。
- **`link-graph`** — ある話題や期間についてのノード／エッジ。可視化用。
- **`co-citation`** — *同じ*外部情報源を引用している記事（「同じ記事」の
  クラスタ候補）を、重なりの件数とともに。

#### P2 — UI: インサイト内の「リンクと情報源」ビュー
- **最も引用されたリンク／ドメイン**のランキング一覧（クリック → それを引用しているすべての記事）。
- 小さなズーム可能な**引用グラフ**（インサイトの地図ですでに使っている SVG の手法を
  再利用 — 新しい依存関係なし）。
- 常に**標本サイズ**を示す（「あなたの記事 14 本が引用」）— 推測ではなく
  計測。ユーザーがクリックし、探索し、判断する。

#### P3 — 元の情報源の系譜
一つの記事をめぐる記事のクラスタについて、シグナルで順位づけした**系譜**を提示する
（それぞれを示し、どれも決定的ではない）:
- 入次数（他の記事から誰がリンクされているか）、
- 最も早い公開タイムスタンプ、
- 通信社のクレジット（AFP/Reuters/AP — すでに `wire-agency` のタグを付けている）、
- **一次資料**（政府／裁判所／データセット／プレプリント）へのリンクの有無。
出力: ユーザーが読む連鎖としての「一次資料 → 最初の報道 → 反響」。

#### P4 — 画一性と反響（メディア集中に結びつく）
- **ほぼ重複の検出**（安価な MinHash/SimHash）で、配信記事やコピーされた文章を
  メディアをまたいでフラグ付けする — `src/ingestor/duplicate_detector.py` を土台とする。
- **反響スコア**: 多くのメディアが**一つ**の情報源を引用する（あるいは狭いループの中で互いを引用する）
  クラスタで、独自のリンクがほとんど加わっていない = 反響が大きい。多様な一次資料の
  引用 = 独立した報道。
- **集中度のオーバーレイ**: 反響を**所有関係**で重みづけする — 反響しているクラスタが
  一つの所有者／ブロックに対応するなら（「約 7 人の億万長者が約 90% を所有する」ケース）、それを浮かび上がらせる。
  `ROADMAP.md` に従い、所有関係のグラフ（Wikidata P127/P749 + 手作業）が必要。

---

### 3. ユーザーに主導権を持たせ続ける（譲れない一線）

- **浮かび上がらせ、決して抑え込まない。** 反響／系譜のスコアは*表示され並べ替え可能*。ツールは
  情報源を決して隠したり自動的に格下げしたりしない。重みを下げることは、明示的で元に戻せる
  ユーザーのコントロールであり、**デフォルトではオフ**。
- **真実のラベルはなし。** 「最初に見たもの」／「最も引用されたもの」≠「真実」。示すのは構造
  （誰が最初に言ったか、誰が誰を引用しているか、誰が誰を所有しているか）であり、そこで止まる。
- **すべてが説明可能でローカル。** あらゆる数値は、ユーザーが調べられる行にたどれる。
  外部呼び出しなし、ML のブラックボックスなし（ハッシュ化 + カウント + グラフの次数）。
- **オープンソースで監査可能。** 純粋関数、単体テスト可能、分類ルールはユーザーが
  編集できるデータ（`LinkClassificationRule`）の中にある。

---

### 4. リスクと正直な限界

- リンク抽出の質は、取得した HTML の質に左右される（ペイウォールや JS がそれを制限する）。
- アンカー／引用の慣習はさまざま。リンクのない「X によると」は見落とされる（
  後の NLP 処理が役立つ可能性はあるが、まずはシンプルに始める）。
- 所有関係のデータは断片的で古い — 推測ではなく、出典を示せるものでなければならない。
- コーパス規模でのほぼ重複検出は、一台のマシンで安価に保つための配慮が必要（ハッシュ化、期間を区切った
  比較）であり、O(n²) の全文比較ではない。

### 5. 推奨する最初のコミット

設定の背後で **P0**（取り込み時に `article_links` を埋める）を配線し、**P1 の
`articles-by-link`** と **`top-cited`** エンドポイント、そして最小限のインサイトの一覧を追加する。それ
だけで「同じリンクを引用しているすべての記事を集める」ことと引用に基づく
トレンドが実現します — 本物の価値を持つ最小のスライスであり、理念に完全に沿ったものです。
