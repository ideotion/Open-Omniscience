## 📜 ミュンヘン憲章：義務と権利の宣言

### 前文
情報を得る権利、表現と批判の自由は、人類の基本的権利の一つです。Open Omniscience を利用する者のすべての権利と義務は、出来事と意見について知らされる公衆の権利に由来します。公衆に対する利用者の責任は、他のあらゆる責任、とりわけ雇用者や公権力に対する責任に優先します。情報という使命には、利用者が自ら進んで自らに課さなければならない制約が必然的に含まれます。これが、以下に定める義務の宣言の目的です。

Open Omniscience の利用者がその利用にあたってこれらの義務を尊重できるのは、独立性と職業上の尊厳という条件が実際に存在する場合に限られます。これが、以下の権利の宣言の目的です。

### 📋 義務の宣言
情報の収集、編集、分析に携わる Open Omniscience の利用者の本質的な義務は、次のとおりです。

1. **真実の尊重：**
   公衆が真実を知る権利のゆえに、自らにどのような結果が及ぼうとも真実を尊重すること。

2. **情報の自由の擁護：**
   情報、論評、批判の自由を擁護すること。

3. **情報源の確認：**
   出所が判明している事実のみを報じること。本質的な情報を隠したり、文章や文書を改変したりしないこと。

4. **公正な手段：**
   情報、写真、文書を入手するために不公正な手段を用いないこと。

5. **プライバシーの尊重：**
   プライバシーの尊重を自らに課すこと。

6. **不正確な情報の訂正：**
   公表した情報が不正確であると判明した場合は、それを訂正すること。

7. **職業上の秘密：**
   職業上の秘密を守り、秘密裏に得た情報の情報源を明かさないこと。

8. **職業上の重大な違反の回避：**
   次のことを職業上の重大な違反とみなすこと。
   - 盗用
   - 中傷、誹謗、名誉毀損、根拠のない告発
   - 情報の公表または隠蔽の見返りとして、いかなる形であれ賄賂を受け取ること

9. **広告・宣伝活動との分離：**
   Open Omniscience の利用を広告販売や宣伝活動と決して混同せず、広告主からの直接的・間接的な指示をすべて拒否すること。

10. **圧力への抵抗：**
    あらゆる圧力に抵抗し、本プラットフォームの倫理的な利用に沿った責任ある者からの指示のみを受け入れること。

### 📜 権利の宣言

Open Omniscience の利用者は、次の権利を主張します。

1. **情報への自由なアクセス：**
   あらゆる情報源への自由なアクセスと、公共生活を左右するあらゆる出来事を自由に調査する権利。したがって、公的または私的な事柄の秘密を利用者に対して主張できるのは、例外的な場合に限り、かつ明確に示された理由がある場合に限られます。

2. **非倫理的な従属の拒否：**
   Open Omniscience の基本方針に反するあらゆるものへの従属、およびこの方針に明確に含まれないあらゆる従属を拒否する権利。

3. **良心と信念：**
   利用者は、自らの信念や良心に反する行為を行うこと、または意見を表明することを強いられることはありません。

4. **意思決定の透明性：**
   コミュニティは、プロジェクトに影響を及ぼしうるすべての重要な決定について知らされなければなりません。プロジェクトの方向性に関わるあらゆる事柄について最終的な決定が下される前に、少なくとも意見を求められるべきです。

5. **公正な報酬と独立性：**
   その職務と責任を考慮し、貢献者は、自らの仕事の物質的・精神的な安定と経済的な独立を保証する評価と条件を得る資格があります。

## 🌍 Open Omniscience の基本原則

1. **情報源の規約の尊重：** スクレイピング対象のウェブサイトの `robots.txt` の指示と利用規約を常に遵守すること。
2. **レート制限：** 単一の取得経路（`EthicalFetcher`）は、ホストごとの最小リクエスト間隔を強制し、
   ホストごとのロックを取得するため、特定のホストへのリクエストが同時に複数実行されることはありません。
   - デフォルト：**ホストあたり毎秒 1 リクエスト** — `EthicalFetcher` の `min_interval_s` で、
     環境変数 `OO_FETCH_MIN_INTERVAL` から設定されます。
   - ホストの `robots.txt` が **`Crawl-delay`** を公開している場合はそれに従います。
     実際の間隔は `max(min_interval, Crawl-delay)` です。
   - （`sources.yml` の情報源ごとの `rate_limit_ms` はデータフィールドであり、取得処理の間隔には
     **接続されていません**。実際に速度を抑えているのは上記の 2 つの仕組みです。）
3. **透明性：** 取得の記録は、運用者自身が確認するためにローカルに保存されます —
   情報源・フィードごとの判定は `data/source_preflight.jsonl` と
   `data/feed_preflight.jsonl` に、フィールドテストの結果は `data/field_test.jsonl` に、
   アプリのエラーは `data/app_errors.jsonl` に記録されます。これらはマシン上にとどまり、
   **クリックしたときにのみ**、設定 → 診断の**デバッグバンドル**にまとめられます —
   自動送信されることは決してありません。（`audit/scrape_log.csv` は存在しません。それは初期の設計で、
   ローカルファースト・テレメトリーなしの方針に置き換えられました。）
4. **データの最小化：** プラットフォームの中核機能に必要なデータ（URL、タイトル、本文、メタデータ）のみを収集・保存すること。
5. **悪意のない利用：** Open Omniscience を次の目的に使用してはなりません。
   - スパムや嫌がらせ。
   - 違法行為（例：ハッキング、著作権侵害）。
   - 許可のない商業的利用。
6. **User-Agent による識別：** 明確で識別可能な User-Agent 文字列を使用すること。ボットは
   `OpenOmniscienceBot/{version} (+https://github.com/ideotion/Open-Omniscience; ethical research crawler)` を送信します
   （保護された／Tor 経由の取得では、紛れ込めるよう一般的なブラウザの UA を送信します）。
7. **IP のスロットリング：** 単一の IP から立て続けにリクエストを送らないこと。サーバーの公正な利用を尊重すること。

## ✅ 遵守チェックリスト

新しい情報源をスクレイピングする前に、次を確認してください。
- [ ] そのドメインが[スクレイピング禁止リスト](#スクレイピング禁止リスト)に**含まれていない**。
- [ ] `robots.txt` ファイルがスクレイピングを許可している（[https://{domain}/robots.txt](https://{domain}/robots.txt) を確認）。
- [ ] その情報源が認証を**必要とせず**、ペイウォールを侵害**しない**。
- [ ] デフォルトで**毎秒 1 リクエストを超えない**ようレート制限が設定されている（センシティブなドメインでは調整する）。
- [ ] User-Agent 文字列が Open Omniscience を識別している（`OpenOmniscienceBot/{version}`）。
- [x] 取得の判定はローカルに記録され（`data/*_preflight.jsonl`）、設定のデバッグバンドルを通じて
  クリック時にのみ提示される — 自動送信されることは決してない。

## 🚫 スクレイピング禁止リスト

このリストは**運用者向けの指針**であり、機械的に強制される拒否リストではありません。アプリは

または URL を明確に許可していない情報源は、スクレイピングされずに拒否されます。それでも運用者は、
情報源を追加する際に判断力を働かせ、以下のカテゴリーを避けるべきです。

### ペイウォールのあるコンテンツ


### ソーシャルメディアプラットフォーム


### 私的またはセンシティブなデータ
- 政府のデータベース（例：`*.gov`、`*.mil`。明示的に公開されている場合を除く）
- 医療記録（例：`*.health`、`*.medical`）
- 金融記録（例：`*.bank`、`*.finance`。公開されている場合を除く）

## 📊 監査と説明責任

取得の記録は運用者自身が確認するために**ローカルに**保存され、**クリックしたときにのみ**
共有されます — 自動送信されることは決してありません（テレメトリーなし、設計としてローカルファースト）。
実際の仕組み（初期の `audit/scrape_log.csv` の設計はこれに置き換えられました）：

- **事前確認（プリフライト）の判定** — 情報源ごと・フィードごとの到達可能性／robots／トランスポートの
  結果は、`data/source_preflight.jsonl` と `data/feed_preflight.jsonl` に追記されます
  （各行：タイムスタンプ、情報源／ドメイン、トランスポートを考慮した判定、そして正直な理由）。
  これらは「失敗したフィードを再試行」の UX と、指数／マーケットのフィードごとの判定を支えています。
- **フィールドテストの結果** — フィールドテストモードがオンのとき、取得機能の試行結果が
  `data/field_test.jsonl` にそのまま書き込まれます。
- **アプリのエラー** — `data/app_errors.jsonl` に上限付きで記録されます（最新の行が保持されます）。

### サポートのための共有

自動アップロードされる CSV や `errors.log` はありません。運用者は**デバッグバンドル**を 1 つ作成でき
（設定 → 診断）、それは上記の JSONL ログにキーワード／ネットワークの診断情報を加えて集約したものです。
バンドルはディスクに書き出され、運用者の明示的な操作によってのみ共有されます。
これがメンテナーの手順です：アプリを一通り操作し、そのうえでバンドルを手渡します。

## 🔒 プライバシーとデータ保護

- **利用者の追跡なし：** Open Omniscience は次のものを収集・保存**しません**。
  - 利用者の IP
  - 検索履歴
  - 個人データ
- **ローカルのみ：** すべてのデータは利用者のマシン上にとどまります。デフォルトではクラウドに依存しません。
- **保存時の暗号化（デフォルトで有効）：** 新しいコーパスは、初回起動時に利用者が選ぶパスフレーズで
  保護され、SQLCipher により**暗号化**された状態で作成されます。**平文**のデータベースで運用するのは
  明示的なオプトアウトであり、示されたリスクを入力して確認する必要があります。パスフレーズを
  忘れた場合の**復旧手段はありません**（コーパスは再スクレイピングで再構築できるため、復旧キーや
  第二の復号経路は追加していません）。脅威モデルは、押収またはコピーされた**電源の切れた**マシンであり、
  すでに実行中の侵害されたセッションではありません（`SECURITY.md` を参照）。
- **GDPR への準拠：** EU 域内の情報源をスクレイピングする場合：
  - 保存したコンテンツ内の個人データ（例：氏名、メールアドレス）を匿名化すること。
  - 消去の権利を尊重すること（要求に応じてデータを削除する）。

## 🌍 法的な留意事項

- **著作権：** 著作権法を尊重すること。コンテンツのスクレイピングと保存は、次の目的に限ること。
  - **個人的・非商業的な**分析。
  - **フェアユース**（例：批評、論評、研究）。
  - **変容的な目的**（例：調査報道のための集約）。
- **GDPR への準拠：** EU 市民のデータを処理する場合：
  - 個人データの収集を最小限にすること。
  - 個人が自らのデータの削除を要求できる手段を提供すること。
- **管轄：** 利用者は、自らの管轄区域の法律を遵守する責任を負います。これには次のものが含まれます。
  - **Computer Fraud and Abuse Act（CFAA、コンピュータ詐欺・不正利用防止法）**（米国）
  - **General Data Protection Regulation（GDPR、一般データ保護規則）**（EU）
  - **著作権法**（各国）

## 🛡️ 技術的な安全装置

悪用を防ぎ、倫理的なスクレイピングを確実にするため、Open Omniscience は次の安全装置を実装しています。

1. **レート制限：**
   - デフォルト：ホストあたり毎秒 1 リクエスト（`min_interval_s`、`OO_FETCH_MIN_INTERVAL` から設定）。
   - ホストの robots の `Crawl-delay` の方が大きい場合はそれに従い、ホストごとに同時に 1 リクエストのみ。

2. **robots.txt の遵守：**
   - スクレイピングの前に `robots.txt` を自動的に確認します。
   - `Disallow` の指示を尊重します。

3. **User-Agent による識別：**
   - `OpenOmniscienceBot/{version} (+https://github.com/ideotion/Open-Omniscience; ethical research crawler)` を送信します。
   - 保護された（Tor 経由の）取得では、特定されないよう一般的なブラウザの UA を送信します。

4. **エラー処理：**
   - 失敗したリクエストを指数バックオフで再試行します。
   - 確認のためにすべてのエラーを記録します。

5. **重複の検出：**
   - URL の正規化とコンテンツのハッシュ化により、冗長なスクレイピングを避けます。

6. **監査証跡：**
   - 透明性と説明責任のため、すべてのスクレイピング活動を記録します。

## 📐 正直な指標 — でっち上げのスコアはなし

構造による正直さ：アプリは**総合的な信頼性／品質／信用度のスコア**を決して提示しません。
アプリが計算するすべてのシグナルには、その手法、注意書き、そして *n* が付いています。
混合スコアを出そうとしたカードは、カードスキーマによって機械的に拒否されます。
使われていないスコア用の列（`credibility_score`、`political_bias`）は NULL のまま保たれ、
どの API レスポンスにもシリアライズされることはありません。

**意図的で限定的な例外が 1 つあります — `reliability_score` です。** この情報源ごとの `1–10` の
フィールドは、**運用者が表明する来歴メタデータ**です：設定ファイルまたは CSV インポートを通じて、
*あなた*（運用者）が情報源ごとに設定する数値です。アプリがこれを**計算することも、デフォルト値を
入れることも、記事データから導き出すことも決してありません** — 以前のでっち上げの `=5`
というデフォルト値は削除されました（マイグレーション `f4b5c6d7e8a9` で NULL 化）。これはあなた自身の
表明であって（ツールが作り出した判定ではないため）、情報源リストに表示され、現れるすべての場所で
**「運用者が設定、計算値ではない」**とラベル付けされます。ブリーフィングカードがこれをスコアとして
提示することは依然として決してできません。リポジトリの不変条件
（`tests/test_repo_invariants.py::test_reliability_score_is_operator_set_never_computed`）
がその状態を保ち、これがいつの間にか計算された品質判定になることはありません。

## 📌 貢献者のためのベストプラクティス

1. **倫理的にテストする：**
   - 規模を拡大する前に、必ず小規模でスクレイピングをテストすること。
   - 可能な場合は `localhost` やステージング環境を使用すること。

2. **情報源を文書化する：**
   - `sources.yml` に、情報源を含める／除外する理由を説明するコメントを加えること。
   - 特別なスクレイピング要件（例：カスタムセレクター）があれば記しておくこと。

3. **オプトアウトを尊重する：**
   - 情報源から削除を求められた場合は、直ちに応じること。
   - そのドメインをスクレイピング禁止リストに追加すること。

4. **影響を最小限にする：**
   - 可能な場合はオフピークの時間帯にスクレイピングすること。
   - 同じコンテンツへの繰り返しのリクエストを避けるため、レスポンスをキャッシュすること。
