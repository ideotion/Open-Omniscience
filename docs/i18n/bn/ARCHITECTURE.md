## Open Omniscience-এর ডেটাবেস কনফিগারেশন

> **অবস্থা (v0.0.7 অডিটে যাচাইকৃত, `docs/archive/audits/00_BASELINE.md`):** ডেটাবেস স্তরটি
> **কাজ করে এবং পরীক্ষিত** — সার্ভার চালু হয়, SQLite স্টোর তৈরি/ব্যবহার করে, Alembic
> মাইগ্রেশন প্রয়োগ করে, এবং সম্পূর্ণ টেস্ট স্যুট (800+) এর বিপরীতে পাস করে। আগে এখানে যে
> "early concept — not functional" ব্যানারটি ছিল, তা পুনর্নির্মাণের আগের অবস্থা বর্ণনা করত এবং
> বহুদিন ধরেই পুরোনো হয়ে গিয়েছিল।

### 🗃️ SQLite — সমর্থিত স্টোর

SQLite হলো **ডিফল্ট এবং একমাত্র সমর্থিত, পরীক্ষিত ব্যাকএন্ড**। এটি পণ্যের
স্থানীয়-প্রথম, একক-অপারেটর নকশার সঙ্গে মানানসই।

- **শূন্য কনফিগারেশন:** প্রথমবার চালানোর সময় ডেটাবেস স্বয়ংক্রিয়ভাবে তৈরি হয়,
  `<data dir>/open_omniscience.db`-এ। ডেটা ডিরেক্টরি হলো `OO_DATA_DIR` (যদি নির্ধারিত থাকে), নইলে সোর্স চেকআউটে
  রিপোজিটরির `data/`, নইলে `$XDG_DATA_HOME/open-omniscience` (`src/paths.py` দেখুন)।
- **স্বয়ংক্রিয়ভাবে টিউন করা:** ইঞ্জিন প্রতিটি সংযোগে `WAL` জার্নাল মোড, `foreign_keys=ON`,
  `busy_timeout=30000` এবং `synchronous=NORMAL` প্রয়োগ করে
  (`src/database/session.py`) — এগুলো আপনাকে নিজে নির্ধারণ করতে হবে না।
- **পূর্ণ-পাঠ্য অনুসন্ধান** হলো SQLite **FTS5** (`article_fts`, external-content, ট্রিগার দ্বারা
  সমলয় রাখা — `src/database/fts.py`)।
- **অবস্থান পরিবর্তন করুন** `DATABASE_URL` এনভায়রনমেন্ট ভেরিয়েবল দিয়ে (সোর্স ফাইল **সম্পাদনা
  করবেন না**): `DATABASE_URL=sqlite:////absolute/path/to/your.db`
- **রক্ষণাবেক্ষণ:** মাঝে মাঝে একটি `sqlite3 <db> "VACUUM;"` জায়গা পুনরুদ্ধার করে (v0.0.7 অডিট
  একটি অপ্রয়োজনীয় ইনডেক্সও সরিয়ে দিয়েছে, যা বড় কর্পাসে ফাইলের ~63% ছিল; বিদ্যমান ডেটাবেস থেকে
  সেটি সরাতে আপগ্রেডের পর একবার `make
  migrate` চালান)।

### 🐘 PostgreSQL — পরীক্ষামূলক কাঠামো, সমর্থিত নয়

আকাঙ্ক্ষার চেয়ে সততা আগে (অডিট পর্যবেক্ষণ ARCH-06): ইঞ্জিন স্তর একটি
PostgreSQL `DATABASE_URL` *চিনতে পারে* (`DB_POOL_SIZE`/`DB_MAX_OVERFLOW`-এর মাধ্যমে সংযোগ পুলিং), **কিন্তু**

- **PostgreSQL-এ পূর্ণ-পাঠ্য অনুসন্ধানের অস্তিত্ব নেই** — FTS5 সেটআপ ইচ্ছাকৃতভাবে
  non-SQLite ইঞ্জিনে কিছুই করে না, ফলে অনুসন্ধান ট্যাব অকেজো হয়ে যাবে;
- টেস্ট স্যুট কখনো PostgreSQL-এর বিপরীতে চলে না, এবং কোনো CI এটি কভার করে না;
- কোনো প্রকাশিত ডিপ্লয়মেন্ট এটি ব্যবহার করেনি।

PostgreSQL-কে **সম্ভাব্য ভবিষ্যতের জন্য অপরীক্ষিত কাঠামো** হিসেবে বিবেচনা করুন, আজ বেছে নেওয়ার মতো
কোনো বিকল্প হিসেবে নয়। যদি কখনো একাধিক-লেখকের পরিসর সত্যিকারের প্রয়োজন হয়ে ওঠে, রোডম্যাপ আইটেমটি হলো একটি
`tsvector` অনুসন্ধান-পথ এবং একটি PostgreSQL CI ম্যাট্রিক্স — তা না আসা পর্যন্ত এই পৃষ্ঠা
ভান করবে না।

### 🔄 মাইগ্রেশন

Alembic **রিপোজিটরির রুটে** কনফিগার করা আছে (`alembic.ini`, `migrations/`)। Alembic
অ্যাপের সঙ্গেই ইনস্টল হয় (এটি একটি মূল নির্ভরতা — আলাদা ইনস্টলের দরকার নেই)।

- **নতুন ডেটাবেস** সম্পূর্ণ অবস্থায় তৈরি হয় (`create_all` + FTS) এবং চালুর সময় স্বয়ংক্রিয়ভাবে
  বর্তমান মাইগ্রেশন হেড দিয়ে চিহ্নিত (stamp) হয়।
- **বিদ্যমান ডেটাবেস আপগ্রেড করা:**
  ```bash
  make migrate          # = alembic upgrade head, from the repo root
  ```
- **একটি মাইগ্রেশন তৈরি করা** (অবদানকারীরা): `src/database/models.py` সম্পাদনা করুন, তারপর
  ```bash
  alembic revision --autogenerate -m "your message"
  alembic upgrade head
  ```
  এবং তৈরি হওয়া ফাইলটি যাচাই করুন — autogenerate FTS ভার্চুয়াল টেবিল ধরতে পারে না (সেগুলো থাকে
  `src/database/fts.py`-এ, চালুর সময় প্রয়োগ হয়)।
- **পূর্বাবস্থায় ফেরানো:** `alembic downgrade -1`।

### 📊 ডেটাবেস স্কিমা

#### টেবিল:

##### `sources`
| কলাম | ধরন | বিবরণ |
|--------|------|-------------|
| `id` | INTEGER | প্রাইমারি কী |
| `name` | STRING(100) | উৎসের নাম (যেমন "BBC News") |
| `domain` | STRING(255) | উৎসের ডোমেইন (যেমন "bbc.com") |
| `rss_url` | STRING(500) | RSS ফিডের URL (যদি থাকে) |
| `rate_limit_ms` | INTEGER | অনুরোধগুলোর মধ্যে বিলম্ব, মিলিসেকেন্ডে |
| `enabled` | BOOLEAN | উৎসটি স্ক্র্যাপিংয়ের জন্য সক্রিয় কিনা |
| `priority` | INTEGER | অগ্রাধিকার স্তর (1 = উচ্চ, 3 = নিম্ন) |
| `tags` | STRING(500) | কমা-বিভক্ত ট্যাগের তালিকা |

##### `articles`
| কলাম | ধরন | বিবরণ |
|--------|------|-------------|
| `id` | INTEGER | প্রাইমারি কী |
| `url` | STRING(1000) | আর্টিকেলের মূল URL |
| `canonical_url` | STRING(1000) | ক্যানোনিকাল করা URL (ডুপ্লিকেট শনাক্তকরণের জন্য) |
| `source_id` | INTEGER | `sources`-এর ফরেন কী |
| `title` | STRING(500) | আর্টিকেলের শিরোনাম |
| `content` | TEXT | আর্টিকেলের সম্পূর্ণ পাঠ্য বিষয়বস্তু |
| `published_at` | DATETIME | প্রকাশের তারিখ/সময় (ISO ফরম্যাট) |
| `language` | STRING(10) | ভাষা কোড (যেমন "en", "fr") |
| `hash` | STRING(64) | বিষয়বস্তুর SHA-256 হ্যাশ (ডুপ্লিকেট শনাক্তকরণের জন্য) |
| `created_at` | DATETIME | আর্টিকেলটি গ্রহণ (ingest) করার টাইমস্ট্যাম্প |

> ওপরের কলামগুলো মূল ফিল্ড; চলমান স্কিমা (`src/database/models.py`)
> এবং `migrations/versions/`-এর অধীনে Alembic মাইগ্রেশনগুলোই সত্যের উৎস।
> `articles`-এ উৎস-বিবরণ/বিশ্লেষণ ফিল্ডও রয়েছে (author, word_count, region,
> country, sentiment) এবং একটি সংকুচিত-বিষয়বস্তুর কলাম।

##### অন্যান্য টেবিল (সম্পূর্ণ কলামের জন্য models / migrations দেখুন)

| টেবিল | উদ্দেশ্য |
|-------|---------|
| `source_groups`, `source_metadata`, `source_group_association` | উৎস গোষ্ঠীকরণ + ভৌগোলিক/robots মেটাডেটা |
| `commodity_prices` | পর্যবেক্ষিত মূল্য-বিন্দু (symbol, date, price, currency, **unit**, market, source) — চার্ট + মূল্য↔সংবাদ সহসম্পর্ক |
| `market_extraction_rules` | প্রতিটি উৎসের নিয়ম (CSS selector / attribute / regex), যা একটি পৃষ্ঠায় একটি ইনস্ট্রুমেন্টের মূল্য খুঁজে বের করে; শ্রেণি financial/stock/commodity |
| `keywords` | স্বতন্ত্র কীওয়ার্ড/সত্তা শব্দ (normalized, language, `is_entity`/`entity_type`, **`extractor`** উৎস-বিবরণ) |
| `keyword_mentions` | প্রতি (article, keyword)-এ একটি: গণনা + প্রথম অক্ষরের অফসেট + ডিনর্মালাইজড `observed_on`/`country`/`city` — অন্তর্দৃষ্টির প্রবণতা, সংযোগ, প্রসঙ্গ, মানচিত্র চালায় |
| `wiki_pages` | একটি ভাষা সংস্করণে একটি ট্র্যাক করা Wikipedia পৃষ্ঠা; **একটি** সংকুচিত পূর্ণ-পাঠ্য বেসলাইন রাখে |
| `wiki_revisions` | একটি ট্র্যাক করা সম্পাদনা: **diff + স্বাক্ষরযুক্ত (signed) বাইট ডেল্টা** + flags/tags (পুনরায় অনুলিপি নয়), ঐচ্ছিক ORES স্কোর, বড়-সম্পাদনার সৎ চিহ্ন + কারণ |
| `article_analyses` | উদ্ভূত LLM ফলাফল (সারাংশ/অনুবাদ), মডেল + প্রম্পটের উৎস-বিবরণসহ |
| `keyword_categories`, `external_sources`, `article_links`, … | কীওয়ার্ড শ্রেণিবিন্যাস + লিংক/উৎস-সম্পর্ক ট্র্যাকিং |

#### ইনডেক্স:
- `idx_article_hash`: `hash`-এর ওপর ইউনিক ইনডেক্স (ডুপ্লিকেট শনাক্তকরণের জন্য)।
- `idx_article_canonical_url`: `canonical_url`-এর ওপর ইনডেক্স (URL খোঁজার জন্য)।
- `idx_article_source_id`: `source_id`-এর ওপর ইনডেক্স (উৎস-ভিত্তিক কোয়েরির জন্য)।
- `idx_article_content`: `content`-এর ওপর ইনডেক্স (পূর্ণ-পাঠ্য অনুসন্ধানের জন্য)।

### 🔍 পূর্ণ-পাঠ্য অনুসন্ধান

পূর্ণ-পাঠ্য অনুসন্ধান **ইতিমধ্যে তৈরি ও সংযুক্ত** — চালু করার কিছু নেই। স্টোরটিতে একটি
FTS5 external-content টেবিল (`article_fts`) রয়েছে, যা ট্রিগার দ্বারা সমলয় রাখা হয়; স্কিমার জন্য
`src/database/fts.py` এবং কোয়েরি-পথের জন্য `src/api/main.py`-এ `search_ids` দেখুন
(চূড়ান্ত ক্রমে শুধু-id সমাধান, সম্পূর্ণ সারি কেবল পৃষ্ঠাটির জন্যই লোড হয়)।

এই অংশে আগে SQLite-এর জন্য একটি "consider creating a virtual table" রেসিপি এবং PostgreSQL-এর জন্য একটি
`to_tsvector` রেসিপি দেওয়া হতো। দুটোই ভুল ছিল: SQLite-এরটি এমন একটি টেবিল হাতে তৈরির বর্ণনা দিত
যা অ্যাপ নিজেই সরবরাহ ও রক্ষণাবেক্ষণ করে (একটি *ভিন্ন* নামে, ফলে তা অনুসরণ করলে
একটি দ্বিতীয়, অরক্ষিত ইনডেক্স তৈরি হতো), আর এখানে PostgreSQL-এর কোনো অনুসন্ধান-পথই নেই,
যা ওপরের স্টোর অংশে এটি সমর্থিত ব্যাকএন্ড না হওয়ার প্রথম কারণ হিসেবে বলা হয়েছে।

  এর উদ্দেশ্য) — অ্যাপের ভেতরের সেটিংস → নির্ণয় (Diagnostics) ব্যবহার করুন, যা অ্যাপ নিজে যে
  সুরক্ষিত সংযোগ-কারখানা ব্যবহার করে সেটির মাধ্যমেই স্টোর পড়ে।

### 🚨 সমস্যা সমাধান

#### সাধারণ সমস্যা:

##### SQLite:
- **"Database is locked"**:
  - SQLite একবারে কেবল একজন লেখককে অনুমতি দেয়। WAL মোড ডিফল্টভাবে চালু থাকে
    (`src/database/session.py`) এবং একটি প্রসেস-ব্যাপী একক-লেখক গেট
    (`src/database/writer.py`) অ্যাপের ভেতরের লেখাগুলোকে ক্রমানুসারে চালায়, ফলে একযোগে ingest +
    import আর সংঘর্ষে জড়ায় না। স্থায়ী লক মানে অন্য কোনো *প্রসেস* লিখছে।

- **"Too many open files"**:
  - SQLite প্রতিটি থ্রেডের জন্য একটি নতুন সংযোগ খোলে। থ্রেডের সংখ্যা সীমিত করুন বা সংযোগ পুলিং ব্যবহার করুন।

- **"Relation does not exist" / "no such table"**:
  - মাইগ্রেশন চালান: `alembic upgrade head`।

### 📌 সর্বোত্তম অনুশীলন

1. **`cp` দিয়ে নয়, অ্যাপের মাধ্যমে ব্যাকআপ নিন**:
   - সেটিংস → ব্যাকআপ ব্যবহার করুন (অথবা একটি সামঞ্জস্যপূর্ণ স্ন্যাপশটের জন্য `GET /api/database/backup`)।
     `open_omniscience.db` হাতে কপি করা ব্যাকআপ **নয়**: স্টোরটি WAL
     মোডে চলে, তাই চলমান ফাইলে `-wal`-এ এখনো যা আছে তা অনুপস্থিত থাকে, এবং ডিফল্ট
     **এনক্রিপ্টেড** স্টোরে কপি করা ফাইল পাসফ্রেজ ছাড়া অকেজো এবং এতে কোনো
     অখণ্ডতার প্রতিশ্রুতি (integrity commitment) থাকে না। অ্যাপের নিজস্ব পথ চেকপয়েন্ট করে, স্ট্রিম করে এবং স্বাক্ষর করে।

2. **মাইগ্রেশন পরীক্ষা করুন**:
   - প্রোডাকশনে প্রয়োগের আগে সবসময় আপনার ডেটাবেসের একটি ব্যাকআপে মাইগ্রেশন পরীক্ষা করুন।

3. **কর্মক্ষমতা পর্যবেক্ষণ করুন**:
   - সেটিংস → নির্ণয় (Diagnostics)-এ রয়েছে ধীর-কোয়েরি লগ, অনুরোধ-বিলম্ব লগ এবং
     write-gate প্রতিবেদন; `sqlite3` CLI একটি প্লেইনটেক্সট স্টোরে কাজ করে।

4. **কোয়েরি অপ্টিমাইজ করুন**:
   - `EXPLAIN QUERY PLAN`-ই হাতিয়ার। লক্ষ করুন, SQLite একটি সাধারণ টেবিল স্ক্যান এবং একটি শুধু-ইনডেক্স
     স্ক্যান — **উভয়ের** জন্যই `SCAN` লেখে — একটি `SCAN <table> USING [COVERING] INDEX …`
     স্বাস্থ্যকর; সমস্যার লক্ষণ হলো `USING` ছাড়া একটি সাধারণ `SCAN <table>`
     (`src/monitoring/slowquery.py` ঠিক এর ভিত্তিতেই শ্রেণিবিন্যাস করে)।

5. **ডেটা সংরক্ষণ সীমিত করুন**:
   - ডেটাবেস নিয়ন্ত্রণযোগ্য রাখতে নিয়মিত পুরোনো আর্টিকেল আর্কাইভ বা মুছে ফেলুন।
   - উদাহরণ: 1 বছরের বেশি পুরোনো আর্টিকেল মুছে ফেলুন:
     ```python
     from datetime import datetime, timedelta
     one_year_ago = datetime.now(timezone.utc) - timedelta(days=365)
     session.query(Article).filter(Article.published_at < one_year_ago).delete()
     session.commit()
     ```

### স্থাপত্য (অফলাইন, নির্ভরতাহীন)

`src/static/i18n.js` + `src/static/locales/<code>.json`। কোনো বিল্ড ধাপ নেই, কোনো নেটওয়ার্ক নেই।

- **ইংরেজিই কী।** লোকেল ফাইলগুলো **ইংরেজি UI স্ট্রিং → তার অনুবাদ** ম্যাপ করে
  (যেমন `"Search the corpus": "Rechercher dans le corpus"`)। এতে প্রতিটি উপাদানে ট্যাগ না বসিয়েই
  বিদ্যমান UI-তে এটি যুক্ত করা যায়, এবং ইংরেজি প্রামাণ্য উৎস হিসেবে থেকে যায়।
- **`OOI18N.setLang(code)`** `locales/<code>.json` লোড করে, পছন্দটি
  `localStorage`-এ (`oo.lang`) সংরক্ষণ করে, `document.documentElement.lang` ও `dir` নির্ধারণ করে (`ar`/`ur`-এর জন্য
  RTL), তারপর **`apply()`** DOM-এর ওপর দিয়ে যায় — যেসব টেক্সট নোডের ছাঁটা পাঠ্য কোনো কী-র সঙ্গে মেলে
  সেগুলো, এবং `placeholder`/`title`/`aria-label` অ্যাট্রিবিউট অনুবাদ করে। অজানা
  স্ট্রিং যেমন আছে তেমনই থাকে (ইংরেজি বিকল্প) — কিছুই কখনো ভাঙে না।
- **গতিশীল বিষয়বস্তু** (ডেটা: আর্টিকেলের শিরোনাম, উৎসের নাম, গণনা) **কখনো**
  অনুবাদ করা হয় না — কেবল কাঠামো (chrome)। JS-রেন্ডার করা কাঠামো (কমান্ড প্যালেট, ড্রয়ার) রেন্ডারের পর
  `OOI18N.apply()` কল করে।
- প্রতিটি লোকেলে `_meta` থাকে (`name`, `native`, `dir`, `status`)।

#### এটি সংযুক্ত করা (Phase 2 — প্রকাশিত; Desk পরে অবসরে গেছে)

`index.html`-এ দুটি লাইন (এবং 2026-06-10 তারিখে অবসরের আগে `desk.html`-এও),
তারপর একটি ভাষা-নির্বাচক:

```html
<script src="/static/i18n.js"></script>
<!-- after first render and on each view change: --> OOI18N.apply();
```

**ভাষা** নির্বাচকটি সেটিংসে থাকে এবং `OOI18N.setLang(code)` কল করে,
অন্যান্য স্থানীয় UI পছন্দের পাশাপাশি সংরক্ষিত হয়।

### বহু ভাষায় ডকুমেন্টেশন

ডকুমেন্টগুলো দীর্ঘ এবং সংক্ষিপ্ত UI স্ট্রিংয়ের চেয়ে এখানে অনুবাদের মান বেশি গুরুত্বপূর্ণ, তাই:

- কাঠামো: `docs/i18n/<code>/<DOC>.md` হুবহু `docs/`-এর প্রতিচ্ছবি।
- **ইংরেজি ডকুমেন্টগুলোই প্রামাণ্য থাকে**; অনুবাদগুলো কমিউনিটি/রক্ষণাবেক্ষণকারীর কাজ,
  প্রতিটিতে অনুবাদের তারিখ এবং যে ইংরেজি কমিট এটি অনুসরণ করে তা চিহ্নিত থাকে।
- আমরা ডকুমেন্ট **স্বয়ংক্রিয়ভাবে যন্ত্র-অনুবাদ করে** সেগুলোকে চূড়ান্ত হিসেবে উপস্থাপন করি **না** — তা
  প্রকল্পের সততার নীতি লঙ্ঘন করবে। প্রতিটি ভাষার জন্য সবচেয়ে মূল্যবান, সবচেয়ে সংক্ষিপ্ত

### অবদানের কর্মপ্রবাহ (নকশাগতভাবে উন্মুক্ত প্রবেশাধিকার)

1. `locales/en.json` → `locales/<code>.json` কপি করুন, মানগুলো অনুবাদ করুন, `_meta.status` নির্ধারণ করুন।
2. RTL ভাষার জন্য `_meta.dir: "rtl"` নির্ধারণ করুন।
3. (পরিকল্পিত) কী-কভারেজ যাচাই চালান: `en.json`-এর তুলনায় অনুপস্থিত/অতিরিক্ত কী জানান।
4. জমা দিন। অনূদিত নয় এমন কী পূরণ না হওয়া পর্যন্ত কেবল ইংরেজিতে ফিরে যায়।

### অবস্থা

**Phase 1 (সম্পন্ন):** i18n ইঞ্জিন (`i18n.js`), সব 12টি ভাষার লোকেল কাঠামো,
এবং **en/fr/es/de**-এর সম্পূর্ণ রেফারেন্স অনুবাদ।

**Phase 1b (সম্পন্ন, `0.4.0`):** বাকি ইন্টারফেস স্ট্রিংগুলো কী-ভুক্ত করে
**বারোটি ভাষাতেই** অনুবাদ করা হয়েছে (`CHANGES.md` 0.4.0 দেখুন), ফলে
`src/static/locales/*.json`-এর প্রতিটি লোকেলে এখন সম্পূর্ণ কী-সেট রয়েছে (যাচাইকৃত:
12টি ফাইল, প্রতিটিতে 6,991টি কী, কোনোটি অনুপস্থিত নয়)। সততা অপরিবর্তিত: নামগুলো
নামবাচক বিশেষ্য এবং অনুবাদ করা হয় না, এবং একটি আংশিক লোকেল এখনো ভাঙার বদলে ইংরেজিতে
ফিরে যায়।

**Phase 2 (সম্পন্ন — একটি প্রকৃত ব্রাউজার যাচাই বাকি):** `i18n.js` অন্তর্ভুক্ত আছে
`index.html`-এ (এবং 2026-06-10 তারিখে Desk-এর অবসর পর্যন্ত `desk.html`-এ ছিল); একটি
**ভাষা** নির্বাচক (`#oo-lang-select`) সেটিংসে রয়েছে এবং স্বয়ংক্রিয়ভাবে সংযুক্ত; গতিশীলভাবে রেন্ডার করা কাঠামো
একটি debounced `MutationObserver` দ্বারা স্বয়ংক্রিয়ভাবে অনূদিত হয় (কোনো ছড়ানো-ছিটানো `apply()` কল নেই); ইংরেজিতে
ফিরে গেলে মূল পাঠ্য পুনরুদ্ধার হয়; `<html dir>`-এর মাধ্যমে RTL। কাঠামো/সিনট্যাক্স যাচাইকৃত, তবে
আচরণটি এখনো একটি ব্রাউজারে চোখে দেখে নেওয়া উচিত।

**Phase 3 (পরবর্তী):** `en.json`-কে *সম্পূর্ণ* স্ট্রিং-ক্যাটালগে প্রসারিত করা (এটি বর্তমানে
বেশি-ব্যবহৃত কাঠামো কভার করে), stub লোকেলগুলো সম্পূর্ণ করা (কমিউনিটি), এবং `ar`/`ur`-এর জন্য
RTL লেআউট পরিমার্জন করা।


## এক্সপোর্ট চুক্তি (সংস্করণযুক্ত)

যন্ত্র-পাঠযোগ্য এক্সপোর্টগুলো একটি স্থিতিশীল, স্ব-বর্ণনাকারী চুক্তি বহন করে (স্কিমা `oo-export-1`,
0.0.8 part 2 / RM-15), যাতে পরবর্তী পাইপলাইনগুলোকে কখনো অনুমান করতে না হয়:

- **JSON** (`/api/articles/export?format=json`, `/api/links/export.json`): একটি খাম (envelope) —
  `{export_schema, kind, app_version, generated_at, query, count, articles|data}`। 
  `query` অবজেক্টটি হুবহু সেই নির্বাচন যা এক্সপোর্টটি তৈরি করেছে; উৎস-বিবরণ ডেটার সঙ্গেই যায়।
- **CSV** (`/api/articles/export?format=csv`): কোনো মন্তব্য-লাইন নেই (তা সরল পাঠকদের ভেঙে দিত);
  একই খাম HTTP হেডার হিসেবে যায় (`X-OO-Export-Schema`, `X-OO-App-Version`,
  `X-OO-Generated-At`, `X-OO-Query`)। কলামগুলোর ক্রম অপরিবর্তিত থাকে, এবং নতুন কলাম কেবল
  শেষেই যুক্ত হয়: `Fetched From Host` (queue item 61), রিডাইরেক্টের পর যে হোস্ট থেকে পৃষ্ঠাটি
  আনা হয়েছিল, রেকর্ড না থাকলে খালি; JSON এক্সপোর্টে এটি `fetched_host` হিসেবে থাকে।
- **উদ্ধৃতি গ্রাফ** (`/api/links/export.graphml`, `.json`): কে-কাকে-উদ্ধৃত-করে গ্রাফ
  (সংরক্ষিত আর্টিকেল → বাহ্যিক নিবন্ধনযোগ্য ডোমেইন)। **কেবল গণনা — কোনো অনুমিত
  বিশ্বাসযোগ্যতা নেই, কোনো স্কোর নেই**; সতর্কতাটি ফাইলের মধ্যেই সংযুক্ত। GraphML
  Gephi/yEd/NetworkX-এ খোলে।

স্কিমা পরিবর্তন হলে `oo-export-N` বাড়ে; বিদ্যমান ফিল্ড কখনো নীরবে অন্য কাজে ব্যবহার করা হয় না। পাশে
যুক্ত একটি ফিল্ড (শেষে একটি CSV কলাম, একটি নতুন JSON কী) প্রতিটি বিদ্যমান পাঠকের
ফিল্ডগুলোকে যেখানে ছিল সেখানেই রাখে, তাই এটি স্কিমা বাড়ায় না।
