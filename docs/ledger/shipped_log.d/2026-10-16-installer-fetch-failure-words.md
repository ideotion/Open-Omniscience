## 2026-10-16 — an installer or prepare failure after a followed redirect says only a status or a class (R142), the HTTP library's log lines carry no path or query, and no host list reaches further than its consent-popup lane (R143) (PR #1414)

R142 (the coordinator session, amending R141's «other failures unchanged»). The installer's two fetches, the `api.github.com` release lookup and the download of the script the release names, answered every failure that was not a host-list refusal with the failure's own text. Measured with `requests` 2.34.2 and `urllib3` 2.8.0, an HTTP error answer and a connection that could not be made quote the path and query, and the download's address is a signed storage URL with its signature in the query, so a 404 or 5xx from the storage hop carried the signature into the 500 and the log; the other failures (a read timeout, a dropped connection, a truncated body, a redirect loop, a `Location` `requests` cannot read, a body that is not JSON) do not quote it today. `src/llm/installer.py` now raises `InstallerFetchFailed` (a subclass of `InstallerVerificationError`, so `/api/llm/install/prepare` answers 502 through `http_detail`) from `_get_within` for all of them: a fixed sentence per stage (`LOOKUP`, `DOWNLOAD`, each ending at https://ollama.com/download) plus `why`, which is `HTTP <status>` or the exception's class name and nothing else (`src/safety/fetcher.py:failure_words`; `FETCH_FAILURES = (requests.exceptions.RequestException, ValueError)` lives there because the installer may not import `requests`). It is raised after the `except` block, so it has no cause and no context, and it is logged with the same two words and no `exc_info`. `raise_for_status()` moved inside the `try`; `TransportUnavailable` passes through (a missing proxy in protected mode); the kill switch is a `RuntimeError` the tuple never catches; a refusal stays `InstallerRedirectRefused`, caught first. `_default_get_json` turns a body that is not JSON, JSON that is not an object (a list, a string, a number, `null`) and JSON nested past the parser's limit into the same failure, named by class (`JSONDecodeError`, `TypeError`, `RecursionError`). A malformed `Location` on a hop is a plain `ValueError` from inside `requests`, caught by `FETCH_FAILURES`, which closes the read's item L2 on #1409. The address the release names is a different case: it is pre-checked, and an unreadable or unlisted one is an `InstallerRedirectRefused`.

The independent read of this PR found a leak R142's exception rule could not reach, reproduced against a loopback socket with a session built by the app's own fetcher and the app's own error-log setup: when a response has a malformed header line `urllib3` logs `Failed to parse headers (url=<path and query>)` at WARNING, with the traceback, on a fetch that SUCCEEDS as well as one that fails, and it logs the target on a retry (WARNING) and on the request line, each redirect hop and each retry increment (DEBUG). `src/ingest/urllib3_log.py` (imported by `src/ingest/__init__.py`, which the fetcher imports) puts a filter on the four `urllib3` loggers that rewrites a request target argument (`/path?query`, or an absolute address with a path, query or fragment) to `[path withheld]`, keeping scheme, host and port and dropping userinfo. `tests/test_urllib3_log_withholds_the_path.py` drives the real library: the malformed header, a retry, the DEBUG request line and redirect hop, and the installer's own `_default_get_bytes` against a loopback server; each case asserts the library did log and the host is still there. Not covered, said so: a `urllib3` release that formats the target into a longer string, and an exception the library attaches to a record.

R143 (the coordinator session, option A of three, after item 3 of the follow-up found three lists wider than the popup that discloses them). `tests/test_session_host_list.py::test_no_host_list_reaches_further_than_the_consent_popup_tells_the_person` maps each of 13 rows (the 11 fixed-endpoint lists and the installer's two) to the `src/static/net-hosts.js` lane that names it (an exact entry is a host; a leading-dot entry is `*.x`) and fails on any host the lane does not name, and `test_every_host_list_a_session_is_built_with_is_pinned_to_a_popup_lane` walks every session built under `src/` and fails on a list that is not a row or is an inline tuple (the read's mutant, a new wide list with a session using it, had passed the first pin). A list may be narrower than its lane. The first pin failed on exactly three lists, which are now exact: `WIKI_SESSION_HOSTS = (".wikipedia.org", "wikimedia.org", "stream.wikimedia.org")` (the `.wikimedia.org` suffix is gone), `ORES_HOSTS = ("ores.wikimedia.org",)` and the DuckDuckGo `ALLOWED_HOSTS = ("html.duckduckgo.com",)`. Each has an exact-list test; the Wikipedia lane also names `dumps.wikimedia.org`, which the wiki session does not fetch, and adding it to the list is killed by the exact-list test alone. A redirect that stays inside the domain but leaves the exact host now fails closed with the existing named refusal, and the ORES client records it as the outcome `refused_redirect` (it was a `transport_error`), the token Q717's probe reads.

Not done, and said so: the lists were narrowed because the code promised the person less than it allowed, not because a live redirect was seen going elsewhere, so whether any real service answers with a redirect off the exact host is an operator look recorded STILL OPEN in `docs/ledger/OPEN_QUEUE.md` (for ORES it is the same look as Q717 (a), the move to Lift Wing); a success's `source_url` is the `browser_download_url` the release names, not the signed storage address.

Tests: `tests/test_session_host_list.py` (the sink test per stage and per kind of failure, 404, 503, connection, timeout, truncated body, bad `Location` and a redirect loop, each with the failure the library really raises or a planted text that quotes the signature, checked against the response, the log and the exception chain; the non-JSON and non-object lookups; `failure_words` alone; the pin, its completeness walk and the three exact-list tests; the ORES refused-redirect outcome) and `tests/test_urllib3_log_withholds_the_path.py`.
