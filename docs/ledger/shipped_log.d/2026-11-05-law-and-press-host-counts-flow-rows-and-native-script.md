## 2026-11-05 — the Law and Press host counts read flow-style and native-script domain rows: Law 260 became 309, Press 9,033 became 9,035 (R189 follow-on to C-L2, PR #1719)

Found while building C-L2 (#1717): the Opus read of that change noticed that `wipolex.wipo.int`, a curated source domain in `configs/legal_sources.yml`, was not among the 260 hosts the Law lane states. It is a defect, not a design question, so it is its own PR under R189, and the files C-L2 was fenced from (R420) are touched here for the first time. The read of THIS change found the second miss below.

**What was wrong.** A class lane's host count is measured by `tests/test_security_endpoint_enumeration.py` as the distinct hosts of the URLs in its catalogues plus the scheme-less `domain:` values (`_YAML_DOMAIN`). The instrument missed two kinds of declared domain.

1. *Flow rows.* The regex read a `domain:` key that starts a line, with an optional dash. `configs/legal_sources.yml` writes all 51 of its curated source rows in the flow spelling, `- {name: "...", domain: x, country: ..., ...}`, where the key follows a `{` or a `,`. The regex found none of them. Two of the 51 (`eur-lex.europa.eu`, `laws-lois.justice.gc.ca`) were counted anyway through a `url:` in the same file, so the count was short by 49 hosts: `wipolex.wipo.int`, `legifrance.gouv.fr`, `boe.es`, `congress.gov`, `govinfo.gov`, `sec.gov`, `curia.europa.eu`, `gov.uk` and 41 more. The app seeds and crawls those rows like any press source, so these were hosts it could always reach; the SECURITY.md Law row and the consent hover said 260 where the catalogues carry 309. The generated file (`legal_sources_generated.yml`: 224 block rows, 210 distinct domains) was never affected.
2. *Native-script names.* The value pattern and the host-shape check are ASCII. `configs/sources.yml` declares three domains in their own script: `åa.no`, `공유.net` and `севернаяправда.рф`. The app reaches a source at `https://<domain>` (`src/ingest/crawl.py`), and `requests` sends the IDNA spelling (checked: `https://åa.no/` becomes `https://xn--a-1fa.no/`), so these are `xn--a-1fa.no`, `xn--ob0b790c.net` and `xn--80aaafcmcb6evaidf6r.xn--p1ai`. The third was counted anyway, through a punycode `rss_url` host. The second is reached elsewhere only as `www.xn--ob0b790c.net`, and the first nowhere else, so the Press lane left out two hosts it can reach: 9,033 where the catalogues carry 9,035.

**What changed.** `_YAML_DOMAIN` reads both row spellings and Unicode values; a key that merely ends in "domain" (`subdomain:`, `source_domain:`) stays out. `_ascii_host` turns a native-script name into the one a connection uses, and the three places that collect domains (the class-lane count, the tree sweep, the oracle) go through it. `hostCount` 260 → 309 (Law) and 9,033 → 9,035 (Press) in `src/static/net-hosts.js`, and the **309** and **9,035** in the `docs/SECURITY.md` Law and Press rows, in the same diff (Q1001). Measured before the edit with a YAML reader as the oracle: Law 260 → 309 (`legal_sources.yml` 51 missed, the generated file 0); Press 9,033 → 9,035, every other press catalogue 0 missed and 0 invented. The tree-wide sweep (`_tree_hosts`, every YAML file under `src/`, `configs/` and `scripts/`) gains 46 host names and loses none: 44 from the flow rows of `legal_sources.yml` (the other flow hosts were already known from another file or a `url:`, and some now also list `legal_sources.yml` as a carrier) and 2 native-script names from `sources.yml`. Nothing outside those two catalogues changes, and every gained name is inside a lane's own `hostsFrom`.

**Why the count guard did not catch either.** `test_a_class_lane_states_the_real_host_count` measures with the regex it is checking, so a number typed from the regex's blind spot agreed with itself for as long as the files existed. New: `test_the_domain_sweep_agrees_with_the_parsed_catalogues` parses every `hostsFrom` catalogue with `yaml.safe_load` and compares the domain sets with the regex's in both directions, and the oracle does NOT filter by the shape check, so a declared domain the shape check cannot read is named instead of dropped from both sides (a first version filtered, and a mutant of that survived: the comparison is now `_sweep_problems`, with its own test on files written for the purpose, one per way a count goes quietly short). A table pins block, indented, quoted, flow, tight-comma, after-a-list and native-script rows and four non-matches; another pins `_ascii_host` on the three real names and four that must pass through. Nine mutants, all killed: the old regex, an ASCII-only value class, `hostCount` left stale, no normalisation in the count, `_ascii_host` as the identity, the unreadable-domain check removed, the oracle re-filtered by shape, misses ignored, and the regex without its anchor.

**Not changed, and what is not known.** No host was added and no consent behaviour changed: the hover now says 309 and 9,035 for the reach the app always had. The flow branch of the regex is not tied to a real mapping, so `{domain: x.org}` inside a comment or a quoted string would match; no file has one, and the oracle test (a `hostsFrom` file) or `test_every_host_literal_in_the_tree_is_enumerated` (any other YAML) fails by name if one ever does. Both instruments look for a key called `domain`: a catalogue that carried hosts under another key would be missed by both, and the URL-literal sweep is the only other half. `_URL_HOST` is ASCII too, so a native-script host written as a URL would be cut short; no catalogue has one. Whether the Law lane's 309 should count the apex and the `www.` spelling of a host as two (it does, as the Press lane always has: they are two names a connection can use) is unchanged. The release-notes line for this fix: the security document's host counts were Law 260 and Press 9,033 and are 309 and 9,035, because the earlier count did not read 49 curated law-source domains written in flow style or two domains written in their own script; no host was added.
