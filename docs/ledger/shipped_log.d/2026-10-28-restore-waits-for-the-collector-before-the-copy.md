## 2026-10-28 — a restore waits for the collector to leave the corpus before it copies it, and the import dialog says what its pause is and is not (R360)

**What was found.** The exclusive window (`runner.exclusive_window`, `pause_for_exclusive_operation`) stops the `oo-scheduler` loop with a bounded join (10 s) and blocks the next `run_now`. A pass deep in a write can outlive that join (one recorded at 39 minutes), and a pass started by Run now before the window opened is untouched. `run_restore` read the window's return as "collection is paused", took the working copy, merged into it and swapped it in, so anything such a pass committed after the copy was discarded by the swap. The import dialog said "Background collection is paused for this whole import and resumes when it finishes." and the restore's own docstring said "nothing else is expected to write the live corpus"; the writers the window never reaches (the housekeeping lane with its crawl and backfill, the Wikipedia drain, registered background jobs, AI sweeps, boot upkeep, 317 API write routes) were named nowhere a person reads.

**What changed.**
- Defect: `src/backup/collector_exit.py` (new), called from `run_restore` (`src/backup/merge.py`) before the snapshot, only for an owner restore that takes a fresh working copy. `wait_for_collector_exit` waits at most 600 s (`COLLECTOR_EXIT_WAIT_S`) for the loop thread and the scheduler's busy flag, polling every second and honouring Stop; the answer (`confirmed` True / False / None with `waited_s`, `bound_s`, `still`, `reason`) goes into `report["collector_exit"]` and a `collector_exit` run-log milestone. `ImportQueueManager.status()` carries `collection_exit_unconfirmed` (true when any restore of the run copied with the answer other than True), and the dialog (`src/static/app-backup.js`) then says the pause could not be confirmed instead of claiming one, and keeps saying it after the run. Failing test first: 5 of the 18 new tests in `tests/test_restore_collector_exit.py` fail on the previous `merge.py`; `tests/import_tail_phase_node_test.js` pins the dialog.
- Wording: the visible line now adds "Other background work is not paused: what it, or you, saves to your corpus while the import runs can be lost." and its hover (the translated `title`, so the long form is layered and the caveat stays visible) names what is paused (the collection loop and the Collect now button), what is not (the background tasks, Wikipedia updates, other background jobs, AI sweeps, start-up upkeep, anything the person changes), that the swap discards what is saved between the copy and the swap except settings, agenda and interface choices, and that the import waits up to 10 minutes before copying. Three new keys in all twelve locales (non-English AI-drafted, flagged for native review); `collection_note` in the queue status says the same; the `exclusive` docstring in `merge.py` and the pause comment in `volume_job.py` no longer say "nothing else writes". A test pins the hover's "10 minutes" to `COLLECTOR_EXIT_WAIT_S`.

**Not changed, on purpose.** No writer other than the collector is stopped, locked or refused: that is a decision for the user (`wal-lane/proposal-uncovered-writers-2026-10-28.md`, options A to D, recommendation C now plus B reduced to one list). `runner.py` is not touched (the keyword lane's file); the wait lives in the restore, so `exclusive_window` itself still returns after its 10 s join.

**Stated limits.** The wait is a courtesy with a bound, not a lock: a pass still running at 600 s is named and the restore goes on. Not measured: rows lost to any writer class during a span (R341's 0 to 1,174 frames, 21 restores, plaintext SQLite 3.45.1, one synthetic writer, is the only figure and is not for these classes).
