## 2026-10-16 — the release primitive sees a write round the ORM, the CHECK-3 lows, and a hold policy on the three count-only re-index drains (PR #1418)

`release_idle_connection` could not see a write that went round the ORM, and rolled it back without a sound; `reindex_all_batch`, the corpus re-index job and the re-index that ends a restore ended a batch by its width alone. This PR is item 1 and item 3 of the coordinator's assignment of 2026-10-16 (the coordinator accepted the rows-changed approach; item 3 had to be on `main` before B3, PR #1417, whose engine stamp re-extracts every real corpus through these drains).

- **Rows-changed baseline** (`src/database/session.py`): a `Session` `after_begin` listener records the DBAPI connection's `total_changes` the first time a ROOT transaction meets a connection (`after_begin` also fires for a savepoint, and the first build retook the baseline there, with an unseen write already counted: the release rolled the row back; reproduced, pinned, and the baseline and the flag are now once per root transaction, cleared in `after_transaction_end` when `transaction.parent is None`). The release declines on any difference, on a count it cannot read, on a transaction with no recorded start and on a session bound to two connections.
- **Statement flag** (`src/database/statement_kind.py`, new): an `Engine` `before_cursor_execute` listener flags the connection when a statement is not a plain read, by an allowlist (SELECT, WITH, VALUES, EXPLAIN, BEGIN, SAVEPOINT, RELEASE, read-only PRAGMA forms; an unknown statement is not a read). It catches `CREATE TABLE` through `session.connection()` and `PRAGMA user_version = 7`, which move no row count. About 0.36 microseconds per statement.
- **Why not the plain `in_transaction` flag:** it is True for an explicit BEGIN (the `read_snapshot` recipe) as for a write, so it reddens `tests/test_all_diag_read_release.py::test_a_pinned_snapshot_is_released_at_the_boundary_so_the_log_can_be_checkpointed`. `query.py` keeps its own snapshot guard.
- **Stated cost and limit:** any statement that is not a plain read declines the release (an UPDATE that matched no row too: nothing is lost, the connection stays until the caller's commit); a schema change or header PRAGMA sent straight to the DBAPI cursor is not seen (docstring and queue entry; no caller does it).
- **Drains** (`src/analytics/store.py`, `src/analytics/reindex_job.py`, `src/backup/merge.py`): `reindex_all_batch(..., should_flush=None)` forwards to `reindex_articles`; the job resolves `reindex_flush_policy()` per page and counts `batch_commits` and `early_batch_commits` in its tally; `run_restore` passes `_restore_reindex_policy(_rx_stats)` and publishes `hold_target_s`. `OO_REINDEX_HOLD_TARGET_S=0` is the count-only rule in all three; the `USER_MANUAL.md` row names them.
- **R138 guard lows** (`tests/test_refusal_detail_source.py`, 159 checks): a module-level container filled without `global`, a `Declined` subclass or alias, and `match`-case and `globals()` stores are followed; the limit list stays at three.
- **Tests:** `tests/test_release_declines_unseen_writes.py` (83: every shape of unseen write and schema change declined and surviving the commit, reads still released, savepoints before and inside), `tests/test_statement_kind.py` (75), `tests/test_reindex_drains_give_the_gate_back.py` (12), and the changed `test_collect_worker_holds_no_session_across_fetch.py`, `test_sink_sweep_records.py` (six exact-line allowances for the `.info` dictionary lines in `session.py`). Mutants, each failing a named test: 13 of the first version of the primitive, 19 of the flag, the savepoint baseline and the classifier, 9 of the drain wiring, 16 of the R138 guard. Ruff total 413 (ceiling 417); mypy clean.
