## 2026-10-16 — the storage-events journal keeps the runs of the volume backup, restore and verify, and the starts that were refused before any run existed (PR #1421)

The Diagnostics zip kept the runs that opened a run journal (`run-journal.json`, the last twenty) and nothing for a start refused before `runlog.begin`, for a worker killed in the middle of a backup, or for a backup that ended "ok" with its summary file not written; the free bytes of the volume a run was writing to were nowhere, and a restore queue that fails eight times pushed everything older out of one ring. This is item 2 of the coordinator's assignment of 2026-10-16 (the coordinator confirmed the rulings below and that the PR body names the limits).

- **Three journal kinds** (`src/monitoring/storage_events.py`): `run_export`, `run_import`, `run_verify`, ten each (`KEEP` is per kind, so a restore queue of eight failures cannot push last week's failed backup out; `total` still counts every run). The API: `run_started` writes the run OPEN (with a key), `run_ended` closes it with one of eight named outcomes, the seconds, the class name of a failure and the facts, `run_refused` records a start that never became a run (closed in one write, `ran: false`, the fixed sentence of a refusal KEY), `run_part` adds a fact to the newest open run of a kind, `run_free_space` / `free_bytes_of` read the free bytes of the volume (absent when unreadable, never 0).
- **Hooks** (`src/backup/volume_job.py`, `src/backup/export_summary.py`): the three start methods record each refusal at the raise (no passphrase, destination unusable, not a folder, a job already running, named by kind); the three workers record the run after `runlog.begin`, close it at every branch (ok with the figures, paused, cancelled, refused, stopped by the operator, error with the class name) and in a `finally` net (`ended-without-a-recorded-outcome`, a no-op once an outcome is written); a backup that ended ok with its summary file not written adds `summary_error` (class only).
- **What the sink takes:** numbers (finite, not bools), a flag (`set_ok`), class names (shaped like one, 80 characters at most, else the fixed marker), five read-back states, and keys of fixed tables (outcomes, refusals). An AST test reads every hook call and fails on a `failure=` that is not `type(<name>).__name__`, on a `**` mapping, on an outcome that is not a table constant and on a fact name the sink does not know; the marker passphrase is planted in every exception text and found in neither the file, the member nor the slot.
- **Budget:** the slot `storage-events.json` is 115,000 bytes (was 90,000): 64,665 with ordinary names, 109,375 with every name at the cut, a run measured with EVERY field present at 734 bytes (a real one 146 to 299). The hard-ceiling pin moved 250,000 to 300,000 (nine kinds of at most 100 events); the line beside it (a tenth of the zip) is the pin that does not move.
- **Tests:** `tests/test_storage_events_runs.py` (62: the API, every end branch of the real `VolumeBackupManager`, the AST pins), `tests/test_storage_events.py` (the full-journal fixture now carries the runs), six exact-line allowances in `tests/test_sink_sweep_records.py`. Mutants, each failing a named test: 37 (the fact table, the class-name shape, the refusal key, each end branch of the three workers, the three nets, the free-space order, the caps, the summary failure, the budget). Ruff total 413 (ceiling 417); mypy clean.
- **Stated limits (in the PR body):** the legacy single-file restore (`restore_legacy_path`), the folder backup, restore and verify (`folder_backup.py`) and the newsletter import (`import_job.py`) open a run journal line and write NO storage event; an older build reading a file with these kinds drops them on its next write; the shape check accepts a one-word message, so the pin on the call sites is the real guard.
