## 2026-10-15 — redirect bypass: host lists on the wiki, ORES and DuckDuckGo sessions (PR #1393)

The parked LOW from the sink sweep (RC2's note `LOW-redirect-bypass.md`, kept in the project pool outside the repo): the Wikipedia/Wikimedia client, the ORES client and the DuckDuckGo search followed any redirect from their fixed
endpoints with no host check and no connect-time SSRF guard. requests calls `Session.send` for the first request and again for every redirect hop, and `GuardedSession` only overrode `request`, so the app-level kill-switch refusal and the transport decision ran on the first
URL only (`requests` carries the proxy mapping onto hops and the airplane socket guard stands under both; no check looked at WHERE a hop went). `GuardedSession.allowed_hosts` (optional, default none) is now checked in `send`, before every request: `EthicalFetcher._refuse_parser_mismatch`, then https only, no userinfo, port 443 only,
and a listed host, each against BOTH readings of the URL (`urllib3`'s and `urlparse`'s: `requests` 2.32.2 and later connects to the latter) (an exact host, or a leading-dot suffix meaning any host under it and never the bare domain or an empty label). A refusal is `RedirectRefused`, a `RequestException` that is not a `ConnectionError`, raised before the
request is sent, naming the clause and never the address. Lists: wiki client `wikimedia.org`, `.wikimedia.org`, `.wikipedia.org` (its one shared session also serves pageviews on the bare apex and EventStreams); ORES
`.wikimedia.org`; DuckDuckGo `duckduckgo.com`, `.duckduckgo.com`. `following_session` keys its cache on the list. Every other session stays unlisted and is pinned in `UNLISTED_SESSIONS` with zero slack and a reason per row: the bulk downloads, the model installer and the statistics catalogue (request-chosen hosts), and,
as the open remainder, six fixed API endpoints (five Wikidata loaders and the Hugging Face release check) that a later change can list. List entries must be names of two or more labels (`_checked_hosts`). `walk.refusal_token` names a
`RedirectRefused` `request_refused`, not `connection_failed`. Tests: `tests/test_session_host_list.py`, each refusal clause with a test only it can fail, and a mutation matrix over the check
with a green-baseline gate and no survivor (a scratch script, not committed). One independent read: 0 block, 2 should-fix, 9 low, folded. Docs: `docs/SECURITY.md`. Not covered, and said so: the unlisted sessions; no connect-time SSRF scope for these three (the hosts are fixed public ones and the list is the gate).
