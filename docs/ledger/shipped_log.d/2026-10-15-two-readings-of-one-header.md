## 2026-10-15 — the boot page check: pages in the file against the header's, at every open, as a fact (PR #1389)

- **2026-10-15 · wal-disk-pool/page-reading (WAL / disk thread; diagnostics-members plan, PR B of A then B).**
The Asus machine's file held 14,981 pages more than its header counted, and nothing in the bundle could say when that began: the only place that read both was `database/verify.py`, after damage had been found. `src/monitoring/page_reading.py` now takes the reading at every open and keeps it on the journal's `open` event as `pages` (`source`, `state`, `pages_in_file`, `pages_in_header` (header-bytes) or `pages_in_database` (engine), `difference`, `page_size`, `header_valid`, `trailing_bytes`, `file_bytes`, `wal_bytes`, `refused_attempts_before`; about 296 bytes of each of the ten events at the widest). At boot `forensics.record_session_start` (or `take_boot_wal_reading` ahead of it, for `serve`) reads the file's first 100 bytes and its length with no engine, before any connection can unlink the `-wal`; at an unlock `_unlock_locked` reads `PRAGMA page_size` and `page_count` off the verify connection before it is checkpointed and closed. A plaintext header whose change counter equals its version-valid-for number gives a `difference` (file minus header); an invalid one gives none, because SQLite would not use it; an encrypted file read by bytes is `encrypted-or-foreign` with its length alone. One WARNING line, counts only, is written when the file holds MORE pages than the database counts and there is NO `-wal` (`boot: ...` / `unlock: ...`).
What it cannot say (all in OPEN_QUEUE.md): a store opened at boot by `OO_DB_PASSPHRASE` is encrypted and has no unlock, so it keeps only the length; the engine's count is the log's last commit when there is a `-wal` (the independent read of the first head found the Asus signature logged about a healthy store whose log held a drained incremental vacuum, so the field is named for what it is and the line needs no log), it cannot show an invalid header, and either sign of the difference is expected with a log; an unlock's reading follows any refused passphrase of the process, which folds the log (`refused_attempts_before`); the reading checks no page.
Rode with it: the journal's reset removes the paths it used and never resolves `data_dir()` (the coordinator's lows 4 and 5); `_CLASS_ONLY_HELPERS` reads the bodies of the two helpers the log guard excuses by name (low 3); the write gate's release line and watchdog line scrub the holder's thread name; the class-only check reads the helpers' bodies default-deny (fifteen planted bodies, among them a renamed parameter, `traceback.format_exc()`, `exc.errno` as text and a module-level rebinding); the tombstone bound's reasoning is written beside `ENDED_KEYS_MAX`; the pool-reader marker test has its positive control; the strict `>` and the restored `writer._JOURNALED_HOLD`. Budget re-measured: 41,538 bytes with ordinary names and 86,248 with every name at the cut, against the row's 90,000 (4 per cent over, was 8).
