## 2026-11-04 — a catalogue row can declare its identity so a treaty is one law (v0.6.0 C-L2, PR #1716)

Row C slice S3 (Q908, Q901's note, Q902 d, Q930; coordinator ruling R420). A treaty is published in several languages by construction, and `lane_sync` could not align them: it keys a law on the number the adapter read out of the body and otherwise on the document's own URL (`local`), and a treaty page offers no number a parser can trust, so six language URLs were six unrelated `local` identities. A `documents:` row in `configs/legal_sources.yml` (or the generated file) may now declare `identity: {scheme, value}`, `doc_type` and `translation_kind`. `src/law/declared.py` (new, pure) checks a declaration (`declaration_problems`), reads it normalised (`declared_of`), finds it by the row's own `(jurisdiction, url)` by exact equality (`declared_for`) and checks the rows that declare one law against each other (`consistency_problems`: one `doc_type`, at most one `original`). `lane_sync.record_document` reads the catalogue once for both the declaration and the licence and records what the row states; a declared identity wins over a number the adapter read, so a document does not change identity between passes depending on whether a parse succeeded. A row that declares nothing is recorded exactly as before (the test compares the inputs for `None`, `Declared()` and no argument).

Rules the slice holds, each with a test that fails when it is dropped: the value is the operator's statement and is never derived from the URL; the scheme is the existing `act-number` (the model's closed vocabularies are unchanged, no schema change, no migration); every declared value must be a STRING (an unquoted `1.10`, `0123` and `yes` are the float 1.1, the octal 83 and true in YAML, and `1.10` and `1.1` would have shared one identity); a declaration the model refuses (unknown scheme, empty value, unknown key inside `identity`, a non-string, `doc_type` outside the vocabulary or one of the four refused by name, `translation_kind` outside it, a jurisdiction that is not alpha-3 or INT) makes the WHOLE row undeclared with a warning rather than applying the half that parsed, and fails `scripts/validate_legal_catalog.py` (generated AND curated rows) and `tests/test_law_declared_identity.py` (which also reads both committed catalogues, vacuously today); a lookup that raises is logged and the document is recorded undeclared, because `record_document` is documented never to raise; the same declared value in INT and ZZZ is two laws; a neighbouring URL, a prefix and the same URL in another jurisdiction declare nothing for this one.

HOW A DECLARATION IS TAKEN BACK (the catalogue is the only writer, so each field must be retractable from it). `translation_kind` is per language version: the pass writes what the row states and `unrecorded` when it states nothing, so deleting the key retracts it and moving the `original` from one version to another needs no extra step. `doc_type` belongs to the identity, which every version's pass writes to: `ensure_identity(doc_type=None)` (new) means "this caller states no category" and leaves a recorded one alone, so five versions declaring `treaty` and one declaring nothing cannot trade the column back and forth in whatever order the passes run; to take a category back a row declares `doc_type: unspecified`, which is a statement like any other. The identity is read fresh each pass: changing it re-files that version on its next pass and the identity it left stays with its other members.

Evidence. `tests/test_law_declared_identity.py` (45 tests, ~9 s) runs the real path end to end on a synthetic treaty: `register_documents` from `tests/fixtures/law/synthetic/treaty/catalogue.yml`, then `track_document` for six HTML bodies in `zxx-en, fr, es, ru, ar, zh` (one right-to-left, three non-Latin scripts) with no socket. Result: one `LawIdentity` (`act-number`, INT, `mtdsg:xviii-1`, `treaty`, `international`), six `LawDocumentMeta`, six separate baselines, the group reads the same from every member (original `zxx-en`, five others), `reader_payload` of each version lists the five others with their kinds, a second pass changes nothing. Negative space: a second declared treaty on the same host and an undeclared row stay apart (three identities); an undeclared row is `local`, `unspecified`, `unrecorded` as before; a misspelt scheme leaves the row `local` and logs it; retraction (moving the original from en to fr leaves exactly one original, an explicit `unrecorded` and an explicit `unspecified` take a value back, omitting `doc_type` does not); an odd YAML key in the identity block cannot break tracking. Twenty-one mutants of the new code were run and all twenty-one were killed. An independent Opus read found six things, all reproduced and folded: a first version of the model change had made a declared kind and category irreversible (`record_document` then reset nothing and the catalogue and law.db disagreed about which version is the original), a non-string YAML key raised out of `record_document`, unquoted YAML numbers merged two laws, the validator skipped curated rows, and two wording points in this entry.

What is NOT done, stated. (1) NO live treaty ingestion: no UN Treaty Collection or WIPO Lex URL is in the tree, because neither host answers from the build sandbox and the brief asks for operator-verified URLs. The fixtures are invented (hosts on the reserved `.test` TLD, `zxx-*` tags, sentences written by the model and not reviewed by a native speaker). The slice's done-when, "one treaty ingested in six languages, aligned", is therefore shown on the synthetic treaty only. (2) No new host, no licence token, `docs/SECURITY.md` and `src/static/net-hosts.js` untouched.

Open operator items (R420). (a) Six verified language URLs of ONE UN treaty, with the robots and licence look, to put in the catalogue with a declared identity; `treaties.un.org` is already in the 260-host count and the law lane is a class lane. (b) `wipolex.wipo.int` is already a curated SOURCE domain (`configs/legal_sources.yml`, the WIPO Lex row) but is absent from the 260 hosts `docs/SECURITY.md` and `net-hosts.js` state: `_YAML_DOMAIN` in `tests/test_security_endpoint_enumeration.py` reads a `domain:` at the start of a line and none of the 51 curated source domains is written that way (flow-style rows), so only the hosts that also appear in a URL are counted. That measurement gap pre-dates this slice and is not touched here (R420 fences those two files); a WIPO Lex DOCUMENT row would bring the host into use by the law tracker, so whether the enumeration needs correcting first is the maintainer's to rule. (c) `model.LICENCES` has no UN or WIPO token, so a treaty row inherits `unknown` until a ruling adds one. (d) WIPO Lex is typed `ip`: a treaty hosted there is category `ip`, and the C-L1 floor counts it in `non_law_documents`, crediting no country; whether a treaty hosted by an IP office should count is a ruling. (e) The UN treaties' texts are typically equally authentic, and the vocabulary has one `original` per group (`official` is a government's translation): the operator declares the kind per row or leaves it `unrecorded`; adding an "authentic text" kind would be a model ruling. (f) Observation, not changed: `track._MIN_TEXT` is 200 CHARACTERS, so a CJK page needs far less content than a Latin one to fall under it ("no usable text extracted"); the first draft of the synthetic `zh` body (115 characters) did exactly that. A real treaty is thousands of characters, but a short Chinese or Japanese document would read as empty.
