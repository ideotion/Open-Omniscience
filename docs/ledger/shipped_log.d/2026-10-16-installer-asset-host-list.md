## 2026-10-16 — the Ollama installer's asset download is held to GitHub's release hosts (PR #1409)

The asset half of R141. `src/llm/installer.py` now has one helper, `_get_within(url, hosts, *, timeout, download)`, behind both getters: `_default_get_json` (the release lookup, `GITHUB_API_HOSTS = ("api.github.com",)`, 30 s) and `_default_get_bytes` (the script the release names, `GITHUB_ASSET_HOSTS = ("github.com", "release-assets.githubusercontent.com", "objects.githubusercontent.com")`, 120 s). Each builds a `guarded_session` with the egress purpose `PURPOSE_AI_INSTALL`, a per-fetch isolation token and its own list, and the list is checked in `GuardedSession.send` on the first request and every redirect hop (https only, no credentials, port 443, no `%`, the host listed under both the urllib3 and the urlparse readings). Because `requests` rejects a malformed address before `send`, with an error that quotes it, the address is also pre-checked with `refuse_unlisted_host` inside the same `try`; a value that is not text is refused as "the release lists no download URL". A refusal raises `InstallerRedirectRefused(download=True)` with its own fixed sentence (`DOWNLOAD_MESSAGE`: "was to be downloaded from somewhere this app does not follow ... Nothing was run and nothing was installed ... https://ollama.com/download"), raised after the `except` block so it has no cause and no context, with only the class name in the log; `/api/llm/install/prepare` answers 502. A 404, a dropped connection, a timeout, `TransportUnavailable` and `NetworkBlocked` are not called refusals.

The hosts are the GitHub hosts the consent popup already lists for the Local AI lane (`src/static/net-hosts.js`); a test keeps the two equal. They come from this repository's own record (`docs/SECURITY.md`: `release-assets.githubusercontent.com` recorded 2026-09-27, `objects.githubusercontent.com` before GitHub moved it), not from a look at the live redirect, which the build sandbox cannot reach. The registry entry `github-release-asset-hosts` (12 months, pinned to `GITHUB_ASSET_HOSTS_AS_OF`) says its date is when the record was written, and the open-queue entry keeps one operator step STILL OPEN: follow the real redirect chain of the `install.sh` asset from the latest `ollama/ollama` release on a machine that reaches GitHub and compare each hop. A move of the storage host makes the install refuse with a sentence that points at ollama.com/download (the safe direction); the fix is the list, the popup lane, SECURITY.md and the registry entry.

Not done, and said so: the list limits where the request goes, not what is installed (`github.com` lets the response name any `github.com` path), so the `sha256` GitHub attests, over TLS from `api.github.com`, is still what refuses a different script; an HTTP or connection error after a followed redirect is an ordinary failure whose text can carry the listed storage address; a malformed `Location` fails inside `requests` as an ordinary error with nothing sent. `UNLISTED_SESSIONS` no longer holds the installer. `docs/ledger/RULINGS_INDEX.md` amends R141 in place (no new number); R137, R139 and R140 are carried by their owning threads.
