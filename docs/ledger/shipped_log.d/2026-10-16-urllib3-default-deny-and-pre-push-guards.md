## 2026-10-16 — the urllib3 log filter is default-deny over a table the installed library proves, the library is bounded and registered, and `scripts/guards_for_diff.py` picks the checks before a first push (PR #1420)

The export lane's follow-up to #1414 (the coordinator's pick of items 1 and 3, 2026-10-16; item 2, a redirect-look probe in the release run, was parked). The filter that keeps the request path out of the HTTP library's own log lines rewrote the target argument of the lines it knew and let the rest through, on four loggers, from the shapes of `urllib3` 2.8.0, and nothing recorded which release it had been read from. `src/ingest/urllib3_log.py` now carries `SHAPES`: for each of the library's NINE module loggers, every log call (template, the source text of each argument, the positions that carry a target), read from 2.7.0 and 2.8.0, which log identical templates and arguments. A record that matches an entry has its target positions rewritten (an absolute address keeps scheme, host and port; anything else becomes `[path withheld]`); a record that matches NO entry (another template, another number of arguments, a non-tuple `args`, a message that is not text, including an unhashable one) has its message withheld whole, with the logger, the level and the exception's class name kept and the arguments, `exc_info`, `exc_text` and `stack_info` gone. It never drops a record and withholding twice is idempotent.

What keeps the table true: `tests/test_urllib3_log_withholds_the_path.py` reads every log call of the INSTALLED library by AST and fails by name on a new, changed or removed call, an argument the table does not name, or a module logger the filter does not cover; it also measures that the objects the table passes unchanged (`Retry`, the request errors) do not quote the target. `pyproject.toml` bounds the library to `urllib3>=2.7.0,<2.9` (the ceiling is the first release not read), the registry entry `urllib3-log-shapes` records floor, verified release, ceiling and an upstream check, and `tests/test_external_freshness.py` ties the pyproject text to the entry, so an upgrade is a decision with the checklist in `docs/maintenance/EXTERNAL_DEPENDENCIES.md`. 32 mutants of the filter (the default-deny rule, each argument check, the target positions, the idempotence, an unhashable message, `stack_info`) are each failed by a named test; the four real-socket tests each also assert the withheld sentence is absent. Not covered, said so in the module, `docs/SECURITY.md` and the queue: a child logger created under those names, and the traceback of a known shape (the header-parsing warning logs the server's header text).

`scripts/guards_for_diff.py` (with `docs/maintenance/PRE_PUSH_GUARDS.md` and `tests/test_guards_for_diff.py`) answers the miss that cost #1414 a CI cycle: it picks the tests `main` added since the branch left it (found through the merges into the branch), the tests the branch changed (untracked included), the test files that walk the tree, and runs the blocking ruff lane and the style ratchet with its ceiling read from `ci.yml`. It says when the base is ahead of the branch. Its selection is tested on a throwaway git repository with a `main`, a feature branch that merged it, an uncommitted edit and an untracked file; 21 mutants, 20 killed, the survivor equivalent to the existence check.
