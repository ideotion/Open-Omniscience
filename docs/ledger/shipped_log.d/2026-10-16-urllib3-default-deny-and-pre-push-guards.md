## 2026-10-16 — the urllib3 log filter fails closed over every carrier, is default-deny over a table the installed library proves, the library is bounded to the releases read, and `scripts/guards_for_diff.py` picks the checks before a first push

The export lane's follow-up to #1414 (the coordinator's items 1 and 3 plus the findings of its fold check, 2026-10-16; item 2, a redirect-look probe in the release run, is parked). The correction first: the filter #1414 merged did NOT cut the header-parsing record. `Failed to parse headers (url=%s): %s` passes the `HeaderParsingError` object and `exc_info=True`, and its text is the raw header bytes the server sent after its first malformed line, a `Location` with its signed query included; #1414 cut the text arguments and let those two through, so a 302 with a signed `Location` after a bad header line (reproduced against a real socket, on a fetch that succeeds) reached the log and the error journal on `main`. This PR fixes it.

`src/ingest/urllib3_log.py` treats every carrier of a record as untrusted (the message, each argument whatever its type, `exc_info`, `exc_text`, `stack_info`, any attribute `extra=` added) and carries `SHAPES`: for each of the library's NINE module loggers, every log call (template, the source text of each argument, the positions that carry a target, the keywords), read from 2.7.0 and 2.8.0, which agree on every template, argument and target position (2.8.0 adds one keyword, an `extra=` on the retry warning). A record that matches an entry has its target positions rewritten (an absolute address keeps scheme, host and port; anything else becomes `[path withheld]`) and its other arguments reduced (a number or `None` as is, text cut the same way, anything else `<ClassName>`); the exception, the stack and the extras are dropped. A record that matches NO entry (another template, another number of arguments, a non-tuple `args`, a message that is not text), or whose handling raises, has its message withheld whole, with the logger, the level and the exception's class name kept. It never drops a record and withholding twice is idempotent. The filters sit on the nine loggers and a log-record factory applies the same rule to any other logger under the `urllib3` name, with one limit stated: the factory runs before `Logger.makeRecord` copies `extra=` onto the record, so for a logger outside the nine its message, arguments and traces are cut and an `extra` attribute is not (no release logs that way, and the qualification test fails by name on a logger it does not list).

What keeps the table true: `tests/test_urllib3_log_withholds_the_path.py` reads the INSTALLED library's log calls by AST (a logger bound any way, every call of a template, the keywords) and fails by name on a new, changed or removed call, an argument or keyword the table does not name, or a logger the filter does not cover; the objects the table passes (`Retry`, the request errors) reach the log as their class names, so their text is never read, and four real-socket cases run, one of them the signed `Location`, which also runs with the filter off and must leak. `pyproject.toml` bounds the library to `urllib3>=2.7.0,<2.8.1` (the ceiling is the first release NOT read, patch releases included), the registry entry `urllib3-log-shapes` records floor, verified release, ceiling and an upstream check, `tests/test_external_freshness.py` ties the pyproject text to the entry, and the CI job `urllib3-floor` runs the table test on 2.7.0. Also in this PR: a wrong-typed release member in the installer (`{"assets":[1]}`) is a named `InstallerFetchFailed`, and the session-host-list walk resolves only the lists the pin reads (a list reached as `wide.API_HOSTS` is not resolved). 88 mutants of the filter (87 failed by a named test; the 88th changes nothing a caller can see), 36 of the host-list walk and the pinned subclass check are each failed by a named test. Not covered, said so in the module, `docs/SECURITY.md` and the queue: a process that never imports `src.ingest` (two operator scripts) and the `httpx` logger (full URLs at INFO, loopback clients).

`scripts/guards_for_diff.py` (with `docs/maintenance/PRE_PUSH_GUARDS.md` and `tests/test_guards_for_diff.py`) answers the miss that cost #1414 a CI cycle: it picks the tests `main` added since the branch left it (found through the merges into the branch, either way round; `--since REF` for a rebase), the tests the branch changed (untracked included), the tests that name a changed support file (a helper, a node test, a data file) or sit below a changed `conftest.py`, the test files that walk the tree, and runs the blocking ruff lane and the style ratchet with its ceiling read from `ci.yml`. It says when the base is ahead of the branch. Its selection is tested on a throwaway git repository (44 mutants, all killed). Its first run on this branch found the one test the branch had not run: `tests/test_sink_sweep_records.py` (added by `main`) flagged the three places the filter touches `exc_info`, and `NOT_RECORDS` now carries a counted entry for `src/ingest/urllib3_log.py` saying why.
