## 2026-10-15 — redirect bypass, the remainder: host lists on the five Wikidata loaders and the Hugging Face release check (PR #1394)

PR #1393 put a host list on the Wikipedia, ORES and DuckDuckGo sessions and pinned every other unlisted `guarded_session` / `following_session` in `UNLISTED_SESSIONS`; its independent read found six of the eleven rows were fixed API
endpoints of the same shape, not CDN redirectors. This change lists them. Each module states the host of the one endpoint it builds and passes it as `allowed_hosts`: `src/analytics/wikidata_rings.py:API_HOSTS` and
`src/catalog/wikidata_enrich.py:API_HOSTS` (`www.wikidata.org`, behind the four Wikidata loaders in `src/catalog/wikidata_apply.py`, `src/entities/items.py`, `src/entities/gazetteer_build.py` and `src/analytics/ring_loader.py`),
`src/catalog/wikidata.py:WDQS_HOSTS` (`query.wikidata.org`, the country-catalogue SPARQL query in `src/catalog/discover.py`) and `src/monitoring/release_run.py:HF_API_HOSTS` (`huggingface.co`, the weights-digest fetch). Exact hosts, pinned equal to the endpoint's host by a test, not a family
suffix: a redirect from one of them to a sibling host (a renamed WDQS graph, say) is then refused with a `RedirectRefused`, which is the failure to want when the redirect behaviour of those hosts could not be looked at. The sandbox this was
built in cannot reach any of the three (its proxy refuses the tunnel), so the lists come from the URLs the code builds, and `docs/SECURITY.md` and the PR say so. `UNLISTED_SESSIONS` shrinks to the five modules whose hosts are request-chosen or move
(dumps, OSM, segmented downloads, the model installer, the statistics catalogue); the installer's release lookup on `api.github.com` is a fixed endpoint still unlisted and its row says so. The table's test now fails on a row with an empty reason. Carried from the check of #1393: the parser-split test asserts its premise (the two real parsers do disagree on
`https://de.wikipedia.org\@evil.test/`), and the one-reading cases now cover a reading with no host (`None` and empty) and a percent in one reading only. Tests: `tests/test_session_host_list.py`, one end-to-end test per module through its own default
getter with a scripted adapter (a redirect off the host is refused before it is sent; one on the host is followed), and a test that each list equals the host of its endpoint and a neighbour host is refused. The source-typing pass counts a refused source (`sources_refused`, class name only, "N refused" on the Diagnostics button) instead of skipping it as "no match". `docs/SECURITY.md` also names the release run's one in-app read of `huggingface.co`. One independent read: 0 block, 4 should-fix, 7 low, folded. Docs: `docs/SECURITY.md`, which says what each loader does with a refusal.
Not covered, and said so: the five unlisted modules; the redirect behaviour of the three hosts was not observed live.
