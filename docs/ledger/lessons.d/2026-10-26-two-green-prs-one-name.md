## 2026-10-26 — two pull requests, each green on its own tree, defined one function name twice, and the later one won for the whole module

`src/monitoring/forensics.py` carried two top-level `_seconds_between`: a float of seconds, `None` when a timestamp cannot be read (the collect-perf tick's time into the pass), and a whole number of seconds, `None` for a reversed order (the previous session's teardown time). Each came from a different pull request: the whole-number one (near the end of the file) was already on `main` when the float one (near the middle) landed from a branch cut before it, so neither pull request's CI could see both. The whole-number one sits later in the file, so it won. Python keeps the later `def` for every caller in the module, the calls written for the first included, so the tick's `since_pass_start_s` read `1` where the test expected `1.5`, and `tests/test_session_forensics.py` failed on `main` and in every pull request cut from it until the second was renamed (`_whole_seconds_between`).

**Why nothing said so.** Ruff's F811 ("redefinition of unused name") ignores every name that matches `lint.dummy-variable-rgx`, whose default is `^(_+|(_+[a-zA-Z0-9_]*[a-zA-Z0-9]+?))$`: every name with a leading underscore, so every module-private helper and every private method. Measured with ruff 0.16.9 on the pre-fix file: silent as it stood; with only the underscore removed from the name (four occurrences) it reports `Redefinition of unused 'seconds_between' from line 665`; with the pattern tightened to `^_+$` it reports the original. A call inside a function body does NOT make the first definition "used" for F811 (ruff resolves those after the module body, so they bind to the later definition); only a use at import time, in the module body, does. A first version of this lesson put the cause on the first definition having callers, which was wrong; an independent read found it. Tightening the pattern for the whole repository is not the alternative: it takes the blocking ruff lane from 0 findings to 130. Merging the two branches textually was clean as well: the definitions sit hundreds of lines apart, far from any conflict.

**The rule.** A name defined twice in one scope is a defect in itself, with no judgement needed about which definition is meant, and the private ones are the ones ruff cannot see. `tests/test_no_duplicate_top_level_defs.py` reads every module under `src`, `scripts` and `tests` and fails on a function or class name defined twice directly in a module body, or twice directly in a class body (a definition under `if` / `try`, the name `_`, and `@overload` stubs that come before their implementation are not read; in a class body the property pair and `register` are not read; at module level `register` is a repeat, since `@f.register(int) def f` replaces the dispatcher). It found exactly one name in 2,284 files, so it is a ratchet at zero and not a list of exceptions. When two branches add helpers to one large module, a merge that is textually clean is not evidence the names are distinct: the check that sees it runs on the merged tree.
