## 2026-10-26 — two pull requests, each green on its own tree, defined one function name twice, and the later one won for the whole module

`src/monitoring/forensics.py` carried two top-level `_seconds_between`: a float of seconds, `None` when a timestamp cannot be read (the collect-perf tick's time into the pass), and a whole number of seconds, `None` for a reversed order (the previous session's teardown time). Each came from a different pull request: the whole-number one (near the end of the file) was already on `main` when the float one (near the middle) landed from a branch cut before it, so neither pull request's CI could see both. The whole-number one sits later in the file, so it won. Python keeps the later `def` for every caller in the module, the calls written for the first included, so the tick's `since_pass_start_s` read `1` where the test expected `1.5`, and `tests/test_session_forensics.py` failed on `main` and in every pull request cut from it until the second was renamed (`_whole_seconds_between`).

**Why nothing said so.** Ruff's F811 ("redefinition of unused name") reports a second definition only when the first was not used in between. Measured on a three-case file: a method defined twice and a test function defined twice are reported; a module-level function that is called once before its second definition is not. The usual way a helper ends up with a twin is that it has callers, so the case that matters is the one F811 is silent on. Merging the two branches textually is also clean: the definitions sit hundreds of lines apart, far from any conflict.

**The rule.** A name defined twice directly in a module body is a defect in itself, with no judgement needed about which definition is meant. `tests/test_no_duplicate_top_level_defs.py` reads every module under `src` and `scripts` and fails on one (a definition under `if` / `try`, an `@overload` stub and a `@x.setter` / `@x.register` repeat are not read). It found exactly this one in the tree, so it is a ratchet at zero and not a list of exceptions. When two branches add helpers to one large module, a merge that is textually clean is not evidence the names are distinct: the check that sees it runs on the merged tree.
