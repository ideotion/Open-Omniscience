## 2026-10-27 — A sentence many writers say and one reader matches is a constant, and the reader's test is built from it (R328)

**What was found.** `network refused: airplane mode is engaged` was a string literal at nineteen places under `src/`: eight HTTP 409 `detail`s (`api/governments.py`, `api/source_management.py` x2, `api/entities.py`, `api/insights.py`, `api/diagnostics/discovery.py` x2, `api/ingestion.py`), the four statistics fetchers (`stats/fetch.py`), three catalogue loaders (`catalog/qid_labels.py`, `discover.py`, `wikidata_apply.py`), two entity loaders (`entities/gazetteer_build.py`, `entities/items.py`), the ring loader and the mailbox import. Each is a pre-check, `if kill_switch_active(): raise ...`, before any request is built. The one reader of the text in `src/` is in another language, `_wikidataRefusedByAirplaneMode` in `src/static/app-insights.js` (`/^\s*(?:network refused:\s*)?airplane mode is engaged\b/i`, anchored on the start by R298). The R317 constant and its pin did not see the nineteen: that pin scans for the fetcher's OTHER sentence (`network kill switch is active -- ...`), so nineteen writers and a copy in the reader depended on a text that nothing tied together.

**How strong the coupling to the reader is, measured (the Opus read of this change, S1).** Weaker than the ruling's wording. `_wikidataRefusedByAirplaneMode` has one caller, `entitySpineFetch`, fed by one route, and that route refuses with a 409: `api()` always sets `err.status`, the reader returns true on `e.status === 409` BEFORE it reads the text, and none of the nineteen writers produces a message with no status on that button. So a rewording at a writer today would not change that toast; the text branch is the fallback for a status-less message, and it is the copy this change ties to the definition. The one path where the sentence really reaches the button is a job that ends `state: "error"` (the switch engages between the POST and the job's first check, `fetch_items` raises `AirplaneRefusal(refusal())`): `app-insights.js` prints `"Wikidata fetch failed: " + job.error` there WITHOUT calling the reader. That gap is older than this change; sending that branch through the reader is a UI edit in a file this lane does not own, and it is routed as a proposal.

**The change.** `NETWORK_REFUSED` beside `KILL_SWITCH_REFUSAL` in `src/ingest/fetch_verdict.py`, text unchanged; the nineteen sites say it by name; the six that continue the sentence (`, so Wikidata labels cannot be ...` at two sites, ` (kill switch)`, `(the gazetteer's Wikidata join ...`, `(the Wikidata item fetch ...`, `(the Wikidata ring load ...`) build on it with an f-string. No behaviour or UI change, and that is shown, not asserted: an AST fold of every message that carried the sentence at the parent commit and after the edit, with the constant substituted, is the same string for all nineteen (`/mnt/project-files/export-lane/r328-network-refused-2026-10-27/bytes_same.py`; the Opus read ran its own fold and agreed). The constant is NOT read by `_OFFLINE_RE` (a pre-check refusal is not a failed fetch; `classify_fetch_failure` still says `other`, exactly as before), and a test now says so.

**Rules.**
1. **A sentence with more than one writer and a reader that matches it is one constant, defined beside the reader's sibling, and a continuation builds on it.** The opening words stay the sentence, which is what an anchored reader needs.
2. **A module that must stay light does not import the constant at its top.** `src/entities/items.py` held the sentence as a module constant and imports neither `src.ingest` nor `requests` when it is imported (measured, twice: both absent from `sys.modules` after `import src.entities.items`). `REFUSAL` became `refusal()`, which imports the constant where it raises. Nothing else read `REFUSAL`.
3. **The scan reads the mechanism, with no exclusion list.** The literal scan of `test_kill_switch_refusal_constant.py` folds `"a" + "b"` and the pieces of an f-string into the text they build (a placeholder is a NUL, so a sentence cut by one is not one), decodes bytes as UTF-8, and for the new sentence squeezes every run of whitespace out of both sides, because the JS reader matches `network refused:\s*airplane` and a space lost at a line wrap is the same copy for it. Docstrings still do not count. It supersedes the R317 lesson's remark that `+` pieces cannot be seen. STATED LIMITS, so nobody assumes more: a sentence built from a value (a variable, `.join`, `.format`), by `%`, by `+=` or by `b"..." + b"..."` is not seen. The use count follows the three ways a name comes in (`from ... import NETWORK_REFUSED [as X]`, `from src.ingest import fetch_verdict [as M]`, `import src.ingest.fetch_verdict [as M]`), fails a relative or re-exported import and a rebinding, and is pinned at 19 with the sites it protects named beside it. It counts READS by name; it does not drive the sites, so a dead read beside a raise of other text still counts, which the literal scan and the byte-for-byte fold cover.
4. **The planted copies are written from the constant, at a position, quoted by the unparser.** The detector test plants a literal, a bytes copy, a `+` copy, an f-string copy, a copy that lost a space, a placeholder-split text (not a copy) and a docstring (not a copy), plus a `.js`, a `.json` and a `.html` copy for the non-Python half (the empty-X trap applied to it too), each with `ast.unparse`/`repr` from halves of the constant. A first draft spelled the sentence in the plants and split it at `": "`; the read measured that a reader-compatible rewording with no colon (a `ValueError`) or with a non-ASCII dash (a `SyntaxError` in the bytes plant) failed THAT test and nothing else, the one test whose comment said it could not. A test that fails for a second reason hides the first.
5. **The reader in the other language is driven with the constant.** `test_wikidata_refusal_toast.py` passes `NETWORK_REFUSED` to the node run in `OO_NETWORK_REFUSED`; `wikidata_refusal_node_test.js` builds its inputs from it (the bare sentence, the sentence with a continuation, and the controls that quote it inside another failure) and prints which copy it used, so a driver that stopped passing the constant cannot go on passing quietly (the direct `node` run says "this file's own copy"). Only the cases that carry no status read the text, so those are the ones that go red on a rewording; the 409 cases pass whatever the sentence is.

**Mutants (thirteen runs: ten red, three controls green).** Constant reworded (red: the pin literal and the node run); constant reworded AND the pin literal edited to `network refused: airplane mode is on` (red: ONLY the node run, which is what the build from the constant is for); one site back to a literal (red: the scan and the count); one site that drops the sentence (red: the count at 18); one site that assembles it from pieces (red: the scan and the count); one site with a space lost at a line wrap (red: the scan, which squeezes whitespace, and the count); one site importing it relatively (red: the import-source check); the JS reader reworded (red: the node run); `refusal()` back to a literal (red: the scan and the count); a stray `.json` copy under `src/static` (red: the non-Python scan). Controls, green on purpose: an aliased import; a reader-compatible rewording with no colon, and one with a non-ASCII dash (`... engaged — no request was built`), each with the pin literal edited alongside: a deliberate rewording that the reader still matches costs the one literal in the pin and nothing else.

**Left alone, on purpose.** `entities/gazetteer_build.py::_reraise_refusal` is `f"network refused: {record_text(exc)}"` around whatever the guarded fetch said: a prefix on another exception's text, not this sentence, and what it should say is not part of this change. `src/wiki/ores.py` (a log line) and `src/ingest/airplane.py` (the socket guard's `airplane mode is engaged: refusing a network connection ...`) are different sentences with their own readers. Two tests read the substring themselves (`tests/test_consent_coverage.py`, in a file the OSM lane owns, and `tests/test_gazetteer_build.py`), and two keep a stub copy (`tests/test_typed_key_routes_scrub.py`, `tests/test_country_data_auto_start.py`); they stay green after a rewording and become copies of a sentence nobody raises, which is a proposal for the lane that owns each, not a change here.
