## 2026-10-29 — 70 vacuity-prone asserts never saw an item; eight were vacuous (in six files), eight bare `pytest.raises(Exception)` accepted any failure, each proven by a source mutant that stayed green (parent sweep R385, candidate 3: the comprehension twin of the zero-iteration loops)

**What the loop audit left out.** [`2026-10-28-zero-iteration-loops-with-asserts.md`](2026-10-28-zero-iteration-loops-with-asserts.md) counted `for` loops. The same shape lives in an `assert all(x ... for x in rows)`, `assert not any(...)`, `assert not [x for x in rows if bad(x)]`, `assert [...] == []` and `assert set(found) <= allowed`: each is TRUE of an empty `rows`, so a fixture that produces nothing makes them pass, and a reader cannot tell from the source whether it does.

**Method (no repo edit).** An AST scan found 1,689 such asserts in `tests/` (735 `== []`, 531 `all`, 274 `not any`, 87 `not [..]`, 50 `<=`, 12 `len(..) == 0`), too many to read. A pytest plugin outside the repo (`/mnt/project-files/fix-source-qualification/empty-fixture-audit-2026-10-29/emptycount.py`, the loop counter's sibling) wraps the OUTERMOST iterable of each comprehension, and the single argument of `all`/`any`/`set`, inside those asserts in a counting generator, and records per site how many items it saw. Whole suite, three shards in a separate worktree (28 to 43 minutes each): 986 measurable sites, **70 that saw no item in any test**, 7 that saw none in some tests. Six tests failed (the stale-install `test_readme_version_matches_package` among them) and five errored in setup (`test_discovery_isolation.py`, `test_commodity_csv_bound.py`); none was investigated, and the sites in those tests are counted up to where they stopped. The `== []` asserts over a call result (`f(x) == []`, about 700) have no iterable to count and were not measured.

**The 70, by hand, each against "is there a positive control in the same test or its twin".** Sixty-two were sound: an absence asserted after the same test showed the thing present (`test_database_verify.py`, `test_repair_kept_copy.py`, `test_release_run.py`, `test_qualification_recheck.py`...), a negative twin of a test that fires (`test_corroboration.py` at 3 versus 4 articles, `test_write_gate_holder.py`, `test_data_location.py`), or an allowlist that is empty by design (`test_no_raw_exc_info.py`). Eight were vacuous (six files; the scanner samples are three sites), each with a mutant that stayed green under the old test:
1. `test_keyword_daily_rollup.py::test_kind_filter_reproduces_apply_kind`: the fixture has no entity, so `kind="entity"` answered `[]` and "keeps only entities" was asserted over nothing. Mutant: the rollup's entity clause `= TRUE` becomes `= NULL` (nothing is served as an entity) stayed green. The test now marks one keyword an entity and asserts it is the one row served.
2. `test_country_wire.py::test_the_registered_statistics_sources_filter_by_every_spelling`: `/api/stats/sources` lists `source_type == "statistics"` only, the fixture's sources are news, so every spelling returned the empty set and `empty == empty` passed for all of them. Mutants: the country filter replaced by `["zz"]`, and the filter removed altogether, both stayed green. The fixture gains two statistics sources; the test asserts the French one is the answer and that `FRA` leaves as `FRA`.
3. `test_source_quality.py::test_build_report_end_to_end_and_newsletter_text_gate`: "none of the zh articles is flagged" was true of any code, because five identical zh articles have no spread (the tail test is strict) and nothing is flagged even when assessed. Mutant: assess unsegmented languages (`if False:` in `compute_metrics`) stayed green. The cohort is ten ordinary articles and one pathological one, which the mutant flags.
4. `test_core_guard.py::test_the_places_of_a_real_machine_...`: a clean tmp working directory holds no dump, so the shape check ran over nothing. Mutant: add a `path` key (the directory of a dump) to each record stayed green. The test drops a `core.4242` in the working directory and asserts the record.
5. `test_search_advanced_api.py::test_saved_search_reruns_identically_and_never_fires`: the fixture's articles are from August 2026 and the watch window was the default 7 days, so NO watch could fire; "the saved search did not fire" said nothing. Mutant: evaluate saved searches too (`threshold >= 0`) stayed green. The window is 3650 days and a second watch (threshold 1, same query and filters) is the positive control, which the saved search must not accompany.
6. `test_i18n_scanner_coverage.py`, three tests (`never_captured` x2, `is_not_chrome`): a scanner that returns the empty set passed all three. Mutant: `_js_chrome` returns early with `set()` stayed green. Each sample now carries one genuine constant and the answer is exactly that constant.

**Bare `pytest.raises(Exception)`.** 1,737 `pytest.raises(...)` blocks; 919 have neither `match=` nor `as`; 25 of them catch `Exception` itself. A recording shim (`rtype.py`, in the same folder as the plugin) logged what each raised: eight were wrong-passphrase or outage tests whose class is known and which accept ANY failure, including the typo that raises before the code under test. Narrowed to the class and a `match`: `test_backup_volumes.py`, `test_stream_backup.py` (x2), `test_volume_backup_roundtrip.py` (`EncryptionError, "wrong passphrase"`), `test_crypto_erase.py` and `test_salvage.py` (`WrongPassphraseError, "does not open"`), `test_qualification_assist.py` (`LLMUnavailable, "simulated outage"`), `test_encrypt_owns_the_machine.py` (`RuntimeError, "the engine failed"`). Mutants, each green before and red after: the chunk decrypt raises `ValueError`; the same raise with another `EncryptionError` message; `connect` raises `ValueError`; the classifier wraps the client's error in `RuntimeError`; the route raises a `KeyError` for a `RuntimeError` only. One mutant on a shared function (`unlock.encrypt_db`) broke an earlier block of the same test and so proved nothing; the mutant had to touch only the block under test. The other 17 were left on purpose: a closed connection (the driver's class differs by build), SQL errors whose text is the driver's, a library `MemoryError` (`test_failed_open_wal_facts.py`) and an engine conversion error (`test_rollup_sharded_build.py`).

**Rule.** (1) An `all`/`not any`/`== []` assert needs a positive control in the same test: show the thing present, or fire the twin, then assert the absence. (2) A mutant that makes the test's subject do MORE (evaluate the saved search, assess the unsegmented language) is the check for "it did not" claims; a fixture that cannot make the subject fire (a date window before the data, a cohort with no spread, a listing of the wrong source type) passes them all. (3) `pytest.raises(Exception)` is a claim that anything fails; name the class when it is known, with a `match`. (4) Of 70 never-saw-an-item sites, 62 were sound: the zero is a prompt to look for the control, not a verdict.

**The fixture that fixed one test broke two others, and only the order of files hid it.** The statistics sources `test_country_wire.py` added went into the app's process-wide engine, which later tests read whole: `test_stats_ingest.py` asserts every statistics source is tagged `official-statistics`, and `test_stats_figures_api.py` that every one is disabled. Run together, the three files gave 2 failures; the full suite hid it because `test_discovery_isolation.py` sorts between them and deletes every source. Rule: a row a fixture puts in a shared engine must look like the real thing the other tests expect (here: tagged and disabled). A subset run (`-k stats`) is what finds this, so the sibling files are part of the check. Also: `test_saved_search_reruns_identically_and_never_fires` reaches the fixture's August articles through a 3650-day window (the API maximum, the same limit as its sibling `test_filtered_watch_fires...`), so it stops finding them in 2036.

**Not covered.** `== []` over a plain call; `pytest.raises(HTTPException)` blocks that do not read `status_code` (14 listed in the scan); the tests that failed during the counting run.
