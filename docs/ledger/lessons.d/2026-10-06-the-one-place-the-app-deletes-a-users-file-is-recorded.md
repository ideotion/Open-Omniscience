## 2026-10-06 — THE ONE PLACE THE APP DELETES A USER'S FILE IS RECORDED AT THE MOMENT THE FILE IS MADE, THE "NOT THE SAME FILE" TEST MUST NOT BE ABLE TO REUSE AN INODE, AND A TEST OF A COPY'S PAGE SIZE NEEDS A SOURCE OF A DIFFERENT ONE (E3, R129)

(1) **Decide what a deletion is allowed to touch when the thing is MADE, not when it is deleted.** The swap gives the damaged file a second name by a hard link, and at that moment it records the inode (and the `-wal` link's inode) in the repair record; the sweep 30 days later compares
the live directory entry with that record (name pattern, folder, plain file, not a link, same inode) and refuses for good otherwise. A path that was stored and re-read a month later is a statement about a name, which anyone can point somewhere else in a month; an inode taken while the link
was made is a statement about the file. The device number was recorded and deliberately NOT compared: it changes across mounts (a re-attached drive, btrfs subvolumes), and comparing it would make the refusal permanent for the exact right file.
(2) **A test that proves "a different file under the kept name is not removed" must put the other file there WITHOUT freeing the old inode first.** Deleting the kept file and writing a new one under the same name lets the filesystem hand the new file the old inode, so the check passes and the test
claims a refusal that never happened; the test writes the new file beside the old one and `os.replace`s it over the name, so the inode cannot be reused while the old one is still referenced. Same family: a "refused" test for a directory under the kept name needs `said=False`, because
the notice's file finder requires a regular file and says nothing about a directory.
(3) **`monkeypatch.undo()` also undoes the patches of every fixture of the test**, not only the ones the test body made (a sweep test that "restored" its own stub with `undo()` silently put back the fixture's real `corpus_path` and then asserted on the wrong file); restore the one attribute with `setattr`.
(4) **A test that a copy keeps the source's page size must start from a source whose page size is not the factory's default.** The app's connection factory creates a fresh encrypted file at 16 KiB when no `cipher_page_size` is passed, so a 16 KiB source copied through a salvage that forgot to pass the size still reads
16 KiB and the assertion holds; a 4 KiB source (a store made before the move to 16 KiB pages) fails with `hmac check failed for pgno=1` when the pass-through is removed (mutant killed: `cipher_page_size=None`). Mutate the line the test claims to pin before trusting it.
(5) **A translated hover sentence that must change in twelve locales is re-keyed by splicing the new sentence into each existing translation** (the English key and the JS literal both change, so `unkeyed t("...")` is the gate that proves the literal and the key agree), after marking where the old sentence starts and ends in each language: one wrong marker raises
on `str.index`, rather than writing a half-replaced translation. A sentence that said "the app deletes nothing" was in the manual's statement, the hover and the notice at once; a ledger that changes what the app deletes changes every one of them in the same PR.
