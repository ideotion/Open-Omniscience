## 2026-10-28 — the release gate judged refs by its own copy of the predicate, so it passed what the fragment check refuses

**What was found (the limit #1643's own lesson stated, closed under R307).** `scripts/release_notes.py:refuse_placeholders`, the gate that stops a release body from citing a row whose `refs` is still a to-do, decided with `"pending" in refs.lower()`. `ledger_shipped.py check` decides with `REFS_PLACEHOLDER` (`\bpending\b`, `#NNNN`, `#PRNUMBER\b`, case-insensitive). The two disagreed in both directions: a cited row whose refs said `#NNNN` or `#PRNUMBER` went through the release gate and into a release body as a permanent citation (the fragment check would have refused it, but a hand-written row in `shipped.csv` never meets that check), and a refs value saying "depending on #1637" was refused at tag time by a rule the fragment check never applied, which is where a lane would first meet the surprise. Nothing was lost on the real ledger: over its 1,677 rows (the file plus every fragment) the two predicates differ on none.

**The rule.** A gate that re-derives a predicate another tool owns is a second copy that agrees until the day the first one learns a token; the release gate is the worst place to find that out, because it runs once per tag. `release_notes.refs_carry_placeholder` now reads `ledger_shipped.REFS_PLACEHOLDER` through one cached loader (`_ledger_shipped`, which the fragment reader already needed), and the refusal message names all three tokens. The deliberate narrowing is stated in the test docstring: `pending` is a word, so a `pending` glued to word characters (`PR_pending`) is not seen by either tool, which is `#1643`'s choice and not widened here.

**What it measured.** Against the old script 9 of the 12 new tests are red (the other 3 are the negative twins, which pass on both): 4 on the predicate (`#NNNN` and `#PRNUMBER` in two spellings each), 3 only on the message (the `PR pending` forms, which asserted the new three-token message), 1 on the narrowing ("depending on #1637" no longer refused), 1 on the source-following test (which cannot even import the loader on the old script). One mutant was run: a private copy of the three-token regex inside `refs_carry_placeholder`. Every fixed-token test passes under it; only `test_the_refs_predicate_is_the_one_ledger_shipped_applies_not_a_copy` (swap the regex `ledger_shipped` owns and the gate's answer must swap with it) goes red, so that one test is what makes the lesson hold. Not measured: any other reader of a ledger `refs` cell; `grep` found `refs_carry_placeholder` at two call sites (the gate and its real-ledger test) and `sweep_pr_number.py` already uses the same predicate (#1648).

**Owner.** `scripts/release_notes.py` is in no lane's file-ownership list; it is Plan's by R307 (the lane that found the defect takes the unlisted file), and this lesson is the index entry that says so for the next session that touches it.
