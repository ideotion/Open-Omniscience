## 2026-10-27 — a refusal that returns an empty tally reads as a quiet result

**Found by** the consent-coverage sweep (item 1, `osm-lane/consent-coverage-sweep-2026-10-27.md`), which was asked "which of the 92 unprompted mutators reach the network without the consent popup" and answered "none is a consent defect, because the kill switch is the gate; but four of them hide that it fired". Pressed in airplane mode, `ingest_source` (a per-source and a batch button), law `track_watched` and wiki `track_watched` answered 200 with an all-zero tally and the same success toast as a feed with nothing new. Invariant #14e's corollary ("a refusal BY THE KILL SWITCH must be named as such wherever it can surface") already said so, for the size probe; nobody had asked it of the buttons that catch and count their failures.

**The shape to look for:** a loop that catches `Exception`/`FetchError` per item and returns an aggregate. Every count in the aggregate is then "zero", and a reader cannot tell "zero because nothing changed" from "zero because nothing was tried". The two consent mechanisms are not the whole answer: `ensureOnline` (and its twin `ensureAiEgress`, which an earlier count of "no own-body prompt" missed because it grepped for one name) only matter on an offline->online transition; the refusal is what a press on an offline app actually meets.

**The rule:** an additive key that is present ONLY when the refusal caused it (`skipped_offline`, int, so the scheduler's generic `_add` sums it and `fetch_failed_reasons` ignores it), every pre-existing key unchanged, and the UI says it in words with no success toast. Classify by the one existing classifier (`fetch_verdict.classify_fetch_failure(...) == "offline"`) or the typed `NetworkBlocked`, never by a new string match.

**Measure before you claim.** The route name graph (forward calls by simple name) was unusable as an egress classifier: threshold 2 found 26 of 709 routes and missed `wiki/pages/{id}/track`, threshold 8 found 609. What worked was a probe: kill switch engaged on a TEMP data dir, one real POST per candidate route, read what the person is told. 4 of 9 egress-reaching buttons were silent; 5 already named it.

**A second, unrelated trap, from the same change:** `tests/test_i18n_scanner_coverage.py::test_every_tf_frame_slot_is_actually_supplied_at_its_call_site` treats a name bound to `OOI18N.tf` ANYWHERE in a file as a `tf` alias for EVERY `tf(` call in that file. A function-local `const tf = ...` in `app-map.js` made it inspect an unrelated `tf(frame, vars)` 300 lines away (it cannot resolve `vars`) and fail. Call `OOI18N.tf(...)` directly in a file that has no module-level `tf`.
