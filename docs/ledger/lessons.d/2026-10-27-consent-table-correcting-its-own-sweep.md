## 2026-10-27 — a ratchet's table is a second reading, and it corrected the first

**Found while building** `tests/test_consent_coverage.py` (R292 C3) from the consent-coverage sweep's classification. The sweep said `importCustomFeed` asked for consent and `refreshStatSubs` did not. The table's own check ("a consent row's client function calls `ensureOnline` or `ensureAiEgress` in its OWN body", read with a balanced-brace extractor) said the opposite for both: `importCustomFeed` (`app-markets.js`) has no `ensureOnline` at all and posts a URL the person typed, and `refreshStatSubs` names the refusal (`skipped_offline`) and asks nothing. Egress-reaching buttons with no popup are therefore 10, not 9. The sweep's mistake was reading a nearby `ensureOnline` (the line above belongs to `importFeed`) as belonging to the function below it.

**The rule:** a classification that will become a ratchet is checked by the ratchet's own predicate BEFORE it is written down, with the function boundary taken by brace matching, never by "the nearest line above". Build the table first, run it, and treat every row it rejects as a correction to the prose, not as a test bug.

**What the ratchet pins.** Two row kinds: `consent` (the client asks, in its own body, with either of the TWO consent functions) and `named` (nothing is asked, because the kill switch already stops every byte; the refusal must be named, proved by a real refusal with the switch engaged). Discovery runs the other way: a `src/api` route handler that names `get_fetcher`, `make_fetcher`, `following_fetcher`, `EthicalFetcher` or `WikiClient` must be a row, zero slack both ways. Its limit is stated in its docstring: a handler that reaches a fetcher only through a helper (stats refresh, weather) is invisible to discovery and is a hand-listed row pinned by its own test.

**A probe must read what the BUTTON reads.** A first version accepted any response whose text contained "kill switch". The read of it showed that feed verification passed that way while reporting the person's own airplane mode as the HOST being unreachable: the words sat in a nested per-feed `error`, the toast said "Checked.", an `unreachable` verdict was stored and the feed was pushed onto the month-long re-check ladder. Probe predicates therefore read the top level of the answer (`detail`, `result`, an integer `skipped_offline`), and a defect the table finds is pinned as a `gap` row (what it does today, with its reason) so that fixing it is an edit the test forces. The same read found the consent check was a substring search that a comment satisfied; it now strips comments and requires an AWAITED call before the first `api(` request.
