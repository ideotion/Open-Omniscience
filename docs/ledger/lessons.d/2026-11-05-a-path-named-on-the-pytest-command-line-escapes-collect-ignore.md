## 2026-11-05 — a path named on the pytest command line escapes `collect_ignore`: a shard should ignore the others' files, not name its own (C10, the test and Core-only shards, PR #1726)

**What was found.** The first sharded Core-only leg passed its test files on the command line (`pytest @shard.args`, the list being its own files) and went red at collection: `tests/test_confidence_intervals.py` and `tests/test_statistical_tests.py` were collected and died at import. `tests/conftest.py` keeps the analysis tests out of a core-only install with `collect_ignore`, and pytest does not apply `collect_ignore` to a path that is NAMED on the command line (reproduced on a toy tree with pytest 9.2.0: the named file is collected and imported, the same file under a directory is not). The unsharded run collects the directory, so it was never exposed, and the `test` job (every extra installed, `collect_ignore` empty) could not show it either.

**The rule.** When a runner splits a suite, hand pytest what to LEAVE OUT and let it collect `tests` itself: `scripts/ci_shard.py plan` writes one `--ignore=<file>` per file of the other shards, so `collect_ignore`, `norecursedirs` and `python_files` stay in force as in the one-process run. Two refusals come with it, because the failure of each is silent: a plan that runs nothing (an empty list of files would make pytest run the whole suite), and a plan that ignores nothing while N > 1 (the same, by the other door). A shard that ignores every file ends in "no tests ran" (exit 5), which is red.

**What the guards were shown to do.** Real pytest on a toy tree in `tests/test_ci_shards.py`: the named-file form collects the ignored module, the plan form does not, and the all-ignored shard exits 5. Mutants killed: the plan inverted (ignores its own files), duplicates unseen, the refusal removed. A CI job (`ci_shard.py collected`) compares `pytest --collect-only -q` of the whole suite with each shard's plan on a REAL core install: 29440 tests in 1555 modules both ways, 0 differences; locally in a core-only-like environment 29501 in 1560.

**Stated limits.** The collection check compares test ids, not whether the tests pass; the passing is the legs' own result. The `@file` argument form needs pytest 8.2 or later.
