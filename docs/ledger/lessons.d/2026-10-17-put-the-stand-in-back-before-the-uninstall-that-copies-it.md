## 2026-10-17 — A STAND-IN PATCHED INTO A MODULE GLOBAL THAT AN UNINSTALL COPIES ONTO THE REAL THING MUST BE PUT BACK BEFORE THE UNINSTALL; A TEST THAT PASSES ALONE AND FAILS IN THE SUITE HAS A NEIGHBOUR THAT LEAKS

(1) **The shape.** `src/ingest/airplane.py` keeps the real stdlib calls in module globals (`_orig_getaddrinfo`, `_orig_create_connection`, `_orig_connect`, ...) and `uninstall_airplane_socket_guard()` COPIES them back onto `socket`. A test that swaps one of those globals for a spy (`monkeypatch.setattr(airplane, "_orig_getaddrinfo", spy)`) and then calls `uninstall_airplane_socket_guard()` before the undo makes uninstall copy the SPY onto `socket.getaddrinfo`; the later `monkeypatch` undo restores only the airplane global, so the spy stays on `socket` for the rest of that pytest worker. `tests/test_airplane_socket_guard.py`, `test_egress_window.py`, `test_ssrf_connect_guard.py` and `test_transport_follows_setting.py` restore the saved originals FIRST and say why; `tests/test_entity_spine.py` did not, and its spy answered an empty list.

(2) **How it showed.** Two tests in `tests/test_event_loop_signal_exemption.py` (a real server, `urlopen` to `127.0.0.1/api/health`) failed in the full suite and in CI, never alone: `socket.create_connection` raised "getaddrinfo returns an empty list" while the server sat idle with no request logged. Wall-clock slowness was ruled out by measurement first (52 boots of the same server beside a full `-n 4` suite: 10.0-13.2 s, median 11.2 s, against a 60 s wait) before the stuck state was read: put the suspect's state IN THE FAILURE MESSAGE (the resolver's repr and what it answers), not in a rerun. The boot sampler also has to use the test's own environment: `tests/conftest.py` sets `OO_AUTOSEED=0` and others, and without them the boot did a first-install seed (24-36 s), which looked like load.

(3) **Method for the next one.** A test that passes alone and in a subset and fails in the full run is leaking state from an earlier test in the same worker. Grep the tests for the global it needs (`getaddrinfo`), reproduce with the suspect test followed by the victim, serially (`-p no:xdist`), and fix the leaker; do not widen the victim's wait. Never start a suite or a sampler under `nohup`: it makes SIGHUP ignored in every child, which failed three `test_osm_reference_run` signal tests that had nothing wrong with them.
