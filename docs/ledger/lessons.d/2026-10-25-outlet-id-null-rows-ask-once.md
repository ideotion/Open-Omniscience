## 2026-10-25 — A derived column that can be NULL on a bad boot must fail toward the SAFE count, and the exact reading is asked once per run, not paid per row

**What was found.** `sources.outlet_id` (R177) is derived by three triggers and a boot heal. A row the heal did not reach (the ADD COLUMN succeeded, the triggers or the heal were refused) is NULL, and `coalesce(outlet_id, source_id)` then counts each feed of an outlet as its own outlet. That is an OVERCOUNT, the direction R146 forbids (manufactured agreement), and the first docstring called it "never fewer outlets than there are" as if that were safe. The Opus read found the claim, and also that a refused ADD COLUMN does worse than miscount: the model maps the column, so every `Source` query fails with "no such column".

**What the exact reading cost.** An always-on correlated `coalesce(outlet_id, (select min(id) from sources where domain = ...), source_id)` measured +29 % on a 2.34 M-mention window, encrypted (`plan-row-j/outlet-id-plan-2026-10-17/RESULTS.md`, addendum). The plain form costs +0 to +8 % over `source_id` alone. Paying +29 % on every healthy store to cover a state that lasts until the next boot is the wrong trade.

**The rules.**
1. **Ask once per run, pass the answer.** `outlets_unhealed(session)` is one `LIMIT 1` probe (0.044 s at 700,000 sources); each gate calls it once and passes `unhealed=` to `outlet_expr`. A healed store reads the plain form; an unhealed one reads the exact form until the next boot heals it.
2. **State the failure honestly, in every comment that states it.** A refused ADD COLUMN fails queries; a refused trigger or heal leaves NULL rows that the gates read exactly. Say which, in `session.py`, `source_identity.py` and `outlet.py`.
3. **Test the state, not the shape.** The NULL-state tests live on the gates whose SQL count IS the verdict (the ripple gate, the link board); `story_propagation`'s SQL count is only a candidate prefilter that Python recounts, so a test there cannot tell the forms apart. Each NULL-state test was shown red with its gate's `unhealed=` forced to `False`.
4. **A trigger list has an edge, and the edge is written next to it.** `INSERT OR REPLACE` across domains fires no DELETE trigger while `recursive_triggers` is off (the repo never sets it): a test documents the gap, another scans `src/` for the shapes, and the boot heal is what repairs it. `UPDATE OF domain, id` closes the id-change case the read found.
