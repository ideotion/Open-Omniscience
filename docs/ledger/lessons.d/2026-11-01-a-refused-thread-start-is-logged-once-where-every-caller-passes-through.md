## 2026-11-01 — a refused thread start is logged ONCE where every caller passes through, class-only and outside the lock, and the callers' own copies go (R386 / R393; PR #1687)

**What was found.** PRs #1661 and #1666 made `BackgroundJob.start` mark a job `error` when its worker thread cannot be created, and re-raise; #1677 gave the routes that call it a 409 and a log line each. Twenty-five other starts in other files neither map the refusal to an answer nor log it, and a line per caller is the wrong place for a fact that one function knows: it is written wherever someone remembered to, and the next caller forgets (R386: a dropped exception that is not logged is a defect).

**The rule.** Log the failure in the one function that knows it, once per event, and take the callers' copies out in the same change or the refusal reads twice. In `BackgroundJob.start` (`start` wraps `_start`, which holds the old body and fills a local `refused` list inside the lock): (a) the line is written AFTER the job's lock is released, because `status()` readers wait on that lock and a log handler can block; (b) it carries the class, the job's own `error` text and a fixed note, never the exception's words: a start's keyword arguments can hold a passphrase or a mailbox password and `start()` has not read the job's secrets (`_job_secrets`), so the exception text is not known to be clean; (c) an interrupt (a `BaseException`) and the "already running" refusal leave `refused` empty and log nothing; (d) the write sits under `contextlib.suppress(Exception)` and the re-raise is a bare `raise`, so a failing handler never changes what the caller sees and the caller catches the very exception object the thread raised, with `__context__`, `__cause__` and `__suppress_context__` as they were (a test pins the identity and the chain); (e) the three vLLM routes in `src/api/llm.py` (engine install, model install, model batch) lose their own line for the same refusal and keep their answers.

**Left on purpose, and why.** `src/database/article_indexes.py:668`, `src/database/repair.py:759` (both WARNING, stating the consequence for the boot step they belong to) and `src/backup/volume_job.py:173` (INFO, fires for any exception, not only a refused start) log a refused start themselves. They are other lanes' files and a second line in a rare out-of-threads event is the whole cost; the coordinator agreed to leave them, and their owners can remove the copy if the duplicate matters.

**Pinned by** `tests/test_thread_start_interrupt.py` (seven new tests: one WARNING with the job's own error text; none of the exception's words; nothing for "already running"; nothing for an interrupt; the refusal still raises when the log cannot be written; the caller catches the same exception object with its chain; the job lock is not held while the line is written) and `tests/test_failed_thread_start_routes_answer_409.py` (a refused vLLM start is one line, not two, and the answers are unchanged); 18 mutants of the wrapper, the `refused` flag, the lock position, the re-raise and the three route edits, all killed.

**Stated limits.** A log handler that blocks forever still blocks that caller (after the lock, not inside it). The 25 other callers still answer as before; this change adds only the log line for them. Not observed in the field: driven by tests that inject the failure.
