## 2026-10-27 — A test that patches a stdlib function through a module attribute patches it for every thread; a thread a test starts must be joined by that test; a cache path a thread resolves late follows whatever the next test set (R333, R336, R344)

**What was found (four facts, one bundle).**
1. **A leaked thread follows `data_dir()`.** `GET /api/briefing` on a stale cache (hit by `tests/test_api_wiring.py`) started `oo-briefing-refresh` with no handle, and the thread resolved `data_dir()` at its WRITE, so one that outlived its test wrote `briefing_cache.json` (25,847 B) into a later test's `OO_DATA_DIR` (R332). Now the Thread is kept (`service._refresh_thread`), the path is resolved once at start and pinned for that thread in a ContextVar (`_cache_path()` reads it in that thread only; `refresh_briefing`'s signature is unchanged, because existing tests stub it with `(session, on_progress=None)`), and an autouse fixture in `tests/conftest.py` joins `oo-briefing-refresh` / `oo-briefing-bg` after every test for at most 30 s in all and fails the teardown naming the thread and the test id. Red first: with the pin ignored the cache lands in the moved folder. Stated: `shutdown.py` joins no named thread, so no shutdown step was added.
2. **A test that counts rows at process exit must poll when the writer defers by design (R336).** `scripts/launch.sh` hands a row to a detached child when it misses the 100 ms lock (R174) and exits; `_assert_all_present` looked once. Forced to 1 ms: 4-8 of 8 rows at exit (mkdir lock 4-7, flock 6-8), 8 of 8 within 0.1 s, never a lost row. It now polls to a named 30 s bound, then makes the same three assertions. The PowerShell variant was not run.
3. **`monkeypatch.setattr(page_reading.os, "fstat", ...)` replaces `os.fstat` for the whole process (R344).** `page_reading.os` IS the `os` module. The test now patches a namespace copy of `os` bound to the one name `read_header` reads, and requires the real `os.fstat(0)` to work inside the window, which is RED on the process-wide form (it reproduces the CI shape: `OSError: [Errno 5] MARKER-passphrase ...` raised in `boom`). The sibling pattern for a module attribute is `_Seen` in `tests/test_backup_download_route.py`.
4. **The test_page_reading red has a named cause: pytest 9.2.0 (R350, found by the Export lane, confirmed here).** `tests/test_page_reading.py::test_a_failing_stat_after_the_open...` went red from about 22:30 on five heads and both install profiles, main included (single-frame traceback `in boom`). `pyproject.toml` installs `pytest>=8.2` unpinned, and pytest 9.2.0 (PyPI, 21:30 UTC) added `os.fstat(self.tmpfile.fileno()).st_size` to both capture `snap()` methods, which run at the end of each setup/call/teardown phase, while the test's process-wide `os.fstat` patch is still live. MEASURED here: the 41fb0f4ac form of the test fails with the MARKER `OSError` under pytest 9.2.0 and passes under 9.1.1; the scoped form passes 47/47 under 9.2.0. Shipped in #1588 first (22453c33f); no pytest pin (ruling). Earlier in this thread a foreign thread, a leaked briefing thread and an import chain were all considered and ruled out by measurement (a foreign thread's `os.fstat` only adds a warning); none of them was the mechanism, which is why the first red-before proposed (a spinner thread) was false.

**Rules.**
1. **Patch the name the code under test reads, not the module attribute it shares with the process.** Replace the module's reference (`monkeypatch.setattr(mod, "os", copy)`), never `mod.os.<fn>`.
2. **A test is not done with a thread it started, directly or through the app.** The fixture makes that a failure at the test that left it, named, instead of a mystery in a later one.
3. **Resolve a background thread's write path once, at start.** Anything that asks the environment at write time is a function of whichever test runs then.
4. **Do not assert a cause you have not reproduced.** The first red-before proposed for fact 4 (a spinner thread fails the test) was false when run; it was withdrawn, and the real mechanism (a tool's own use of the patched function after the call phase) came from diffing the CI package versions between a green and a red job.
5. **A process-wide patch of a function the test runner itself calls is a time bomb that goes off when the runner is upgraded.** Sweep (grep of `tests/`): the only `fstat` patch is this one; the many `os.replace` / `os.fsync` / `os.kill` / `os.stat` patches are untouched by 9.2.0's change.

**Not checked, stated.** How long a real briefing rebuild takes on a large corpus; `warm_cache` and `_dismissed_path` still resolve their own paths; the scheduler's `oo-briefing-bg` (runner.py, `refresh_briefing` on the scheduler's thread) is joined by the fixture but NOT pinned: it still resolves the cache path at each use, as before; the fixture runs at the last teardown (autouse fixtures tear down in reverse order of setup and it is set up first), so a thread still running then sees the suite's folder and the real functions, not the test's patches, and a survivor is reported once (a weak set), against the test that left it. R339 sweep: no other test that patches `is_encrypted_file` also boots the app through the lock gate (read, not run), so none can poison the 5 s header cache as #1588's did.
