## 2026-11-05 — "no such table" beside a non-empty -wal is NOT a sign of an unfolded log: a read-only SQLite open reads the wal, so the table is absent from both (R432 withdrew R429, item 47)

**What was found.** R429 asked `kv_get_json_checked` to raise `KvReadError` when a non-empty `<db>-wal` sits beside the file and `app_state` is not visible, on the premise that the table might only be unfolded. An independent read of the built change (PR #1732, never merged) measured otherwise: with plain sqlite3, a wal holding `app_state` plus a row, a 4 KB main file and nothing folded, a `mode=ro` connection returned the row, and still did after `-shm` was deleted. The one case where a read-only open cannot see the wal (it cannot create `-shm`) already takes the `_RO_ONLY_FAILURES` read-write retry and never reaches the first-run fold.

**What the change would have done.** On a store that has tables but predates `app_state` and was left with a non-empty wal, `init_db()` calls `refuse_if_unfinished()` before `create_all`, which reads the journal key through the checked read. The raise became `StoreFormUnreadable` and aborted every boot, because nothing creates the table before the raise; `load_settings()` flipped to `fetch_mode=protected, read_failed=True`. The change's own test shared the flaw: its wal held only an unrelated table, so it pinned "absent table plus wal = error", not the unfolded case it claimed.

**The rule.** Before building a guard on "the file may not show what the wal holds", MEASURE that a read-only open misses the wal; and write the positive test with the wanted row living ONLY in the wal. A guard that turns a true absence into a failure belongs in the boot path's callers' view too: grep who reads the key before the table is created (`init_db`, `refuse_if_unfinished`, `store_form`, `load_settings`). A symlinked database path also splits one file into two answers when a side file is stat'd on the unresolved spelling (`connect.py` resolves, the stat did not).

**Where enforced.** Nowhere: the code was dropped. R256's wait stands; a new design needs a new ruling.
