## 2026-10-17 — copying a file is a sink as much as printing an exception; the sweeps that scrubbed exception text left every verbatim copy open

Three sweeps closed the exception-text sinks and the records guard now pins every `src` module, and an audit of what the code does with file CONTENT still found four raw copies: the single-file backup's `logs/*` members, the volume backup's staged copies of the same files (`shutil.copy2`), the restore's merge of a backup's lines into the live logs, and a quoted sidecar reason cut before it was scrubbed. A verbatim copy reads as plumbing, not as a record, so no grep for `str(exc)` or `record_text` could find it. **Look for the sink by what leaves the install (zip members, staged copies, API bodies quoting a file), not by the name of the helper you expect to see.** The fix is one streaming copy that scrubs a whole line before writing it; the cost of a backup member scrubbed on staging is a second pass over small jsonl logs, and the live file is never rewritten. A file an older build wrote can hold a key, so the reader scrubs too, even when the writer now does.
