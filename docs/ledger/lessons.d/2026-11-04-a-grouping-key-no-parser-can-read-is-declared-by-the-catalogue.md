## 2026-11-04 — a grouping key no parser can read is declared by the catalogue, and a write that runs every pass must not treat "nobody said" as a value (PR #1717)

**What was found.** The law lane aligns language versions of one law by an identity, formed from the number an adapter read out of the body, else from the document's own URL. A treaty page states no number a parser can trust, so the only key left was the URL, which differs per language, and the alignment the model was built for (Q908) never happened for the one kind of instrument published in several languages by construction. The honest key is a statement by the person who knows which URLs are one treaty, written where they already write the URLs: the catalogue row. It is looked up by the row's own `(jurisdiction, url)` by exact equality (a host match would hand one declaration to everything the host serves), never derived from the URL, and a row that declares nothing is recorded exactly as before. YAML needs one more rule: a declared value must be a string, because `1.10` is read as the number 1.1 and merged two laws.

**The rule that makes a declaration safe.** (1) One function checks it, and the validator, the test over the committed files and the tracker all call that function, so what CI accepts is what the tracker applies. (2) A declaration with ANY problem is treated as absent as a whole: applying the `doc_type` while dropping the identity files a language version under the wrong law with nothing to say so, where an ungrouped one is visible. (3) Rows that declare one law are checked against each other (one `doc_type`, at most one `original`), because the group reader would otherwise resolve the contradiction silently with a log line. (4) The jurisdiction is part of the key: the same declared value in INT and in another jurisdiction is two laws.

**The second finding, on the same path, and the way the first fix was wrong.** `record_document` runs on every tracking pass and passed `doc_type="unspecified"` every time, and `ensure_identity` wrote it over whatever was recorded. The identity is shared by every language version, so five versions declaring `treaty` and one declaring nothing would undo and redo the column in whatever order the passes ran. The first fix was "an incoming `unspecified` or `unrecorded` never replaces a recorded value". The review showed that made declarations irreversible: the catalogue was the only writer, so after a row declared `original`, deleting the key, or writing `unrecorded` outright, changed nothing, and moving the original from one version to another left two (the group reader then reported the OLD one). The rule is two-sided. (1) A caller that states nothing must be told apart from one that states "unspecified": use `None` for the first and keep the vocabulary word for the second, so the explicit word can always take a value back. (2) Ask where each field lives. `translation_kind` is per language version, so the pass should write exactly what its row says (omitting the key retracts it); `doc_type` is per identity and written by every version, so omission must mean "no statement" and the retraction is the explicit word. For any field the catalogue alone writes, ask "how does the operator take this back?" before shipping, and put a test on the answer.

**A test-data trap.** The synthetic Chinese body was first 115 characters, under the tracker's 200-character floor, and was recorded as "no usable text extracted": the floor counts characters, which is about four times less content for CJK than for Latin script. A fixture in a non-Latin script has to be checked against the floor, not assumed to clear it; the floor itself was left alone (a threshold change is a behaviour ruling) and is recorded as an observation.

**What is NOT known.** Nothing here was read from a real treaty site: the fixtures are invented and the live URLs wait on the operator. The shape of a real UN Treaty Collection or WIPO Lex page, its licence and its robots rules are unverified.
