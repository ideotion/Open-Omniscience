## 2026-10-28 — a quoting rule is one function with a test per clause

**What was found (the Opus read of #1639, findings 2 and 5, and the read of this change).** The ledger tools skip quoted text (a lesson may QUOTE `PR pending`) with a rule that existed as four loops: `ledger_fold._prose`, the unclosed-fence and second-heading loop in `problems`, the index in `lessons.py`, and the sweep script's own. Each toggled on any line that STARTED with three backticks or tildes, and `_INLINE_CODE` was `` `[^`\n]*` ``. So a `~~~` line inside a backtick block closed it, a closer with trailing text closed it, a double-backtick span (``like `this` ``) matched as an empty pair and left its contents visible, and `` ```a``` `` (a code span) opened a fence that hid the rest of the file. The same sweep carried a `pending in refs` test that the ledger's own check did not, so what the script left alone and what CI refused could disagree.

**The rule.** A quoting rule is ONE function that every reader calls, and each clause of it has a test that goes red when the clause is removed: a fence closes only on its own character, at least as long, alone on its line (an indented closer and trailing spaces are fine); a backtick fence's info string holds no backtick, a tilde fence's may; an unclosed fence is named with its line instead of silently hiding the rest; a code span pairs a run of backticks with the next run of EXACTLY that length, shortest first. `lessons.outside_fences` is that function (it lives in the lowest module because `ledger_fold` imports `lessons`): `check`, the placeholder scan and the lessons INDEX all call it, so a fragment that passes `check` is indexed exactly as `check` read it. The first version moved only `ledger_fold`'s half, and the read found the cost at once: a heading after a `~~~` line inside a backtick block passed `check` and became a second index entry after a fold. A predicate that two programs must agree on (`REFS_PLACEHOLDER` for the `refs` column, `pending` a whole word) lives in the program that enforces it.

**What it measured.** Over the 269 real files on main (267 fragments and both archives) the new `_prose` changed the TEXT of 9 (all double-backtick spans, now removed whole), changed the placeholder verdict of none, and found no unclosed fence; the lessons index of the real tree (1,002 entries) is identical before and after. 20 of the new tests are red on the old tools, and 27 of 27 mutants of the new clauses are killed. The first run claimed 18 of 18 and was wrong in the way that matters: six clauses had no test (the closing run's two lookarounds, shortest-match, an indented or space-padded closer, the tilde info string), found only by running those mutants. Stated limits: the sweep script and `release_notes.refs_carry_placeholder` keep their own loops and their own broader `pending` test (follow-ons), and a code span is read per line (CommonMark lets one cross a line).
