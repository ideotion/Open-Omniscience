## 2026-10-26 — what an injected binding can reach is bounded by the names AND by what each name does

**Found (audit 0.5.0, A-004 / A-010 / A-011).** `oo-on.js` delegates `error`, `load`, `toggle`, `focus` and hover, so markup that reaches `innerHTML` is a zero-click call of any allowed name. The allowlist of 468 names is the boundary, and three things inside it were wider than they looked: the two DOM helpers took ANY id (`ooSetValue('atrest-pw1', x)` then `encryptCorpus(this)` encrypted the corpus under an attacker passphrase; the earlier note that it was "not injectable in practice" read the function and not the helpers beside it); a destructive name with no `confirm(` of its own body (`secureErase` posts `confirm: true` itself) needed no click at all; and `ooOpenUrl`'s "first characters" same-origin test passed a slash followed by a backslash and a host, which a URL parser reads as another origin.

**Rule.** (1) A helper that takes an id takes a literal set of ids, and a test holds that set equal to the ids the markup actually binds (both directions, so a dead entry also fails). (2) A name that erases or removes and does not confirm in its own body runs only for `event.isTrusted` and a click or Enter/Space; the scan that finds the names is `^(delete|remove|secure|panic|uninstall|shutdown)` over the allowlist, read against each function's own body. (3) A handler that reads consent-bearing fields reads them from the panel the pressed control sits in (the binding hands in `this`), never by a bare `getElementById`, and asks before the step that cannot be taken back. (4) "Same origin" is decided by RESOLVING the string with `new URL(s, location.origin)` and comparing origins, never by looking at how it starts. (5) "A handler that reads form fields is as safe as the field" is wrong: it is as safe as the first element with that id and as everything able to write the field.

**Sibling (A-020).** A command-line tool that refuses a secret on argv must still not let argparse print it back: "unrecognized arguments: --flag VALUE" echoes the value. Keep the old flags defined only to refuse them by name, and use `parse_known_args` so an unknown argument is reported by count.

**Limits.** Resolving from an ancestor does not help against an injection inside that ancestor; the prompt is then the only gate, so its text is fixed. The generalised fix (refuse every name on a zero-click event type unless the markup binds it there) is not built. Not browser-verified. Audit routing rows #2, #9, #10, #12.
