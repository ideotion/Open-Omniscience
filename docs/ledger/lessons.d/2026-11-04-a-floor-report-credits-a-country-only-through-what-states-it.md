## 2026-11-04 — a floor report credits a country only through what states it, and its bytes are measured in the smallest shape and the largest (PR #1710)

**What was found.** The coverage floor (`configs/language_countries.yml`, 140 countries over the twelve UI languages) is a denominator of countries, and a report that says where each one stands is only honest if nothing credits a country on evidence that is not its own. Four things can, and each was made a refusal with a test that fails when it is dropped: (1) a source filed under a many-country code (`eu`, `int`: 18 catalogue rows, 12 of them law authorities) serves many countries at once, so it is listed under `many_country_sources` and credited to nobody; (2) a jurisdiction code is "ISO-ish" (`uk` documents state `gb`), so a country is read only from `LawDocument.country`, never from the code; (3) an IP office or a case-law site is not a law authority (read as `is_law_source_type(source_type_for(row))`, so a row that declares no type is the legacy `legal` and IS one; the first draft compared with `== "law"` and would have called a typed-by-omission row "no source"), so it makes no country's law reachable, and a tracked IP or case-law DOCUMENT credits no country either (counted in `non_law_documents`); (4) a document that states no country (6 `tl` documents on a freshly seeded install) is counted in `unplaced_documents`, not credited to Timor-Leste. The report also keeps a failed lookup apart from an empty one: an unreadable catalogue puts every untracked country in `unchecked`, because "no eligible source" would turn a failed read into a research gap.

**Two fields both called "verified".** `verification.status` is the research channel (fetched, search-verified, lead) and `verified.tier` is the app's own (Q924: an adapter in this tree read the host live or a fixture of it; 274 of the 275 rows record none). They answer different questions and stay apart everywhere they are shown. They are joined in exactly one place, `source_is_verified`, which reads like `verified_tier` does on a rendering path (a `verification` that is not a mapping is unverified rather than an exception that takes the whole report down; a status is compared without its case or stray spaces), to answer the one yes/no the floor asks, and `RESEARCH_VERIFIED_STATUSES` is now the one spelling of the research half (`registrable_documents` reads it too). On the shipped catalogue: 5 tracked on a seeded install, 109 verified-not-yet-tracked (at most one of them through the adapter channel), 25 unverified, 1 with no eligible source (Yemen). "Verified-not-yet-tracked" therefore says a researcher reached the portal, never that this app can read it, and the panel's hover says only what was recorded.

**The mutants that survived.** Thirty-one mutants of the report, the panel's wiring and the renderer were run in the first pass; one survived: replacing `_floor_unchecked(catalog_error, docs) if catalog_error else floor_report(docs, catalog)` by a bare `floor_report(docs, catalog)` left every test green, because the unit tests called `floor_report(..., None, reason=...)` directly and nothing drove `law_coverage_report` with an unreadable catalogue. A test of a pure function with `None` does not prove the caller passes `None`; the integration test (`test_the_report_with_an_unreadable_catalogue_...`) kills it. The Opus read then found a second, which the first pass could not have: `reachable[cc] = reachable.get(cc, False) or verified` mutated to `= verified` (the last source for a country wins) left every test green, because no test gave one country two law sources and the real-catalogue test pinned only the no-eligible-source half (on the shipped catalogue it changes `cr`, `kn` and `mm`). It is killed by a two-source test in both orders and by an independent `any()` recomputation over the real catalogue. A mutation list written by the author mirrors the author's attention: the second survivor sat on the line where several rows combine into one answer, and only a reader who was not holding the design went there.

**The bytes (the diagnostics room is net-zero).** The block is 5,774 B compact. Paying for it in the same commit: each coverage reason is stated once per state in `coverage_reasons` instead of once per jurisdiction row (the same 710-byte paragraph on every row in the commonest state), and the `country` key each `untracked` figure repeated under a row already keyed by that country is dropped. Measured on the real catalogue, compact JSON, against `main`: a young install (8 jurisdictions) goes 29,643 to 34,289 B (+4,646), a 54-jurisdiction one 66,064 to 45,279 B (-20,785). They move in opposite directions, so a single measurement would have said either "no cost" or "it does not pay"; measure the smallest shape and the largest, and say both. The member is not a slot, so it sits inside the measured zip figure and no pin in `diagnostics_slots.py` moves.

**What is NOT known, stated.** (a) The ruled order of work, many-country sources first and then by population reached, is applied to the first half only: the tree holds no dated population table and the sandbox cannot fetch one (World Bank and Wikidata answer with a CONNECT 403), and a table written from memory would be a fabricated denominator. Within a state countries are listed by code and the report and the panel say so; the table is an operator step. (b) Yemen's recorded "confirmed gap" is not told apart from "no row": the loader drops a row with no domain, so the vetting board holds that fact and this report cannot see it. (c) Hong Kong and Macau are named by the Chinese seed row, are not on the floor (its territory exclusion is a recorded scoping decision) and are reported beside `zh`; both read `no-eligible-source` because the catalogue has no row for either.

**Words that collide in translation.** Two of the new panel words already existed as keys (`Not checked`, `contested`), and the first draft of "Not verified" came out identical to the existing "Not checked" in French, Japanese and Portuguese and close to it in several more. That was fixed by rewording "Not verified" as "no verification recorded" in every language, and the first version of this entry said the collision was closed. It was not: the OTHER direction had been left alone, and the existing "Not checked" itself reads "not verified" in French ("Non vérifié"), Portuguese ("Não verificado"), Japanese ("未確認") and Bengali ("এখনও যাচাই হয়নি"), so an unreadable catalogue showed a French reader "Non vérifié 135", a lookup that happened and found nothing, for a lookup that never happened. The `unchecked` state now has its own key, "Not looked up", in all twelve files. Two states that read the same on one panel are a defect the English text hides; compare a new word with the EXISTING translations of every word on the same panel, in every language, and when an existing key's translation is the collision, give the new state a new key rather than editing a string other screens use.

**The rule.** A report over a denominator credits an item only through evidence that names it, lists what could have credited it and did not, keeps a failed lookup apart from an empty one, and drives its caller (not only its pure core) with the failure. A block added to a diagnostics member is paid for in the same commit and measured in the smallest and the largest shape the member takes.
