## 2026-11-06 — a stored summary of the current places is keyed by the country row, which is sound only while the cut and the daily apply are the sole writers of `osm_objects` (OSM R439)

**What was found.** The brands, contact-channels, freshness and geography readers each ran their own aggregations over `osm_objects` on every request (on a 2 M place lane: 3.2 s, 2.9 s, 2.4 s and 6.6 s for one country). The summary stores what those aggregations would count, under a header of `rule_version` (a digest of the revision number and every key set the parts count), the country's `finished_at` and its `diff_sequence`. Three facts decided the design. (1) The key is enough only because exactly two modules write `osm_objects`, the cut (`ingest.py`, delete then insert, which resets `finished_at` and `diff_sequence`) and the daily apply (`apply.py`, one transaction per file that moves `diff_sequence` and `diff_timestamp` in the same transaction as the rows); `tests/test_osm_places_summary.py::test_only_the_cut_and_the_apply_write_osm_objects` pins the list, so a third writer fails a test rather than quietly serving a stale count. (2) The last edit is stored as a histogram BY DAY, not by age bucket: the buckets (within a year of the vintage, and so on) move with the reference date, so a stored bucket would have been wrong the day after the apply that moved the date, while a day histogram answers every reference date. (3) Every distinct value is stored (20,000 brand rows on the 2 M lane) and the reader applies its own `limit`, because a stored top-100 cannot serve "Show more", and the total the page states ("100 of 20,000") must be the real total.

**The rule.** One function (`places_summary.compute_part`) defines each part and both paths use it, so a stored answer and a computed one cannot drift except by stamps; the parity test asserts stored == computed on every surface at several limits. A stored summary is served only while all three stamps match the country row; a build that finds the row moved while it counted writes nothing ("superseded"). A test that edits `osm_objects` by hand has changed what a summary should say without changing any stamp, so such a test must drop the summary (`forget_places_summary()` in the shared helpers) — the one case the key cannot see, and the reason the invariant is a test and not a hope.
