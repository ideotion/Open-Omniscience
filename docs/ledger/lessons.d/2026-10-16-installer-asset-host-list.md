## 2026-10-16 — a host list for an address the server chooses: pre-check the address, pin every argument of the shared helper, and date the list by what the date really records (PR #1409)

**What was found.** The Ollama installer's asset download builds its session from `browser_download_url`, a value the release response chooses, and it followed a redirect to wherever the answer pointed. Giving it a list was small; the independent read of the fix found three things the list alone did not do.

**The rules.**
1. **`requests` rejects a malformed address BEFORE `send`, with an error that quotes it.** A host list checked in `GuardedSession.send` never sees `https:///x`, a port over 65535 or a non-text value from a response, so the address leaked into a 500 and the log. A response-chosen address is checked once by hand with `refuse_unlisted_host(url, hosts)` before the request, inside the same `try`; a value that is not text is refused as a missing URL. The same applies to a malformed `Location` on a hop, which fails inside `requests` before `send`: it is not followed and nothing is sent, but it is an ordinary error, not a refusal, and the prose must not promise a 502 for it.
2. **A helper shared by two callers is only pinned when a test fails for each of its arguments.** `_get_within(url, hosts, timeout=, download=)` passed with the timeout dropped, the egress purpose dropped, the lookup given the download's timeout, `NetworkBlocked` called a refusal and the stream-isolation token dropped, with every test green. Record the `timeout` the adapter was sent with (30 and 120), run both getters with the real kill switch engaged inside `open_window(PURPOSE_AI_INSTALL)`, feed `TransportUnavailable` and `NetworkBlocked` and assert neither is a refusal, and check the two sessions' proxies differ in protected mode.
3. **Remove the `UNLISTED_SESSIONS` row; do not set it to 0.** The AST scan has zero slack, so a session that now carries a list is deleted from the table, and the module's docstring and comments are reworded in the same commit.
4. **A percent-sign case is only a case for the percent clause if the host clause does not also refuse it.** `release-assets%2B.githubusercontent.com` is refused as an unlisted host too. Test the clause with a name whose decoded form IS listed (`%6D`), and say the other is defence in depth.
5. **A date in a freshness registry says what it records.** The list came from this repository's own record (SECURITY.md, 2026-09-27) and the build sandbox cannot reach GitHub's storage, so `GITHUB_ASSET_HOSTS_AS_OF` and `last_verified` are the day the record was written, not a day anyone watched the redirect; the registry text and the constant's comment say so, and the queue entry keeps ONE operator step STILL OPEN (follow the real chain of the `install.sh` asset and compare each hop). A number that reads as an observation and is not is the fabricated-verification shape the project refuses.
6. **Say what a list does not do.** Listing `github.com` (the host of the address the release names) lets the response name ANY `github.com` path; the list limits where the request goes, not what is installed. The `sha256` GitHub attests, over TLS from `api.github.com`, is what refuses a different script. An HTTP or connection error after a followed redirect also still carries the listed storage address, signed query included, into the 500 and the log: R141 kept "other failures unchanged", and the queue entry says so.
7. **A ruling number is the owner's to record.** The assignment named the rows R137, R139 and R140 as missing from the index; their owning threads hold the verbatim text, and a row written from a relay's paraphrase was refused by the permission check. The PR amends R141 in place and writes no other row; the coordinator moved the rest to the threads that own them.
