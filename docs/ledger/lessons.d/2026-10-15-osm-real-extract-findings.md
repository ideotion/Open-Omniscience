## 2026-10-15 — a real extract found three defects the fixture could not: rank-only ordering, a guessed disk floor, and an index build that read the country at once (PR #1398)

**What was found.** Row D had only ever run on a synthetic fixture. With the user's diagnostics unavailable, the lane was run on the real extracts a public repository carries as test data (Liechtenstein 2013, which closes; three bounding-box files, which the ingest refuses by name) and on a 1x/4x/16x composite of real Utrecht data inside a 3.5 GiB, 2-core envelope (a bind-mounted cgroup that the reader's own headroom check reads). Three defects appeared. (1) `search_names` ordered by FTS5 `rank` alone and BM25 favours the SHORTEST document: the town "Vaduz", whose name is stored in six spellings, came 16th behind a one-word post office, and the search box shows three. (2) The runner's disk floor was 2x the extract; real data settled at 6.0x (Liechtenstein) to 7.5x (Utrecht) its bytes, and a big file also keeps 16 bytes a node of locations while the cut runs. (3) `build_search_index` read every object with `.all()`: the build's memory grew with the country (peak 2,213 MB at 2.88 M objects), where a page of 50,000 rows holds it to 1,443 MB.

**The rules.**
1. **A ranking function that rewards brevity needs a salience key ahead of it.** `ORDER BY o.notable DESC, rank`. A fixture whose names are all about the same length cannot show it; a real multilingual name list does.
2. **A floor that is a guess is allowed to stay one, if it says so, but a worst case computed from measurements belongs beside it.** Refusing at the worst case (10.5x: 7.5x for osm.db and 3x for the node-location file) would turn away a country that fits (France from a continent file needs 2x); so the preflight WARNS with `worst_case_bytes` (before the run starts, through `on_preflight`) and names `--min-free-gb` to refuse. It is an extrapolation from two small files and says so. A test pins both: the 14 GB class file on 100 GB is ok-with-warning, 20 GB free is refused, a measured prior report or an override is not warned.
3. **Never `.all()` a table whose size the country decides.** Page by keyset (`id > last ORDER BY id LIMIT n`), with the page size a named constant that says what it protects, and test the page count with a `before_cursor_execute` spy so the test fails when the paging goes. **And read the query PLAN, not only the statement count:** with a filter on an indexed column SQLite chose that index and a temp b-tree sort, so every page re-read the whole remainder (about N squared over the page size; the lane never runs ANALYZE). `+column` keeps the index off and the rowid drives the scan; the test runs EXPLAIN QUERY PLAN on the statement the build sent.
4. **A scale composite must keep the properties the reader depends on.** An id-sorted file (libosmium's sparse location index needs it) and ids spread over the planet's range (an `osmium.index.IdSet` costs by the SPAN of its ids, about 1.4 GB flat for nodes, not by their count): the first two tilers produced a file that resolved one copy's ways, then one whose id sets were an order of magnitude too cheap.
5. **`pkill -f` with a pattern that appears in your own command line kills your own shell.** Kill by PID.
6. **A slope that survives the explanation you removed is not that explanation.** The cut's steady memory climb was first read as per-object growth (and extrapolated to a ceiling), then as the in-memory location array; forcing the file index left the slope untouched, and a ten-line probe (sorted ids added to `osmium.index.IdSet`, RSS sampled along the pass) reproduced it with no cut at all: the bitmap's cost follows the SPAN of the ids, up to 1.43 GB of node ids at today's range (4 MiB for every 2**25-id window touched), and it arrives as the scan walks the id space. Refute the hypothesis with the control run, then isolate the real source on the smallest thing that shows it. An `array('q')` of the ids as they arrive (files list them ascending) with a binary search costs 8 bytes an id, an out-of-order id goes to a side set, and the run record counts the disorder: peak 1,443 to 823 MB on the 16 x run.
