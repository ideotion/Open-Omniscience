## 2026-10-17 — A LOCK LEFT HELD IS DECIDED BY WHERE ITS OWNER IS, NOT FOR HOW LONG, AND A DEAD OWNER'S THREAD IDENT IS HANDED TO THE NEXT THREAD

(1) **The detector (R144(b)) has no timeout and no number.** `kv_store._hold_lock` is taken only for bookkeeping, inside `_write_slot` and `hold_writes`, never across I/O or a wait. So an owner that has NO frame of those two functions on its stack, or is not a live thread at all, left a section without letting go, and "for how long" needs no figure. `_stuck_owner` reads the owner from `repr(threading.RLock())` (`owner=<ident> count=<n>`; taking the lock to look would be the very thing that can leave it held; a test pins the wording on this Python and a wrapper whose repr names no owner makes the detector silent, never wrong), reads that thread's stack from `sys._current_frames()`, and `_refuse_if_stuck` requires the SAME owner with the same last-section entry on two looks one scheduling turn apart. It raises `KvLockStuck(KvWriteRefused)` with fixed words (operation, thread kind, UTC time, never a thread name, "nothing was written", "restart"); it never replaces the lock. The no-fixed-caps rule asks what a number protects; here nothing needs one.

(2) **A dead thread's ident is reused.** The first version of the test left the lock held by a thread that ended and then asked from a NEW thread: the new thread had the dead owner's ident, `owner == me`, the RLock re-entered, and the section ran. That is also what happens in production: a thread started after the owner died can re-enter a lock nobody else can take, so the detector refuses every OTHER thread and that one thread passes. The test now starts the asking thread BEFORE the owner ends, and the code says so as a residual (with an identical re-entry between the two looks, and a lock leaked after the check).

(3) **A test for a detector must not hang the suite.** With the check removed, the call waits for ever on a lock no one will release; a mutant run hung for the whole timeout. The test runs the call on a daemon thread with a 10 s join and fails with "nothing refused it". Five mutants (no check in the save, none in the hold, stack not read, looks not compared, entry never named) each turn at least one test red; the "looks not compared" mutant survived until a test fed `_refuse_if_stuck` two different looks on purpose.

(4) **Cost.** Measured with the same SIGALRM loops as the rest of R144 (25 s each, before 77b4b9c88, after the detector): write slot 28,593 and 30,759 interrupts, 0 locks left held and 0 in-flight counts leaked on both sides; restore hold 82,281 and 82,292 interrupts, 0 left owned, 0 counters wrong, 0 stale waiters. About +3.1 us per save in an empty-save loop (an upper bound).
