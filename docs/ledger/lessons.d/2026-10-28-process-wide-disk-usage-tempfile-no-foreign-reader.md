## 2026-10-28 — Process-wide patches of shutil.disk_usage and tempfile have no foreign reader in the suite: measured, no defect (parent sweep R385 item 2, after the os/time/open guards)

**Question.** The os, time and builtins.open sweeps asked who reads a process-wide patch at call time. The same question for `shutil.disk_usage` (44 patch sites in 12 files, 50 installing tests) and `tempfile` (`mkstemp`, `tempdir`, `SpooledTemporaryFile`; 9 sites in 4 files).

**Method (no repo edit).** A pytest plugin outside the repo replaced the module's class so that a `setattr(shutil, "disk_usage", fake)` wraps the fake in a recorder (caller module and function, thread, test); for `tempfile` it wrapped `gettempdir`, `gettempdirb`, `mkstemp`, `mkdtemp`, `mktemp` and walked past the module's own frames to the real caller. Each file ran once, unchanged.

**Result.** `disk_usage`: 135 events; every caller of a fake is the module under test (`maintenance`, `article_indexes`, `keyword_log_export`, `storage_events`, `vitals_history`, `hardware_reading`, `bulletin.evidence`, `folder_backup`) on the test's own thread or its own named background thread (`bgjob-article-indexes`, `volume-backup`); one test reaches two modules of the same pipeline (`bundle._hardware_profile` then `storage_events.free_bytes_of`). Neither pytest nor the standard library reads `disk_usage`. `tempfile`: during the patched windows the callers are `keyword_log_scan.mkstemp` (100), `keyword_log_export.mkdtemp` (40) and `gettempdir` from `src.api.diagnostics`; the only foreign reader is `_pytest.capture` creating a capture inside `test_guards_for_diff.py::test_a_guard_main_added_is_green_on_the_branch_and_red_on_the_merged_tree`, which reads the patched `tempdir`, a scratch folder that exists. No defect, no guard needed.

**What would change that.** A patched `tempfile.tempdir` that points at a folder that does not exist, in a test that also uses `capfd`/`capfdbinary` (their `TemporaryFile` asks for the temp folder at fixture time); none exists today. Rule: a fake that replaces a stdlib function process-wide is safe here because every reader is the code under test; re-run the spy if a background sampler ever starts calling `disk_usage` from a thread the suite leaves running.
