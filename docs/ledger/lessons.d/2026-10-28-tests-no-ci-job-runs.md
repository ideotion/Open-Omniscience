## 2026-10-28 — Nineteen test files (151 tests) skip in every CI job: a test gated on an optional package is green by skipping wherever the package is absent, and nothing named the files the one job that has it must run (parent sweep R385, candidate 1)

**Question.** Which tests does no CI job run? A test counts as never-run only when it is skipped in EVERY job, so the measure is the job install sets in `.github/workflows/ci.yml` against every skip site, not the skip list of one environment.

**Method (no repo edit, no ci.yml edit).** (1) The install set of each job: `test` = base + `[analysis,dev,segmentation,pdf,ocr,geo]` + `PySocks==1.7.1` and a bare `pytest -q`; `core-only` = `[dev]`, bare; `portability` = `[analysis,dev]`, bare, observation only; `crypto` = `[analysis,dev,pqc,timestamping]`, five named files; `columnar` = `[analysis,dev,columnar]`, nine named files plus one `-k` step; `sqlcipher-engines` and `urllib3-floor`, targeted. (2) Every `importorskip` and every `skipif`/`skip` on a package, 214 skip-capable files run once with `-rs`, the skip reasons grouped. (3) For `duckdb`, which only `columnar` installs: the 20 gated files that `columnar` does not name were run with `duckdb` made unimportable by a meta-path finder that raises `ModuleNotFoundError` (pytest 9 `importorskip` skips only on that, not on a plain `ImportError`, which fails collection instead). Then the same 20 files with `duckdb` present.

Not package gates, so not covered by the ratchet: `tests/test_fault_harness.py` (6 tests, `OO_FAULT_HARNESS=1`, no job sets it), one test that needs `pytest -n N`, and two that need operator-built `osm_admin*.json`.

**The 151 were not just unrun, one was red.** With `duckdb` present, 250 of the 251 tests passed; `test_the_join_feeds_the_text_grouping_one_row_per_keyword_not_one_per_keyword_and_day` failed (`[None]` operator types) because it read DuckDB 1.x's profile JSON (`operator_type`, `operator_cardinality`, nested under `children`) and `pyproject` says `duckdb>=1.4` with no ceiling, so pip resolves 2.0.0 today, whose profile is `type`, `intermediate_rows`, under `operator`. Making the reader read both fixed the red and exposed something worse: under 2.0.0 the optimizer aggregates BELOW the join by itself (`PERFECT_HASH_GROUP_BY` under the `HASH_JOIN`), so the shipped join-first query and the pre-aggregated one produce the same 9-row join, and the test passed for either (the mutant "use the shipped query" stayed green on 2.0.0, red on 1.5.6 with 87 rows against 9). The test now plans the shipped query as a control and skips, saying why, where the engine does that itself; the equality tests above it still tie the two shapes together on every version. All 251 pass on 1.5.6 and on 2.0.0 (one skipped).

**Rule.** (1) A skip is a green. Count a test as run only where some blocking job installs the package AND runs the file; a job that installs the extra but names a fixed file list covers only that list, and the list does not grow when a test file is added. (2) `tests/test_skipped_tests_have_a_ci_job_that_runs_them.py` reads ci.yml and pyproject, and fails when a file gated on `importorskip(P)` or `duckdb_available()` is not covered by a blocking job; `KNOWN_UNCOVERED` records today's gap and is compared both ways with zero slack, so it can only shrink. (3) A test file that has never run in CI has no proof it passes: run it once under the real extra before adding it to a job. (4) A plan-shape assertion is a claim about the optimizer; give it a control that proves the engine does not already do the thing the code under test exists to do.

**The fix is a ci.yml edit and ci.yml is Export's**: the proposal (name the 19 files in the `columnar` step; a `fault-harness` job; a Chromium job for playwright; `-n 2` for the one xdist test) is in `/mnt/project-files/fix-source-qualification/proposal-tests-no-ci-job-runs-2026-10-28.md`.

**Not covered.** A gate the checker has no name for (bare `try: import x`, `find_spec`, a `skipif` on an unrelated condition); a job that names a file but deselects its gated tests with `-k`; the columnar job's own `-k` step.
