## 2026-10-16 — a lock for a native abort nobody can explain: cover the whole call tree, price it before defending it, pin its coverage with a walk, and write the evidence down as inferred

**What was found.** The collector aborted (SIGABRT, no Python traceback) inside `lxml.html.document_fromstring`, called from `trafilatura.load_html` <- `bare_extraction` <- `extract_article`, in a pass with about 50 workers, one boot in seven (2026-10-14). A reading of lxml 5.2 to 6.1.3, libxml2 2.12 to 2.15, trafilatura, htmldate and justext found no changelog or tracker entry for it. The one loose match, trafilatura issue #840 (concurrent extraction, fixed in 2.1.0), is a release OLDER than the one the trace points to: its line numbers (`utils.py:345`, `core.py:382`) are those of trafilatura 2.3.1, while `requirements.lock` pins 2.1.0, so the machine that aborted was not running the lock either.

**The rules.**
1. **When the cause is unknown, make the guarantee structural and make it cover the WHOLE call tree.** `src/ingest/extract.py:_LXML_LOCK` is a process-wide `RLock` around `extract_article` as a whole, not around the parse: the frame that aborts is where an earlier corruption surfaced, and a tree released after the lock is given up frees libxml2 memory concurrently again. The result holds text only, so every tree dies with the call's last local, inside the lock. A test releases a sentinel tree and asks whether the lock was held at that moment.
2. **Say that the evidence is inferred, and name the heavier fix and the event that would call for it.** The versions are read off line numbers, not off the machine; absence of a tracker report is weaker than a report; nobody reproduced the abort, so a lock that "works" is learned only by not seeing it again. The OPEN_QUEUE item records all three, what a recurrence looks like in a build that carries the lock (frames `extract_article` <- `_extract_locked`) and the next step then (extraction in a subprocess: the only way to survive a native abort).
3. **Price the lock before defending it, and put the figures in the PR.** Measured on 4 CPUs: extraction alone, 24 pages of 22,000 characters, 1 / 4 / 16 / 50 threads, 213.6 / 57.1 / 52.7 / 46.1 articles per second unlocked against 231.6 / 218.1 / 221.0 / 209.4 locked; the whole pass (96 articles) at 1 / 8 / 50 workers, 1.5 s fetch delay, 0.51 / 2.40 / 3.77 against 0.51 / 2.45 / 3.92. The belief that a lock "serialises the work and so costs throughput" was wrong here: unlocked threads are three to four times SLOWER (on trafilatura 2.2.0 and again on 2.3.1). One thread is the noise floor (3.85 against 4.21 articles per second at one worker with nothing to contend), so a difference under about 10% is not a claim. The explanation (threads that parse without overlapping fight for the GIL and the allocator) was NOT profiled and is written down as a guess. The bench gained a `threads` mode (`collect_throughput_bench.py threads`) so the next person measures the same thing.
4. **A lock is only as good as its coverage, and coverage is a property of the tree, so walk the tree.** `tests/test_extract_lock.py` walks `src/` for every way libxml2 can enter the process: an import of lxml, trafilatura, htmldate, justext or readability, a dynamic import of one, `pandas.read_html` (lxml by default), and `BeautifulSoup(...)` without an explicit `html.parser` (bs4 picks the best parser INSTALLED, which is lxml when it is there). Inside `extract.py` only the two locked functions may call trafilatura and only under `with _LXML_LOCK:`; `from trafilatura import bare_extraction` and `import trafilatura as tf` are refused because they hide the calls from the walk. The walk is proved on fixture sources (it must see each way in, and accept what is allowed), and the module was mutated seven ways (no lock, a plain `Lock` that deadlocks a nested call, a lock leaked on a raise, a blank page taken inside the lock, a tree kept past the call, the lock released before the work, the fallback outside the lock): all killed.
5. **Check that a proposed version bound would have excluded the version in the trace, and record only versions a test run exercised.** `trafilatura>=2.1.0` is justified by #840 but would not have changed the machine that aborted (it ran a newer release), so it is built, with its registry entry, and the PR does not offer it as the fix. The registry says `verified` 2.3.1 (run), and that the floor 2.1.0 was run by hand only: the `lockfile-install` job imports the app and runs no test, and the `test` job resolves whatever release is newest that day.

**What it does NOT cover, said so.** A native abort under the lock still kills the process; `gc.collect()` and `malloc_trim` run from the memory guard during a pass and are not kept out of it (48 extractions left zero unreachable objects, so a collection had no tree to free, but the exception path was not measured); a dependency that parses with lxml on its own thread would not go through the lock.
