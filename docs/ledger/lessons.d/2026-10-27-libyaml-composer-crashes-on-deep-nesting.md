## 2026-10-27 — libyaml's loader segfaults on deep nesting where the pure loader raises, so a "same result, faster" swap is not the same behaviour

**Found by** swapping the uploaded-export reader to the shared libyaml loader (#1561) and running the existing `test_an_upload_nested_too_deeply_is_a_400_not_a_500`: the whole pytest process died with a segfault, not a failure. The pure-Python loader raises `RecursionError` at about 500 levels, which the readers turn into a 400; libyaml's composer recurses on the C stack with no limit and no Python exception, so a 200 KB document (100,000 levels) takes the process down. Measured on an 8 MiB stack, main and worker thread alike: maps parse to 23,681 levels and crash at 23,925; sequences 25,876 and 26,364 (the 512 KB and 1 MB crash depths are inferred from 351 B/level, not measured).

**The shape to look for:** a speed-up that "returns the same objects" and is proved on parity tests over REAL files. Real files nest 5 levels; the difference is entirely in the failure path, which a parity test never visits. The swap was safe on every input the repo contains and fatal on one a user can hand it (an upload, or a restored backup's file written unparsed: finding F5).

**The rule:** before moving a parse call to the shared loader, classify its input as app-written, operator-editable or untrusted, and run the repo's own deep-nesting test through it. The shared loader now refuses past 256 levels itself (`src/utils/safe_yaml.py`, `YAMLDepthError`, a `yaml.YAMLError`), counted from libyaml's event stream before anything is composed; the pure path gets no pre-pass because it already fails safe and the pass would cost it 78%.

**Two measuring traps from the same work:** a block-mapping generator indented by depth is quadratic (100,000 levels is 10 GB; the process was OOM-killed, not crashed), so deep block maps are tested at 2,000 levels; and a helper script named `bisect.py` in the working directory shadows the standard library's `bisect` and silently re-runs itself when `statistics` imports it. PR #1569.
