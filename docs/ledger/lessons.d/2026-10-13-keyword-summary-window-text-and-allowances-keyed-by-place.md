## 2026-10-13 — a sentence that names a window must be built from the window and the cap it was built under; an allowance is keyed by where a line stands, not by what it says; a removal leaves its keys unless a test pins them gone

**(1) A description built from a constant lies when the parameter moves, and "every" is a claim about what is on disk, not about what was asked.** `summary.json`'s `method` said "top 5000 PER dominant signature language" over the All keywords set, which is built over every keyword (`per_lang` a billion, no cap): the number came from the module constant, not from the window the set was built for. The first fix said "every keyword" whenever no language was cut, and an independent read showed it false in the next regime: with the attachment cap on (the 9 MB default of a zip or parts build; `format=parts` with no `max_mb` is what the 404 text tells a person to ask for) the trim drops the lowest-mention entries of every language AFTER the summary's text is fixed, so 1,801 keywords under a small cap left 1,266 in the files (975 for parts) and the text still said "every keyword". **Say "every keyword" only where nothing can remove one (window uncut AND `max_bytes is None`); otherwise state the window and say the cap may trim, pointing at the manifest field that counts what was omitted.** Pin each regime with a case that makes it happen (a small `max_mb` and a corpus larger than the cap), and assert the precondition in the test (`held < total`) so the case cannot pass by trimming nothing. A text built as "(X PER dominant signature language …)" also reads as "X per language" when X is a count: put the window first and the quota after a semicolon, not inside one clause.

**(2) An allowance keyed by line text excuses that text anywhere.** The slot producers' guard excused one raw `getattr(pool, name, None)` by its text alone, so the same line pasted into another function passed. It is now keyed by (module, owning function, text) with a count, which reports a copy elsewhere, a second use beside the original, and a rename of the function. The independent read found the last hole: the owner name left out class names, so MOVING the line into a method of another class with the allowed function's name was excused (a copy is caught by the count; a move changes no count). **The owner is the dotted path of the classes and functions that hold the line, and the test that plants a copy must also plant a move.**

**(3) A removal PR leaves its locale keys behind, and the i18n gate is green with them.** Twenty keys, translated in each of 12 files, belonged to buttons and hovers that no control carries (one an unconditional claim about the digest that the live hover no longer made), and no test noticed because the gate counts keys across languages, not against the code. Finding them: take every candidate key from `en.json`, look its first 60, 30 and 20 characters up across `src` (HTML, JS, Python, scripts) and READ every hit, because a prefix that matches is a different string more often than not (a docstring that begins the same way, the 4 MB variant of a 1 MB hover, the live `{mb}` template of a dead `{n}` one); remove by LINE (one key per line) asserting exactly one match per key per file; then pin the prefixes gone from all 12 locales and from every `.js` and `.html` below `src/static` (the first version read only the top level and missed `guis/`). The independent reads found seven more of the same family that the first sweep's own comment had promised to cover: compare the comment's scope with the list's scope.

**(4) A constant only governs a site if a test can move it.** Six cuts in `volume_job.py` were literals (`limit=2000`, `[-8000:]`) beside `runlog.FAILURE_MSG_KEEP` and `FAILURE_TRACEBACK_KEEP`; a test run with the real values cannot tell a literal 2000 from the constant 2000. The test makes both constants small (120 and 300), runs one failure per branch (backup, the newsletter-free refusal, restore) and bounds the journal's message and traceback AND the error the job serves; each one-literal mutant is killed and none by a test that passes at the real values. Two details cost a round: the restore's refusal exception takes a different branch (a `run_end` with a 500-character detail, not an `error` milestone), so the restore case needs a generic failure; and the refusal case holds only while its fixed sentence is longer than the cut, so the test asserts that precondition instead of assuming it. Two `said[:500]` cuts of the `run_end` detail remain literal in the same file and are named here rather than left unmentioned.
