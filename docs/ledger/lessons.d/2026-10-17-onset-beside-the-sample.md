## 2026-10-17 — The first event of a kind is recorded at the event, beside the sample, because a keep rule drops exactly that one (PR #1421)

**What was found.** Two Diagnostics bundles of ONE process put the first bad hour of the pool at 16:00 in one and 15:00 in the other: the reader took the oldest KEPT pool timeout as the onset (10 of 1,575 kept, then 10 of 1,362), and the keep rule (the longest and the newest) moves that event as new ones arrive. The onset is a time EXTREME, and a rule that keeps extremes of length keeps none of time.

**The rules.**
1. **A fact about the whole history is written when it happens, never read off the sample.** `storage_events.ONSET_KINDS` (`gate_hold`, `pool_timeout`) set `first_seen_at` under the journal lock in `record()`, before the keep rule can drop the event; it is written with the counters and read back across restarts, and `total` is the count since it (both start at the kind's first event), so no second count is stored.
2. **An onset the file never recorded is unknown, not the next best time.** A file that counted events before the field existed has `first_seen_at: null` plus `first_seen_unknown`; this process's first event is a later time and would pass for the onset. A junk value in the file reads the same way, and a kind with no event has neither field.
3. **Only the kinds read by the hour carry it.** In a slot that is full at its widest every key is bytes: the other kinds are runs and transitions. The two keys are 88 bytes, paid by tightening the method's own sentences (the fixed part grew 22), so the widest journal keeps the same 5 of 20 splits (44 bytes free, was 66) and the test asserts at least 5.
4. **The test has to lose the event.** The first event is recorded SHORT and the events after it LONGER, so by the keep rule it is neither among the longest nor among the newest; the test asserts it left the sample (anti-vacuity), that the sample's own oldest is an hour late, and that the onset is still the first. Ten mutants (onset from the sample, reset on every record, not written, new process overriding, legacy taking the new first, junk accepted, no reason, every kind, cut with the events, reason on an empty kind) are killed.
