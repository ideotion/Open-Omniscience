## 2026-10-17 — The first event of a kind is recorded at the event, beside the sample, because a keep rule drops exactly that one (PR #1421)

**What was found.** Two Diagnostics bundles of ONE process put the first bad hour of the pool at 16:00 in one and 15:00 in the other: the reader took the oldest KEPT pool timeout as the onset (10 of 1,575 kept, then 10 of 1,362), and the keep rule (the longest and the newest) moves that event as new ones arrive. The onset is a time EXTREME, and a rule that keeps extremes of length keeps none of time.

**The rules.**
1. **A fact about the whole history is written when it happens, never read off the sample.** `storage_events.ONSET_KINDS` (`gate_hold`, `pool_timeout`) set `first_seen_at` under the journal lock in `record()`, before the keep rule can drop the event; it is written with the counters and read back across restarts, and `total` is the count since it (both start at the kind's first event), so no second count is stored.
2. **An onset the file never recorded is unknown, not the next best time.** A file that counted events before the field existed has `first_seen_at: null` plus `first_seen_unknown`; this process's first event is a later time and would pass for the onset. A junk value in the file reads the same way, and a kind with no event has neither field.
3. **Only the kinds read by the hour carry it.** In a slot that is full at its widest every key is bytes: the other kinds are runs and transitions. The two keys are 88 bytes, paid by tightening the method's own sentences (the fixed part, the member with every events list emptied less the 20 bytes of the empty `dropped_to_fit`, grew 24: 5,152 to 5,176 once the file has been written; an independent re-measure corrected the first cut's 26 and 5,178), so the widest journal keeps the same 5 of 20 splits (17 bytes free, was 43) and the test asserts at least 5; an unknown onset shows a short reason instead of a time and costs a split at the widest names (4 kept), which a test pins.
4. **The test has to lose the event.** The first event is recorded SHORT and the events after it LONGER, so by the keep rule it is neither among the longest nor among the newest; the test asserts it left the sample (anti-vacuity), that the sample's own oldest is an hour late, and that the onset is still the first. Fourteen mutants (onset from the sample at the member, the file write and the file read, reset on every record, not written, new process overriding, legacy taking the new first, junk accepted, no reason, every kind, cut with the events, set by a refused record, stamped before the lock, shown while the history is unread) are killed; the second read of the fold found the three that survived the first ten.
5. **Take the stamp under the lock that orders the records.** `at` was stamped before the journal's lock, so a recorder that stamped 15:00 and reached the lock after one that stamped 16:00 left the onset (and `since`) at 16:00 beside a kept event of 15:00. The stamp is one more call under the lock (fixed width, so the size check is unchanged); the test holds the first recorder between its build and the lock.
6. **While the history cannot be read, say so instead of showing this process's first event.** A read that ends in "retry later" leaves the journal with this process's events only; its first event is not the first ever, and the next bundle of the same process would say a different time. The member shows null with `history-unread` until the file has been read; the file's value then wins.
7. **The unknown states cost bytes the known one does not.** A reader of the first cut measured only the known onset; a file from before the field (23 bytes more) or an unread history (62 bytes more) costs the widest names one more split. Measure every state a field can be in, and keep the reasons short codes defined once in the method.
8. **Measure a budget in the state the running app is in, and take the timing out of the test.** The first cut measured the member before the background writer's first write; the member's `file` block carries `last_write_ok_at`, null then and a 25-character time after (23 bytes more), so the 17 free bytes were really negative once written and the widest-names floor failed 4 runs of 6 (20 of 20 under load). The test now makes the delay long, writes the file itself, and says which state it measures; the text was tightened by 25 more bytes (the first cut said 23) to give the written state its margin.
