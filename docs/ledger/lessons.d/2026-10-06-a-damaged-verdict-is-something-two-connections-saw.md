## 2026-10-06 — A DAMAGED VERDICT IS SOMETHING TWO CONNECTIONS SAW (E2 fold 3, the coordinator's ruling on the check's verdicts, R100)

(1) **A check that files `damaged` from ONE read puts a latch, an incident and the repair's trigger behind a read that may have differed.** The per-table check, the list of tables and the page pass each read once on one connection, and what a connection answers can differ from what the next one
answers (memory pressure, a log folding, a page cache; the damaged-page poison of #1333 is the same family). So each of the three is read AGAIN on a NEW connection and is filed `damaged` only when the second read agrees (`second_read: agreed`); a second read that is clean or could not be made files `unchecked` with the
first read's first line, the key of what the second read did and the sentence «nothing was concluded», and nothing latches or is repaired on it. An `ok` or an `unchecked` first read stays one read: only the verdict that acts is paid for twice.
(2) **The re-read's merge rule already said the other half.** `DamageRegistry.recheck_finished` keeps an older `damaged` entry over a newer `unchecked` one («a read that could not happen is no answer»), so a re-read whose second read differs does not erase a finding two reads agreed on; the test pins that, not the
opposite it first asserted.
(3) **Test a flaky pair by TABLE, not by call number.** The order the tables are read in is the check's business (smallest first by the planner's statistics), so a stand-in that counts opens («the third read is the healthy file») passes for the wrong table; count the reads of the table under test instead.
(4) **What a second read does not prove.** It is not independent of the machine: a pressure that lasts through both reads fails both. It guards against a read that differs, and says so; the page numbers kept are the first pass's.
(5) **A fact that three paths file is tested at all three, with a record that exists (E2 fold 4).** The boot check, the manual call and the re-read all meet a table list that reads as damage on one connection and as a list on the next. The first two filed `(schema)` `unchecked`; the re-read filed it as the schema reading CLEAN and released a latch whose only entry was `(schema)`. A latch made by `_note_verified_damage` has
no record, so a test built on it cannot see an `ok` replace a `damaged` in the record (R100): start from a real start-up check, which leaves one. A label is read from the entry that earned it: the `(schema)` entry filed for a failed page pass carries the PAGE pass's `second_read`, not the list's.
