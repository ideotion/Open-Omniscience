## 2026-10-28 — A test that spawns a helper subprocess imports the PRIMARY checkout's src, so a merged tree checked in a scratch worktree reports reds that belong to neither PR (R382, the #1617 pre-flight)

**What was found.** To check #1617 against the main of the moment, the merge was built in a scratch `git worktree` and `tests/test_restore_collector_exit.py` run there: 4 failed. The helper that file spawns (`tests/torture_helper.py cmd_merge`) failed with `ImportError: cannot import name 'collector_exit' from 'src.backup' (/home/user/Open-Omniscience/src/backup/__init__.py)`: the subprocess resolved `src` from the primary checkout (an editable install / the working directory it was launched from), which was still at the older base, not from the worktree the test ran in. Main ALONE in a second worktree failed the same 4, which is how the artifact was told apart from a regression. The same merge built as a throwaway local branch in the primary checkout gave 145 passed.

**Rules.**
1. **Check a merged tree where the interpreter's `src` is that tree.** For any test that spawns a subprocess (the restore, torture and CLI helpers), run the merge in the primary checkout on a throwaway branch (`git checkout -b local/mergecheck`, merge, run, delete), never in a scratch worktree. A worktree is fine for in-process tests only.
2. **An ImportError naming a path outside the tree under test is the tell**, and a red that reproduces on the base alone is not the PR's. Run the base first when a red names a module the PR does not touch; do not call it a regression of the lane that owns the module (here WAL's #1607 restore wait) until both are checked.
3. **State it where the next lane reads it**: the PR body's limits and this fragment, so four reds in a worktree are not filed as a WAL regression.
