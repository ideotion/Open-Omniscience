## 2026-11-07 — A list of dangerous names fails open; a rule for every name fails visibly (A-024 stage 2, R286/R412/R443)

**What it replaced.** `src/static/oo-on.js` carried `GESTURE_ONLY`, 31 names that ran only for a trusted click or Enter/Space. It was found by two finders (the verbs in a name, the request a function makes) and the code comment itself called it "a net, not a proof": `lawSetWatched`, `toggleAiCoordinator`, `mbRun` and `familySplit` had no listed verb and were found only after a later read. Every name NOT on it ran for any event the per-event table allowed, trusted or not. A destructive name added without a line there failed OPEN, silently.

**The rule now.** `run()` refuses a `click`, `keydown` or `submit` unless `ev.isTrusted === true`, for EVERY name (`TRUSTED_EVENTS`). A new name is protected by default; a script that really needs to click a bound control fails visibly (the control does nothing, the console says which name and event). Measured first: no `data-on-*` binding is dispatched synthetically by the app (every `.click()` in `src/static` is a blob-download anchor or the unlock page's own buttons; the one dispatched `change` targets four inputs with no binding), so no exception set was needed. `input`, `change` and `toggle` stay out of the rule on purpose (Playwright's `selectOption`/`setInputFiles` and an extension's autofill fire them untrusted); the per-event table still limits which names they reach.

**What stands behind a trusted click.** The list did not disappear, it moved to where it can be argued with: `tests/trusted_click_table.py`, 26 rows, each with the reason a person's click alone is enough (job control: restartable, nothing authored is lost; one-click curation: redone or reversed in one click). Both finders now demand "confirms in its own body, or a row there, or an exemption with a reason", and an entry whose function starts to confirm fails and is named. Reading the 31 again for that table found four that were not like the rest and now ask first: `removeAnnotation`, `removeAuthor` (it also drops every annotation the author imported), `removeDraftItem` (the note on the item goes with it) and `familyResetGroup` (clears every override on a family). `secureErase` already asked and had stayed on the list from before that.

**Rule.** For a security boundary that is a list of what is dangerous, ask which way a forgotten entry fails. If it fails open, invert it: make the safe behaviour the default for every name and keep the short list of exceptions, where a forgotten entry fails visibly. Keep the ACCOUNT (why each exception is acceptable) in the tests, where a reviewer reads it, not in the shipped dispatcher, where it would gate nothing and could only drift.

**Not solved, stated.** A trusted event is not intent: an injected binding a person then clicks (an overlay, an accesskey) is a trusted click on any name the click row lists, and a browser's own `change` after a script's `checkbox.click()` is trusted (the A-023 chain, held shut only by `CLICK_IDS`). The two DOM helpers `ooClickId`/`ooSetValue` are the next step (a follow-on PR, R443): three call sites, replaced by named handlers.
