## 2026-11-04 — A new module that builds a session or a lane table is pinned by tests the module's own suite never runs (PR #1712)

The OSM daily change-file module (`src/osm/replication.py`) built its guarded session with `allowed_hosts=[self.host]`, and its lane model widened `osm_countries` from 17 to 21 columns. Both were checked by the tests of the module and by the OSM, sink-sweep, network-consent and ledger suites, all green locally. Two other files pin exactly these two things for the whole tree: `tests/test_session_host_list.py` (every host list a session is built with must be a module-level name that is a row of `POPUP_LANE_LISTS`, read against the popup lane that names the host) and `tests/test_versioned_models.py` (the widest lane table has a zero-slack column ceiling). Both went red in CI, on the first push, in the 85-minute `test` job and again in the `Core-only` job: one wasted cycle.

The rule: before the first push of a branch, run `python scripts/guards_for_diff.py --onto origin/main --run` (it builds the merged tree and picks the guards the diff touches, 4,318 tests here), not a hand-picked subset of the tests one expects to matter. A hand-picked subset is chosen by what the author remembers, and these two pins live in files nobody would think to name for an OSM change.

Two smaller facts from the same fix. A host list that is a `list` can be widened in place by any caller (`REPLICATION_HOSTS.append(...)`), and the pin only catches rebinding of the name; the sibling lists are tuples, so this one is too. And a lane-table ceiling raise states what it moved: the ceiling moves by the widest table's change (19 to 21), not by the number of columns added (four, to a 17-column table that was not the widest).
