## 2026-11-05 — a comparison of two empty sides passes: give every "nothing differs" check a refusal for "nothing was compared" (C10, `ci_shard.py parity`, PR #1726)

**What was found.** An independent read of `scripts/ci_shard.py parity` found that it compared NAMED modules only. If the unsharded junit report holds no named module of the shard and the shard's own report holds none either, the list of differences is empty, the two total counters are both empty, and the leg exits 0 with "0 modules compared". A conftest import error produces exactly that: one testcase with no module in the unsharded report and the same in every shard's, so all three parity legs would go green on nothing. (The real legs would be red in that case; the point is that the temporary job exists to produce evidence, and an empty comparison is not evidence.) Reproduced with two hand-written reports, all four combinations of an empty oracle and an empty shard exit 0. `ci_shard.py collected` already refused this ("the whole-suite collection holds no test id"); `parity` had no twin.

**The rule.** A check built on "no difference found" needs a second line that says how much was looked at. Here: refuse when neither side holds a named module. The coordinator's request for the report goes the same way: each parity leg must state modules compared and test totals, and the sum must equal the unsharded run's, with 0 compared counted as a failure.

**What the guard was shown to do.** `test_a_parity_that_compared_nothing_is_not_a_pass` runs three shapes (no module on either side, no testcase on either side, an oracle that holds nothing of this shard and a shard that ran nothing) and fails with the refusal removed or weakened to "only when a side is non-empty". The condition that was first written, `not theirs or not named`, had an EQUIVALENT mutant (`not theirs` alone): the difference list already fails every case where exactly one side is empty, so the only case the refusal can add is both empty, and the condition was reduced to say so.

**Stated limits.** It cannot tell a thin comparison from an honest small one; it only refuses zero. The reports are read from the legs' own logs (modules compared, passed, skipped, xfailed), so a human still compares the sums with the oracle's.
