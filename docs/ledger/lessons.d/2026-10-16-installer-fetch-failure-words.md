## 2026-10-16 — a failure's text, the library's own log lines, and a pin table that nothing checks: keep two words, test against a real socket, walk for completeness (PR #1414)

**What was found.** R141 left «other failures unchanged» on the installer's two fetches, and the download's address is a signed storage URL. Measured with `requests` 2.34.2 and `urllib3` 2.8.0, only an HTTP error answer (`raise_for_status`) and a connection that could not be made (`MaxRetryError`: refused, DNS, TLS, proxy, connect timeout) quote the path and query into the exception text; a read timeout, a connection dropped after connect, a truncated body, a redirect loop, a `Location` `requests` cannot read and a body that is not JSON do not quote it today. Cutting every failure to a class name is still the right rule, because it holds when a library release starts to quote the address. The independent read then found what the exception rule could not reach: `urllib3` logs `Failed to parse headers (url=<path and query>)` at WARNING, with the traceback, when a response has a malformed header line, even on a fetch that SUCCEEDS, and it logs the target on a retry and on every DEBUG request line. And the first pin of the host lists to the consent popup was a hand-kept table that a new wide list walked past.

**The rules.**
1. **Keep the two words the caller needs and nothing from the exception.** `failure_words(exc)` is `HTTP <status>` (only an `HTTPError`'s response, an int in 100 to 599 and not a bool) or `type(exc).__name__`. Never `str(exc)`, never a slice of it, never `repr`. A mutant that replaces the class name with `str(exc)[:80]` must fail the sink tests; it does.
2. **Set a flag in the `except`, raise after it.** `raise X(...)` inside the handler keeps the original as `__context__` and a traceback printer or a log with `exc_info` prints the address again. The flag pattern leaves no cause and no context, and a test asserts both are `None`. Log the same two words, with no `exc_info`.
3. **Order the handlers by what each is allowed to say.** The refusal first (its own fixed sentence), `TransportUnavailable` re-raised (a missing proxy in protected mode: a fixed text with no address), then the broad `(RequestException, ValueError)`. A mutant that catches the broad tuple first turns every refusal into a fetch failure; one that drops the re-raise turns a missing proxy into «the lookup failed (TransportUnavailable)». `NetworkBlocked` (the kill switch) is a `RuntimeError`, which the tuple never catches, so it needs no re-raise.
4. **`raise_for_status()` belongs inside the `try`.** Left outside, an HTTP error escapes the handler with the URL in its text. A bad `Location` is a plain `ValueError` (`Invalid IPv6 URL`), not `InvalidURL`: put `ValueError` in the tuple and test the class the library really raises. JSON that parses but is not an object, or nests past the parser's limit (`RecursionError`), is a fetch failure too, not an unhandled 500.
5. **An exception-level scrub is blind to the library's own loggers, and a scripted adapter cannot show them.** `urllib3` writes the request target on its own loggers (`urllib3.connection`, `.connectionpool`, `.poolmanager`, `.util.retry`) before any exception exists. A test that scripts the transport replaces `urllib3` entirely, so it can never see such a line: drive the REAL library against a loopback socket (a header line with no colon, a connection that drops once under `Retry`, a redirect at DEBUG), assert the library DID log (so the case cannot pass because it stayed quiet) and that the host is still there (so the filter did not just blank the record). The cut is a filter on the logger, which sees the record before any handler, so console, files and the error journal are all covered; it rewrites the target ARGUMENTS and says so, and an upgrade that formats the target into a longer string is the one shape it would miss.
6. **A comparison between a list and its disclosure is a test, and the table it reads is checked for completeness.** One parametrised test maps each list to the popup lane that names it and fails on any host the lane does not name; a walk over every session built under `src/` (the AST scan the unlisted-sessions guard already uses) fails on a list that is not a row, or is an inline tuple. The mutant that adds a new wide list plus a session using it passed the first version of the pin. A list may be narrower than its lane; wider is the failure; and because the pin allows narrower, each tightening also needs an exact-list test (adding the unused dumps host is killed by that test alone).
7. **Fix a wide list by tightening the code first.** The popup is what the person agreed to, so widening it to match the code is a consent change; narrowing the code is not. The cost is a closed-failing redirect inside the domain, which is the safe direction, is recorded as an OPERATOR LOOK and never as an observation, and must be NAMED where a probe reads it (the ORES client records `refused_redirect`, not `transport_error`).
8. **A ruling the code makes true is written in the same PR.** R142 and R143 were issued by the coordinator session; the rows were checked free on `origin/main` and on every remote branch right before they were written, because rulings in this repository have collided before.
9. **After merging main, run the tests main ADDED, not only the guards you already know.** The merge of #1413 brought `tests/test_sink_sweep_records.py`, a tree-wide reading of every handler in `src/`, and the first CI run of this change failed exactly there: a name given to `failure_words(exc)` in a handler, `exc.reason` on a refusal, and the helper's own `getattr(exc, "response", None)` are each a use of the caught exception outside a scrubbing call. They went in as three line-by-line entries (function plus exact line text, counted), not as a name allowance for `failure_words`, so a later line in that helper that reads the text is still reported (a mutant that makes it `str(exc)[:80]` fails the sweep for `fetcher.py`, one that makes the installer keep `str(exc)` fails it for `installer.py`, one that makes ORES keep `str(exc)` fails it for `ores.py`). Before a push that follows a merge: `git diff --name-only <old base> origin/main -- tests` and run every file it lists, then the tree-wide guards (`grep -l "rglob\|os.walk" tests/test_*.py`, 46 files, about five minutes).
