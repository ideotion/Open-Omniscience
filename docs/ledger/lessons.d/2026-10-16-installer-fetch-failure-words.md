## 2026-10-16 — a failure's text quotes the address; keep two words, raise outside the handler, and pin every host list to the popup that discloses it (PR #1414)

**What was found.** R141 left «other failures unchanged» on the installer's two fetches, and the download's address is a signed storage URL: any error `requests` raises after a followed redirect (an HTTP status, a dropped connection, a timeout, a loop, an unreadable `Location`) quotes the address it was fetching, query and signature included, into the exception text. The first fix was already known (a fixed sentence); the checks this PR made are what the next session needs. And item 3 found that a host list in code can be wider than the consent popup that tells the person where the app may go, and nothing compared them: three lists were, by a whole family (`.wikimedia.org`, `duckduckgo.com` and `.duckduckgo.com`).

**The rules.**
1. **Keep the two words the caller needs and nothing from the exception.** `failure_words(exc)` is `HTTP <status>` (only an `HTTPError`'s response, an int in 100 to 599 and not a bool) or `type(exc).__name__`. Never `str(exc)`, never a slice of it, never `repr`: a test replaces the class name with `str(exc)[:80]` and the planted signature must fail it.
2. **Set a flag in the `except`, raise after it.** `raise X(...)` inside the handler keeps the original as `__context__` and a traceback printer or a log with `exc_info` prints the address again. The flag pattern (`failure = failure_words(exc)`, then `if failure is not None: raise ...` outside) leaves no cause and no context, and a test asserts both are `None`. Log the same two words, with no `exc_info`.
3. **Order the handlers by what each is allowed to say.** The refusal first (it has its own fixed sentence), `TransportUnavailable` and `NetworkBlocked` re-raised (each carries no address), then the broad `(RequestException, ValueError)`. A mutant that catches the broad tuple first turns every refusal into a fetch failure; one that drops the re-raise turns the kill switch into «the lookup failed».
4. **`raise_for_status()` belongs inside the `try`.** Left outside, an HTTP error escapes the handler with the URL in its text. A bad `Location` is a plain `ValueError`, not `InvalidURL`: put `ValueError` in the tuple and test the class the library really raises.
5. **A comparison between a list and its disclosure is a test, not a convention.** One parametrised test maps each list to the popup lane that names it and fails on any host the lane does not name. A list may be narrower (the Wikipedia lane names `dumps.wikimedia.org` and the wiki session does not fetch it); wider is the failure. Because the pin allows narrower, each tightening also needs an exact-list test: adding the unused dumps host is killed by that test alone.
6. **Fix a wide list by tightening the code first.** The popup is what the person agreed to, so widening it to match the code is a consent change; narrowing the code is not. The cost is a closed-failing redirect inside the domain, which is the safe direction and is recorded as an OPERATOR LOOK, never as an observation.
7. **A ruling the code makes true is written in the same PR.** R142 and R143 were issued by the coordinator session; the rows were checked free on `origin/main` and on every remote branch right before they were written, because rulings in this repository have collided before.
