## 2026-10-16 — an `except` written for one engine's spelling of "this connection is finished" must name the fact, not the spelling

**(1) Two engines, one fact, two exception types.** SQLCipher 4.12 poisons a connection with an empty `MemoryError` after a damaged page; 4.19 answers the real code-11 corruption error instead. `lane_search.search` re-raised `MemoryError` from the snippet read and swallowed every other exception ("a snippet must never fail the search"), so on 4.19 the same fact was swallowed: the hits were built with one snippet missing, then the session's close raised an unnamed `PendingRollbackError` and the caller lost them. The fix (PR #1400) names the fact (`damage.is_corruption(exc)`), not an engine's spelling of it.

**(2) How it was found: damage every page, on both engines, and diff the outcomes.** A grep for `MemoryError` finds the handlers; only running them shows which ones matter. Every one of the 328 pages of an encrypted lane file was overwritten in turn and the search and the indexer run on a fresh engine on 4.12 and 4.19 (`/mnt/project-files/fix-source-qualification/lane-search-audit/probe_*.py`). The indexer behaved alike on 324 pages and the other four raised `OperationalError` on one engine and `DatabaseError` on the other, both re-raised by the same clause, so no change was needed there. A diff of per-page outcomes between engines is the whole method, and it is cheap enough to repeat for the next release.

**(3) What the user sees did not change, and the entry says so.** The route already caught the `PendingRollbackError` (a `SQLAlchemyError`) and answered the fixed `lane-unreadable` reason, so the gain is the logged cause and not building hits that are then thrown away. The route test drives the real `search()` and checks the response AND the log line for the driver's words, the statement and a bound value, using tokens that appear in no source line of a traceback; it fails when the route logs the exception plainly. A fix whose benefit is the log line is still worth its six lines when the log line is what an operator reads, but it should not be reported as a user-visible repair.
