## 2026-10-12 — A SECOND HAND-ROLLED SCRUB BESIDE THE SHARED ONE LEAKS WHAT THE SHARED ONE LEARNED, AND A GUARD THAT TRUSTS A HELPER MUST READ THE HELPER (engine_text onto exception_text, #1342)

(1) **`engine_text` kept its own loop over two needles (the session's passphrase and `OO_DB_PASSPHRASE`) while the shared scrub grew a third (`OO_KEY_PASSPHRASE`, the one that wraps the signing keys), the fail-closed floor for a passphrase under four characters, and the by-class-only answer for a `UnicodeError` (whose words name the character and offset).** Four of the new tests fail on the old body: the key passphrase, a text that cannot be checked, a floor passphrase and a `UnicodeError`. The rule: a net that cleans a caught exception's text is ONE call to `secret_scrub.exception_text(exc, limit=..., typed=False)`; a second implementation is a place the next secret kind is forgotten. The cut comes after the scrub; the held passphrases are read when asked, never kept.
(2) **The import of the scrub stays INSIDE the function.** `engine_text` is loaded by an index pass and the engine stamp (`src/analytics/engine_identity.py`) lists every module a pass loads; a module-level import of `secret_scrub` would change the stamp and read every article as owed a re-index. The scrub is needed only on a failure, so it is loaded only then. If the import fails the answer is the class and none of the words.
(3) **An AST guard that allows a handler to hand its exception to a helper (`_skip_error`, `_cut_reason`) is only as good as the helper's body.** The guard now reads each helper: its first parameter may appear only as `engine_text`'s first argument or inside `type()`/`isinstance()`. The other holes it had: `engine_text` bound twice or by `import engine_text`; a traceback reader written as a bare name (`from traceback import format_exc as fe`, `from sys import exc_info`, `from logging import exception`). The guard has its own refusal tests (one parametrised case per bypass), because a scan that cannot fail guards nothing.
(4) **A log line that carries only `engine_text(exc)` is blank for `KeyError()`.** Three `merge.py` lines and the write-cost debug line now name the class beside the words; the returned values did not change.
(5) **`stopword_batch.py --apply` wrote a Latin word read in a Korean log to `ko.yml`, which `tests/test_stopword_file_scripts.py` refuses; batch 1 moved the ten words by hand.** The tool now splits by the guard's own script map (pinned equal by a test, since a script must not import a test) and prepares both appends before it writes either, so a refusal in the second file leaves the first as it was. A language the map does not know writes everything to its own file.
