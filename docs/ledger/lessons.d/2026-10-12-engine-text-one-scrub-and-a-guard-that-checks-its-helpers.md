## 2026-10-12 — A SECOND HAND-ROLLED SCRUB BESIDE THE SHARED ONE LEAKS WHAT THE SHARED ONE LEARNED, AND A GUARD THAT TRUSTS A HELPER MUST READ THE HELPER (engine_text onto exception_text, #1344)

(1) **`engine_text` kept its own loop over two needles (the session's passphrase and `OO_DB_PASSPHRASE`) while the shared scrub grew a third (`OO_KEY_PASSPHRASE`, the one that wraps the signing keys), the fail-closed floor for a passphrase under four characters, and the by-class-only answer for a `UnicodeError` (whose words name the character and offset).** Four of the new tests fail on the old body: the key passphrase, a text that cannot be checked, a floor passphrase and a `UnicodeError`. The rule: a net that cleans a caught exception's text is ONE call to `secret_scrub.exception_text(exc, limit=..., typed=False)`; a second implementation is a place the next secret kind is forgotten. The cut comes after the scrub; the held passphrases are read when asked, never kept.
(2) **The import of the scrub stays INSIDE the function.** `engine_text` is loaded by an index pass and the engine stamp (`src/analytics/engine_identity.py`) lists every module a pass loads; a pass that loaded `secret_scrub` would fail the closure test (`tests/test_index_engine_stamp.py`) until it was listed under `NOT_OUTPUT_AFFECTING`; it would NOT change the stamp, which hashes only `ENGINE_MODULES` (the first version of this lesson and of the module docstring said otherwise, and the independent read caught it). The scrub is needed only on a failure, so it is loaded only then and the registry stays as it was. If the import fails the answer is the class and none of the words.
(3) **An AST guard that allows a handler to hand its exception to a helper (`_skip_error`, `_cut_reason`) is only as good as the helper's body.** The guard now reads each helper: its first parameter may appear only as `engine_text`'s first argument or inside `type()`/`isinstance()`. The other holes it had: `engine_text` bound twice or by `import engine_text`; a traceback reader written as a bare name (`from traceback import format_exc as fe`, `from sys import exc_info`, `from logging import exception`); a helper rebound (`_cut_reason = lambda ...`, an import, an `async def`, a second `def`) and the exception passed in a helper call's second position. The guard now reads every way a name is bound (`def`, class, assignment, import, parameter, `except as`, `match`), and has its own refusal tests (36 parametrised bypasses plus 5 canonical-import cases, through the same file-level scan the real test uses; deleting any of its binding, first-argument or canonical-import rules turns some of them red), because a scan that cannot fail guards nothing. The first draft's `_scan` helper skipped the binding checks, so those checks could have been deleted with every test still green. **Blind spots left on purpose** (the scan reads one file's syntax, not the program): a star import, a `getattr` alias of a logger method outside the `getattr` ban, and a name rebound through `globals()` or `setattr`; closing them would mean running the code, which is what the caplog tests do for each handler.
(4) **A log line that carries only `engine_text(exc)` is blank for `KeyError()`, and a class written by hand beside a withheld text prints twice** (`RuntimeError: RuntimeError: its text is withheld`). `engine_text(exc, limit, typed=True)` writes `Name: words` once; the three `merge.py` lines, the write-cost debug line, the cleanup skip record and the stoplist recompute record use it. The returned `reason` of the backlog keeps the words alone (its value did not change).
(4b) **A shapes x forms test must assert on what the form WROTE.** The first draft looked for the secret as typed; in `repr`, JSON, bytes-`repr` and SQL-doubled forms the typed secret is not in the text at all, so 14 of 36 cells passed with no scrub. Each form now carries its own encoder and the assertions (absent, prefix absent, cut inside) are on the encoded stretch; a scrub that removes only the typed secret fails 13 cells.
(5) **`stopword_batch.py --apply` wrote a Latin word read in a Korean log to `ko.yml`, which `tests/test_stopword_file_scripts.py` refuses; batch 1 moved the ten words by hand.** The tool now splits by the guard's own script map (pinned equal by a test, since a script must not import a test) and prepares both appends before it writes either and writes through temporary files that are renamed afterwards, so a refusal or a write error leaves both as they were, and a rename that fails after the first landed names the file that did. **The temporary path is a path like any other:** it is created with `open(..., 'x')` (refuses an existing path and never follows a link left there) and is tracked only once this run made it (a path planted between the check and the open is refused by the open and left alone), and a `finally` removes whatever this run made, a Ctrl-C included, so a planted `ko.yml.tmp` is refused and left alone and a failed write removes only its own partial file; the first version of the fold reopened the symlink hole the target's own check had closed. A language the map does not know writes everything to its own file.
