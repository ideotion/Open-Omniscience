## 2026-10-17 — A CHECK THAT MUST RUN AFTER EVERY FIXTURE AND `monkeypatch` UNDO IS A HOOK WRAPPER, NOT AN AUTOUSE FIXTURE; BLAME ONLY CALLABLES THE TESTS WROTE

(1) **The shape.** A guard that wants to know whether a test left a stand-in on a process-wide call (`socket.getaddrinfo`, `create_connection`, `socket.socket.connect`) cannot be an autouse fixture: `monkeypatch` is an ordinary fixture and its undo can run AFTER the autouse fixture's teardown, so the guard reads the patched state and blames the test for something that is about to be undone. Write it as `@pytest.hookimpl(wrapper=True)` on `pytest_runtest_setup` (record) and `pytest_runtest_teardown` (compare after the `yield`), which runs once every fixture has finished.

(2) **What counts as a leak.** Compare by identity, and blame only a callable defined in test code (module `conftest` or a first segment of `tests`). Counting every difference blamed 43 tests in the first version: other tests legitimately leave the guard's own wrappers installed (every `EthicalFetcher` fetch installs the connect guard and nothing removes it). Read class attributes with `getattr` on the class: `socket.socket` patched by an unrelated test raised `AttributeError` in a fixture version that went through an instance. Put the original back after reporting so the next test is not blamed for this one's leak; a put-back that runs always (as in the fixture version) desynchronised eleven ssrf tests that expected their own patch to survive until their own undo.

(3) **The message names the test and the call**, so the failure is at the leaker rather than at a victim in another file that only passes alone.
