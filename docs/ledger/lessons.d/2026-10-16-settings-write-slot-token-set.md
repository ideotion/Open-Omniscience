## 2026-10-16 — a count that two statements keep can be wrong in either direction after an interrupt; keep it as one add and one idempotent discard

**(1) The shape.** `kv_store._write_slot` counted a settings save as in flight with `_inflight += 1` and then `counted = True`, and released it in a `finally` that subtracts only when `counted`. An exception that lands between the two statements (a signal handler's `KeyboardInterrupt` on the main thread; a worker thread cannot be interrupted this way) leaves the count raised with no flag, so nothing ever lowers it and every later `hold_writes` waits out its budget and raises `KvWriteBusy` until the process restarts. Swapping the two statements only moves the error to the other side: the flag is set, the increment never ran, the `finally` subtracts, and the count goes below the real number of writes, so a restore's hold can start while a save is still writing the old file. The first is a refusal; the second is the one that loses data, which is why the original order was the right one to keep until the shape itself was fixed.

**(2) The rule.** Keep a count of "things in flight" as a SET of per-thing tokens: one `add` is the only statement that counts, `discard` is the only release and does nothing for a token that was never added, and the release reads `token in the_set` first. No order of two statements is then wrong, because there are not two. The same shape applies to any "in flight" or "held" counter kept with a flag beside it (`hold_writes` already sets its `held` flag before the hold itself for the same reason).

**(3) How it is pinned.** `tests/test_kv_store_write_hold.py::test_an_interrupt_inside_the_slot_neither_leaks_a_count_nor_releases_another_writes` interrupts the add after and before the token is in, with another write's token already counted, and asserts that the other token is still there and a hold still waits for it. Two mutants were run and caught: `clear()` in place of `discard(token)`, and the release switched off. Readers of the count (`while _inflight:` in `hold_writes`, two tests that polled it as an integer) read it as a truthy set.
