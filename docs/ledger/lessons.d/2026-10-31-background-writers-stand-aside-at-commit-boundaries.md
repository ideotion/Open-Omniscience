## 2026-10-31 — a pause that guards the write-ahead log has to be asked by every bulk writer, and it can only wait where the writer holds no transaction

**What was found (R398, B1; the WAL lane's read of three field zips, 2026-10-31).** The storage guard paused collection passes, the housekeeping lane, `stoplist_recompute`, the heavy reads and the maintenance writes while its log latch held, and named the reader that pinned the log. Two bulk writers never asked: the re-index resume drain (`api/backup_v2.py::_reindex_resume_worker`, whose `should_stop` was `ctx.stopping or _yield_to_import()`) and the article-index build (`database/article_indexes.py::build_missing`). With a reader holding the log's checkpoint mark they went on appending (8.8 MB/s and 3.1 MB/s measured while the guard was engaged), the log reached 80.6 and 219.8 GB, a commit on it took 260 to 441 s, collectors queued for the gate holding a pooled connection each, and the next unlock spent 105 to 1,776 s recovering the log. A guard that names the pin but is not asked by the writer that deepens it is a report, not a bound. The class repeats: every writer added after a "gate every entry point" ruling is the one that is missing, so the question to put to a new bulk writer is "what does this do while the latch holds?".

**The rule, and the three places it can go wrong.** (1) **Wait, do not stop.** A stop leaves the backlog until the next boot or the end of an import run; the pause ends by itself when its cause does (`StorageGuard.wait_if_engaged(should_stop=..., on_wait=...)`, the log AND the drive latch, never the operator's "Resume anyway", which forces collection on). The wait also ends on the writer's own stop and on an import claiming the machine. (2) **Wait only where nothing is held.** The first poll of a call to `reindex_imported_articles` comes before the call has committed anything, and its session holds a checkout: a waiter there would be the very reader that pins the log. So the drain waits before each batch (the worker holds no session or lease) and from the SECOND poll of each call (the commit that ended the last window has ended its transaction), and the index build waits before each statement on no connection at all. (3) **A pause is not a crash.** The index build records an attempt before its first statement so that a build that brings the process down is not repeated at every start (two unfinished starts decline the third). A build that waits for hours with that record in place, and is then killed by a power cut, would count the wait as a crash. The first wait therefore comes before the free-space and memory readings and before the record (the readings are taken right before the build, not hours before it), and the wait between the two statements gives this start's attempt back (`_give_back`, which leaves an earlier unfinished start counted) and takes it again after.

**Stated limits.** The re-index an import runs inside its own run (an operator-started, exclusive operation) does not wait; only the background drain that finishes an interrupted one does. The first window of a call runs even if the latch engages in that instant (one window); the drain's closing whole-corpus counter sweep in its `finally` is another writer with its own slices, not covered; boot's later steps wait behind a paused index build, as they do behind a slow one (`boot_sequence`: no timeout, the slow step is the fault and has to be seen); the free-space and memory readings of the build are not repeated after the wait between its two statements.

**A test lesson from the same change.** `assert snapshot().get("preflight") is None` was written to prove the readings come after the wait, and passed with the wait moved after them, because the snapshot is only updated at later points: a value that cannot change while the code under test runs proves nothing. The assertion that failed under the mutant was a recorder on `preflight` itself. Every check was mutant-proven (18 mutants of the new checks, each killed by at least one new test), and the tests wait for the writer to have REACHED its pause (observed on the job row it publishes) rather than for a time.
