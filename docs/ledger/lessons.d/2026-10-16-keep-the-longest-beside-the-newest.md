## 2026-10-16 — a journal that keeps "the newest N" shows the lead-up to a failure and hides the worst event of the week: keep the longest beside the newest, and let each kept event say which it is (PR #1421)

**What was found.** The 16 Oct 2026 diagnostics bundles carried the storage-events journal with the newest 20 gate holds. The longest hold of the whole session, 219.6 s, was not among them: a stream of newer holds of 15 to 60 s had pushed it out of the cap, and the exporter that wrote the member had no way to know it was the one a reader wanted most. The question the journal exists to answer ("was the log pinned by a reader, or outrun by a writer") needs the worst stall; the cap threw it away because age was the only thing it looked at.

**The rules.**
1. **A retention cap on events that have a size, a duration or a cost keeps two lists inside one number: the `n` largest by that measure and the rest of the cap for the newest.** The cap does not move, so the slot's measured width does not change (here the rule added 1,494 bytes to a journal of 118,424 against a slot of 125,000); counts and dropped totals still say everything that was cut.
2. **The overlap is counted once and the room it leaves goes to the next newest.** An event that is both the longest and the newest takes one place; keeping the list below its cap because of a repeat is the quiet way a rule like this stops keeping what it promised.
3. **Every kept event says why it is there** (`picked_by`: longest, newest or both) and the member names the rule (`keep_rule`), so a reader of a zip does not take a list of twenty for "the last twenty" or for "the worst twenty".
4. **Ties go to the newer, and a value that is not a number is never a length.** A bool is an `int` in Python (`True` is 1.0), a string does not compare, and a NaN in a sort key leaves the order of every other key undefined: test the function by itself on a whole list with a NaN among real lengths, because evaluating it one append at a time can hide the scrambled order.
5. **Apply the rule everywhere a list is cut:** on record, on reading the file, on combining the file with this process, and in the budget cut, which drops the oldest of the OTHERS first and an event kept as a longest last. An event that is cut is also released from the table that lets a late update find it (`update` then returns False, with no error).
6. **Do not split a kind that already has its own lane.** The checkpoint has a notable list for the slow ones and the run kinds keep a still-open run, so the rule names four kinds and a test pins that the others are not in it.
