## 2026-10-26 — `CREATE TRIGGER IF NOT EXISTS` never upgrades a body, and a boot step that skips a trigger "by name" is the same defect

`ensure_source_outlet_id` (`src/database/source_identity.py`) read the names of the triggers on `sources` and skipped any it already found, so a store made by an older build kept the old body of `trg_sources_outlet_id_ai/au/ad` for the life of the file while a new install got the new one. The same shape had already been met and fixed twice in `fts.py` (`_heal_unscoped_update_trigger`, `_heal_raw_triggers`); nothing named it as a class, so the third copy was written the same way. Found by the 0.5.0 audit (item 14), no field incident.

**The rule.** Any boot step that creates a trigger (or a view, or an index) idempotently must decide on the STORED TEXT, not on the name: read `sqlite_master.sql`, compare it with what this build would make, and drop and re-make on a difference inside the transaction that owns the rest of the step. SQLite keeps the statement as written minus `IF NOT EXISTS`, so compare with whitespace collapsed and that phrase taken out of the wanted text (case kept: the body is the module's own). A body that merely differs in whitespace must not churn; a matching trigger must issue no `DROP` on the steady boot (pinned by recording the statements). A NULL stored text is a difference.
**The test shape that proves it.** Plant the OLD body (drop the trigger, create the older text), produce a row the old body gets wrong, run the boot step, and assert the new body is stored, the wrong row is healed and the next insert is right; then run it again and assert it wrote nothing. A test that only checks "the trigger exists afterwards" passes on the unfixed code. `triggers` in the return value now counts triggers WRITTEN (made new or replaced).
Pinned by `tests/test_source_outlet_trigger_upgrade.py`. Audit 0.5.0, 0.5.1 item 14.
