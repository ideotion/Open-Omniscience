## 2026-11-01 — a worker that ends in a `BaseException` left its background job "running" for the life of the process

**What was found (candidate 2, from the keyword lane's scan of the housekeeping and job code).** `BackgroundJob._run` (`src/jobs/background.py`) caught `Exception` only. A worker that ended in `SystemExit` (a library calling `sys.exit`) or `KeyboardInterrupt` skipped the handler: the `finally` stamped `_ended_at` and the state stayed `"running"`. The task manager then showed an active job that was gone, a writer job held `db_writers_busy` (`is_writer`), and nothing ever finished it. REPRODUCED before the fix with a worker that raises `SystemExit`: `state == "running"`, `ended_at` set (`tests/test_background_job_base_exception.py`, red on main for both exceptions).

**The fix.** A second clause, `except BaseException`, sets the state to `"error"` with the exception's CLASS only (`SystemExit: its text is withheld`), logs one WARNING that names the class, and re-raises, so the thread sees what it saw before. The class only, never the words: a `SystemExit` carries the caller's own text, and a job's kwargs can carry a passphrase (the existing handler scrubs its text; this path has no scrub step to rely on, so it carries no text). The WAL lane's failed-start bundle (#1687) owns the sibling edit in `start()`; this change is in `_run` and was rebased onto it.

**The rule.** A `try/except Exception` around a worker is a decision that a `BaseException` ends the worker WITHOUT the cleanup the handler does; when the handler sets a state that the outside reads ("running" until told otherwise), the base-exception path needs its own line that ends the state, or the state outlives the thread. Same family as R393/R395 (`Thread.start()` interrupts), opposite end: there the interrupt must NOT mark the job "error" because the thread may be running; here the thread is certainly gone.

**Pinned by** `tests/test_background_job_base_exception.py` (6): `SystemExit` and `KeyboardInterrupt` each end `"error"` with the class only and no words in the status, the job can be started again, an ordinary exception and a clean run are unchanged, the log names the class once at WARNING with no words, and the exit goes on up after the state is set. Mutant-proven: no clause (3 red), words in the log (1 red), swallow instead of re-raise (1 red).
