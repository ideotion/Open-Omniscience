## 2026-10-17 — A cleanup that takes a plain lock more than once is blocked by its own first failed exit: take it once, and count sections in the source (PR #1442)

**What was found.** ``swap_window``'s cleanup passed three ``with _STATE:`` sections after the body (the read of ``_DISK_CHANGED``, ``_revive``, ``_close_window``). A swap passes more before that: the reset of the flag, ``bump`` and ``_open_window`` open the window, and a swap that changes the disk calls ``disk_changing()`` in its body (every restore, repair and encrypt does), which is a fourth. ``_STATE`` is a plain ``threading.Lock``. A normal ``with`` exit on CPython 3.13 builds a 3-tuple for ``__exit__(None, None, None)``, so it allocates when the tuple free list is empty, and a failed exit leaves the lock held (measured earlier with ``_testcapi.set_nomemory`` on cold free lists, see the lesson of ``#1435``). Every later ``with _STATE:`` then blocks for ever. In the old cleanup a failed exit at any section but the last therefore blocked the cleanup's own next section while the swap still held the exclusive library window: every new pooled connection waited in ``shared()`` until the process restarted (5 of 6, on a swap that changed the disk and on one refused before it). A plain, unlocked read of ``_DISK_CHANGED`` in the cleanup did not help (``#1435``'s dropped fix F3): the hang at allocation 24 of the cleanup moved to allocation 25, to the next section.

**The rules.**
1. **Count the sections a cleanup passes, not the lines.** When a lock's failed exit cannot be prevented (it can only be named), the safest cleanup passes it ONCE, as the last thing that needs it: then a failure there raises the error, the ``finally`` still gives the window back, and the pool serves again. The cost moves rather than vanishes: ``_STATE`` stays held, so the NEXT swap blocks at its first section with its own window held, and the pool stops again as before.
2. **Merge the sections, keep the meaning.** ``_close_window(*, swapped, earlier=None)`` now reads ``_DISK_CHANGED``, gives the earlier connections' validity back and clears the window's stamp in one section; ``earlier=None`` means none to give back, so a caller that only ends a window (the interrupt tests) is unchanged. ``_revive`` is gone. One difference, on the safe side: a failure before the close (at ``held_here()``, the call or the section's enter; found by the independent read) now leaves only the new generation valid, where the old cleanup had already revived the earlier connections: they stay refused, never wrongly valid.
3. **Say what is NOT fixed, and pin it.** The sections before the close are the same exits, and a failure there still blocks this swap's own close: a swap that changes the disk passes 5 sections and 4 of them block it (4 of 5); one refused before ``disk_changing`` passes 4 and 3 block it (3 of 4); before the merge both were 5 of 6. Merging the opening sections into one would leave one such exit and the same block (it cuts the sites, it does not remove them), so it is not done; only having no ``_STATE`` removes it, and that is a separate change (whether it guards anything not already serialised by the exclusive window is its own proof, not a claim of this one). Four tests fail an exit of each section before the close and assert that the swap blocks with the window held. They assert the worst outcome, so they see a change that FIXES a site; one that adds a section is seen by the count test, which pins 3 opening, 1 for ``disk_changing`` and 1 in the cleanup, and by a test that the cases cover every one.
4. **Pin the shape by counting, in the source, to any depth.** The pin counts the ``with _STATE:`` sections in the ``finally`` blocks of ``swap_window`` (a ``finally`` nested in another once) plus what every module function called there passes, followed through helpers of helpers, so a section moved into a helper is still counted. It reports 1 on the module and 3 on the module rewritten back to the old cleanup (a test makes the rewrite, requiring each anchor to match once), and a synthetic source pins the depth and the nesting.
5. **The instruction sweep cannot inject at a lock exit, so use a stand-in lock.** A stand-in for ``_STATE`` whose Nth exit raises MemoryError and leaves its real lock held models the failed exit (and one whose Nth enter raises before the lock is taken models a ``BEFORE_WITH`` that could not allocate); the swap runs in a thread because a block is an answer, not a hang of the test; the stand-in sets an event when a section waits behind the failed exit, so a passing run never waits for a bound, and the teardown gives every lock and thread back in a ``finally``. Red without the merge: the same failed exit blocks the old cleanup (window held), and gives the window back in the new one.
6. **A merge can also close a path the sweep could not see.** On the old cleanup, an allocation failure before the read of ``_DISK_CHANGED`` (the ``BEFORE_WITH`` of that section) left ``swapped`` false, and the old ``_close_window`` did not look at the flag: the window's own connections became valid again AFTER ``disk_changing`` had said the file under them was not the library's. Reproduced on main's module with the stand-in (valid set ``{stamp, new generation}`` where the merged section leaves ``{new generation}``) and pinned by a test beside its red-without. The sweep never saw it: it skips ``with`` lines and never checked the valid set. When two reads and a decision are one section, they cannot disagree.
