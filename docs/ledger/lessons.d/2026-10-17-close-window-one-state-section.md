## 2026-10-17 — A cleanup that takes a plain lock more than once is blocked by its own first failed exit: take it once, and count sections in the source (PR #1440)

**What was found.** ``swap_window``'s cleanup passed three ``with _STATE:`` sections after the body (the read of ``_DISK_CHANGED``, ``_revive``, ``_close_window``), and a swap passes six in all (the reset of the flag, ``bump``, ``_open_window`` before the body). ``_STATE`` is a plain ``threading.Lock``. A normal ``with`` exit on CPython 3.13 builds a 3-tuple for ``__exit__(None, None, None)``, so it allocates when the tuple free list is empty, and a failed exit leaves the lock held (measured earlier with ``_testcapi.set_nomemory`` on cold free lists, see the lesson of ``#1435``). Every later ``with _STATE:`` then blocks for ever. In the old cleanup a failed exit at any of the first five sections therefore blocked the cleanup's own next section while the swap still held the exclusive library window: every new pooled connection waited in ``shared()`` until the process restarted (5 of 6). A plain, unlocked read of ``_DISK_CHANGED`` in the cleanup did not help (``#1435``'s dropped fix F3): the block only moved from line 24 to 25 of the sweep, to the next section.

**The rules.**
1. **Count the sections a cleanup passes, not the lines.** When a lock's failed exit cannot be prevented (it can only be named), the safest cleanup passes it ONCE, as the last thing that needs it: then a failure there raises the error, the ``finally`` still gives the window back, and the pool keeps serving. The cost moves rather than vanishes: ``_STATE`` stays held, so the NEXT swap blocks at its first section with its own window held.
2. **Merge the sections, keep the meaning.** ``_close_window(*, swapped, earlier=None)`` now reads ``_DISK_CHANGED``, gives the earlier connections' validity back and clears the window's stamp in one section; ``earlier=None`` means none to give back, so a caller that only ends a window (the interrupt tests) is unchanged. ``_revive`` is gone.
3. **Say what is NOT fixed, and pin it.** The three sections that open the window are the same exits, and a failure there still blocks this swap's own close (3 of 4 sections block the same swap, from 5 of 6). Merging them would move the block to the next swap, not remove it, so it is not done; three tests fail an opening exit and assert that the swap blocks with the window held, so a change that fixes it (or makes it worse) fails them and the docstring and this lesson change with it. The only complete fix is no ``_STATE`` at all; whether it guards anything not already serialised by the exclusive window is a separate proof (its own note), not a claim of this change.
4. **Pin the shape by counting, in the source, including helpers.** The pin counts the ``with _STATE:`` sections in the ``finally`` blocks of ``swap_window`` plus one per section of every module function they call, so a section moved into a helper is still counted. It reports 1 on the module and 3 on the module rewritten back to the old cleanup (a test makes the rewrite, requiring each anchor to match once).
5. **The instruction sweep cannot inject at a lock exit, so use a stand-in lock.** A stand-in for ``_STATE`` whose Nth exit raises MemoryError and leaves its real lock held models the failed exit; the swap runs in a thread because a block is an answer, not a hang of the test; the stand-in sets an event when a section waits behind the failed exit, so a passing run never waits for a bound. Red without the merge: the same failed exit blocks the old cleanup (window held), and gives the window back in the new one.
