## 2026-10-28 — an «exclusive» window covers every named writer or says which it does not, and a fix names the consumer it actually changes

**What was found (R360, WAL's read-only enumeration; R362, OSM's correction).** The restore's exclusive window stops the `oo-scheduler` loop and `run_now` (`runner.py:2931`) and nothing else, and the restore never confirms the loop exited. WAL listed 12 unleased committing writers (the housekeeping lane's crawl and backfill, the Wikipedia drain, registered jobs, AI sweeps, boot upkeep and the API write routes, 317 of them in 60 modules among them); two committing jobs, `wikidata-items` and `resolve-places`, were `is_writer=False`. The first reading of the second finding said that flag keeps the restore from running beside them. It does not: the restore never reads the job registry, and the flag's only consumer is the offline maintenance hold-off (`offline_maintenance.yield_reason`, `offline_maintenance.py:124`), which skips the whole maintenance window while a writer job runs. The flip is still a defect (maintenance could run beside a committing job), but for that reason.

**The rules.** (1) A window called exclusive lists the writers it covers and says which it does not; the restore's own text, not only the code, carries the list. (2) A fix names the consumer it actually changes: before a flag is flipped, grep who reads it. The restore's exposure to those jobs is a separate design question (R360 options A, B, C), not something the flag settles. (3) A flag whose True value starves the thing it guards (`ai-coordinator`: sweeps commit, but it loops with a 30 s sleep and stays running while enabled) is left off and recorded by name (`WRITERS_LEFT_UNFLAGGED`), with the reason, not silently.

Sources: `wal-lane/` (the writer list), PR #1605 (OSM, draft at the time of writing).
