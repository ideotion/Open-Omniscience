## 2026-10-15 — A COLUMN TYPE THAT SPEAKS THE STORE'S FORM MEETS EVERY SIDE FILE A TEST BUILDS, A RAW COPY NEVER GOES THROUGH THE TYPE, AND AN EXEMPTION'S REASON GOES STALE THE DAY A NEW HANDLER COPIES THE COLUMN

(1) **The form is a fact about the FILE, and a process-wide type cannot see which file a session is bound to.** `CountryCode` (`src/database/country_form.py`) binds in the form the live store's marker says (`app_state` key `store.country_form`) and reads back lowercase alpha-2. Any test or tool that fills a SIDE file (`create_all`, a merge's working copy, a generator) with the same ORM writes it in the PROCESS's form, while the marker of that file is absent (alpha-2). The file then holds one form and claims the other, which is the mixed state the marker exists to prevent. It showed up only in a full run, never in isolation: an earlier test had booted the app, so the process store was alpha-3 by the time the carry, merge-identity, places and facets tests built their files (all four passed alone, all four failed in a shard). **Rule: a block that fills a file that is not the live store pins the form it writes in (`writing_in(form)`, a ContextVar, per context), and a test that must agree with an app it boots seeds in the form that app will read.** Run the files that build corpora in a shared process before believing a green isolated run.

(2) **A raw INSERT ... SELECT does not pass through the column type, so every such copy has to write the store's form itself.** The derived-row carry (`src/backup/merge.py`, `_plan_derived_carry`) copied a certified article's mentions and places from the staged backup straight into the live tables and wrote `de` where a re-index writes `DEU`. The differential test that compares a carry with a re-index (`tests/test_derived_carry.py`) caught it, and only once it ran under BOTH forms: it is now parametrised over `alpha2` and `alpha3`, which is the check that any new raw writer of a country column needs. The inputs digest of an article is taken from what the ORM hands the engine (lowercase alpha-2), so a raw reader of the stored value converts it back before digesting and forward before writing.

(3) **An exemption's REASON is a claim about the code, and it goes stale when someone adds a handler.** `article_mentioned_places.country` sat in `COUNTRY_COLUMNS_EXEMPT` for "no handler copies it, so it can never reach a value-keyed join". The carry is a handler that copies it. The normaliser's registry test checks that every country column is registered or exempt, and cannot check that the exemption is still true; the failure came from the differential, not from the registry. When a handler starts copying a column, read the exemptions for it.

(4) **One migration engine, one registry, three consumers.** The migration's column list is the typed columns of `Base.metadata` (`migration_columns()`), and a test equates it with the normaliser's registry plus the exemptions, so the scan, the normaliser and the migration cannot disagree about which columns hold a country. An unmapped value (`uk`, `eu`, `int`, junk) stays exactly as stored, is counted and listed by table and column, and balances in the verification (R100); the marker flips in the last transaction, after the per-column balance against the ORIGINAL snapshot passed, so a store never claims a form it does not hold.

(5) **An estimate is scaled by what each part scales with.** The sweep is rows, the safety copy and the proof are bytes. `scripts/country_migration_evidence.py` reports the measured sweep rate and the measured seconds per GB separately and labels the extrapolation to the 2026-07-09 field store an ESTIMATE with its basis; the first draft divided rows by the whole run's seconds and quoted a rate a third of the real one.
(6) **A state with two forms in it must stop everything that reads or writes, not only the next run of its own tool.** The first design said "an interrupted run leaves a store the app can still use", because the marker still read alpha-2. It does not: the windows already committed hold `FRA`, so an equality filter on `fr` misses them, a restore keyed on a law document's value inserts a duplicate, and one app write changes a row count the verification compares, so the run can never finish and the data ends alpha-3 under a marker that says alpha-2. A read of the B1 head reproduced all three. The journal's `running` / `interrupted` state is now read by `init_db()` (every start path passes it) and by `store_form()` (a subclass of the unreadable-form error, so every caller that already fails closed does here too); `writing_in(form)` stays exempt because it fills a side file. **Rule: when a migration's intermediate state is invalid for the app, put the check where every reader already goes, and write the test as a boot of the real entry point, not a call to the helper.**

(7) **JSON text inside a row is a column nobody listed.** A recorded difference keeps a row's values and a law item's identity (`jurisdiction`) as JSON, so the column rewrite never reached the codes inside it. The conversion (`convert_alternate_countries`) is one function used by the migration (in its last transaction, with the marker) and by the restore (on the staged copy, toward the store it merges into), edits through SQLite's `json_set` so the text stays byte-comparable with what `json_object` writes (the restore's de-duplication compares the text), and takes its keys from the two registries that already say them. The swap, which writes a stored value back with raw SQL, and the two law-identity matchers also bind through the store's form: a record the conversion never saw is then found, not reported "gone". The test that matters is the mutant: remove each of those and exactly one test fails.

(8) **A safety copy is written under a name that is not its own, and never over a file that is there.** `--backup-dir` fixed the file name, and the snapshot helper unlinks its destination first, so migrating a second store into the same folder silently deleted the first store's only pre-migration copy. The name now carries the run's time and a digest of the store's full path (two stores never share one), the copy is written as `*.partial`, checked (`quick_check` and the row-count comparison) and published with a hard link, which fails where a rename would replace a file that appeared since the check (a drive with no hard links falls back to the check and a rename), a path that cannot be examined is refused by class (only "no such file" means free), and its path is made absolute before the journal keeps it (a relative path made a resume from another folder claim the copy was gone). The lock screen's passphrase function may not write a caught exception into a text, so its 409 for a store that waits for a migration is a fixed, translated sentence chosen by a flag set in a handler that binds nothing, not the error's words. Known and left: the app's cached form is cleared only by the migration's own process; the exclusive lock is what protects an app that has cached `alpha2`, and no path was found that opens a moment with no connection.

(9) **A column type that is only an adapter is not a schema change, and a lane that never got to the tests tells you nothing about them.** Declaring the nine country columns as `CountryCode` made `alembic check` read `VARCHAR(2)` against `CountryCode(8)` as drift no migration should ALTER; `migrations/env.py` now compares a `CountryCode` column as the string it sits on (`_compare_type`, `None` for everything else). The same push also failed the advisory ruff ratchet (+8) and two bandit B608 sites, and because the first red step ended the CI job, nothing after it (drift, the whole suite) had run on the first three heads. **Rule: before the first push of a PR that adds a column type, a model change or a new module, run the CI job's own step list top to bottom (ruff ratchet at its ceiling, the planned-work gate, the three i18n gates, `alembic upgrade head && alembic check`, mypy, bandit `-ll`), not the subset that touches your tests.** The first full CI suite on the branch then found five repo-wide guards I had not run: a new bundle member needs an area (`diagnostics_plan.MEMBER_AREAS`), a new inline `data-on-click` name needs `OO_ACTIONS`, the record sweep over `src/backup` and `src/database` refuses any caught exception read as text (so "no such table" is asked of `sqlite_master` and a lock is classified by `is_locked_error`, never read off `str(exc)`), and every test file's text I/O names its encoding. **Run the guards whose scope is the whole tree (`test_sink_sweep_records`, `test_inline_handler_ratchet`, `test_utf8_file_io`, `test_diagnostic_slots`) with every PR that adds a module or a bundle member.**
