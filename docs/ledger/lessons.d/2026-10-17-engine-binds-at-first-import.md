## 2026-10-17 — Two things name one store and are read at different times: the engine at first import, the settings store at every call

**What was found.** `src.database.session` computes `DATA_DIR` / `DATABASE_URL` from `OO_DATA_DIR` once, at its first import (`tests/conftest.py` says so); `src/config/kv_store.py::_db_path()` reads `OO_DATA_DIR` on every call. A test that moves the variable to its `tmp_path` and only then imports `src.api.main`, in a run where nothing imported the session earlier, binds the engine to its own tmp_path for the rest of the process. `tests/test_init_steps.py::test_a_marker_in_a_raising_steps_message...` (the `dd` fixture) did exactly that. A later test (`tests/test_country_migration.py::test_the_diagnostics_card_reads_the_form_and_the_estimate_and_starts_nothing`) then booted the app on the dead store (stamped alpha-3 there) while `store_form()` read the suite directory's file, found no marker, and answered alpha-2 (no marker is alpha-2 by design). Shown, not inferred: a probe plugin printing the session URL and the settings path after each test showed the same directory when the test ran alone and two directories after the first; bisect over 41 files found only `test_init_steps.py`. Write-up: `/mnt/project-files/plan-row-j/country-migration-order-2026-10-17.md`.

**Why it hid.** A full run collects every test module before any body runs, and module-level imports reach the session under the suite's directory first; only a selection with no such module leaves the first import to a test body. 220 test files mention `OO_DATA_DIR`; run alone with the net in, 42 of them bound the engine to their own tmp_path (list in the write-up).

**The rules.**
1. **Make a selection behave like the full run, structurally.** `tests/conftest.py` now imports `src.database.session` itself, right after its env defaults, so the engine binds to the suite's directory before any test body can move the variable. The scan found 42 test files that bind it themselves when run alone (list in the write-up); fixing them one by one would leave the next one exposed. Cost, measured alone: +0.21 s per pytest process (1.06 s against 0.85 s, median of 10, a one-test file); nothing extra in a full run, which imports the session at collection anyway.
2. **Import the thing that binds BEFORE you move the variable it binds to** where a test file does move it (`dd` in `tests/test_init_steps.py` now does).
3. **Keep a net under the structural line, and run its failure.** `_engine_binds_to_the_suite_directory` (autouse) looks only at the FIRST binding, at the binder's own teardown, and names it. `tests/test_suite_dir_guard.py` runs a child pytest on the bad order: with the real conftest it passes, with a copy of the conftest that lost the import it fails by name, and the good order passes under both.
