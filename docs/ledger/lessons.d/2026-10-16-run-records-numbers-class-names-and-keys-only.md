## 2026-10-16 — a durable run record is written OPEN at the start, closed at every branch, and takes only numbers, class names and keys of fixed tables; a refusal is a run that never existed (PR #1421)

**What was found.** The Diagnostics zip kept the runs that opened a run journal (`run-journal.json`, the last twenty, `runlog.begin` first) and nothing for the three things that happen BEFORE or WITHOUT one: a start that is refused (`start_backup` raises on a missing passphrase, a destination that cannot be made, a path that is not a folder; every start raises on a job already running), a worker killed in the middle of a backup (the run journal's lines are flushed on a schedule, and a kill leaves whatever was flushed), and a backup that ended "ok" with its summary file not written (`write_summary_for_export_job` logs and returns None). The free bytes of the volume the run was writing to were nowhere, and a restore queue that fails eight times pushed everything older out of a single ring.

**The rules.**
1. **Write the record OPEN at the start and close it at each branch, with a `finally` net.** `storage_events.run_started` records the run with a key, `run_ended` closes it; a process killed in the middle leaves "started, never ended" (the next read marks it "the process ended while this was open"), and the `finally` calls `run_ended(note, "ended-without-a-recorded-outcome")`, a no-op once an outcome was written, so a `BaseException` that no `except Exception` takes still closes it (tested with one).
2. **A refusal before any run exists is recorded at the raise, closed in one write (`run_refused`, `ran: false`).** The start methods raise before `runlog.begin`; a record made only in the worker would never see them. Every `raise` in a `start_*` has a `run_refused` statement EARLIER IN THE SAME BLOCK (an AST pin checks the position, which a count of `run_refused` calls does not: a record made after the raise is never reached), and the one rejection every start shares takes the kind as an argument so the record names the kind that asked.
3. **The sink takes numbers, flags, class names and keys of tables, and drops everything else; the hooks are pinned to hand nothing else.** `_run_fields` keeps a fact only if its NAME is in the table for its kind (number, flag, class, one of five read-back states); `_class_name` keeps a value only if it is shaped like a class name (else the fixed marker); a refusal is a KEY and the journal writes the sentence. An AST test then reads every hook call in `volume_job.py` and `export_summary.py` and fails on `failure=` that is not `type(<name>).__name__`, on a `**` mapping, on an outcome that is not a constant of the table and on a fact name the sink does not know. A one-word message passes the SHAPE check, so the pin on the call sites is the real guard.
4. **Caps per kind of run, not between them, and a run in flight is the last to go.** Three journal kinds (`run_export`, `run_import`, `run_verify`, ten each): a restore queue of eight items that all fail must not push last week's failed backup out; `total` still counts every run (a test sends thirteen restores and one backup). Inside one kind the trimming skips an event that is still OPEN, so a burst of refused starts during a long backup cannot push the backup's own record out and lose its end (the first version dropped the oldest event, which is the run in flight when it is the oldest). The other kinds keep the plain rule.
5. **An unreadable figure is absent, never zero, and it is the figure of the path asked about and no other.** `free_bytes_of` stats the path as given and answers `None` for one that does not exist or cannot be read: it does not walk up to the nearest parent that does (that is a DIFFERENT volume's free space reported as the destination's, the worse lie), a `0` would read as a full drive, and an unreadable volume is neither counted as a journal fault nor logged (a failure that is not an `OSError` is, by class). The field is not written. It is read AFTER the run is written open, so a stat that hangs on a dead mount leaves the run open, which is the fact; a test pins the order at the call site by filtering the `disk_usage` calls to the destination, because `runlog.begin` also stats the data folder. The restore reads the data folder's free bytes (where it stages) only after the "already merged" skip, so a restore that writes nothing does not stat a drive.
6. **The budget is the widest event times the cap, with EVERY field present at once.** The fixture fills each run with every fact at a large value, the longest class name and sentence and a day-long `seconds` (734 bytes; a real run is 146 to 299); the member went from 86,658 to 109,766 bytes at full retention (65,056 with ordinary names) and the row from 90,000 to 115,000. THE FIXTURE ASSERTS ITS OWN KEYS: it first passed `error=` where the sink reads `failure=`, the sink dropped the field without a sound, and the committed test measured less than the documents quoted; after each kind it now checks that the last event carries every key the sink can write. The "hard ceiling" pin (250,000) was the then-current ceiling of six kinds, not the protection: it became 300,000 for nine, and the line beside it (a tenth of the zip) is the pin that does not move.
7. **The sink sweep reads a PARAMETER named `error`, `exc` or `exception` as a caught exception.** The class-name parameter is `failure` (the stored field is still `error`), and the six `_internal_failure(..., exc)` handlers that every journal function has are allowance lines keyed by function and exact text, like the rest of the file.
8. **A fact reaches a run only through its own note.** `run_started` returns a note, `run_facts(note, ...)` and `run_ended(note, ...)` write to the run it names and to no other, and the summary writer is handed the note (`run_note`). The first version had `run_part(kind, ...)` add to the newest open run of a kind, and the folder backup's summary failure (the same writer, no volume run) landed on an unrelated volume backup that happened to be open. A failure with no note lands on no run.
9. **The ok end of the real restore is tested through the real merge path.** The restore's ok record sits on a branch the unit fixtures bypassed; without a test that drives `run_restore` (with the heavy steps stubbed, not the worker), every successful restore could have read `ended-without-a-recorded-outcome` from the net with the whole suite green.
10. **A hook that takes a `**` mapping defeats the AST pin.** The verify hook first passed `**({"set_ok": ok} if ... else {})`; it now passes `set_ok=<value or None>` and the sink drops a non-bool.

**Stated limits.** A flood of refused starts (more than ten of one kind) pushes older CLOSED runs of that kind out of the ten kept; `total` still counts them, and only a run still open is protected. A newsletter-filter-refused backup is `error` in the run journal and `refused` here (nothing ran). Three paths open a run journal line and write no storage event: the legacy single-file restore (`restore_legacy_path`, `runlog.run`), the folder backup, restore and verify (`folder_backup.py`, `runlog.run`) and the newsletter import (`import_job.py`, `runlog.begin`); the shape check accepts a one-word message; an older build reading a file with these kinds drops them on its next write.
