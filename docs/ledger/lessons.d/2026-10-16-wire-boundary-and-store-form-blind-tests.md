## 2026-10-16 — A WIRE FORM IS CHOSEN AT THE BOUNDARY, A REWRITE MAY ONLY TAKE CODES (NEVER NAMES), AND A PARAMETER TEST THAT RUNS IN ONE STORE FORM PROVES NOTHING ABOUT THE OTHER

(1) **When a representation changes between "inside" and "outside", change it where the data crosses, not at the hundred places that produce it.** Row B2 had to make `country` alpha-3 in every payload. A scan found about a hundred dict literals carrying a country (analytics rollups, map features, briefing recipes, law, timemap ...), most of them reading a value Python already holds as lowercase alpha-2, and every one of them is also read back by Python (dict keys, joins, comparisons, caches). Editing each would have changed the shape of values the program itself consumes, and each new endpoint would have needed someone to remember. The boundary (`src/api/country_wire.py`, the app's default response class) is the same move B1 made for the file (`CountryCode`): Python keeps speaking alpha-2, the thing it talks TO speaks alpha-3, and the choice is made once. A new endpoint is covered by construction. **Rule: pick the boundary the data crosses, name the registered fields once, and enforce "nothing builds a response around it" with a source guard that is mutation-checked.**

(2) **A rewrite of a field may only take what is a CODE.** `normalize_country` resolves names, slugs and shorthand as well as codes, so running a payload's `country` through it would turn `Niger` into `NER` and `France` into `FRA` in a field that held a name. The rewrite accepts only two or three ASCII letters that `country_payload_iso3` recognises; everything else, an unrecognised code included, travels exactly as it was (a blank would say "no country", a different claim). It also never touches a field that names its own form (`iso2`, `cc`, `alpha3`), returns the very same object when nothing changed (so identity says "unchanged"), never mutates a cached payload (the analytics read-models hand every request the same dict), is idempotent, and walks a non-string value under a registered key (the map's `country` geometry object holds rings, and a code can sit inside).

(3) **A test of "every parameter accepts both forms" that runs in ONE store form proves nothing about the other.** The first version of the parameter fixture passed on a fresh alpha-3 store even with the normalising line removed from five of the seven Insights handlers, because the column's own bind step converts `fra` to `FRA` there; an unmigrated store binds the value as given and would have found nothing. The proof that survives is the argument the handler passes DOWN, asserted spelling by spelling with the analytics function replaced by a spy (seven of seven red without the guard). **Rule: assert what a handler hands its callee, not only what the whole stack returns in the form the test happens to run in.**

(4) **A shared engine outlives the test, so a fixture that inserts must find what it already inserted.** The module's corpus fixture collided on `sources.domain` the second time it ran (the app's engine is one per process); it now looks first. The cost of finding it out was one failed run of fourteen tests, which is also the cheapest it ever is.

(5) **Changing what a key means touches its consumers' indexes.** The map's polygons and its `names`/`values` tables key on alpha-2; a payload whose `country` became alpha-3 would have drawn nothing and said nothing. Five surfaces index by it, so the conversion sits behind one helper (`ooCountryKey`, over the existing `ooCountryAlpha2`) rather than in each. Where the change reaches a screen, a payload test cannot show a blank map: a rendering check has to.
