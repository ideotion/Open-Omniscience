## 2026-10-29 — pytest's `-r` REPLACES its default `fE`, so `-rs` alone hides a red run's FAILED and ERROR lines; and a failing command inside an `&&` chain does not stop a `bash -e` step (PR #1663, found by its Opus read)

**What was found.** The awk-step PR added `-rs` to the CI `test` job's pytest line so each skip's file, line and reason would be in the log. The read caught that `-r` is `action="store"` with `default="fE"`, so `-rs` replaces the default instead of adding to it. Measured on a scratch file with one pass, one fail, one skip and one error, pytest 9.1.1: `-q` prints `FAILED ...` and `ERROR ...`; `-q -rs` prints only `SKIPPED [1] ...`; `-q -rfEs` prints all three. The result line and the exit status do not change, which is why nothing red would have shown it: only the tail of a red run's log, which is all a reader that returns the last lines of a job ever sees (the reason the installed-versions record, R364, sits straight after the suite), would have lost the names of the failing tests. **The rule: any `-r<chars>` flag names the whole set, so write `fE` into it** (`-rfEs`, or `-ra`). A comment that says a flag "adds" a block is a claim to measure, not to assume.

**The shell twin.** The same step had `sudo apt-get update -qq && sudo apt-get install ...` on one line. GitHub's default shell is `bash -e {0}` with no pipefail, and `-e` ignores a failing command that is not the last member of an `&&` list. A failed `apt-get update` therefore skipped the install, let the next line run, and exited 0: the step was green with nothing installed and both awk tests skipping again without a sound. Simulated with stubbed `sudo`, `apt-get` and `update-alternatives`: update failing exited 100 after the split, binaries missing exited 1, the happy path 0. **The rule: in a CI step, one command per line, and a `command -v <tool>` (alone on its line) after an install that a later test depends on.** `command -v a b` is not a substitute: it returned 0 here although the first name was missing. A `&&` chain is safe only as the LAST line of the script, which is why the tesseract step beside it is fine.

**Where it applies.** Every `pytest` line in `.github/workflows/*.yml` that grows a `-r` flag, and every `run:` block that chains an install with `&&` before a step whose tests depend on it. `tests/test_skipped_tests_have_a_ci_job_that_runs_them.py` accepts `-rfEs` (its `_SELECTING` matches `-k`, `-m`, `--deselect`, `--ignore`, `--lf`, `--ff` and `--co`, none of which is an `-r` flag).
