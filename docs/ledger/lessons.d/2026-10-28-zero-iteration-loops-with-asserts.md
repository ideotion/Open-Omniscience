## 2026-10-28 — Twelve asserting `for` loops never iterate in the suite; seven were vacuous, each proven by a source mutant that stayed green (parent sweep R385, candidate 2: the dynamic twin of the callback-list guard)

**What the static guard cannot see.** `tests/test_loops_over_callback_lists_assert_non_empty.py` reads loops over a LIST OF CALLBACKS, whose emptiness is visible in the source. A loop over a RESULT (`for it in res["items"]: assert ...`) is empty or not depending on the fixture, and no reader of the file can tell.

**Method (no repo edit).** A pytest plugin outside the repo (`/mnt/project-files/fix-source-qualification/zero-iteration-audit-2026-10-28/loopcount.py`) rewrites every `for` whose body holds an `assert` (or an `assert*`/`check_*` call, `raises`, `fail`) in `tests/*.py` to iterate through a counting generator, and records per loop how many times it ran and how many of those runs yielded nothing. Class-private name mangling bit once: an injected `__name` inside a test class became `_Class__name`, 11 tests failed with `NameError`, and the name lost its leading underscores. The whole suite ran in three shards in a separate worktree (about 32 minutes each, 4 CPUs): 2,937 asserting loops reached, 12 that never iterate in any test, 38 that iterate in some runs and not others (nested inner loops and parametrized cases; read, nothing in them).

**The twelve, by hand.**
- Empty by design (4): `test_country_filename_rule.py:234`, `test_event_loop_rows_pinned.py:67`, `test_migration_self_heal_drift.py:229` and `test_inline_handler_ratchet.py:118` loop over tables that are EMPTY because the debt they list is paid (an owed-conversion table, an exemption list, a pin table); each says so, and an empty table must pass.
- A sound guard (1): `test_recursive_logs.py:223` (`flags_only_bare_scans`) iterates over the scans the probe FLAGGED, which is none on a healthy store; the mutant "flag index scans as well" turns it red.
- Vacuous (7), each with its mutant: 
  1. `test_emergence.py`: `test_no_score_and_caveat_present` used 3 sources and the producer needs 4 recent articles, so `items` was empty; mutant "add a `score` key to the item" stayed green. Fixed with the firing fixture (5 sources) plus an assertion that it fires.
  2. `test_headline_body.py`: the German article was chosen so that it does NOT fire, then `for it in res["items"]` asserted the gap is None for a non-English item; mutant "compute the sentiment gap for every language" stayed green. Fixed with a headline that shares one word with the body (d_lex 0.8, below the method-failure ceiling of 1.0), asserting the item exists.
  3. `test_producers_card_shapes.py`: the fixture's articles are shorter than `story_prominence`'s `min_chars` (200), so `lonely_signal` never fired and its "if it fires" loop never ran; mutant "`article_ids=[]`" stayed green. Fixed with one long single-source article and an assertion that a card exists.
  4. `test_query_expansion.py`: `test_a_multi_word_ring_member_is_emitted_as_a_phrase` searched the member's FIRST word, which is not a ring member, so nothing expanded; mutant "emit multi-word siblings unquoted" stayed green. Fixed by searching the quoted phrase and asserting a multi-word sibling exists.
  5. `test_recency_windowed_verdict.py`: the route test checks the historical rows carry no windowed field, on the route's own EMPTY store; mutant "write `window` into every row" stayed green. A second test seeds ten sources and calls the route function with a session.
  6. `test_i18n_scanner_coverage.py`: `test_aux_inline_js_excludes_the_external_i18n_script_tag` looped over `_aux_inline_js()`, which is `{}` now that the pages have no inline script, so it could not fail; worse, the regression it names (an empty body captured for a `src` tag) produces `""`, which does not contain `i18n.js` either. Rewritten on a temp page with one src'd and one inline script, asserting exactly the inline body; the mutant "drop the lookahead" turns it red (and so does its neighbour that asserts `{}`).
  7. `test_osm_reference_run.py`: the "no secret in the child's logs" loop globbed `kept/logs`, which a kept store never has (the runner removes the raw logs, driven by `test_the_childs_raw_logs_do_not_stay_on_disk_in_a_kept_store`). A hardening, not a defect: the loop now asserts the folder is gone; the mutant "leave the logs in a kept store" is red under the new line and was green under the old loop (the secret was not in them).

**Rule.** (1) A loop that asserts on every element of a result needs an assertion that the result is not empty, in the same test, unless emptiness IS the claim (then assert the emptiness and say so). (2) A fixture that is chosen so that something does NOT fire cannot test what the thing does when it fires. (3) Of twelve zero-iteration loops, seven were vacuous and four were healthy: the zero is a prompt to run the mutant, not a verdict.

**Not covered.** Comprehensions and generator expressions with an `assert` helper inside; `while` loops; `for` loops whose body asserts only through a helper whose name is not in the plugin's list; assertions inside `with pytest.raises` blocks within the body are counted, a bare `try/except` is not.
