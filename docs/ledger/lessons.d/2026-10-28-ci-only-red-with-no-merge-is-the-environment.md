## 2026-10-28 — a CI-only red that appears with no merge gets an installed-versions diff before a commit bisect: an unpinned test dependency is a moving part of the environment, and a process-wide patch of a function the test runner itself calls is a time bomb on runner upgrade

**What was found (R344 to R351; six sightings in two hours).** `tests/test_page_reading.py::test_a_failing_stat_after_the_open` went red on keyword's PR, on Q's PR, on OSM's, on Export's and on `main` itself (`023d59443` after #1593, Core-only), while it passed locally 47 of 47. Three explanations were tried and were wrong: a leftover thread (R343), the head that happened to be under test (R345), and a merge since the last green (Export's first reading). The tell that settled it (R349): Q's #1588 was green on `30cc7a545` (20:38) and red on `41fb0f4ac` (about 22:50) with only a test file and the ledger changed and no merge of main. Same code, green then red, then red everywhere: an environment change, not a commit.

**Cause (R350, Export's diff of a green job against a red job; three comparable job pairs of 86 to 104 packages each).** The only package that differed was pytest 9.1.1 to 9.2.0 (PyPI, 21:30 UTC on 27 Oct). `pyproject.toml:368` installs `pytest>=8.2`, unpinned. Runner 2.338.0, Python 3.13.16 and SQLAlchemy 2.1.6 were the same in both. 9.2.0 added `os.fstat(self.tmpfile.fileno()).st_size == 0` to both capture `snap()` methods, run at the end of every setup, call and teardown phase, and the test's `monkeypatch.setattr(page_reading.os, "fstat", boom)` patched the process-global `os.fstat` and was still live at the post-call snap. Reproduced on one checkout: passes under 9.1.1, fails under 9.2.0 with the test's own marker `OSError`. Q reproduced it independently (the old form fails under 9.2.0 and passes under 9.1.1; the scoped form passes 47 of 47 under 9.2.0).

**Rules.** (1) A CI-only red that appears with no merge in between gets an installed-versions diff (packages, runner image, Python patch) between a green job and a red job before any commit bisect (R349). (2) An unpinned test dependency is a moving part of the environment; the fix here was the test (the patch is scoped to the name `page_reading` sees), NOT a pytest pin, because a pin would hide the class defect and touch `pyproject.toml` and the lock for no shipped benefit (R350). (3) A process-wide patch of a function the test runner itself calls is a time bomb on runner upgrade (R351). The other process-wide `os.*` patches under `tests/` (`replace`, `fsync`, `kill`, `stat`, `getpid`, `access`, `open`, `scandir`, `link`) are none of them called by pytest 9.2.0's capture code; they are the same class and become one 0.5.1 test-only sweep for Q (OPEN_QUEUE).

Fix: Q's R344 scoped patch (namespace copy of `os` with `fstat=boom`, plus a guard that the real `os.fstat(0)` works inside the window), merged in #1588 (`10ec983de`). Report and the 9.1.1 to 9.2.0 source diff: `export-lane/r349-ci-env-diff-2026-10-27/`.
