## 2026-10-27 — an entity-load sweep is ranked by table size, most hits are not defects, and a peak-RSS delta read 0 until the seeding moved to another process

**Found by the entity-load sweep of `src/api` that followed A-025 (`GET /api/sources`, #1522).** 32 `.query(Model)...all()` chains and every other `.query(Model)` form were read. One was an unbounded whole-entity load of a large table: `GET /api/catalog/export.csv` built a mapped `Source` (24 columns) for each of 86,000 sources to write twelve of them. Reading the column list the CSV carries and asking the database for exactly those twelve took the GET from 2.7 to 3.6 s to 1.7 to 2.0 s with a byte-identical body (10,084,877 B, one sha256).

**Rules.**
1. Rank the hits by the table's size and by whether the route is bounded, before measuring anything. Of 32 chain sites, the Article loads are all id-list or page bounded and need `content` by design (the reader, evidence export, synthesis), the Source page lists are bounded by `limit <= 1000`, and the Law/Wiki tables hold tens to low thousands of rows: reporting them as defects would have been thirty false findings. A "loads full rows" grep is a list of places to read, not a list of defects.
2. A write that goes through the ORM (`source_management.py` disabling unmanaged languages, `src.enabled = False` per row) is not the same finding as a read. Replacing it by a column read plus a bulk UPDATE bypasses the ORM events, and a speed-up that does that must keep every side effect; it stays a proposal until someone audits them.
3. A column projection is pinned three ways, because each catches an edit the others cannot: a recording stand-in handed to the row builder proves the column tuple is exactly what the builder reads (a thirteenth value added to the builder alone writes an empty cell); the route's body equals the entity path's body on a catalogue with every shape the builder meets (no country, an aggregate country, quotes and commas in tags, a disabled source, non-ASCII); and a SQLAlchemy `load` listener on `Source` proves no instance is built, so an edit back to `.query(Source)` fails here instead of at the next field catalogue. Mutants: back to entities, a thirteenth attribute, a dropped column: all red.
4. **Measure memory in a process that did not seed.** The first bench seeded 86,000 rows and then read `ru_maxrss` before and after the GET: it read 0 KiB of growth on both sides, because the seeding had set the high-water mark above anything the GET reached. A seeding process and a measuring process (the store on disk between them) plus `tracemalloc` over the one GET gave 216 MiB before and 124 MiB after, repeatable to the MiB. Peak RSS only grows past a mark the process already set, so a delta taken inside a process that did the heavy work first is a measurement of the order of events, not of the route.
5. State the limit with the figure: the bench store is synthetic (86,000 rows of eight repeated shapes, not the field catalogue), and the time is a range of two benches of three runs each.
