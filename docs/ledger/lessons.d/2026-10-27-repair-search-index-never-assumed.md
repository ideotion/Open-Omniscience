## 2026-10-27 — when the only thing keeping a half-built file from being swapped in is the ORDER of two steps, the file's own check cannot see it: pin the order with a real kill, and assert every figure that rides a sidecar against what the finished file holds

**What was found.** The repair rebuilds the article search index inside its scratch copy as the last step of the copy, then checks the copy, writes the sidecar, renames the copy and swaps it in. Killing the process inside the rebuild (a real SIGKILL at a named batch) leaves a scratch copy with every article, a `PRAGMA quick_check` of ok, a `salvage.check_copy` of `(True, [])` and an index holding 0 documents. Nothing in the check would object, and the boot would heal only this exact case, a fully empty index (`ensure_fts`, an O(1) probe of `docsize == 0`); it does not look for a PARTIAL one by design (a count of articles is a corpus scan), so a copy swapped in with part of its index stays that way. The protection that exists is the order (rebuild, check, sidecar, final name) and the name (a `.partial` with no sidecar is scratch). A rebuild that stops early and honestly counts what it indexed (a mutant) passes everything except a comparison of the finished file's index rows with its articles.

**The rules.**

1. **A guard that is only an ordering is tested by an interruption between the two steps, not by reading the code.** Kill a real child process with `os.kill(os.getpid(), SIGKILL)` at a named point (not on a timer): no `finally`, no atexit, no handler runs, which is what a power cut does, and the parent examines the folder and then runs the next start.
2. **A figure that rides a sidecar or a record is asserted EQUAL to what the finished file holds, in the file, by a second route** (the shadow table's own row count, not the figure that was written, and not a probe that reads the content table), not merely present: "present" passes a figure that is honestly wrong.
3. **An absence is a claim too.** A stopped repair's record carries no `search_index`, no `kept_rows`, no `kept_file`: assert the keys are absent, so a later change that adds a figure for a file that was thrown away is red.
4. **A stop poll that counts SQLite virtual-machine steps fires by volume, not by time.** The step count of a prepared statement accumulates across its runs; with the poll at 100,000 steps a 4,000-document rebuild never noticed a stop (honoured afterwards at the copy's check) and an 8,000-document one did, after 7,500. To test a stop INSIDE a rebuild without a store that size, set a finer handler of the same shape on the same connection (reading the stop the code under test was handed, and asserting that it is the stop the caller meant) and say so in the test; pin separately that the production connection polls its stop; state the production figure as a measurement, never as a constant.
5. **The app's own probe of an external-content FTS5 index reads the CONTENT table, so it cannot see the index.** `fts.fts_status` (probe and count) said "healthy, 300 rows" over an index emptied with `delete-all` (`article_fts_docsize` 0). In a test, read the index's own shadow table (`article_fts_docsize`) for its size; a test that ends on `fts_status` rows equal to the articles is a tautology, which an independent read of the new tests found before it shipped.
6. **A mutant that stays green is a finding, not a failure to hide.** The "interrupted" → stopped mapping in `_raise_for_target` is shadowed by the `_check_stop()` before it and has no source today; the shipped log says so.
