## 2026-10-16 — a run-record hook reads its keys from a report it does not own: test it against the producer's real output, because a wrong key records None without a sound; and a path the system cannot examine is a refusal that is recorded, not a crash that is not (PR #1421)

**What was found.** The folder verify's closing line in the run journal (`runlog.end("ok", checked=res.get("checked"), mismatches=res.get("mismatches"))`) had always recorded `None` for both: `verify_folder_backup` returns `files_checked`, `files_total` and a `summary` dict (`missing`, `size_mismatch`, `checksum_mismatch`, `traversal_refused`, `malformed_entries`) and has never had a `checked` or a `mismatches` key. Nothing failed, because `dict.get` answers `None` and the journal drops a field that is not a number. It surfaced only when a test of the new storage-events record ran the REAL engine (`write_folder_backup` then `FolderBackupManager.start(mode="verify")`) and found the field absent; a test with a stubbed `verify_folder_backup` returning `{"checked": 2}` passes against the wrong key. A read of the first version then found the same family at the other end: a path the system cannot even look at (a name too long, a denied parent) raised from inside the start, before any record, so the run the record exists for left nothing.

**The rules.**
1. **A hook that reads a producer's report is tested against the producer's real output at least once**, not only against a stub whose keys the test author chose. Both journals now take their figures from one `_verify_counts(res)`, which returns `(None, None)` for a report with no counts (no manifest, a damaged one): absent, never `0` and never a made-up count. A mismatch is what the verdict counts as a failure (missing, size, checksum, traversal, malformed entries and a bad signature); `size_only` is not one.
2. **One kind, several ways in, told apart by a fixed-table fact.** `run_import` is the run journal's name for the volume restore, the legacy single-file restore, the newsletter folder import and the folder restore; every run carries `via` (`volume-set`, `single-file`, `newsletter-eml`, `folder`), a key of `RUN_VIA`. A value outside the table is not recorded, so a path or a folder name cannot become it; the AST scan accepts `via=` only as a constant of the table (or the one local that holds such a constant), and it counts hooks PER FILE with a floor each, so a file whose hooks were deleted cannot hide behind the others' count.
3. **The free bytes of a destination that does not exist yet are those of its nearest existing parent**, chosen by the CALLER (`validate_dest` has already refused a destination with no writable parent), because `free_bytes_of` stats the path as given and answers `None` for one that is not there. The first version passed the destination itself and the field was absent in exactly the case of a fresh backup folder. The walk to the parent is itself a read of the filesystem: `_volume_probe` returns `None` when it cannot finish (a parent that cannot be examined after the start), and the field is then absent, never the data folder's figure. A folder RESTORE reads none: it writes to the live folder of each category, which can be on several volumes, and one number for the data folder would read as the volume it writes to.
4. **A path the system cannot examine is a refusal, recorded and re-raised unchanged.** `storage_events.run_refusals_net(kind, via=, refused_as=)` stands round a start (on its `with self._lock,` header, or as a decorator) and never round or inside the statement that looks at the path (see the CodeQL lesson of the same date): an `OSError` out of that statement (`ENAMETOOLONG`, `EACCES`, `ELOOP`) records `refused` with the key `path-unreadable` and the class name, and the caller sees the same error it saw before the record existed. Only an `OSError` is a refusal by itself; an error of a class handed over in `refused_as` is the refusal of its pair, and a kind the journal does not have records nothing. An unread free-space figure is the other half: `free-space-unreadable` ("could not be read") is not `no-space`, because a shortage claimed from a figure that was never read is a false statement about someone's drive.
5. **A refusal sentence says what it can be true of.** `destination-unusable` read "could not be created", which is false for a destination that exists and is a file or is not writable; it now says "could not be used (empty, not a folder, not writable or not creatable)".
6. **An outcome that is a local variable defeats the AST scan.** The verify worker first computed `outcome = ... if ... else "ok"` once and passed the name twice; the scan reads constants and conditionals of constants only, so the conditional stays inline in the call (written twice, as the other workers do).
7. **A flag two records report is read once.** `cancelled = self._cancelled` is taken once per worker, so the run record, the run journal and the job state say the same thing when a stop arrives between the writes (three reads could say "paused", "ok" and "cancelled" for one run).
8. **`isinstance(exc, X)` on a caught exception inside a function that holds the passphrase fails the P0 AST guard** (`tests/test_p0_validation.py`: a caught exception there may reach only a scrub or `type(exc)`). The legacy restore's stop was asked with `isinstance`; it is `issubclass(type(exc), RestoreStopped)` now. Run `test_p0_validation.py` and `test_derived_read_seam.py` after touching a hot file: both caught the first version and neither is in the run-record suites.
9. **A mutant whose anchor moved is "BAD ANCHOR", not a survivor, and a run that prints `survivors: []` can still have tested less than it says.** After a lint fix reordered one expression and a rewrap changed one string, three of thirty mutants did not apply; the summary line was empty. Read the log for `BAD ANCHOR` as well as `SURVIVED`.
10. **The slot bounds every field present on every run at once** (`_fill_runs` fills all thirty runs with all the numbers): 116,930 bytes widest, ordinary names 72,220; the slot is 125,000, the free room 1,613,784 (pin 1,500,000).
