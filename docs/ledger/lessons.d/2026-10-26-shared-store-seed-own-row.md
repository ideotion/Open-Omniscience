## 2026-10-26 — A test that reads a row of the shared store seeds that row itself: "the table is not empty" is not "my row is there" (0.5.1 item 43)

**What was found.** Shard 1 of WAL's run failed both slow-count tests of `tests/test_figures_cold_start.py` (`avg_word_count` None at line 139, then the `failed` state never reached at line 164), and passed when the file ran alone. The README said which earlier file left the state was unknown. Measured: the same 59 files in that order, with a census of the test store (`count(*)`, `count(word_count)` of `articles`) after every test, show 32 articles and no word count among them when the file's first test starts; the only files after whose tests the article count changed are `test_ai_custom_prompts`, `test_ai_keyword_evidence`, `test_country_wire`, `test_dateextract` and `test_evidence_review` (the census logs the NET change after each test, so a test that adds and removes rows inside itself is invisible to it). The file's `_seed_article` returned early on `if s.query(Article).count()`, so it seeded nothing, `avg_word_count` (an average over the non-NULL counts) was None, and the failed assertion came before `release.set()`: the background count stayed parked in the test's `slow_count` for five seconds, holding the figures' single flight, and the next test waited ten seconds behind it for a state that could not arrive. One polluter test (`test_run_custom_prompt_writes_typed_ai_metadata_only`) followed by the old file reproduces both failures; the fixed file passes the same 59-file order (879 passed). The twin on main failed the other way round: `test_served_counts_cache.py::test_figures_are_served_stale_rather_than_recomputed_inline` waited ten seconds for `keyword_mentions_state` on an EMPTY store (run alone, or first), because `_compute_figures_counted` answers an empty corpus with the cheap figures only. The production behaviour is right; the test assumed a populated corpus it never made.

**Rules.**
1. **A test seeds the row it reads, keyed by a value of its own (a URL), and never returns early on the table being non-empty.** The store is one per process; every other file's rows are in it, and none of them was written for this assertion. The old guard was the wrong-way round of the emptiness the twin test hit: both took the state of the store from the files that ran before them.
2. **Release what a test parks in a `finally`.** An `Event` a worker waits on is set before the assertions that can fail, not after them; a failed assertion otherwise hands the next test a held single flight and a second, unrelated failure that looks like a second cause.
3. **Find the polluter by census, not by guessing predecessors.** Pair-runs of the file with predecessors chosen by guess did not reproduce it; a pytest plugin that logs the table's `count(*)` and `count(col)` after every test, run over the 59 files of the failing shard, named the five files that add rows and showed the state at the file's start. Keep the plugin out of the repo: it is a probe, and the fix does not depend on which file leaves the rows.
4. **Not claimed:** that no other file depends on the shared store's content. This fixes the two files the evidence names; a sweep of the suite for the same early-return shape is a separate, larger audit.
