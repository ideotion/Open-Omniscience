## 2026-10-26 — The sentence that defines a log field is the most expensive thing in a diagnostics copy: price where it rides on the real copy before carrying it

**What was found (PR #1481).** The extraction lock's per-tick block (`extraction_lock`: `held_frac`, `wait_rate`, `holder_age_s`) was planned with its defining sentence (`lock_stats.LIVE_METHOD`, 517 characters) riding once on the pass summary line, "once per pass, not in every tick". Priced on the real copies (the slim `debug-bundle.json` keeps the newest 17 log rows, the whole one 191), with a real gauge fed by the real marks over five simulated passes, the block and the four trims that pay for it came to -61 to -1 B deflated per slim copy WITHOUT the sentence and +210 to +264 B WITH it. A copy taken after a pass ends is the common copy, and its newest row is that pass's summary, so "once per pass" is "once per slim copy". The numbers repeat and DEFLATE prices them at 8 to 14 B a tick; prose is unique and it prices it at about 0.45 B a character. Even without the sentence the claim "net zero" did not hold everywhere: on the lock-saturated pass the block is the highest-entropy thing in the row (a standing queue moves `wait_rate` and `holder_age_s` on almost every tick) and the copy came out +34 B (slim) and +223 B (whole) deflated, about 0.9 % of the copy, while the same pass was 1,088 and 13,311 B smaller raw. The shipped row says so in those words.

**The rules.**
1. **Price a new log field on the copy the user ships, with its sentence in it, and state the cell where it loses.** Raw bytes pinned in a test are the budget; DEFLATE is recorded beside them in the shipped row, and the two can disagree in sign (here raw -1,088 to -15,185 B, deflated -107 to +223 B). A claim of "net zero" is per cell, and the cell that breaks it is named, not averaged away.
2. **Words that only a reader of the code needs live in the code.** `LIVE_METHOD` stays a module constant that a test pins to name every field, and the shipped row repeats it; the tick's field names say what they hold. The repo's "a signal carries its method" rule is for what a user reads; the diagnostics log is read by us, with the manual beside it.
3. **A key removed because another key in the same row equals it is free only while the equality holds on the path the app runs.** `process_budget.collector_kbps` equals the tick's `download_rate_kbps` because `_measure_rate` rounds to 0.1 and floors at 0 before `compose` sees the figure, and `mode` equals `rate_mode`; a test compares both against the real producers (a rate with a long tail, an idle tick, a counter that went backwards) and fails if either side changes, where a comment would not.
4. **Before dropping a field from a record, grep the whole tree for its readers, including the ones in another module.** The tick's `elapsed_s` was also read by `monitoring/forensics.py` (the previous-session report); a first grep missed it and the independent read found it. The replacement (`since_pass_start_s`, derived from `ts` and `pass_id`) says what it is: the runner stamps `pass_id` before source selection, so it is time into the pass, not time since the monitor started. Unknown is `null`, never `0`.
5. **A difference of two cumulative readings is written as it is.** `held_frac` is not clamped to 0..1: the gauge's totals only grow and its lock is exclusive, so a value outside the range would be evidence that an assumption broke, and clamping would hide it. A rate with no earlier reading, or no time between readings, is `null` with a reason, never `0`, which would read as "the lock was idle". A fact that does not depend on the missing reading (the holder's age at this instant) is still written on those paths.
6. **Drive a thread-keyed gauge with the real marks from one helper thread per simulated worker, in lockstep, with the clock replaced.** The gauge keys waiters and the holder by thread ident, so one thread playing fourteen workers would record one waiter; the harness in `audit-0.5.0/inputs/remeasure-tickblock/` calls `asking`, `holding` and `released` from fifty parked helper threads and moves a fake `lock_stats.now` between marks. Replace a module's clock with a namespace holding only the function the code under test calls: patching `monotonic` on the shared `time` module would move every other reader in the process.
