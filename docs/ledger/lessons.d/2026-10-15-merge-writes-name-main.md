## 2026-10-15 — a class of "left unqualified rather than churned" is closed by a scan, not by remembering to qualify

**(1) "Qualify one when its handler is next edited" never closes a class; a scan over the module's strings does.** Sixty-five writes in `src/backup/merge.py` named no schema for weeks, on the reasoning that `init_db` makes the hostile case impossible. The rule that finishes it is a source scan (`tests/test_merge_writes_name_main.py`) that FAILS CLOSED: it reads the SQL at every `execute`/`executemany`/`executescript` (through `text()`, concatenation, `%`, `.format`, f-strings, conditionals and a name's assignments) and at every helper that hands a parameter on (found by fixpoint, not listed by hand, and followed by position AND by keyword), and a statement it cannot read is a problem unless the allowlist gives a reason (and a dead entry fails). Planted cases, one per shape (upsert, `REPLACE INTO`, `INSERT OR REPLACE`, script, built, `WITH ... INSERT`, helper caller, unreadable), prove it fails when it should and passes the qualified spellings; run on the module as it was it reports 127 findings (some statements twice). A scan that matches nothing proves nothing, so a floor on how many writes it reads is pinned too.

**(2) The cheap mechanical change needed the same two proofs as any other.** Line-targeted regex edits (the scan lists the lines, the edit touches only those) left 65 changed lines and no others (`git diff --stat`), `main.{table}` inside an f-string and `UPDATE main.articles AS m` are valid SQLite, and the four FTS5 command inserts accept `main.article_fts(article_fts, rank)`. What the scan does NOT read is stated in the OPEN_QUEUE entry: the ORM (silently unseen, not a failure), a method fetched by a computed name, writes done by helpers in other modules (the ones that exist, `fts.index_articles` and `fts.rebuild_index`, are qualified and read by their own test; `normalise_staged_country_codes` writes `inc.` on purpose), and `CREATE TABLE IF NOT EXISTS`, which always creates in `main`.

**(3) A CI pin that searches a whole job's text proves less than the line it names.** The floor-leg export (`OO_EXPECT_SQLCIPHER_ENGINE`) is now required in the `env:` MAPPING of every step that runs pytest (the workflow parsed as YAML, so a job-level export, a comment or the `run:` text does not count); moved to the job level it still reached pytest but the test went red, which is the cost of asking for the narrower fact.

**(4) A review of the scan found the same class one level up: the checker's own blind spots.** The first version read only positional arguments, so `run(con, sql="WITH ... INSERT ...")` and `s.execute(statement=text(...))` scanned clean; `sql.replace("main.", "")` inside a helper removed the very prefix the scan demanded; a leading comment hid a write from the head check; and the one text guard (`test_wiki_version_anchor`) that searched for the unqualified spelling went red on the fix itself. A fail-closed checker is finished only when each way of NOT being read has a planted case that fails ON THAT CLAUSE ALONE: a case with a literal `DELETE FROM t` at the call site is also caught by the any-string-that-starts-like-a-write net, so it proves nothing about the argument reader. The cases for each clause therefore use a BUILT statement (an f-string that starts with a placeholder), and each clause was switched off in turn to see a case fail (a readable PASS case where the clause makes a read readable: `text()`, `.bindparams`, a name's assignments, a closure, a positional-only parameter, a conditional; the `%` branch is an equivalent mutant, since the concatenation branch reads the same text). A helper that REASSIGNS its parameter stays a pass-through AND has its own assignments read, because a conditional or nested reassignment leaves the caller's text reachable. Two forms stayed unread until the follow-up (2026-10-16): `.replace` fragments of the prefix (`.replace("ma", "").replace("in.", "")`, now refused when the replaced text is a substring of `main.` or `temp.`), and aliases or `partial`s of `execute` and of the helpers (an alias is followed; a callable used as any other value, `partial(run, con)` or `map(con.execute, rows)`, is a problem).
