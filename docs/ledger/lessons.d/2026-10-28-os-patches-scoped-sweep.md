## 2026-10-28 — A replacement of an `os` function belongs to the module under test, not to the process; a scoped patch can pass without ever being used, so count its calls once (R351, after R344/R350)

**What was found.**
1. **`monkeypatch.setattr(module.os, "replace", f)` is a process-wide patch.** `module.os` IS the `os` module. The 2026-10-27 lesson named the class (R344/R350: pytest 9.2.0 calls `os.fstat` at the end of every test phase and met a test's process-wide `os.fstat` patch) and listed 45 files as the scope of a sweep. This is the sweep: about 120 call sites in 47 test files now replace the name the module under test reads, through one helper, `tests/os_scope.py` (`scope_os(monkeypatch, module, replace=f)`; `hide_os(monkeypatch, module, "statvfs")` for a name the platform lacks). A second `scope_os` on the same module adds to the first one's namespace; `monkeypatch` puts the real module back at teardown.
2. **The 2026-10-27 list was a grep for the attribute form and missed a shape.** Six files patched by STRING target (`monkeypatch.setattr("src.safety.file_lock.os.replace", f)`: test_briefing_shared_files, test_expedition_log, test_runs_log_sinks, test_scheduler_shared_files, test_session_history, test_settings_file_temp). They were found by the guard below, not by the grep.
3. **The module that is patched is often not the module the test is about.** Ten tests went red on the first scoping because the code under test writes through `src.safety.file_lock.atomic_replace` (the swap, the temp name's `getpid`, the `fsync`), so the name to scope is `file_lock`'s: vitals_history, vllm_lifecycle, errorlog, forensics, memstop and the rewrite test of diagnostics_runs. That is the point of the exercise: the old patch reached `atomic_replace` only because it reached every caller.
4. **A scoped patch can pass without being used.** Two of those tests (forensics `test_a_writer_...` with a replace hook that runs a second writer, and the not-synced test) stayed GREEN when scoped to the wrong module, because their assertions held with the hook never called. To find them the whole set was run once under a throwaway plugin that wrapped every replacement and listed the ones with zero calls (not committed). Of 14 never-called replacements, 12 are by design (three guards that nothing opens a file or syncs: `core_guard` os.open, `file_lock` fsync when no flush is asked, the forensics not-synced test; and the neutral `cpu_count` default of the inference-hardware gate's autouse fixture, nine of whose tests never reach it), 1 is a vacuous patch that this change did not make (test_country_migration: `_path_exists` is stubbed to raise before `os.link` is reached; read from the code path, not run in the old form), and 1 is a patch the code under test never reaches (diagnostics_runs `getpid`, which the module calls only when a run begins, before the patch). Nothing was left unused by accident.
5. **Two deliberate exceptions stay process-wide, and a guard lists them.** `os.kill` in test_backend_launch and test_gpu_arbitration (a GUARD that no process anywhere is signalled: a scoped patch would not see a signal sent from another module), and the pass-through `os.open` spy of test_session_hwm_light (an observation of every route into /proc, in any module the sampler calls). The first fault-injecting test written the other way would be R344 again.

**Rules.**
1. **A replacement of an `os` function is `scope_os(monkeypatch, <module>, name=fn)`, bound to the module that READS the name.** Find it by reading who calls the function in the path under test; when the path goes through a helper (`atomic_replace`), the helper's module is the target.
2. **A fault injected into a scoped namespace is not proven by the test passing.** Count its calls (or assert them), unless the test is a guard whose expected count is zero.
3. **The guard is `tests/test_os_patches_are_scoped.py`:** it reads every test file's AST for `setattr`/`delattr` with `os` or `<x>.os` as the target, a string target ending `os.<name>`, and `patch.object(os, ...)`; it fails on any outside its three-entry allowlist, and fails on an allowlist entry that no longer matches. Its scanner is pinned on the exact line for each shape.
4. **Patching the name the module reads also changes what the test can reach:** code that does `import os` inside a function, or `Path.replace` (which calls `os.replace` through pathlib's own `os`), no longer sees the replacement. That is wanted; a test that depended on it fails loudly (none did).

**Also in this bundle (the two low notes of the delta read of #1596).** `tests/test_briefing_background_handle.py` gained a test that fails when the ContextVar reset in `_bg_refresh`'s `finally` is removed (both exits: a rebuild that ran and the early return of the write-ahead-log latch; both red against the mutant), and the quiesce fixture in `tests/conftest.py` now waits, inside its bound, for a briefing thread that is listed but has no ident yet, instead of skipping it (red against the old skip; a thread that never gets an ident is reported, not ignored).

**Not checked, stated.** `os.path`, `os.environ` and `builtins`/`io` patches are different shapes and were not swept. The test files were run (2,338 passed on the touched set, plus the six string-target files), not the whole suite; the full run is CI's. Windows branches of the touched tests were not run.
