## 2026-11-06 — a cache of a read surface: the build is a write (so never a GET), a lane file does not gain tables on open, and the cached path must be the same code (OSM R435)

**What was found.** The planet-prior readers re-aggregated 12M history rows per request (115 s for the four surfaces). Three things were not what the proposal assumed. (1) `store.lane_session` on an EXISTING lane file does not create tables; only `store.create_lane` (called by every ingest and history cut) runs `create_all`, so "created on open" was wrong, and a lazy build for a cut cut by an older build must call `create_lane` itself (additive, idempotent). (2) Building the cache on first read would make a GET write, which `tests/test_get_routes_side_effects*.py` measures as a security property; the lazy build is a POST that starts a thread, asked for once per country per session by the page, with a cheap header-only GET to wait on. (3) A cache stays honest only if the stored rows are the very tuples the computed path hands the series builders: one function (`prior_summary.surface_rows`) defines what is counted, used by the fallback and the writer alike, so there is nothing to drift but the stamps.

**The rule.** A stored summary is served only when its rule digest (key sets plus a revision number, so adding a key group makes every summary stale by construction) AND the cut's `finished_at` it was computed from both match; anything else computes from the source rows and the answer says `computed` and why. Read the cut's stamp BEFORE the pass and store that, and re-check it before writing, so a cut re-run mid-pass leaves a summary that reads stale, never one that passes for current. Read and write in two sessions: a write after a minute-long read in one transaction can be refused by a writer that committed meanwhile.

**Measured.** Synthetic Germany-scale lane (2.0M places, 1.8M change rows, 12M history rows): four surfaces 115 s computed, 9.8 s from the summary (the rest is the unchanged snapshot and window reads); the prior step 0.7 to 5 ms; one build 80 s for all four surfaces in one temp-table pass. The bench history carries only event and freshness rows, so the adoption and signal parity is pinned by `tests/test_osm_prior_summary.py` on a hand-built history, not by the bench.

**Where enforced.** `tests/test_osm_prior_summary.py` (parity on every surface, each stale state not served with poisoned rows, old lane gains the tables on build, a reader never writes, a failed build never fails the cut, cut re-run mid-pass), `tests/osm_prior_summary_node_test.js`, `tests/test_get_routes_side_effects_with_data.py`.
