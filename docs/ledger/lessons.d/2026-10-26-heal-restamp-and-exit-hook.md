## 2026-10-26 — A heal that changes a stamped field must re-stamp in the same commit, and a limit written from reading the code is measured before it is built on (0.5.1 items 39 and 41)

**What was found.** (39) `upsert_law_corpus_article` healed an article whose text had not changed: it cleared a poll date from `published_at` (and set the language the catalog states) and committed, but never indexed the article again. `index_article` STAMPS both onto the mentions (`observed_on` from `published_at or created_at`, the mention language from the article's), so the heal left every mention carrying the poll day: the article sat in one period by its own clock and in another by every reader of `observed_on`, and the A-003 story read (which chooses articles by the clock) and the older readers (which choose mentions by the stamp) disagreed about it. (41) The 0.5.1 item said a graceful-shutdown cancel during a snapshot leaves `.oo-backup-*/snapshot.db`. That was inferred from reading the code, and it was wrong in the form stated: a native cancel and an anyio cancel scope both end clean. What leaves the full plaintext copy in the data folder is a FORCED exit (a real uvicorn, `SIGINT` twice, an 8 s snapshot): the loop closes with no task left, the interpreter waits for the non-daemon worker thread, and the process exits `rc=0` with the copy behind it.

**Rules.**
1. **A heal of a field that is denormalised onto other rows re-stamps those rows through the one hook that stamps them, in the same commit.** Committing the column first makes a failed re-index unrepeatable, because the next call finds nothing left to heal; the test makes the hook raise once, rolls back as the batch caller does, and asks the next call to heal. Say what the heal does NOT cover: the content-changed branch of the same function still commits before it indexes (not changed here).
2. **The steady state pays nothing.** The re-index is conditional on the heal having changed something; a test replaces the hook with one that fails if called and asks for the unchanged, already healed article.
3. **Measure a limit before writing it into a ledger, and when the measurement disagrees correct the earlier text in place.** The corrected lesson (`2026-10-26-backup-get-cross-site.md`, rule 7) now says which cases are clean (and pins them with two tests that pass before and after: a pin is not a repair) and which leaked. The probe is a real server process, the real app, a patched slow `backup_to`, a socket client and the signals; the unit tests alone could not have shown it, because the leak needs the loop to close while a thread is still running.
4. **Python runs exit hooks after it has joined its non-daemon threads.** That order is what makes an `atexit` removal correct for a file a worker writes AFTER the main thread ended; the test runs a real interpreter whose non-daemon thread writes the file a second after the main thread finishes. Stamp the table with the pid that made the entry: a forked child inherits the table and the hooks and must not remove its parent's live download. A kill runs nothing; leave that to the sweeps and say so.
