## 2026-10-31 — a junit testcase time is setup plus call plus teardown and not the job's wall time, and a tool the runner image provides is a dependency that fails by skipping (PR #PRNUMBER)

**What was found.** (1) Measured on pytest 9.1.1 with `--junitxml`: two tests sharing a session fixture (0.4 s setup, 0.2 s teardown), each with a 0.1 s + 0.1 s function fixture and a 0.3 s body, under a `conftest.py` that took 0.5 s to import, wrote `time="0.903"` and `time="0.704"` (sum 1.607 s) in a process that took 2.68 s. A testcase's time is setup + call + teardown; a session fixture's SETUP is charged to the first test that asks for it and its TEARDOWN to the last test of the WHOLE run, even one in a module that never used the fixture (a second experiment: 0.502 s, 0.101 s and 0.301 s for a test that did not use it); collection and `conftest.py` imports are charged to no test. So the sum of times per module ranks modules by what their tests cost, not by wall time, and a module that uses a heavy session fixture first, or holds the run's last test, carries that fixture's cost. (2) 54 test files skip when `node` is missing (46 with a decorator or `pytestmark`, the rest in the body); run with no node on PATH they give 99 skipped, 590 passed and one failure (`test_release_run_panel_node_suite` calls node without a probe). Five more files skip on `bash`, three on `git`, one on `unzip`, one on a C compiler, and `ci.yml` installs none of them: the `ubuntu-latest` image provides them, with no `setup-node`, no pin and no assertion. A runner that lost one would turn those tests into green skips. The real skip summary of the `test` and `core-only` jobs (353 skips in 44 modules, 419 in 73) shows the node files are not among the skipped, so today they run; nothing said so before.

**The rule.** (1) A per-module timing printed from junit names its meaning in its first line ("per-test times summed, not the job's wall time"), takes a time only if it is a plain decimal (`[0-9]{1,9}(\.[0-9]{1,9})?`: `nan`, `inf`, a sign, an exponent and a digit outside 0-9 are counted in one line and added to nothing, with a permissive variant shown to break), and gates nothing (R350). (2) A tool a test skips on is either installed by a workflow step whose failure is red (`original-awk`: `command -v` under `bash -e`) or asserted by a test that is red on a Linux CI runner without it (`tests/test_ci_runner_has_the_tools_that_tests_skip_without.py`, the shape `test_installer_windows.py` already had for PowerShell), and the list of such tools is checked in BOTH directions against what the tests actually probe, so a new `shutil.which("x")` gate fails until its tool is named. The end-to-end proof runs the very test in a process whose `PATH` has no `node` (red, names it) and one with a `node` (green); the macOS and Windows legs of the observation lane skip it because the blocking jobs are the Linux ones (a leg that never turns a PR red is not where a runner image is pinned).

**Where it applies.** Any test that skips on a tool, a package or a platform feature the CI image happens to ship; any timing read from a pytest report (compare it with the wall time before calling a module "slow").
