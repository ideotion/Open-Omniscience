## 2026-10-17 — A lock that guards writes an exclusive window already serialises guards nothing, and its failed exit is all it does: prove the serialisation, pin the callers in the source AT THE POSITION THAT MATTERS, delete the lock

**What was found.** ``library_generation`` wrote four names (``_GENERATION``, ``_VALID``, ``_WINDOW_STAMP``, ``_DISK_CHANGED``) under a plain ``threading.Lock``, ``_STATE``. Every writer (``swap_window``, ``bump``, ``_open_window``, ``_close_window``, ``disk_changing``) runs on the thread that holds the exclusive library window, and the window is held by one thread at a time; no reader (``current``, ``valid``, the stamp in ``attach``, ``connecting``) ever took ``_STATE``. So the lock excluded no writer from another writer and no reader from a writer. Its one effect was a hazard: on CPython 3.13 a ``with`` exit builds a 3-tuple and can fail on cold free lists, a plain lock whose exit failed stays held, and every later ``with _STATE:`` waits for ever, with the window still held, so the pool stops until restart. The earlier merge of the cleanup's sections (the lesson of the close-window merge) cut that to a named residual (4 of 5 sections of a swap that changes the disk could block that swap's own close, 3 of 4 for one refused before it; the last one blocked the NEXT swap, so by that count all five were such sites) and said that only having no ``_STATE`` removes it.

**The rules.**
1. **Before deleting a lock, write the inventory, not the intuition.** The claim has three parts and each is a list. Writers: ``swap_window`` itself (the reset of the flag, ``bump``, ``_open_window``, ``_close_window``) and ``disk_changing``, called from the body of the restore's window (``backup/merge.py``) and of the encrypt tool's (``database/encrypt_tool.py``); the repair reaches a window only through the restore's swap. Readers: ``current``, ``valid``, ``connecting`` (under a shared level, which excludes the window, or on the holder's own thread) and the stamp in ``attach``; none took the lock. Paths outside a window: none in ``src/`` (startup, shutdown, the diagnostics bundle, the dump swaps and the test hooks were each looked at; ``session.py`` and ``read_snapshot.py`` call only ``attach`` and ``guarded_creator``). A reader of a PAIR of the names can see them between two writes of one writer (``valid()`` between the clear of the stamp and the union), and could at the base too, because readers never took the lock; it lands on the refused side.
2. **Give the proof an executable form, in the direction a future change would break it, and make it say WHERE in the function.** ``tests/test_library_generation_writers_run_in_the_window.py`` reads ``src/`` and fails a call of a writer that is not inside the BODY of a ``with <...>.swap_window(...)`` block (everywhere else) or inside the part of ``swap_window`` that holds the window (in the module); a writer REFERENCED and not called (a thread target, ``atexit.register``, a variable, ``getattr`` by name); a store to one of the four names in any form (plain, augmented, tuple, ``for`` or ``with`` target, ``setattr``) or a ``global`` of them from anything that is not a writer; and it finds the module through every import form of ``src/`` (absolute, relative, bare, ``as``). The first version accepted any statement inside ``swap_window`` as "inside the window". The independent read moved ``_DISK_CHANGED = False`` above ``_LOCK.exclusive(...)``: the pin and four other test files passed, and run with two threads (swap A calls ``disk_changing`` and its replace fails; swap B is waiting for the window) A's cleanup gave the connections from before its disk change their validity back (the valid set after A's close was ``[-1, 0, 1]`` against ``[1]``): a swap that is only waiting reset the flag of the swap that holds the window. The pin now reads "inside the window" as "after the acquire returns, or in the cleanup behind ``held_here()``", says so when the function no longer has the shape it reads, and keeps that placement as a red-without twice: as a rewrite of the real source the pin must see, and as the two-thread run. **A pin that treats "inside this function" as "inside the window" passes the placement bug it exists for; pin the position relative to the acquire, and run the one placement that matters.** It is an AST pin, not a proof: a module reached by a computed name is not seen, and the docstring says so. The test names the real callers that change the disk, so it cannot go quiet by finding nothing.
3. **Pin the absence too.** ``tests/test_swap_window_allocation_failures.py`` fails a ``with`` statement in any writer, or in a module function a writer calls (to any depth), and a module-level ``threading.Lock()``/``RLock()``, and a synthetic source with one proves the pin sees it.
4. **What the deletion does and does not change.** The swap now passes no lock for the module's state, so the failed-exit class for THE STATE is gone, not shrunk. What remains of that class is the call that gives the window back (``release_if_held_here``) and the window's own ``with self._lock:`` sections (``shared``, ``release_shared_since``, ``exclusive``, ``held_here``), which are sites of the same kind on the plain lock under the Condition as the interrupt ruling (R144) has it: they predate this change and it does not touch them (not measured here; named so it is not lost). ``bump``'s two stores (the generation and the valid set) were never atomic against an interrupt and are not now; the lock did not make them so. Several servers on one data folder each have their own module state and window; neither lock protected across processes and nothing here changes that.
5. **Deleting the ``with`` lines gives the instruction sweep nothing new to reach, and the lesson that said it did was wrong.** The sweep skips lines that start with ``with`` (it cannot inject at an exit), so the enter and exit of ``with _STATE:`` were never sites; the bodies of those blocks always were. Run in count mode on the module before and after, the sweep's site lists are identical (8 sites with the source present and no disk change, 6 for each of the other three combinations; the functions that hold the sites are the same). What the change adds is a second sweep that calls ``disk_changing()`` in the body and asserts that after a MemoryError at any instruction of the cleanup only the new generation is valid; its red-without is a rewrite of the source that decides the flag in a step of its own that can allocate (the shape that revived the window's connections after ``disk_changing``). That case only bites with the source still present: with the source gone the close never revives. **Measure a claim about what a sweep reaches before writing it; a sweep run in count mode on the old and the new source takes one minute.**
6. **A test that injects through the lock it is about to lose has to change with it.** One interrupt-safety test raised from ``_STATE`` to model a statement between the acquire and the ``try``; with no ``_STATE`` there is no such statement to inject at, which is the point. The lane that owns that file changed it first, in the change that added the detector: it injects at ``bump`` now (checked on a tree with and on a tree without the state lock: the window is still given back), so this change touches none of that lane's tests.
