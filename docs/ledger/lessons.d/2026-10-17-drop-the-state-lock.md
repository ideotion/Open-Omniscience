## 2026-10-17 — A lock that guards writes an exclusive window already serialises guards nothing, and its failed exit is all it does: prove the serialisation, pin the callers in the source, delete the lock

**What was found.** ``library_generation`` wrote four names (``_GENERATION``, ``_VALID``, ``_WINDOW_STAMP``, ``_DISK_CHANGED``) under a plain ``threading.Lock``, ``_STATE``. Every writer (``swap_window``, ``bump``, ``_open_window``, ``_close_window``, ``disk_changing``) runs on the thread that holds the exclusive library window, and the window is held by one thread at a time; no reader (``current``, ``valid``, the stamp in ``attach``, ``connecting``) ever took ``_STATE``. So the lock excluded no writer from another writer and no reader from a writer. Its one effect was a hazard: on CPython 3.13 a ``with`` exit builds a 3-tuple and can fail on cold free lists, a plain lock whose exit failed stays held, and every later ``with _STATE:`` waits for ever, with the window still held, so the pool stops until restart. The earlier merge of the cleanup's sections (the lesson of the close-window merge) cut that to a named residual (4 of 5 sections of a swap that changes the disk, 3 of 4 of one refused before it) and said that only having no ``_STATE`` removes it.

**The rules.**
1. **Before deleting a lock, write the inventory, not the intuition.** The claim has three parts and each is a list: every writer and where it is called from, every reader and that none takes the lock, and every path that could reach a writer outside the window (startup, shutdown, the diagnostics bundle, tests, other processes). The inventory is in ``/mnt/project-files/wal-disk-pool/night-2026-10-16/plan-close-window/D-PROOF-NOTE.md``; the lock covered nothing else.
2. **Give the proof an executable form, in the direction a future change would break it.** ``tests/test_library_generation_writers_run_in_the_window.py`` reads ``src/`` and fails a call of a writer that is not inside ``swap_window`` (in the module) or inside the BODY of a ``with <...>.swap_window(...)`` block (everywhere else), including a call from a function defined inside the block (it may run later), a call after the block, a store to one of the four names from another module, and an assignment to them from a function that is not a writer. It resolves the import aliases of each module, so ``from src.database.library_generation import disk_changing as dc`` is still seen. A new writer outside a window then fails a test and does not race. The test names the two real callers that change the disk, so the pin cannot go quiet by finding nothing.
3. **Pin the absence too.** ``tests/test_swap_window_allocation_failures.py`` fails a ``with`` statement in any writer and a module-level ``threading.Lock()``/``RLock()``, and a synthetic source with one proves the pin sees it.
4. **What the deletion does and does not change.** The swap now passes no lock for the module's state, so the failed-exit class for the state is gone, not shrunk; the named residual that remains is the call that gives the window back (``release_if_held_here``). ``bump``'s two stores (the generation and the valid set) were never atomic against an interrupt and are not now; the lock did not make them so. Several servers on one data folder each have their own module state and window; neither lock protected across processes and nothing here changes that.
5. **When the ``with`` lines go, the sweep gets sites it skipped.** The instruction sweep skips lines that start with ``with`` (it cannot inject at an exit), so every section it never saw in ``_close_window`` is now ordinary code that the sweep injects into. A second sweep calls ``disk_changing()`` in the body and asserts that after a MemoryError at any instruction of the cleanup only the new generation is valid; the red-without is a rewrite of the source that decides the flag in a step of its own before the close (the shape that revived the window's connections after ``disk_changing``).
6. **A test that injects through the lock it is about to lose has to change with it.** One interrupt-safety test raised from ``_STATE`` to model a statement between the acquire and the ``try``; with no ``_STATE`` there is no such statement to inject at, which is the point. The lane that owns that file changed it first, in the change that added the detector: it injects at ``bump`` now (checked on a tree with and on a tree without the state lock: the window is still given back), so this change touches none of that lane's tests.
