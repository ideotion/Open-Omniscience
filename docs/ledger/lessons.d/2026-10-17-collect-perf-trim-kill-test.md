## 2026-10-17 — a log's trim that rewrites the file in place can empty the evidence it keeps: test the kill window with a child that dies there, written against the effect

**What was found.** `collect_perf._trim_jsonl` cut `collect_perf.jsonl` back to its newest 5,000 rows with `path.write_text(...)`, which opens the file for writing (truncating it) before the rows are written back. A process killed in that window leaves the log empty, and this is the log crash forensics reads for the last samples before a crash: the crash destroys its own evidence. It was found by RC2's sweep of every writer of the `data/*.jsonl` files (`/mnt/project-files/rc-diagnostics/exit-evidence-sweep/B-other-writers-report.md`), not by a failure in the field. `search_timing` and `vllm_lifecycle` already cut their logs through a copy and `os.replace`; this log never had.

**The rules.**
1. **A rewrite of a file whose half-written state would be misread goes through a copy beside it and `os.replace`, synced first.** The in-place version has a window in which the file is empty, and no later code can know a row was lost. The cut is the same bytes as before (the test compares against what `write_text` wrote); the sync adds about 4 ms to the write and swap of a 5 MB log (median of 7 runs on this sandbox's disk: 8.7 ms with it, 4.4 ms without; one disk, not a slow one), at most at a pass's start and at its end.
2. **Name the copy for the process and the thread, and sweep the ones a dead process left.** A fixed name is overwritten by the next cut but is one file for two processes cutting at once, so one can swap in the other's half-written copy. With a per-process name a kill between the write and the swap leaves a 5 MB orphan that nothing would ever overwrite, so the next cut removes copies whose pid is gone (`psutil.pid_exists`), and removes nothing when it cannot tell live from dead.
3. **Test a crash window with a child process that `os._exit`s there, and assert on the effect.** An exception raised at the same point runs the `finally` and `except` handlers a real kill never runs, so it proves the handler and not the window. The child kills itself the moment the cut is written to whichever file the code opened for writing, so the same test fails on the in-place version (log empty, or cut short) and passes on the swapped one; it checks the exit code is the kill's, so a child that finished or failed cannot pass it.
4. **State what the fix does not cover.** A row another process appends between the read and the swap is still lost, here as before; closing it needs a lock across processes, and whether two servers on one data directory are a supported case is a ruling, not a code change.
