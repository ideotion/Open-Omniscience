## 2026-10-27 — a "delta" between two counts read from the same table can never be non-zero: before trusting a comparison in a report, ask whether the two sides can differ

**What was found.** The integrity report carried `delta = articles - fts_rows` beside a note "a large delta means the index is stale", and `fts_status` documented a "damaged/incomplete index" verdict. Both read the full-text index through its external content table (`articles`), so the health probe was healthy and the row count equal to the article count over an index that had been emptied, or that held only the first half of the articles; the delta was 0 whatever the index held. The merge's restore path had already named this ("tautological") and probed the index's own shadow table; the diagnostic that existed to catch the same state never did. It was found because a new test ended on the same comparison and an independent read asked whether that comparison could fail; the Export lane's measurement then showed the prefix state reading as settled in the boot, the status and the search.

**The rules.**

1. **A comparison in a report or a test is worth something only if the two sides can differ.** Before shipping `a - b`, find the path by which `a` and `b` come apart; if both are answered by the same table, the field is decoration with a confident note beside it.
2. **For an external-content FTS5 table the index's own record is `<name>_docsize`** (one row per indexed document; its `id` is the document's rowid); the probe and the count of the virtual table read the content table. `COUNT(*)` of the shadow table is a scan of a small b-tree, `SELECT 1 FROM <name>_docsize LIMIT 1` is O(1), and a build with `columnsize=0` has no shadow table: say `unprobeable`, never rebuild on that account.
3. **State only what an O(1) probe can state, and name what it compared.** The highest id of the index against the highest id of its source (two b-tree end lookups, 0.1 to 0.25 ms at 400,000 articles) sees an empty index and a missing TAIL; it does not see a hole in the middle or a missing head, and it cannot say how many are missing. So the state says what it is (`partial (inferred)`, `ends-agree`, never "whole" and never "agree"), the limit is pinned by a test that builds the hole and shows the count comparison is what sees it, and the exact count stays where the cost is accepted (a bounded caller, not a boot). A verdict that refuses `healthy` may still repair nothing. And say how long the verdict lasts: a missing tail turns into a hole in the middle at the next ingest, so `partial (inferred)` is a window, not a standing fact; a docstring that says "reports a partial index" without that claims more than the probe can keep.
4. **Numbers that must describe one moment are read in ONE statement, not ordered.** The first version read the articles' top id first (it only grows) and asked again when the ends disagreed (a delete takes the index rows with it). An independent read built the interleaving that beats both: the top article is deleted, the index's ends are read, a new article is ingested and, with no `AUTOINCREMENT`, takes the freed id and is indexed by its trigger, and the "second look" then reads an id above the index's. Ids are reused, so no order of separate reads is safe, and a re-read that comes after the thing it guards against only moves the race. `SELECT (SELECT max(id) ...), (SELECT count(*) ...), (SELECT max(id) ...)` is one statement and so one read snapshot: measured with another connection deleting the top article in the middle of the statement, WAL returns all three numbers from the snapshot it started in and rollback-journal mode refuses the writer until the statement is done. A test pins the shape (one statement carries all three; a statement with fewer is red), because a spy that acts "in the gap" cannot test a gap that no longer exists.
5. **A block that bounds its own work answers to its own deadline and its own error.** Run the population read inside a deadline of its own (a mutant that drops it is red), apply the verdict only after the read has come back (a timeout claims nothing), clear every derived field on a timeout or error, and never let a later step's failure, or a later step's label, replace the error an earlier step already named: the first failure stays the one named and the state field carries the verdict. A torn copy, the cause of a partial index, is exactly where a corruption error on the content count is likely.
6. **A report block that gains fields is paid for in the same commit** (the diagnostics room is net-zero): shorten the prose by more than the keys add and measure the largest shapes (the longest label with a timeout, every longest value at once, and the longest NEW shape), not only the healthy one, against the baseline the rule means (`main`, not an earlier unmerged version of the same change); replace two booleans that cannot both be true with one named state.
7. **A mutation harness that restores with `git checkout -- <file>` also restores your uncommitted edits to that file.** Commit the change first, then mutate; a first run here reverted the whole fix and reported the next mutant as unmatched.
8. **A guard test that greps statements must catch the other spellings.** The "no count of the articles" check was a case-sensitive substring over `session.execute`: `COUNT(*) FROM articles`, extra whitespace or a different route to the engine slipped past it. Take the statements at the cursor (`before_cursor_execute`), normalise case and whitespace, and show the spy is listening (it saw the population read).
