## 2026-11-14 — A merge that "keeps both sides" of a key path can still need new trust logic; decide ownership by position in the chain, never by key (R681 + #2005, PR #2003)

**What was found.** #2003 (R681: a verified custody bundle also says whether it was signed by THIS installation's keys) met #2005 (signing-key rotation records) in a merge. Keeping both sides was not enough: a rotated bundle has several signers by design, so "yours" needed new logic to credit this installation's earlier keys. The first version credited an earlier key BY KEY, wherever it signed. It passed an Opus read. A second, independent security read then broke it twice. (1) A forger holding a leaked old key P replays the genuine endorsed P→L record from the user's own export, forges an unendorsed L→P after it, and signs new entries with P. With "accept unendorsed rotation" ticked, that read "verified against your keys". (2) After the fix moved to position, a one-item bundle still fell: it is not chained (its rotation record links to an entry the bundle does not carry), so P could rewrite the stretch it signed before the rotation while the record, the last entry and the head stayed genuine.

**What it cost.** Two must-fix rounds on a PR first in line for the merge slot. One CI run was cancelled, and a head that read clean to one reviewer would have shipped a forgeable "yours".

**The rule.** (1) A merge resolution in a key, restore, consent or custody path that ADDS a decision neither side made (here, crediting earlier keys) gets its own independent security read, even when each side was reviewed and the resolution "only keeps both". Point the reader at forged chains, not at your conclusion. (2) Credit a key only for the positions it signed before handing over: cut the chain at its rotation records, credit the last stretch only when its key is yours, and credit each earlier stretch only when the next one is credited and the record between them is endorsed (`_own_positions`). A key that was rotated away from may have been rotated away from BECAUSE it leaked. (3) Credit an earlier stretch only where the bundle CHAINS it to the rotation (the whole log). In a one-item bundle, say why it gets no credit and point to the whole-log check.
