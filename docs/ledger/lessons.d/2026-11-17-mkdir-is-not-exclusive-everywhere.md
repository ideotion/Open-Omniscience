## 2026-11-17 — mkdir is not exclusive everywhere: a lock is held by an O_EXCL file create, never by mkdir alone (row 100, PR #2066)

**What was found.** The launcher's record lock without flock (macOS, and CI where flock is hidden) was "whoever's `mkdir` of the lock directory succeeds". On the Ubuntu 26.04 runners `mkdir` and `ln` are uutils coreutils 0.10, while `mv` is still GNU. uutils 0.10's mkdir checks that the name is free, then creates it, and returns SUCCESS when another process created it in between: `Err(_) if path.is_dir() => Ok(())`, without `-p`. 0.12 fixed it. Two launchers then each "made" the lock and both held it, and a trim's rename could drop the other's row. The eight-taker test failed twice on CI and never locally, in about 1,000 local rounds under load, with uutils 0.12 and a jitter fuzzer. An independent read found no interleaving, because the bug was not in the script. What found it was making the detector name both pids AND print the tools in use (`readlink -f $(command -v mv ln mkdir)` plus `--version`). The first failure message that carried them showed `uutils coreutils 0.10.0`.

**What it cost.** Three CI rounds and a day on #2066. Two rounds of lock redesign answered a cause that was a tool's, not the script's: the directory mark rewritten from mv-into-place to mkdir, which was itself the non-exclusive step.

**The rule.** (1) Shell mutual exclusion takes its exclusivity from the KERNEL in this shell's own process, not from an external tool's exit status. Use `set -C` (noclobber, O_EXCL) to create a pid file, or `ln` (link(2) refuses an existing name, in GNU and uutils alike). `mkdir` is the container, not the claim (`_oo_rec_claim` and `_oo_rec_take` in scripts/launch.sh). (2) A test for mutual exclusion must model the weakest tool it may meet. Here that is an `mkdir` that succeeds on an existing directory, and the eight-taker test's `mkdir-not-exclusive` case fails on the old launcher. Its detector must not rest on the tool under suspicion either: an O_EXCL file, and any failed create counts as an overlap. (3) When a race fails on CI and never locally, print the tool identities in the failure message before redesigning anything. The runner's coreutils can differ from yours, and from each other within one image.
