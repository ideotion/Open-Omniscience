## 2026-10-27 — A recorder that remembers an outcome asks the switch, after the step, whether the person stopped it; it never decides from the words of the failure, and each guard it adds is proved by taking that guard out (R327, D1 and D2)

**What was found.** Export drove every recorder that stores a fetch outcome with the production fetcher and the kill switch in each state a Stop leaves it in. Two recorders in the collector stored the person's own Stop as the host's behaviour. The housekeeping lane checks the switch once, before it starts, so the crawl rung stamped `Source.last_crawled_at` on outlets it never visited (3 of 3 with the switch engaged before the step; the outlet cut in flight), which sends them to the back of the rotation. The feed pass stored the feed's ETag after a Stop mid-feed and climbed the backoff to 300 s, so the entries never asked for were not asked for again until the feed changed; and a Stop before the feed GET took the fetch-error branch that resets the backoff, erasing a quiet feed's history. Both are the same class as R293 (the person's setting written down as the target's behaviour).

**Rules.**
1. **Decide from the switch, read AFTER the step (`kill_switch_active()`), never from the text of the refusal (R320).** Words can be wrapped, translated or retried away; the setting cannot.
2. **A long step has a check at every boundary a record is written after, not one at the head of the lane:** before each outlet, after discovery (a discovery cut short reports "no sitemap" only because it was stopped, so the fallback must not run on it), after each page (the cut page is not an attempt) and immediately before the stamp or the stored validator.
3. **A Stop leaves the row as it was.** The next pass then re-reads with the old validator and the dedup step skips what was stored, which is cheaper to reason about than a validator that vouches for entries nobody asked for.
4. **Redundant guards pass their tests until each is taken out.** The first version of these tests killed only 4 of 7 statements: two guards were covered by a neighbour. Each guard got a test whose scenario only that guard handles (the discovery call counted, the fallback crawl counted, the entries walked counted), and the seven mutations (statement replaced by `if False`) each fail exactly their own test.
5. **The honest limit stays written:** a Stop cleared again within one request's flight reads as the host's failure (the law tracker's stated window); closing it needs an engagement epoch read before and after each request, which touches every reader and is a proposal.
6. **Proposal for the user list, not built here:** a lane-level pause (`out["_paused"] = {"reason": "airplane mode", ...}`) beside the memory and storage guards in `run_housekeeping_lane`, so a Stop between two lane steps stops the later kinds from starting at all. It changes what the lane reports and which kinds run offline (some do no fetching), so it is a design change rather than a defect fix.
