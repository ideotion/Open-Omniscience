## 2026-10-16 — a scrubber for another library's log lines treats every carrier as untrusted, is default-deny over a table the installed library proves, and fails closed; and the checks before a first push are picked by what changed

**What was found.** The filter #1414 put on `urllib3`'s loggers (R142) rewrote the text arguments of the log lines it knew, on four loggers, from the shapes of one release, and let everything else through. The independent read of the follow-up found the line that matters: `Failed to parse headers (url=%s): %s` passes the `HeaderParsingError` OBJECT as an argument and `exc_info=True`, and its text is the defects plus the raw header bytes the SERVER sent after its first malformed line, a `Location` with its signed query included. Reproduced against a loopback socket: a 302 with a signed `Location` after a bad header line, on a fetch that SUCCEEDS, put the signature into the log and the error journal on `main`. The first default-deny build of this PR fixed the target argument and still passed the exception argument and `exc_info`. Separately, the push of #1414 was red in CI for `tests/test_sink_sweep_records.py`, a file `main` had added a day earlier and the merge had brought in; a CI cycle here is about fifty-five minutes.

**The rules.**
1. **Every carrier of a record is untrusted, not the one you looked at.** A `LogRecord` carries text in the message, in each argument (whatever its type: an exception's `str()` is the library's or the server's text), in `exc_info` and its cached `exc_text`, in `stack_info`, and in any attribute `extra=` or a record factory added. A filter that cuts "the arguments that are text" has chosen the carriers it knows. `scrub` cuts the target positions, reduces every other argument (a number or `None` as is, text cut the same way, anything else to `<ClassName>`), and drops the exception, the stack and the extras.
2. **A scrubber for text you do not write is default-deny.** `SHAPES` keys `(logger, message template)` to the source text of each argument, the positions that carry a target, and the keywords the call passes. A record with no entry, another number of arguments, a non-tuple `args` or a message that is not text has its message replaced whole: logger and level kept, the exception's class name kept, arguments and every trace gone. The record is never dropped (a dropped record hides the very failure the journal exists to show), and doing it twice leaves the first result.
3. **A filter must never raise, and what it does when it cannot decide is withhold.** An unhashable message raises `TypeError` inside the lookup, a hostile argument raises from `__class__`; `scrub` catches everything and withholds the message whole, and the test calls `scrub` alone (the logger's filter and the factory both run it, so a record half-cleaned by the first pass is finished by the second and a test through the logger cannot tell the fallback from the main path).
4. **Prove the table against the INSTALLED library by AST, and make the reader unable to pass vacuously.** The test reads every log call of the installed `urllib3` and fails by name on a call not in the table, an argument whose source differs, a keyword the entry does not name, a table entry the library no longer has and a module logger the filter does not cover. The reader binds a logger however it is bound (any `getLogger` assignment form), compares EVERY call of one template (two calls with one template are both checked), and fails an unclassified call by name. A reader that finds no calls would pass; the test pins 16 calls and 9 loggers. The real-socket tests stay, because they show a shape the AST reader cannot, and each asserts the withheld sentence is absent so a known shape that falls through to the default is a failure.
5. **Bound the dependency by what you read, to the next patch release.** `pyproject.toml` has `urllib3>=2.7.0,<2.8.1`: the floor and the verified release are the two read (identical templates and arguments), the ceiling is the first release NOT read. `<2.9` would have admitted 2.8.1, and a patch release can change what the library logs (2.8.0 added `extra=` to the retry warning). The registry entry `urllib3-log-shapes` (floor, verified, ceiling, `upstream_check`) and a freshness test tie the pyproject text to it; a CI job (`urllib3-floor`) runs the table test on 2.7.0, because the test lane resolves 2.8.0 and the lock file ships 2.7.0, so a range proved at one end is half proved.
6. **A contrast test for every real-socket repro.** The signed-`Location` test also runs with the filter switched off and must leak; a repro that cannot fail proves nothing about the filter.
7. **State what a filter on a logger cannot see.** A process that never imports `src.ingest` (two operator scripts) has no filter, and the `httpx` logger logs full URLs at INFO for the loopback Ollama and vLLM clients. Both are written in the module docstring, `SECURITY.md` and the queue entry.
8. **Pick the pre-push checks from the diff, with a tool, and test the tool.** `scripts/guards_for_diff.py` picks (a) the tests `main` added since the branch left it, found through the merges INTO the branch (the line brought is the parent already inside the base, which is the FIRST parent when the merge was made the other way round; `--since REF` covers a rebase, which leaves no merge), (b) the tests the branch changed, untracked included, (c) the tests that use a changed support file (a helper, a `*_node_test.js`, a data file; a deleted helper too, because its importers fail on import; a nested `conftest.py` picks its subtree and a root one says to run the suite), (d) the test files that walk the tree (a star-led `rglob` on a repository-rooted receiver included, a scratch directory not), then the blocking ruff lane and the style ratchet with its ceiling READ from `ci.yml`. Paths come from git with `-z` (without it a non-ASCII name is quoted and silently dropped) and the printed command is shell-quoted. Its selection is tested on a throwaway git repository (40 live mutants, all killed). The first real run of the picker found the miss it exists for, before any push: `main`'s records sweep (`tests/test_sink_sweep_records.py`) reads every module under `src/` for the word `exc_info`, and the rewritten filter, which must assign it, needed a counted, commented entry (three mentions, none of them a stored exception).
