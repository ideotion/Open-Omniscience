## 2026-10-16 — a serve-stale cache still pays its whole scan on the request thread at its first call, and a ring of "recent slow statements" belongs to no request in particular (PR pending)

**What was found.** The 2026-10-16 field diagnostics showed `GET /api/database/figures` taking 55.6 s once. It was the first call of a process 8.5 hours old: `served_cache` serves stale values and refreshes in the background, but a COLD entry was computed inline, and the figures' compute holds the one whole-table query, `SELECT count(*) FROM keyword_mentions_all` (55,310.8 ms of the 55,554.8 ms request, 99.6 %, about 12 million mentions; 182 s for the same shape under other load). Nothing warmed the key and the route had no statement deadline (only the insights routes wrap `_deadlined`). The stall record for that request named the wrong statement: `stall_forensics._statement_evidence` took the worst of the last 20 slow-query rows with no check that the statement ran inside the request, so it named a writer's 56.9 s SAVEPOINT (`share_of_request` 1.023, impossible) and attributed the same COUNT to two later requests that began minutes after it ended.

**The rules.**
1. **A cache that is warm-or-background has a third state, cold, and for a whole-table scan that state needs its own answer.** `served_cache.cached(..., cold_payload=...)` starts ONE background compute and answers at once with the cheap part marked `pending` (`pending_since`); the value that is not known is `null` with a named state (`computing`, `counted`, `failed`), never a zero and never a wait. Warming the key at boot was rejected: it puts the scan into the contended boot window.
2. **A background scan gets a statement deadline that says what it protects.** The 300 s deadline of the figures count protects the pooled connection and the read snapshot it holds (an open read pins the WAL), 1.6 times the worst measured 182 s; a count that cannot finish is recorded by kind, deadline and time, and held for a stated window (900 s) through the entry's own `__ttl_s__`, so a failure is not retried per poll. An error other than the deadline is named by its class only.
3. **Evidence taken from a shared ring must be tied to the thing it explains.** A recorded statement counts for a request only if it ended inside the request's window and was not longer than the request; otherwise `found: false` with the reason. A share above 1.0 is the tell that the match is wrong.
4. **A tile that waits on a background value says so where the value would be**, and carries the long form on hover (the informed-consent layering): "counting…" with the start time, or "not counted" with the kind, the deadline and the retry window, ×12 locales.
5. **A test that expects a refresh must make the cache's probe move.** With nothing written, `served_cache` re-stamps a stale entry as verified and starts no refresh, so a test of "a failure inside its window is not retried" passes for the wrong reason unless `change_probe` changes.
