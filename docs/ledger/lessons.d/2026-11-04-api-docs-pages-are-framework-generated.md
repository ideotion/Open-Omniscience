## 2026-11-04 — A page the framework generates is a page nobody grepped: `/docs` and `/redoc` made the browser fetch from three third-party hosts (A-021, R285/R411)

**What was found.** `FastAPI(...)` in `src/api/main.py` set no `docs_url` / `redoc_url`, so the defaults served Swagger at `/docs` and ReDoc at `/redoc`. Both are small HTML shells that make the BROWSER load their script, style and favicon from `cdn.jsdelivr.net` and `fastapi.tiangolo.com`, and ReDoc also loads a web font from `fonts.googleapis.com`. The CSP middleware exempted both prefixes so the browser would allow it. `docs/SECURITY.md` named Swagger only, and said "the app itself never fetches it", true of the server and beside the point of the stance (no external resource in a page the app serves). It stood from the first release until the OSM lane measured it on 2026-10-27.

**Why nothing caught it.** Every "no external resource" check in the tree scans files WE wrote (the static tree, the locale strings, the `@font-face` rules). These two pages exist in no file of ours: the framework renders them from a template inside the installed package, and the route is registered by a constructor default. A grep over the repo cannot see a page that is generated at request time, and the ratchet that bans `requests`/`httpx` imports cannot see a browser doing the fetching.

**Rule.** For "no external resource", the unit to check is what is SERVED, not what is committed. The new test fetches `/` and scans the served HTML and the static tree for the three hosts and for any link to the two pages, and for the pages themselves it asserts the route is absent (404) by default and present with the exact value `OO_API_DOCS=1`. A framework default that serves a page is a decision somebody else made: when adding or upgrading a framework, list the routes it registers on its own (`app.routes` before and after you add your first route) and read each one's HTML.

**How it was proved.** Mutant-first: always serving the pages, always exempting them from the CSP, accepting `true` as the switch, restoring the fallback page's link and restoring the Help link each turn a named test red. The switch-on half runs in a child interpreter because the switch is read once at import and the `app` singleton is process-wide.

**Not done, stated.** Vendoring swagger-ui so the pages could be on with nothing third-party (option B in R285) is a separate PR with a registry entry and a pin test. The Help panel and the command palette no longer link the pages at all, even with the switch on (they would need to learn the switch's state from the server); `/openapi.json` is the in-app pointer a developer needs.
