## 2026-10-13 — the log half of a sink guard does not see the record half

The exc_info ratchet (`tests/test_no_raw_exc_info.py`) finds the log calls that ask for a traceback. Across `src/bulletin` (every module of it), `src/api/bulletin.py` and `src/briefing/card_audit.py` the same `except` blocks also wrote the exception's own words into the RECORD they return (`str(exc)`, `f"{type(exc).__name__}: {exc}"`, a route's `detail=str(exc)`), beside 34 log calls that asked for the traceback, and those records ride the diagnostics bundle, the backup and the annexes. The ratchet cannot see them, so converting only the log call would have left the passphrase's other door open in the very block just fixed. `_leaks` in `tests/test_runs_log_sinks.py` reads the other half: a handler's bound exception may only be handed to a scrubbing call or to `type()`. Rule: when a handler is converted, convert what it RETURNS in the same edit (the record keeps the class; the words go to the scrubbed log line).

Five things the conversion taught, each a way the next one goes wrong:

1. **Read the directory, do not list the files.** `_SWEEP_MODULES` is `src/api/bulletin.py`, the card audit and a glob of `src/bulletin/*.py`, so a module added later is held to the rule from its first commit. A hand-kept list of three modules left thirteen others (and the routes) outside the guard for as long as nobody remembered them, and a filter added to the expression that builds the list would hide a module again, so the test that checks the list globs the directory a second time.
2. **Class-only moves the words, it must not delete them.** A handler that wrote the words into its record and logged nothing (`gate._degraded`, the narration job's "no local model", the evidence plan's folder check) would lose them entirely once the record is class-only. Each such handler got a `log_failure` line, or, where the only reader is the operator who just asked (a route's refusal, "this folder cannot be written"), `exception_text`: the words stay, the held passphrase is out, and no chained cause is raised (`from None`, because `from exc` makes the traceback print the cause's message).
3. **Messages other code matches on.** `narration_job._OUTAGE_MARKERS` finds an outage by a substring of `fallback_reason` ("the model call failed"); the class-only reasons keep that phrase and put the class in brackets after it, and a test reads `_is_outage` on the new text.
4. **The guard has to be as strict as the rule.** `_leaks` first accepted the exception as an argument of any scrubbing call, so `{"error": exception_text(exc)}` and `log_failure(_LOG, exc, exc)` (the words as the line) passed the source scan and only a behaviour test at that one site could catch them. The sweep now reads `only_scrubbing`: `type`/`isinstance`, and `log_failure` with the exception as its THIRD argument. The few sites that tell the words to the person who just asked (a route's refusal, the evidence plan's folder check) are lines of `_SWEEP_WORDS_KEPT`, keyed by (function, line text) with a count like the bundle writer's table: an allowance per MODULE let `edition["x"] = exception_text(exc)` pass in the routes, and a translator's refused frame, which looked operator-only, rode `bulletin-language.json` in the bundle (a record, so class-only). One helper (`_sweep_leaks`) serves the sweep and the snippet tests, so loosening the sweep's own call fails a snippet test.
5. **Check what a pointer points at, and what a callee returns.** The card audit's producer row said "the log has them" while `observe_producers` logged nothing, so the words were in no place at all (an independent read probed every logger to find out). And `reindex_backlog()` catches its own failure and returns `reason=engine_text(exc)`: a record that stores a callee's returned dict carries the callee's words, so the caller replaced the reason with fixed ones, and the test runs the callee's REAL handler (`session_scope` patched), not a stand-in that skips it. Saved reports are read back whatever build wrote them: `last_card_audit_report` replaces an old row's `error_message`. The same shape one callee further: the hardware gate stores `inference_capability()`'s dict in the edition, and that dict's reasons were written in `src/llm/backend.py` as `str(exc)[:120]`, cut BEFORE any scrub (a prefix of a passphrase survives a scrub that matches whole secrets), so the fix is at the handler that makes the words and the test patches the probe (`detect_gpu`), not `inference_capability`, whose own handler would then never run.
