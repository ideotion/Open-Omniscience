## 2026-10-15 — A stand-in goes at the HTTP session, so the app's own builders and parsers still run (PR #1396)

**Found.** Row F's «analytics 4–5 render from real rows» had only ever been looked at on rows `analytics45_seed.py` writes straight into the tables, which proves the readers read what a script wrote and nothing about what the walk stores. The walk and the stream take their client by injection, but the useful seam is lower: `WikiClient(session=...)` accepts any object with `get(url, params, timeout)`. A stand-in that answers in MediaWiki's shape at THAT seam leaves `build_walk_params`, `parse_walk_batch`, `parse_statistics`, the walker's cursors and samples, the stream parser, `drain_once` and the service's pageview refresh all real; only the network is fake (`src/testing/wiki_standin.py`).

**What it bought.** The generator reads the lane back against a plan computed from the world, never from the lane, and exits non-zero on any difference; the first runs disagreed twice for honest reasons (the walker is round-robin, so `en` took one window past the target; the service refreshes every followed edition's top list, so editions the stand-in had no list for stored empty ones). Both were the stand-in's plan being wrong, found because the plan and the app's rows were two independent computations.

**The rules it gives.** (1) Fake at the session, not at the client's typed methods, so the parsers run; make the stand-in raise on any URL or parameter it does not serve, because an empty answer reads as «nothing happened». (2) Compute the truth from the world, and compare the lane to it; a truth read back from the lane judges nothing. (3) Generated rows are labelled *stand-in* wherever they are shown: a clause that says «real» stays open until a real install supplies it. (4) A socket tripwire for the run is cheap evidence that the stand-in was the only door; do not use the kill switch for it, because the stream correctly refuses to open under it.
