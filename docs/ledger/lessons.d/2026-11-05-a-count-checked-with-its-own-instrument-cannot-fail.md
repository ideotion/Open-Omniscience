## 2026-11-05 — a count checked with its own instrument cannot fail: measure it a second way, and do not let the second way share the first one's filter (PR #1719)

**What was found.** The Law lane stated 260 hosts in `docs/SECURITY.md` and in the consent hover; the catalogues carry 309. The Press lane stated 9,033; they carry 9,035. The guard that pins the number (`test_a_class_lane_states_the_real_host_count`) was green the whole time, because it measures with `_YAML_DOMAIN`, the same regex that produced the numbers in the first place. The regex read `domain:` at the start of a line, and `configs/legal_sources.yml` writes all 51 of its curated rows as `- {name: ..., domain: x, ...}`; and it read ASCII only, while `configs/sources.yml` declares three domains in their own script. Hosts the app seeds and crawls were missing from a statement made to the person about to switch network access on. The Law gap was noticed by a reader who knew one of the hosts, not by a test; the Press gap was found by the independent read of the fix for the first.

**The rule.** A test that checks a number against the procedure that made the number can only catch someone typing it wrong, never the procedure being wrong. When a count is a claim about what a file contains, give the guard a SECOND instrument that does not share the first one's assumptions: parse the file with a real reader and compare the two sets (not the two sizes) in both directions, so a spelling nobody has written yet fails by name. Here that is `yaml.safe_load` over the catalogues against the regex. This is the 2026-09-07 "assert the produced value, not the symbol" trap one level up: there the test asserted a name existed, here it asserted a number agreed with itself.

**The second instrument must not inherit the first one's filter.** The first version of the oracle ran its parsed values through `_HOST_SHAPE`, the same ASCII check that had hidden the native-script names, so a declared domain the shape check cannot read vanished from BOTH sides and the comparison still said "agree". It survived a mutant (the oracle re-filtered by shape) because today every declared domain passes. The fix is to refuse, not drop: the oracle reports a declared domain the shape check cannot read, by name. And a guard whose two halves agree today is not proven until it has been shown to FAIL: the comparison is a function (`_sweep_problems`) with its own test on small files written for the purpose, one per way a count goes quietly short (a spelling the regex cannot read; a domain the shape check drops).

**The corollary for a regex over structured text.** If the format has two spellings of the same thing (YAML block and flow), a regex written from the first example you saw reads one of them. Pin each spelling you know with a table row, and pin the near-misses that must NOT match (`subdomain:`, `source_domain:`, a comment) so that widening the pattern cannot quietly widen the meaning. Mutate the pattern both ways (back to the old one, and with its anchor removed) and see the table fail. State the limit you accepted in the pattern's own comment: the flow branch is not tied to a real mapping, so `{domain: x}` in a comment or a quoted string would match; no file has one, and the oracle fails by name if one ever does.

**What is not guarded.** Both instruments look for a key called `domain`. A catalogue that carried hosts under another key would be missed by both and the count would agree with itself again. `test_every_host_literal_in_the_tree_is_enumerated` covers URL literals anywhere in the tree, which is the other half, and `_URL_HOST` is ASCII too: a native-script host written as a URL would be cut short; no catalogue has one.
