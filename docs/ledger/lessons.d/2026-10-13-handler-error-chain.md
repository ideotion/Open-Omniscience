## 2026-10-13 — a log call that scrubs is not a log call that cannot leak: the handler's own failure prints the original

`secret_scrub.log_failure` (and before it `exc_info=True`) hands a handler a scrubbed record, but when the HANDLER fails (a full disk on a `StreamHandler.flush`, a closed stream) `logging.Handler.handleError` prints the handler's own traceback to `stderr`, and that traceback's `__context__` is the exception the code was handling when it logged: the driver's error, unscrubbed, with the passphrase in its text. The record's scrub never ran on it. `secret_scrub` now replaces `Handler.handleError` once, at import (a handler can fail at the first record of a boot), with a one-line, class-only notice that honours `logging.raiseExceptions`, never logs and never raises; `tests/test_handler_error_scrub.py` fails when it goes (a non-vacuous control runs the stock method and must leak) and when a handler class in `src` defines its own `handleError`. `logging.raiseExceptions = False` alone was refused: it also silences the signal that the disk is full.
