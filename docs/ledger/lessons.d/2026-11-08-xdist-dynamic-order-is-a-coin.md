## 2026-11-08 — pytest-xdist's own scheduling makes a required check a coin; place the files instead (R597, queue item 27 option B, PR #1816)

**What was found.** CI's wall time on a busy day was not the tests: on #1786's run the jobs waited 90 to 195 minutes for a runner and then ran in about 30. Each run cost about 200 runner-minutes (six full-suite legs of 25 to 31 minutes, pytest about 95 % of each), so a handful of open PRs filled the free runner pool. `-n auto --dist loadfile` on the runner's 4 CPUs ran the whole suite locally in 19 minutes against about 80 in one process.

**What it cost.** Two full runs at ONE commit in xdist's own `loadfile` order failed on three tests and then on four OTHER tests. xdist hands the next file to the first free worker, so which files share a process moves with timing, and this suite has tests that read what an earlier file in the same process left: a lane file in the shared data directory (`test_backup_inventory`), a download registry another test kept alive (`test_process_budget`), the insights read cache answering from before a file's seeds (`test_map_coverage`), and others the run named once and not again. A one-process run in a fixed order hides such a test the same way every time; a timing-driven order shows a different few each run.

**The rule.** (1) Parallelise by a placement that depends only on the files and the worker count: `tests/_xdist_placement.py` deals the collected files longest first on `configs/ci_shard_costs.json` and runs each worker's files in collection order, swapped in by `tests/conftest.py` for `--dist loadfile`, and announced in the log. Then a hidden dependency shows on every run or on none, and the one that shows is fixed in the test (each of the three above now isolates the state it reads). (2) Keep one serial lane (the weekly `portability` job runs one process per leg), so the parallel placement is not the only order anyone ever sees. (3) Before blaming the tests for a slow CI, read the jobs' `created_at` against `started_at`: queue time and run time need different fixes.
