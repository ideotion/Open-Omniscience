## 2026-10-13 — a removal is justified by a test that names what the replacement does not carry

R123 let two buttons ("Keyword log", "Last keyword files, again") go only in the PR whose test showed the Diagnostics archive's keyword digest "carries what they gave". Read literally that is false, and a test written to its words would have been a lie: the log gave the top 5,000 keywords per language, the digest carries a labelled top 100. The test that could be written, and was, compares the two as they are. It pins the key set of the export's summary and the digest's key set (so a key either side gains fails and asks for a decision), compares what is equal, states the two that differ on purpose and how the file says so, shows that the per-keyword sample is the export's own entries, the highest by mentions, with the number left out stated, and shows that the control that stays (the "All keywords" link) begins with exactly the log the removed button built. The removal then rests on a fact the reader can see, not on a word ("carries") that stretches to cover the gap.

Two things made the comparison honest rather than vacuous. A fixture with no user curation compares two empty lists for `overrides` and `supergroups` and passes whatever the digest does, so the test plants a manual merge, a manual split and a super-group, and asserts they are non-empty first. And the low-memory case, where the families are grouped over the first keywords of each language only (R130), is tested in both directions: the digest says so and points at the link that covers the rest, and the export it replaces is partial the same way, so the removal loses nothing against the button. Mutating the code under the claim (one entry short, sorted the wrong way, the count of the rest wrong, the pointer text gone, the digest dropping the corrections, the button back, the route renamed) failed the test every time, which is the check that a "no loss" test is not a "no test" test.

The rule: **when a ruling lets a control go on the condition that its replacement carries the same content, write the test as a statement of the difference (equal keys, labelled differences, what is not carried and where it is), never as "everything it had", and plant the data the claim is about so equality cannot be two empty things.** A consequence no test can pin (here: after a page reload there is no screen path to save the last numbered set again, though its route stays) goes in words to whoever ruled, before the push.
