## 2026-10-17 — AN "INSTALLED" FLAG THAT RETURNS EARLY MUST CHECK THE THING IT GUARDS; RECORD A REAL CALL BEFORE THE GUARD IS INSTALLED AND THE UNDO REMOVES THE GUARD; IMPORT THE MODULE THAT SAVES THE STDLIB BEFORE ANY TEST CAN SWAP IT

(1) **The shape.** `src/ingest/airplane.py` installs wrappers on `socket.getaddrinfo` and four other calls and sets `_installed`; the second install returned at `if _installed` without looking at the calls. A `monkeypatch.setattr(socket, "getaddrinfo", fake)` that runs BEFORE the process's first fetch records the REAL function; the fetch then installs the guard over the stand-in; the undo writes the recorded real function back over the guard. State: `_installed` True, `socket.getaddrinfo` the stdlib's own. Airplane mode refused nothing at DNS, and `install_airplane_socket_guard()` (called by the next test's fixture) was a no-op. `tests/test_dns_proxy_guard.py` did this for every one of its tests; `tests/test_egress_window.py` then reached the real resolver ("Name or service not known") in the same worker. It passed in the full suite by luck of order (an earlier test uninstalled), which is why it looked like a flake of the egress test and was not.

(2) **The fix has a boundary.** The already-installed branch of `_install_patches` replaces only a call that holds a REAL function: the saved `_orig_*` or the stdlib's own, kept in `_REAL_AT_IMPORT` because tests swap `_orig_*` for spies, so "is it `_orig_x`" alone would miss the exact case above. A test's deliberate stand-in is left alone (replacing it would break every test that sets a resolver after the install). A scan test forbids a variable-name `getattr` in `src`, so the standing values come from `_standing_calls()`, a list in a fixed order.

(3) **The second form.** The module saves the stdlib calls when it is IMPORTED. Run `tests/test_dns_proxy_guard.py` alone and the first fetch imported it inside a `monkeypatch` window: the saved "real" `_orig_getaddrinfo` was the test's stand-in (`__module__` `tests.test_dns_proxy_guard`) for the rest of the process. The conftest hook imports it at the first test's setup, before any test can swap a call.

(4) **How it was found.** Not by reading the failing test: by logging, after every test of the worker, whether `_installed` agreed with `socket.getaddrinfo is _guarded_getaddrinfo`, over the same 120 files, and reading where the first disagreement started. A failure that passes alone and in the full suite and fails in a subset is state left by an earlier test of the same worker; log the state, not the failing line.

(5) **Open limits of the stand-in check (recorded here so the docstring is not the only place).** The conftest hook (#1434, extended here) does not support: a class-, module- or session-scoped fixture that installs a stand-in (it is set up in the first test of its scope, so the first test is blamed and the stand-in is taken out under the rest); a `MagicMock` or `functools.partial` stand-in (its `__module__` is the library's, so it is not seen; every stand-in this suite has used is a lambda); a skip raised inside a teardown (the leak is put back but no failure names the test). The airplane snapshot's `_orig_socks_connect` is not covered (its only two swappers restore it; PySocks is not installed in the test environment).
