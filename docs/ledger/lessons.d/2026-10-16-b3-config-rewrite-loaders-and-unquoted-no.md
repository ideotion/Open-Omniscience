## 2026-10-16 — A DATA REWRITE IS PROVED BY COMPARING WHAT THE APP DOES WITH IT, NOT BY GREPPING THE READERS; YAML'S `no` IS FALSE; AND EVERY TOOL THAT WRITES THE FILES HAS TO FOLLOW

(1) **The readers of a rewritten file are found by running the old tree beside the new one, not by searching for them.** Row B3 rewrote 5,699 `country:`/`jurisdiction:` values in 12 configs from lowercase alpha-2 to the wire's alpha-3. A grep for the loaders found five that only `.lower()` the raw value (gazetteer, timeline anchors, events, feed families, catalogue discovery) and the law catalogue; it could not say whether that was all. What can: a throwaway script that loads every catalogue through its real loader and seeds a database (sources, law documents), run once in a worktree of the commit before and once in the tree after, dumping JSON. The two dumps were identical except for one row (below), which is the proof the thing the rewrite had to leave unchanged is unchanged, and it would have caught a sixth reader. **The first version of that dump lowercased what it printed, and said "identical" over a real change:** the events and the feed families have always been read in UPPERCASE alpha-2 (`US`, `EU`, `INT`), the new loader handed them lowercase, and only nine existing tests (which assert the case) turned red. A comparison that normalises its own output proves only what the normalising left alone; the second dump prints values as the loaders return them and the case-sensitive result is the one that counts (one differing row, the Norway fix). The script is not committed (it is a measurement, and its job is done when it says identical); the committed guards are the per-loader tests, each shown red by reverting only that loader.

(2) **A key that looks harmless can be a UNIQUE row.** The law catalogue's `jurisdiction` is the first half of the `(jurisdiction, url)` unique index of `law_documents`. Read as `GBR` beside a stored `uk`, the seeding would have tried to insert a second row at every boot and failed the whole registration with an IntegrityError, in an alpha-2 store and an alpha-3 store alike (the store migration deliberately leaves `uk`, `eu` and `int` as they are, because they have no ISO meaning, R100). Measured before it was written, on both forms, with the old and the new catalogue. The loader now lands a catalogue's jurisdiction on the spelling the rows hold (`law_jurisdiction`: `GBR` and `uk` both read `uk`), and `country` on the app's alpha-2.

(3) **YAML 1.1 reads an unquoted `NO` as the boolean `false`.** One event in `world_events.yml` (the Norges Bank rate decision) carried `country: NO` and had been a Python `False` since it was written: it never said Norway to a loader. The rewrite makes it `NOR`; the equivalence proof (old and new parse differ only in country values, each reading as the same country) needed one explicit exception for exactly this, `False -> NOR`, named in the code so the next reader does not take it for a hole. The 119 quoted `'no'` in `sources.yml` were strings all along. **Rule: a country list in YAML is quoted, or it is wrong for one country; and a check on such a file reads the PARSED value, so a bare `NO` shows up as a boolean, not as text.**

(4) **A rewritten file is only rewritten until the next tool runs.** The catalogues are not only read: a batch merge, an enrichment merge, a tag cleanup and the world-catalogue generator all WRITE country values into them, in the app's alpha-2, and a legal validator and a coverage report READ them expecting that form. Left alone, the next batch merge would have put lowercase values back, and the validator would have refused the shipped file. Each now writes the shipped form (`country_payload`), the validator reads both (its job is shape, and a session's raw output is still alpha-2), the report counts by the app's form, and the repo test names the fix command in its failure message. **Rule: when a data file changes form, list its writers and its checkers before the rewrite, not after; a guard that fails on the next ordinary merge teaches nobody what to do unless it says how to fix it.**

(5) **A "same value" helper must not call junk a country.** `country_payload` returns an unrecognised value as written (so a payload never blanks something). Using it as the validator's membership test accepted `XXX`; the test needed `country_payload_iso3`, which answers `None` for what it cannot place. Two helpers that look interchangeable differ exactly where a check lives.
