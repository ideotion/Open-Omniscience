## 2026-10-26 — A GET that does work is a request a web page of another site can make: refuse it in the route, write where the corpus lives, take one at a time, and free the slot on every exit

**What was found (audit 0.5.0, A-008).** `GET /api/database/backup` wrote a full plaintext snapshot of the corpus into the operating system's temporary directory for ANY GET and removed it after the response. A page of another site can issue a GET with an `<img src>`, so one page view made the machine copy its whole corpus out of the data folder into a shared directory (the route unlinked the owner-only file `mkstemp` made and let the backup API re-create the path, so the copy's mode was not owner-only by construction), as often as the page liked, with nothing to stop a second copy while the first was still being written. (Browsers do not let that page read the response; the harm is the plaintext copy on disk and the disk it fills.)

**What the fix does.** The refusal lives in the route (`_refuse_cross_site`), not in a middleware: `Sec-Fetch-Site` must be `same-origin` or `none` when present, and `Origin`/`Referer` must name the request's own `Host` when present; the stricter of the two decides and a request with neither (curl, a script) is served, because only a browser sends a page's origin and a page cannot omit it. The snapshot goes in a `.oo-backup-*` directory (mode 0700) beside the database, a free-space gate compares the database plus its WAL against the volume (507 with both figures; a volume that cannot be read is not a refusal and the response says `X-OO-Free-Space-Check: not-read`), one snapshot is made at a time (429 for the second), and a `FileResponse` subclass removes the directory and frees the slot in a `finally`, so a client that goes away mid-body leaves nothing.

**Rules.**
1. **A GET that writes, spends CPU or fills a disk is not safe because it is a GET.** If the route does work, it refuses cross-site callers itself; a route that is only safe while a middleware someone else owns stays in place is not safe.
2. **Refuse before the first effect.** The test spies on `mkdtemp` and `backup_to` and asserts neither was reached for each foreign form (another origin, another port of the same host, `Origin: null`, a foreign `Referer`, `cross-site`, `same-site`, and `same-origin` fetch metadata with a foreign `Origin`).
3. **Put a copy of the corpus where the corpus is.** The data folder is the user's, with the user's permissions and the user's volume; the system temporary directory is neither. And say what a gate could not read instead of treating "unknown" as "fine" or as "refuse".
4. **A claim on a shared slot is released by the code that will not run if the response does not.** The slot is released in the response's own `finally` (and by `BaseException` before the response exists), and a claim whose response never ran is taken over after a stale age, so a crashed handler cannot lock the route for the process. The sweep removes only `.oo-backup-*` directories older than that age, so several servers on one data folder (R176) never delete another's live snapshot.
