## 2026-10-17 — A read inside the gate hold that can only return nothing is a statement every other writer waits behind (PR #1421)

**What was found.** `index_article` read the article's stored mention rows inside the write-gate hold, one statement per article, to diff them against the rows the pass produces. The batched collect flush calls it for articles it has just INSERTED in the transaction it is still in, so the read cannot return a row, and it lengthens the hold that the whole write queue waits behind (the longest recorded holds are made of per-article statements). The case that could have made "nothing" false is an id handed out again after a delete (SQLite keeps no counter without AUTOINCREMENT, `src/database/query.py`): the old article's mention rows would be met by the new one. They are not there, because every pooled connection runs `PRAGMA foreign_keys=ON` and the mention model's `article_id` is `ON DELETE CASCADE`.

**The rules.**
1. **Skip a read only on the caller's say-so, and say so in the name.** `index_article(inserted_in_this_transaction=True)` is to be passed by `ArticleBatch._index_one` and nowhere else (the one line is in `src/ingest/batch.py`, in the SAME commit as the parameter: a batch that passes a keyword `index_article` does not take fails every article's indexing as "kept unindexed", so a caller and its callee's new parameter ship together, never in two PRs); the default reads, so every other caller (a re-index above all) is unchanged.
2. **Write the reason down as a test that runs the read.** The proof test calls the REAL read before every `index_article` of a batch, including a batch whose first article takes a deleted article's id again, and asserts every answer is `{}`; it also reads `PRAGMA foreign_keys` from the pooled connection, so the premise is measured, not assumed (turning the pragma off fails it).
3. **The claim must fail loud if it is ever false.** The flag on an article that has rows meets the unique index `(keyword_id, article_id)`; the test pins that, so a wrong claim is an error in the batch's savepoint, never a second stored row.
4. **Hand the diff `{}`, not `None`.** `None` means "two rows share a keyword" and takes the delete-then-insert shape: a DELETE statement for nothing. A mutant that passed `None` stored the same rows; only the assertion on what the diff was handed catches it.
5. **A docstring that names the table trips the raw-SQL ratchet.** `tests/test_derived_read_seam.py` counts the literal token in `src/`; describe the model's column instead.
