## 2026-10-15 — A NUMBER FROM THE ENGINE AND THE SAME NUMBER FROM THE BYTES ARE TWO READINGS, A RESET IS KEYED TO THE PATHS IT USED, AND AN ALLOWANCE BY NAME NEEDS ITS BODIES READ (the boot page check, PR #NNNN)

(1) **"Pages in the file against the header's" is two readings, and each one says what it cannot see.** The header's own count (bytes 28 to 31) is read from the file's first 100 bytes with no engine, so it can run at boot before any connection exists (a connection that opens and closes a WAL store unlinks the `-wal` and rewrites the header); but a SQLCipher file has an encrypted first page, so the answer is `encrypted-or-foreign` with the file's length alone, and a page size nobody could read is never divided into it. The engine's `PRAGMA page_count` can read an encrypted store, but when the header's size is not valid (zero, or the change counter in bytes 24 to 27 differs from the version-valid-for number in bytes 92 to 95) SQLite answers the file's length instead, so a difference of 0 from that source does not rule out a stale header. Rule: a figure that comes from two instruments travels with its `source` and with `header_valid` (`None` for the engine, never `True`), and an absent figure carries its reason (`no-file`, `empty`, `short`, `bad-page-size`, `unreadable`) and is never a zero. A torn tail (`trailing_bytes`) is counted apart and never rounded into a page.
(2) **A reading that has to describe the file the PREVIOUS session left is taken before anything can change it, and the order is pinned on the source when the test cannot reach it.** The unlock takes `from_connection` off the verify connection BEFORE `_close_after_checkpoint` folds the log into the file; a reading taken after it describes what the unlock left. The behavioural tests stub the close out (they have to), so `test_the_unlock_reads_the_pages_before_the_connection_that_proved_the_key_is_checkpointed_and_closed` compares the two positions in `_unlock_locked`'s source and names itself a mutation target.
(3) **A reset that decides "was it touched" from module state is blind to the path that tried and failed, and one that resolves the directory at teardown is not free (lesson 15 of the journal's PR, refined).** The first fix for the reindex-job reds skipped the removal when `_LOADED or _STATE or ...` was false; a journal that could not READ its file (EIO, the folder gone) left none of those set, so its file was kept, and a touched journal still resolved `data_dir()` at the reset. The journal now remembers the PATHS it used (`_used_path()` adds each one it resolved to a set under a leaf lock) and the reset removes exactly those and the `.tmp` beside each, inside `suppress(Exception)`, without resolving anything; `keep_file=True` leaves both the set and the file. A test makes the resolver raise and counts calls (0 across both a touched and an untouched reset), and another has a read fail first and asserts the file is gone. Rule: a reset removes what the instrument recorded it used, and the recording is made where the path is resolved, not guessed afterwards from the state it left.
(4) **An allowance by NAME in a sink guard excuses every body that name ever has.** `_SLOT_PRODUCER_SCRUBS` treats a call to `_label` or `_internal_failure` as a scrub, so a later `return f"{name}: {exc}"` inside `_label` would be excused without a test failing. `_CLASS_ONLY_HELPERS` pins the BODIES, default-deny: the exception parameter may appear only as an argument of an allowed call (`type`, `isinstance`; `_label`, `log_failure`) or as `.errno`, so `str(exc)`, an f-string, `exc.args`, `repr(exc)`, an alias (`held = exc`) and `exc_info=exc` are each reported, and seven planted bodies prove it. The test also asserts the helpers it checks are exactly the ones the guard excuses, so a third excused name cannot slip in beside them.
(5) **A negative assertion on a log needs a positive control that the line was logged.** `assert MARKER not in caplog.text` passed vacuously whenever the pool watch's 30-second throttle swallowed the invalidation line (conftest resets the throttle today; if that reset goes, the check goes with it). The test now asserts `"pool connection invalidated: held by oo-osm-" in caplog.text` first. The same family: a relaxed `>=` on a value that must strictly grow lets a mutant that never merges pass; the sampled seconds are compared with `>` again, and a module global the tests set (`writer._JOURNALED_HOLD`) is restored by the fixture that owns the journal.
