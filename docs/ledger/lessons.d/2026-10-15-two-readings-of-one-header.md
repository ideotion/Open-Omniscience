## 2026-10-15 — A NUMBER FROM THE ENGINE AND THE SAME NUMBER FROM THE BYTES ARE TWO READINGS AND A -WAL CHANGES BOTH, A RESET IS KEYED TO THE PATHS IT USED, AND AN ALLOWANCE BY NAME NEEDS ITS BODIES READ (the boot page check, PR #1389)

(1) **"Pages in the file against the header's" is two readings, and each one says what it cannot see.** The header's own count (bytes 28 to 31) is read from the file's first 100 bytes with no engine, so it can run at boot before any connection exists (a connection that opens and closes a WAL store unlinks the `-wal` and rewrites the header); but a SQLCipher file has an encrypted first page, so the answer is `encrypted-or-foreign` with the file's length alone, and a page size nobody could read is never divided into it. The engine's `PRAGMA page_count` can read an encrypted store, but it is NOT the header's count: with a `-wal` it is the database's size at the log's last commit, and when the header's size is not valid (zero, or the change counter in bytes 24 to 27 differs from the version-valid-for number in bytes 92 to 95) SQLite answers the file's length instead. So the engine's field is `pages_in_database` and never `pages_in_header`, and a difference of 0 (or -1 with a torn tail) from it does not rule out a stale header. Rule: a figure that comes from two instruments travels with its `source`, is named for what that instrument measured, and carries `header_valid` (`None` for the engine, never `True`); an absent figure carries its reason (`no-file`, `empty`, `short`, `bad-page-size`, `unreadable`) and is never a zero; a torn tail (`trailing_bytes`) is counted apart and never rounded into a page.
(2) **A positive difference is not the Asus signature while a `-wal` holds frames; this was found by the independent read, not by the first fixtures.** The first draft called only a NEGATIVE difference normal with a log ("the header counts pages the file lacks"), logged every positive one at WARNING, and tested crafted headers and a plain store with no log. The read ran the engine against an encrypted WAL store whose log held a drained `incremental_vacuum` (what `maintenance.maybe_incremental_vacuum` leaves at any kill in the idle window): the engine counted 3 pages, the file held 103, and the app logged "the file holds 100 pages more than its header counts" about a healthy store; the header-bytes source gave the same positive number after a passive checkpoint that backfilled page 1 but could not truncate under a pinned reader. Either sign is expected with a log (growth gives a negative, a shrink a positive until a checkpoint truncates). The figures stay on the event with `wal_bytes` beside them, and the sentence is written only when there is no log (a log that is there and cannot be looked at, a permission or I/O error, is not "no log" either: only an absent file is, the rest is `wal_error`). Rule: probe an instrument in the state the incident leaves behind (an unclean end: a log with frames), not only in the state of the fixture; `_wal_store_with_a_shrunk_database_in_its_log` in `tests/test_page_reading.py` is that state.
(3) **A reading that has to describe the file the PREVIOUS session left is taken before anything can change it, and a refused passphrase is something.** The unlock takes `from_connection` off the verify connection BEFORE `_close_after_checkpoint` folds the log into the file (pinned on the real close in `test_the_verify_connection_is_checkpointed_through_execute_before_it_closes`, and on the source), with the busy timeout zeroed first so an instrument cannot make an unlock wait. But each wrong key's connection already checkpoints the log into the file and deletes it (`record_session_start`'s docstring said so; the unlock's comment said "the one moment the store can say it"), so a 0 after a typo is the file after the fold. `_REFUSED_ATTEMPTS` counts the refusals under the one-attempt-at-a-time lock and the reading carries `refused_attempts_before`.
(4) **A reset that decides "was it touched" from module state is blind to the path that tried and failed, and one that resolves the directory at teardown is not free (lesson 15 of the journal's PR, refined).** The first fix for the reindex-job reds skipped the removal when `_LOADED or _STATE or ...` was false; a journal that could not READ its file left none of those set, so its file was kept, and a touched journal still resolved `data_dir()` at the reset. The journal now remembers the PATHS it used (`_used_path()` adds each one it resolved to a set under a leaf lock) and the reset removes exactly those and the `.tmp` beside each, inside `suppress(Exception)`, without resolving anything; `keep_file=True` leaves both the set and the file. Rule: a reset removes what the instrument recorded it used, and the recording is made where the path is resolved.
(5) **An allowance by NAME in a sink guard excuses every body that name ever has, and a check of the bodies is only as good as what it refuses to take on trust.** `_SLOT_PRODUCER_SCRUBS` treats a call to `_label` or `_internal_failure` as a scrub. The first body check followed `ast.Name` nodes spelled `exc`, so six bodies passed it: a renamed parameter (the check became vacuous), `traceback.format_exc()`, `sys.exception()`, `exc.errno` interpolated (an `OSError("/home/x", "boom").errno` is the path), a shadowed `type`, and a module-level `_label = repr`. `_CLASS_ONLY_HELPERS` is now default-deny: the parameter must exist and be used and may go only to an allowed call; no name may be bound that is not on the body's list; nothing may be defined or imported inside; the traceback module and `sys.exc_info()` are roads of their own; `.errno` may only feed `isinstance(..., int)` and `errno.errorcode.get(...)`; and `_label`, `log_failure`, `errno`, `type`, `isinstance`, `str`, `repr` are bound at module scope exactly as often as they should be. A parameter default is refused too (`def _label(exc, type=str)` rebinds an allowed callable with no store in the body; the coordinator's check found it), and eighteen planted bodies each fail it; the real source passes with no allowance of its own.
(6) **A negative assertion on a log needs a positive control that the line was logged, and an autouse reset must cover every global the new code adds.** `assert MARKER not in caplog.text` passed vacuously whenever the pool watch's 30-second throttle swallowed the invalidation line; it now asserts the line first. The new `forensics._EARLY_PAGES` leaked from an in-process `_serve()` into the next test's boot exactly as `_EARLY_WAL` had, which is why the conftest fixture exists: it clears both now, and a PAIR of tests (the first takes the early reading, the second asserts it is gone) fails if that goes. The same family: a relaxed `>=` on a value that must strictly grow lets a mutant that never merges pass (the sampled seconds are `>` again), and a module global the tests set (`writer._JOURNALED_HOLD`) is restored by the fixture that owns the journal.
(7) **A test that cuts a program's source with a string anchor is counted by a shared ratchet, and the related battery must include the ratchets.** `_whole_label` spliced the source with two `index("def ...")` calls; `tests/test_source_slicing_discipline.py` counts `.index/.find/.split` taking a literal with `def `/`const `/`class ` in it and fails at one over its budget (230), and it was in neither my battery nor the first CI look (core-only failed it, an hour in). The splice is bounded by the parser now (`ast` node line span), the count is 230 again, and the check that costs nothing is to run the discipline tests with the file you add.
