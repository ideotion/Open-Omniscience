## 2026-10-12 — A PRIVATE SCRUB PER MODULE LEAVES THE NET'S GAPS IN EACH: THE OSM REFERENCE RUN'S OWN EXACT-MATCH `scrub` MISSED A UNICODEERROR'S LETTER, THE OPERATOR'S HELD PASSPHRASE, AND WHAT ITS CHILDREN WROTE THEMSELVES (OSM-lane thread, 2026-10-12, PR #1340, `src/osm/reference_run.py`, `src/osm/ingest.py`, `src/osm/history.py`, `src/osm/completeness.py`, `scripts/osm_*ingest.py`)

The runner had its own `scrub(text, secrets_=...)` (the throwaway store's key, one needle at a time through `scrub_text`) and a hand-made `Type: message` for the two handlers that write a caught exception. Gaps followed, found by the coordinator's checks and not by a test of the runner's own: a `UnicodeEncodeError` from `Popen` (an environment value the locale cannot encode) names the letter and its offset, which no exact-match form of the key matches (PR #1337 wrote the class alone, by hand); the passphrase the OPERATOR's process holds (the session's, `OO_DB_PASSPHRASE`) was never taken out, because the runner only knew the key it had made; and the children wrote the same hand-made `Type: message` themselves (`src/osm/ingest.py` and `history.py` into `report.error`, which rides the child's JSON into the runner's report; the two `scripts/*ingest*.py` and the gazetteer build onto the terminal). The module is now on the shared helpers: `scrub` calls `secret_scrub.scrubbed(text, *secrets)` (every shape of every secret, plus every held passphrase, a too-short secret withholding the text), the handlers and the children's texts write `exception_text(exc, ...)` (a `UnicodeError` by class alone), `exc_info=True` in a child is the same hole (the traceback goes to the stderr the parent reads), so the child's log lines go through `log_failure`, and so does the app's own admin-1 count in `completeness.py`, whose stored `error` was the hand-made form too; the KEYS of a child's JSON are engine text too, so they are scrubbed and two keys that scrub to one text stay apart (`#2`).

**Reusable:** (1) a module that holds a key and writes engine text belongs in `_GUARDED_MODULES` of `tests/test_p0_validation.py` (here `osm/reference_run`: `_run` and `run_phase`, two routed calls), not in `_NOT_GUARDED`. The walk reads only functions that name a secret from `_SECRET_NAMES`, and a secret held as a TUPLE (`secrets_`, passed on as `*secrets_`) is a secret too: the walk maps `secrets_` and accepts an `ast.Starred` of a secret name wherever it accepts the name, so the next tuple is read instead of exempted. (2) The finished report keeps a PATHS-ONLY pass (`paths_only=True`): every engine text was scrubbed where it was made, and a pass of the key over the finished record can rewrite a verdict word the exit code reads (a key `ok`, or a held one); the test sets the verdict word as a HELD passphrase, because the runner never puts its own key in its environment. (3) A child's raw logs hold the child's words unscrubbed, so any store that is LEFT (kept, survived by a group, or half-deleted) has them deleted (`logs_removed` in the report; the removal never raises), and the third signal removes them before the runner goes, since no report follows it. A command is wholly under one `except Exception` that writes `exception_text` (the key lookup and the file stats ran outside the `try` and would have printed a default traceback); the runner's CLI handler is as wide as the run's own. (4) Mutation-check each behaviour test: the "handler written by hand" mutation of the two exception sites fails only the UnicodeError tests, because the `scrub` after it still takes out the key; the held-passphrase and short-secret tests are the ones that fail when `scrub` goes back to one needle at a time.
