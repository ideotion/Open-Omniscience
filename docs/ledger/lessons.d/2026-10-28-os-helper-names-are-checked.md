## 2026-10-28 — A fault injected under a name that does not exist injects nothing: the os helpers' names are now checked, and one "unreached" patch of the #1602 audit turned out to be a guard (R385, after R351/#1615)

**What was found.**
1. **`scope_os(monkeypatch, mod, replcae=f)` passes silently.** The helper replaces with `raising=False` so that a name the platform lacks (`os.statvfs`, `os.ST_RDONLY` on Windows) stays replaceable for the tests that model that platform; the price is that a misspelt name creates an attribute nothing reads and the test goes green without injecting anything (the same vacuity as #1615, made by a typo). Measured on main 7a67e1184: 136 literal names across `scope_os`, `scope_os_path` and `hide_os` call sites in `tests/`, all 136 exist on the platform the suite runs on, so nothing is wrong today. `tests/test_os_scope_helper.py` now reads every call site (AST) and fails on a literal name that is not an attribute of `os` (or `os.path` for `scope_os_path`), on the exact line; the scanner is pinned on nine cases, and the tree test also fails if it reads no call of one of the three helpers. Mutant: `replace=` misspelt as `replcae=` at one site in `tests/test_briefing_shared_files.py` turns the tree test red on `test_briefing_shared_files.py:72 scope_os(replcae)`.
2. **Skipped on Windows, with its reason.** The names the suite replaces only to model a platform that lacks them are absent from Windows' `os`; the check is made on Linux and macOS, where every call site is covered.
3. **One of the "never reached" replacements named in the #1602 audit is a guard, not a vacuous patch.** `tests/test_diagnostics_runs.py::test_no_clock_and_no_process_start_time_decides_what_is_this_process` replaces `getpid` after the run began; the read path never calls it (a run is "running" because it is in `_RUNNING`), which is the expected count of zero for a guard. Mutant-first: change the read to decide by pid (`elif begin.get("pid") == os.getpid()` in `src/monitoring/diagnostics_runs.py`): with the replacement the test is RED, without it GREEN. So the replacement has the power the test claims, and nothing was changed except a comment saying so. The #1602 lesson counted it among "patches the code under test never reaches"; that classification was wrong in kind (it reaches the code only if the code regresses).

**Rules.**
1. **A helper that tolerates absent names needs a separate check that the names are real.** Leniency for a platform difference is a hole for typos unless something reads the call sites.
2. **"Zero calls" is the right count for a guard.** Before calling a never-called replacement vacuous, run the mutant that makes the code read it.

**Not covered, stated.** Names that are correct but not READ by the module under test (the per-test call-count assertion of #1615 covers that, case by case); a name built at run time (`**{NAME: f}`, a variable passed to `hide_os`) has no literal to check; Windows. No `src` file changed.
