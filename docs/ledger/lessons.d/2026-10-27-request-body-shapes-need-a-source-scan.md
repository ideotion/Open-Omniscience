## 2026-10-27 — a count of route body shapes read from the schema misses the handlers that parse the body themselves

**Found (audit 0.5.0 item 35, item 3).** The first draft of the request-body inventory counted the 317 state-changing operations by what the OpenAPI schema says they declare: 165 JSON, 148 none, 4 multipart/form-data, and a source grep for `request.body()` found ONE handler that reads a raw body (`POST /api/claims/trail-bundle/verify`). That table was sent to the coordinator and written into a proposal. It was wrong in the direction that matters: two corpus-WRITING upload routes, `POST /api/newsletters/import` and `POST /api/documents/pdf/upload`, take `request: Request` and call `await request.form(max_files=...)` themselves, so the schema shows them as "declares no body" (inside the 148) while they are multipart in practice. The grep missed them because it looked for four literal spellings of `request.x()` that did not include a call with keyword arguments. The AST scan that replaced it found them on its first run, in the test written to pin the five shapes. Probing them showed the consequence: both answer 200 to NO body and to any Content-Type (`text/plain`, urlencoded, JSON, octet-stream), and an empty POST to the newsletter import still get-or-creates the "Imported newsletters (.eml)" source row. Behind them stands the Origin layer alone; the strict JSON check cannot apply to a route that declares no body.

**Rule.** (1) A statement of the form "N routes take X" is made from BOTH the schema (what is declared) and a scan of the handlers (what is read): a handler that takes `Request` and parses it by hand is invisible to the schema and is exactly the shape a declared-body layer does not guard. (2) The scan is an AST walk for a call to `.body()/.stream()/.form()/.json()` on a request-named variable, not a text grep for spellings, and it is tested against synthetic sources (it must flag the four readers and stay quiet on `request.url`, `request.headers` and an HTTP client's `response.json()`). (3) A pin of such an inventory fails by the route's NAME, so a seventh body shape or a fourth raw reader is decided in the PR that adds it. (4) A claim sent upward ("only one handler reads a raw body") is re-derived with the second method before it is written into a proposal.

**Limits.** The scan sees a request read through a variable named `request`, `req` or `http_request`; a handler that builds a `starlette.requests.Request` from a scope or reads `receive` directly is invisible to it. The Content-Type table measured one request per cell with a trivial payload and status only.
